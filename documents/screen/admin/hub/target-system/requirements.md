# 요건 정의서 — 대상 시스템

## 개요

- **무엇을 하는 화면인가**: API 도구의 Base URL·인증 방식 등 접속 정보를 제공하고, Portal 사용자에게 대상 시스템 계정을 매핑할 기준 정보를 제공한다. 실제 사용자 계정 매핑은 Portal 사용자 관리에서 설정한다.
- **프로세스상 위치**: 운영 배포의 YAML 기술 정의 → 기동 동기화 → 이 화면의 표시 정보 보완·연결 확인 → API의 대상 시스템·명시 연결 선택 및 Portal 신원 매핑.
- **이 데이터를 누가 쓰나**: API 관리, Portal 사용자 신원 매핑, agent 및 저장된 워크플로우 실행 전 검사. 계정 매핑은 접속 자격증명이나 API 권한을 대신하지 않는다.
- **바꾸면 어디가 흔들리나**: YAML에서 제거된 시스템/연결은 DB 참조를 보존하지만 현재 호출은 차단한다. REQ-601.asset_availability의 관리자 경고·현재 유효성 검사에 연결한다.

> 2026-11-01 사용자 승인 설계다. 제품 화면·서버·시드는 아직 미구현이다. system 환경설정의 YAML 기본값과 DB 보완값 분리 원칙을 사용하되, 그 기존 구현이 기동 DB 동기화나 DB 잔재 노출을 이미 제공한다고 보지 않는다.

## 3. 조회 — 테이블과 범위

DB의 시스템·연결 메타데이터를 기준으로 조회해 YAML 제거 항목도 보존한다. 현재 실행에 사용하는 동일 배포/설정 버전의 유효 YAML을 대조한다. 주소와 인증 방식은 현재 로드 정의의 서버 정제 투영이며 원문·비밀값·헤더·암호문은 반환하지 않는다. 실제 누락/확인 실패 시 이전 현재값을 재사용하지 않는다. 여러 노드가 서로 다른 구성으로 DB 현역 상태를 덮어쓰지 않도록 동기화 기준을 통일한다.

## 6. 규칙 — 저장 · 실행

### 6-1. YAML·DB 소유와 동기화

- 기술 정본은 YAML이다. 식별자·소속·Base URL·인증·자격증명 참조·테스트 설정을 화면에서 바꾸지 않는다. 전체 YAML 검증 성공 후 DB에 추가/변경만 반영하며 제거 항목을 물리 삭제하지 않는다.
- 동기화는 YAML 소유 기본값/정의 상태만 갱신하고 관리자 보완값과 최초 등록 감사를 보존한다. 동일 내용 재기동에 수정 이력을 반복 생성하지 않는다. 이름/설명 원천의 우선순위는 REQ-604.authority를 따른다.
- 불일치와 기술 유효성은 서버 판정이다. YAML 읽기 실패를 일괄 삭제로 처리하거나 과거 주소를 실행에 사용하지 않는다. 상단 불일치 집계 ON만으로 시스템 전체를 차단하지 않는다. 시스템 자체 정의 상태(systemDefinitionStatus)가 MISSING이면 그 시스템의 모든 하위 호출을 차단하고, 특정 연결만 MISSING이면 그 연결을 사용하는 API만 차단한다. 같은 시스템의 다른 현재 유효 연결과 API는 계속 사용할 수 있다. UNKNOWN은 정상으로 간주하지 않는다.
- 변경 권한자가 직접 보완값과 사유·전후 이력을 저장한다. 관리자 간 승인 요청과 지식 본문 영향 검토 절차를 추가하지 않는다. SCR-040은 이 화면을 읽기 전용으로 상속하고 현재 관측을 과거 값으로 합성하지 않는다.

### 6-2. 호출·신원·경고

- API는 대상 시스템 선택 후 해당 시스템의 유효한 연결 식별자를 필수로 선택한다. 기본 연결·다른 호스트 자동 대체는 없다. 신원 매핑은 Portal 사용자+대상 시스템 기준이며 접속 자격증명/그룹 권한과 별개다.
- REQ-601.asset_availability에 따라 일반 호출·저장된 워크플로우의 예약/수동/재시도/재개에서도 호출 직전 현재 시스템·연결과 자산 사용 여부를 검증한다. 설정 누락이면 전송 전에 오류를 남기며 이미 수행된 앞 작업을 자동 재실행하지 않는다.
- 제거 원인과 저장된 참조 관계로 영향 API·도구·워크플로우를 집계해 관리 대시보드에 경고한다. 자동 판정은 수동 사용 여부를 OFF로 덮어쓰지 않으며 복구도 수동 OFF를 ON으로 바꾸지 않는다.

### 6-3. 접속 테스트

- READ+EXECUTE와 테스트 설정·현재 유효 연결을 서버에서 재검사한다. 임의 URL·헤더·인증값을 브라우저에서 받아 시험하지 않는다. YAML의 GET/HEAD 확인용 경로·제한 시간·성공 기준만 사용한다.
- 결과는 성공/실패/시간 초과/확인 불가와 확인 시각·소요 시간으로 구분한다. 시험 성공은 업무 API의 권한·사용자 신원·개별 계약 성공을 보장하지 않는다. 비밀 응답·원문은 결과/로그에 반사하지 않는다.
- 목업 결과는 명시적인 정적 검토 예시이며 실제 호출·서버 저장·연결 유효성 판정을 수행하지 않는다.

| 상세 API-002 | getOne | /service/admin/targetSystem/getOne | READ | id → 보완값/기준 버전·현재 설정 근거 |
| 연결 API-003 | getConnections | /service/admin/targetSystem/getConnections | READ | 시스템 식별자 → 불일치 포함 연결 목록. API 후보는 validOnly 적용 |

| 보완 저장 API-005 | save | /service/admin/targetSystem/save | SAVE | 기존 id/expectedVersion/commandKey/표시 보완값/reason → 성공 또는 충돌 |

| 접속 테스트 API-070 | testConnection | /service/admin/targetSystem/testConnection | EXECUTE | 시스템/연결 키 → 비밀 없는 테스트 결과·확인 근거 |

삭제 API는 제공하지 않는다. 관련 현재 경고는 API-071 getConfigurationAlerts가 소유하며 관리 대시보드에서 소비한다.

## 8. 시드 · 데이터 전제

HUB_TARGET_SYSTEM READ/SAVE/EXECUTE/EXPORT의 계획이며 실제 시드 변경은 하지 않는다. MSG.ADMIN_TARGET_*는 구현 시 등록할 라벨 키다. YAML의 선택 이름/설명은 DB 기본값과 분리하고 비밀 연결 설정은 보호된 배포 경로만 사용한다. 운영 공통코드·SYS_CONFIG에 주소·비밀값을 넣지 않는다.
