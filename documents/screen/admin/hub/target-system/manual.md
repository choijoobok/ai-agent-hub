## 1. 먼저 알아 둘 것

시스템과 연결은 운영 담당자가 서버 YAML에 정의합니다. 이 화면에서는 등록된 시스템·연결의 이름과 설명을 보완합니다. 서버 주소·인증값·연결 종류를 편집하거나 일반 행 추가·삭제를 할 수 없습니다. 서버 재기동 뒤에도 표시 보완값은 유지됩니다.

## 2. 표시 정보 보완

1. 시스템을 조회하고 한 행을 선택합니다. 연결 상세가 로드되면 이름과 설명을 편집할 수 있습니다.
2. 시스템명·설명 또는 연결 정보 탭의 연결명·설명을 셀에서 수정합니다.
3. 상단 **저장**을 누르고 새 변경 사유를 입력합니다. 선택 시스템과 연결의 표시 보완값을 함께 저장합니다.
4. 성공 확인 후 목록이 재조회됩니다. 실패하거나 버전이 충돌하면 입력을 보존하므로 현재값을 확인한 뒤 다시 작업합니다.

**표시 보완을 YAML 기본값으로 복원**은 선택 시스템과 모든 연결의 보완값을 편집본에서 해제합니다. 저장해야 반영됩니다. 설명을 빈 문자열로 입력하면 명시적 공란이며 기본값 복원과 다릅니다. 이름을 비우면 YAML 이름 또는 식별자로 돌아갑니다.

## 3. 연결과 사용 API 확인

불일치는 시스템 자체 또는 현재 남아 있는 일부 연결이 YAML에서 사라졌다는 뜻입니다. 일부 연결만 누락되면 같은 시스템의 정상 연결은 유지됩니다. **확인 필요**는 정상 판정이 아닙니다. 현재 정확 연결을 확인할 수 없으면 과거 주소·인증 방식을 현재값으로 표시하지 않습니다.

사용 API 정보는 탭을 활성화할 때 조회합니다. 현재 업무 API 관리 기능은 후속 구현 대상이므로 **업무 API 관리 기능이 아직 연결되지 않았습니다**라고 표시합니다. 이 안내를 사용 API가 없다는 확정으로 해석하지 않습니다. 이후 일반 REST와 SAP API가 같은 자산 ID를 사용하는 목록으로 연결됩니다.

## 4. 연결 테스트

현재 READ·EXECUTE 권한, 유효 연결, 서버의 시험 설정이 모두 있어야 **연결 테스트**가 활성화됩니다. 미저장 편집이나 처리 중에는 실행할 수 없습니다. 저장 권한과 실행 권한은 별개입니다.

버튼을 누르면 YAML에 정한 GET 또는 HEAD 시험을 실제로 실행하고 성공 여부·확인 시각·소요 시간을 안내합니다. 임의 주소·인증값을 입력하지 않습니다. 시험 성공은 개별 업무 API나 Portal 사용자 신원 검증의 성공을 뜻하지 않습니다. 목업 링크의 결과는 정적 예시입니다.

## 5. 누락 항목 정리

1. 미저장 변경을 저장하거나 되돌리고 상단 조회조건을 지정합니다.
2. **누락 시스템 일괄 정리**는 조회조건 전체의 누락 시스템, **누락 연결 일괄 정리**는 선택 시스템의 전체 누락 연결을 미리 보여줍니다. 현재 페이지나 선택한 하단 행에만 한정하지 않습니다.
3. 참조가 남거나 참조·허용 기동을 확인할 수 없으면 전체 실행이 차단됩니다. 기존 API·사용자 연결을 자동 삭제하지 않습니다.
4. 전체 대상과 새 사유를 확인한 뒤 실행합니다. 대상이 없으면 확인 버튼은 비활성화됩니다. 미리보기는 5분간 유효하며 그 뒤나 설정·참조가 바뀌면 다시 조회해야 합니다.
5. 성공 시 현재 메타와 정리 결과·이력을 원자 반영합니다. 연결만 정리하면 부모 시스템은 남습니다. 과거 이력·서버 YAML·외부 업무 데이터는 그대로입니다.

응답을 받지 못하면 **원 명령 결과 확인**으로 같은 명령을 확인합니다. 새 명령으로 중복 정리하지 않습니다. 정리로 점검 대상이 사라진 경고는 해소되지만, 이것은 외부 접속이 복구됐다는 뜻은 아닙니다.

## 6. 후속 제공 범위

업무 API·워크플로우의 실제 소비, 관리 대시보드 경고 영역, 별도 관리 변경 이력 화면, SAP OData 호출은 후속 소유 기능에서 제공합니다. 현재 Portal 사용자 신원 매핑은 이 시스템 기준과 연결되어 있습니다.
