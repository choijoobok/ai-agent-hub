## 1. 먼저 알아 둘 것

대상 시스템은 API의 접속 정보와 Portal 사용자가 사용할 대상 계정 매핑의 기준입니다. 시스템과 연결을 새로 만들거나 삭제하려면 운영 담당자가 배포 YAML을 변경해야 합니다. 이 화면에서는 시스템명·연결명·설명을 보완합니다. 화면의 수정값은 재기동 후에도 유지됩니다.

## 2. 표시 정보 보완

1. 시스템을 조회하고 한 행을 선택합니다.
2. 시스템명·설명 또는 연결 정보 탭의 연결명·설명을 셀에서 수정합니다.
3. 저장으로 선택 시스템의 표시 보완값을 반영합니다. 다른 행으로 이동하거나 재조회할 때 미저장 안내를 확인합니다. 행의 되돌리기는 해당 행 입력만 취소합니다.

식별자·Base URL·인증 방식은 조회만 가능합니다. YAML과 관리자 보완값이 모두 없으면 이름 대신 식별자를 표시합니다. YAML 기본값 복원과 설명을 빈 값으로 보완하는 동작은 구분합니다.

## 3. 연결과 사용 API 확인

연결 정보 탭에서 서버 설정 불일치 스위치와 설명을 확인합니다. 상단 켜짐은 시스템 자체 또는 일부 연결을 운영 YAML과 맞춰야 한다는 경고입니다. 특정 연결만 없어진 경우 다른 정상 연결까지 중지하지 않습니다. 시스템 자체 정의가 없어졌을 때는 그 시스템의 모든 연결을 사용할 수 없습니다. 확인 필요는 정상이나 단순 꺼짐이 아닙니다. 사용 API 정보 탭에서 해당 연결을 사용하는 API를 찾고 API 관리에서 수정합니다. 각 API는 사용할 연결을 직접 선택하며 기본 연결은 없습니다.

## 4. 접속 테스트

테스트 설정과 현재 실행 권한이 있는 유효 연결만 접속 테스트 버튼이 활성화됩니다. 연결 행의 버튼을 누르면 그 연결의 확인 결과·시각·소요 시간을 확인합니다. 시험 성공이 개별 API 권한이나 사용자 신원 검증 성공을 뜻하지는 않습니다. 목업에서는 실제 외부 요청을 보내지 않고 검토용 결과만 보여 줍니다.

## 5. 설정 불일치가 보일 때

YAML에서 시스템이나 연결이 제거되어도 목록과 사용 API·신원 매핑은 보존됩니다. 이전 주소로 호출하거나 다른 연결로 자동 대체하지 않습니다. 대시보드의 연결 설정 오류와 영향 목록을 확인하고 운영 설정 또는 API 연결 참조를 정정합니다. 복구되어도 관리자가 사용 중지한 자산은 자동으로 사용 상태가 되지 않습니다.
