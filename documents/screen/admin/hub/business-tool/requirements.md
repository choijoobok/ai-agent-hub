# 요건 정의서 — 업무 도구

## 개요

- **무엇을 하는 화면인가**: REQ-612의 Hub 내부 서비스 빈 기반 도구를 등록하고 사용 가이드·입출력 구조·코드 의미·그룹·마스킹을 한 구성으로 관리한다. 업무 API 화면의 편집 흐름을 공유한다.
- **프로세스상 위치**: 구현 배포·검수 → 전용 레지스트리의 서비스 빈 선택 → 7탭 보충 설정 → 전체 검증·직접 저장 → 지식 연결 및 현재 권한 안에서 호출.
- **이 데이터를 누가 쓰나**: agent가 지식 연결·권한·입력·현재 구현 계약을 확인한 뒤 실행한다. 연결 지식 편집은 SCR-011의 소유다.
- **바꾸면 어디가 흔들리나**: REQ-612·114·601의 현재 구성과 전체 이력, 호출·마스킹 통제. 외부 업무 API는 REQ-608의 계약에서 실행 기술자를 구성하며 이 화면에 별도 등록하지 않는다(ADR-042).

### 1-1. 마스터-디테일 연동

- 안정 도구 식별자·기준 리비전의 전체 구성을 확보한다. 다른 대상 선택·재조회·이탈은 미저장 입력 확인 후 수행한다.
- 서비스 빈 선택 시 실행 레지스트리가 자바 타입·제네릭·직렬화/검증 애너테이션으로 분석한 입력/응답 구조를 자동 설정한다. 업무 의미·값 확보·코드·개인정보/마스킹은 관리자가 보완한다. 상단 서비스 빈 정보 리로드로 입력·응답을 함께 동기화한다.
- 서비스 빈을 바꾸면 새 계약과 입력/응답·코드·결과 판정 참조의 차이를 표시한다. 기존 입력을 조용히 삭제하거나 자동 적용하지 않으며 보완 전 저장·호출을 막는다.
- 조회 실패·부분 목록·접힌 탭을 빈 집합이나 삭제로 처리하지 않는다. 중복 저장을 막고 결과 불명은 원 명령키로 확인한다.

### 멱등성과 후속 결과 확인

멱등성은 해당 API·도구 자체의 보장 여부만 설정하며 기본값은 false다. 기간·키 조건 입력/검증은 두지 않는다. true도 실행 승인·재전송 제한을 면제하지 않는다. 결과 확인에 사용할 등록 API는 사용 가이드에서 안내한다. 구체적인 입력값 확보와 응답 해석은 그 조회 API의 자체 가이드·입력/응답 명세를 사용한다. 원 실행의 requestId 등 실제 근거와 연결은 보존하며 부족한 값을 추측하지 않는다. 결과 판정 창은 현재 API·도구 자신의 응답에 대한 판정만 관리한다. 자동 폴링과 결과 불명 원 실행의 자동 재전송은 허용하지 않는다.

### 입력값 확보용 API 선택

값 출처에서 API 조회를 선택하면 조회 API 검색 선택 셀이 활성화된다. API명·대상 시스템·안정 ID로 식별해 선택하고 apiId만 저장한다. 입력 매핑·결과 필드 선택·판 고정 설정은 제공하지 않는다. 값 확보 가이드에 업무 목적과 주의사항을 작성하면 LLM이 선택 API의 현재 명세/가이드로 파라미터를 구성하고 실제 응답을 해석한다. 예를 들어 주문 식별값이 필요하면 주문 조회 API만 지정하고 찾을 주문의 조건은 가이드와 대화 문맥으로 판단한다. 부족/모호한 값은 질문하며 현재 권한·필수·자료형은 서버가 검증한다. 대상 API 필드 변경만으로 연결 설정 재저장을 요구하지 않는다. 원천·명세 변경 후 현재 호출 검증 실패는 추정 대체하지 않는다. API 조회에서 다른 유형으로 바꾸면 로컬 조회 API 선택을 해제하며 행 되돌리기로 원래 선택을 복원한다. 다른 유형에는 null로 저장한다. 보충 설정 복사에는 조회 API 안정 ID와 가이드를 함께 포함하고 현재 대상 허용 여부를 다시 검사한다.

매핑 활성 여부는 REQ-601.asset_mapping_active를 따른다. 소유 매핑 그리드는 신규/조회 행 모두 설정 스위치로 바꾸고 원 소유 구성 저장과 전체 이력에 반영한다. 역조회 그리드는 같은 원값의 읽기 전용 스위치이며 현재 참조 존재 여부는 기술 참조 보호용 비표시 응답 문맥으로 보존하고 매핑 활성은 원 소유 링크의 별도 값으로 표시한다. 비활성 행도 관리 조회에 남기고 실제 후보/접근/검색/호출 경로에는 활성 링크만 사용한다. 자동 SQL 카탈로그 참조는 읽기 전용 필수 기술 참조이며 임의 해제하지 않는다. 같은 부모의 다른 행/탭 입력·선택과 원복을 보존한다.

## 6. 규칙 — 저장 · 실행

### 6-1. 검증

- REQ-612.internal_invocation을 따른다. system 스케줄 배치의 BatchJobRegistry처럼 전용 인터페이스를 구현한 빈 목록에서 선택하고 고정 진입점으로 호출한다. 스케줄·배치 실행·배치 결과 형식을 그대로 사용하는 화면은 아니다.
- 서버는 저장과 실제 호출 직전에 구현 존재·계약 버전·검수 유효성·현재 권한을 검사한다. 서버 판정 보존 불일치/재확인 설정과 그 기존 참조는 오류 상태로 저장할 수 있지만 정상 실행 계약에는 포함하지 않는다. 임의 빈 이름·클래스·메서드·스크립트는 거부한다. 실행 노드의 레지스트리 확인 실패도 차단한다.
- 7탭과 상단은 TOOL_ID 소유 전체 저장 단위다. 빈의 실제 시그니처/자료형/필수/조회·실행 유형을 UI 편집으로 바꿀 수 없다. 관리자 필드 설명·값 확보 가이드·개인정보 분류는 구현 계약과 대조하며 보호 수준을 낮추지 않는다.
- REQ-608.field_value_mapping의 참조 가이드/직접 등록을 입력·응답 두 영역에 적용한다. 같은 필드의 타입/코드 중복을 거부하고 문자열 001을 보존한다. 자연어 가이드는 허용 조회를 안내하며 임의 SQL/비밀 접근·권한 우회를 허용하지 않는다.
- 결과 판정은 응답의 결과 필드와 직접 등록 코드 항목 ID를 참조한다. 코드/필드 삭제·변경 시 재검증한다. 접수·완료·실패·결과 불명을 구분하고 자연어 명칭이나 미등록 응답만으로 성공을 확정하지 않는다.
- REQ-608.response_access 및 REQ-611의 마스킹 유형/수준을 적용한다. 개인·민감 응답의 그룹별 예외가 없으면 이력과 같은 마스킹을 portal에 적용한다. 허용된 복수 그룹의 같은 유형에서는 덜 엄격한 수준을 선택하고 명시 원문 허용 그룹은 마스킹 해제를 허용한다. 이력 마스킹은 바꾸지 않는다. 비교 불가 유형은 저장 충돌로 보완하고 실행 시 해당 값을 비노출하고 설정 오류를 알린다. 미분류/미등록 응답은 원문으로 통과시키지 않는다.
- 서버가 인증된 사용자·회사·권한 범위·실행 식별자를 신뢰 실행 문맥으로 전달한다. 모델의 입력 JSON으로 해당 문맥을 덮을 수 없다. 내부 도구라는 이유로 실행 사용자 확인·감사·행/필드 권한을 면제하지 않으며 대상 시스템 신원 토큰을 모든 내부 도구에 요구하지 않는다.
- 멱등성은 기본 미보장이며 도구 자체의 보장 여부만 설정하고 추가 설명은 자유 메모로 남긴다. 호출 제한은 1~600초 정수 또는 공란(null=공통값)이다. 초과는 강제 중단·롤백·실패 확정이 아니다. 결과 불명일 수 있으며 자동 재호출하지 않는다.
- 사용 OFF·구현 없음·계약 불일치·확인 불가는 후보와 저장 정의/워크플로우의 후속 호출을 차단한다. 구현 복구가 수동 사용 값을 바꾸지 않는다. 이미 발생한 효과는 소급 취소하지 않는다.
- 현재 변경 권한·기대 버전·전체 구성/참조 검증 후 현재값·전체 이력·명령 결과를 원자 저장한다. 메모에 검수 근거를 기록하며 별도 검수 승인 탭/절차를 추가하지 않는다. 연결 지식은 읽기 전용이다.


### 배열 원소의 의미 매핑

`states[]`처럼 문자열·숫자·불리언 배열인 경우 해당 경로의 각 원소에 코드 의미 매핑을 적용한다. 컨테이너의 배열 자료형을 바꾸지 않고 배열 항목 자료형으로 직접 코드값을 검증한다. 객체 배열은 `items[].status` 같은 스칼라 속성을 선택한다. 배열 전체·객체 자체에는 코드 하나를 매핑하지 않는다. 원소별 의미 해석은 전체 실행 성공 판정이 아니며 배열을 단일 결과 코드로 자동 승격하지 않는다.

### 조건부 보충 설정

고정/기본값·마스킹·식별 용도·형식/시간대/단위·별도 검증 조건은 §4의 적용 조건이 성립할 때만 필수다. 적용 대상이 아닌 값은 null로 저장한다. 출처/분류 변경으로 기존 설정이 불필요해지면 삭제될 설정을 확인하고 같은 전체 저장에서 정리하며 다른 영역의 값을 임의 초기화하지 않는다. 보호값·개인정보 미검수는 이 예외로 우회하지 않는다.

### 스키마 원천·필드 동기화

- 상단 툴바의 서비스 빈 정보 리로드는 선택한 도구의 현재 실행 레지스트리 명세를 요청 시점에 다시 확인한다. 입력·응답을 같은 관측/계약 버전으로 확보하고 차이를 미리 본 뒤 함께 로컬 반영한다. 각 탭에는 JSON 등록/샘플/리로드 버튼을 두지 않는다.
- 리로드한 구조 계약과 배포/계약 버전·관측 근거를 전체 도구 구성에 저장한다. 현재 관측을 과거 이력에 덮어쓰지 않는다. 빈 문자열·실패·부분 조회·미해석 구조를 빈 스키마로 대체하지 않는다. 본문 없음은 명시 선택으로 미리보기/확인한다.
- 필드는 방향/영역과 정적 경로 토큰으로 대조한다. 현재 원천의 새 필드만 자동 추가하며 수동 추가·경로/형/필수 편집과 행별 삭제 컬럼은 제공하지 않는다. 같은 경로는 안정 필드 식별자와 보충 설정을 유지한다. 원천에 없어진 필드는 스키마 일치 여부=false로 표시하고 기존 설정을 보존한다. 자료형/필수 변경은 경로가 있으므로 true인 채 설정 재확인을 요구한다. null/대조 실패는 삭제 대상이 아니다.
- 필드 설정 이관 조작 순서는 **원본 필드 한 행 선택 → 필드 설정 복사 버튼 → 같은 도구/같은 탭의 붙여넣을 대상 필드 한 행 선택 → 필드 설정 붙여넣기 버튼 → 원본/대상 경로와 덮어쓸 설정 확인 → 설정 덮어쓰기 버튼**이다. 붙여넣기는 로컬 편집이며 상단 저장으로 확정한다. 확인 창을 취소하면 대상 설정을 바꾸지 않는다.
- 설명·값 확보/해석 가이드·고정/기본값·개인정보/마스킹·결과 설명 같은 보충 설정만 옮긴다. 경로·자료형·필수·ID·스키마 판정·원천 버전은 복사하지 않는다. 기존 대상값 덮어쓰기는 명시 확인하며 다른 대상/탭·자료형 불일치·정책 변경 권한 없음은 거부한다. 별도 필드값 의미 매핑·결과 판정·다른 필드 참조는 자동 복제/이동하지 않고 명시 재연결한다.
- 각 탭의 스키마 불일치 필드 일괄 삭제는 현재 탭 전체 목록 중 false인 행만 대상으로 건수/경로를 확인한다. 일치·미확인 행은 제외한다. 의미 매핑·코드·결과 판정·값 출처·응답 접근 예외 등의 현재 참조가 있으면 전체 삭제를 막고 해소할 참조를 표시한다. 확인 후 로컬 삭제 표시하며 실제 삭제는 전체 저장에서 서버가 원천·기대 버전·대상/참조·권한을 재검증한 뒤 수행한다. 과거 이력과 실행 근거는 지우지 않는다.
- 불일치 필드는 정리 전 저장하여 설정 이관에 사용할 수 있지만 현재 실행 명세·프롬프트·신규 의미/결과 후보에서 제외한다. 현재 유효 참조가 불일치 필드를 가리키거나 구조 변경의 보충 설정 검증이 끝나지 않으면 정상 실행 계약으로 사용하지 못한다.
- 원천·도출 필드·불일치 판정/대조 근거·보충 설정·명시 정리 결과·전체 이력은 하나의 원자 저장 단위다. 클라이언트가 보낸 일치 플래그만 믿고 삭제하지 않는다. 저장 실패·미리보기 취소는 기존 편집값을 보존한다. 필드 보충 설정의 행 원복은 현재 원천의 구조/일치 판정을 과거 값으로 돌리지 않는다.

### 6-2. 영향 테이블

ENT-015·016 및 도구 소유 논리 하위 구성·그룹·ENT-038을 같은 저장 단위로 관리하고 ENT-067·069·093에 전체 복사한다. API 소유 필드의 API_ID를 내부 도구 키로 사용하지 않는다. 물리 자식 테이블은 화면 합의 후 상세 설계한다.

### 6-3. 상태 전이

로컬 신규/편집 → 전체 검증 → 직접 저장·전체 이력. 실패는 현재 유효본 보존, 결과 불명은 원 명령 조회. 구현 관측과 수동 사용 값은 분리한다.

### 6-4. LLM 입력 준비

[REQ-610](../../../../spec/10-requirements/012-reference-business.yaml)의 `prompt_contract.admin_input_preparation.sources.business_tool`가 이 화면의 **프롬프트 포함 후보 / 서버 집행 / 관리·감사 항목**, 해석 가이드 및 제공 단계·조건을 정의한다. §4의 실제 컬럼과 대응하며 공통 해석 규칙은 같은 절의 `guides`·`conditions`·`stages`를 따른다.

화면 목록/상세 응답을 그대로 모델에 전달하지 않는다. 기존 관리 값을 사용하고 입력 분류용 컬럼·탭을 추가하지 않는다. 실제 조합·전송과 최종 JSON/CLI·API 계약은 업무 지식 관리·전체 흐름 합의 뒤 소유 작업흐름에서 구체화한다. 아래 검수는 설계 대조이며 목업에서 LLM 호출을 시연하거나 제품 실행 검증을 완료한 것으로 표시하지 않는다.

## 7. API

FEAT-021 공개 관리 계약은 documents/spec/50-api/007-admin-api-tool-contracts.yaml을 따른다. 내부 실행 호출은 REST 연결 설정을 만들지 않는다. 외부 업무 API의 실행 기술자는 REQ-608·ADR-042 소유이며 별도 업무 도구 등록을 요구하지 않는다.

## 8. 시드 · 데이터 전제

그룹·마스킹 유형/수준은 현재 권한 안의 기준정보이며 서비스 빈 목록은 실행 레지스트리에서 얻는다. 그림의 구현/데이터는 가상이며 실제 등록·실행하지 않는다.
