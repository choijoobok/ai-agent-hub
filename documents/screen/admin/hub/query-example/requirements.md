# 요건 정의서 — 인증 예제 쿼리

## 개요

- **무엇을 하는 화면인가**: 한 제목 아래 설명과 SQL을 갖는 여러 변형 예제를 관리하고 실행 데이터소스·추출 카탈로그를 확인한다.
- **프로세스상 위치**: 관리자 직접 등록/성공 조회에서 승격 → SQL별 기술 검증 → 묶음 전체 직접 저장·이력 반영 → 허용 SQL 선택·현재 입력 구성·공통 실행 검증
- **이 데이터를 누가 쓰나**: 권한 있는 관리자와 연결 업무의 담당자가 현재 적용값 또는 업무 처리 근거로 사용한다.
- **바꾸면 어디가 흔들리나**: 소유 기능의 저장·권한·참조 및 이력/감사 연결을 함께 확인한다.

> 미구현 화면 초안이며 사용자 화면 합의·제품 구현·G3(설계 승인 게이트) 승인이 아니다. [화면 정본](../../../../spec/60-screens/_index.yaml)과 [기능 정본](../../../../spec/31-features/002-admin.yaml)을 따른다. 표시 예시는 실제 데이터·물리명·운영 기본값이 아니다.

## 1. 화면 구성

상단 조회조건 → 인증 예제 쿼리 목록 → SQL 예제 · 참조 카탈로그 · 관계 참고 · 연결 지식 순서다. 상단은 제목·실행 데이터소스·적용 리비전을 관리한다. SQL·검증 상태·등록 경로는 상단 및 숨김 선택 컬럼에서 제외한다. 폐기 후보 작성·과거 내용에서 후보 작성 버튼과 파라미터·변경/복원 근거 탭은 제공하지 않는다.

첫 SQL 예제 탭은 좌측에 순번·간단한 제목의 목록, 가운데 너비 조절 스플리터, 우측 상단 상세 설명 textarea와 하단 SQL textarea를 둔다. 좌우 편집에 필요한 최소 폭을 유지하고 좁은 화면에서는 가로 스크롤을 제공한다. SQL은 줄바꿈·들여쓰기를 보존하고 고정폭 글꼴로 넓게 편집한다. 순번은 표시 순서이며 보이지 않는 SQL 안정 ID와 구분한다. 행/탭 전환 중 각 SQL의 입력을 보존하며 추가/삭제/원복도 해당 SQL에만 적용한다. 감사 컬럼은 공통 표준을 유지한다.

상위 제목은 같은 업무를 조회하는 SQL 변형의 묶음이며 지식 연결·전체 저장·리비전의 단위다. SQL은 하나 이상 등록한다. 각 SQL은 같은 실행 데이터소스에서 조인·조건이 다른 예시와 조회 목적/사용 상황을 갖는다. 현재 사용자에게 제공할 후보와 필수 참조 완전성은 SQL별로 판정한다. 저장 시 새 사유를 입력하고 변경 사유·원본 근거는 SCR-049(인증 예제 변경 이력)에서 확인한다.

### 1-3. 마스터-디테일·이력 경계

- 선택 변경·조회·이탈 때 미저장 변경을 확인하고 취소하면 선택·입력을 보존한다. SQL 간 이동은 같은 편집본을 유지한다.
- SCR-049는 같은 저장 시점의 상위 제목과 모든 SQL 자식·추출 참조·원 출처를 읽기 전용으로 상속한다. 변경 사유와 기존 복원 근거는 이력에서 확인하며 원 이력을 수정하지 않는다.
- 소유 전체 집합을 확보하고 미열람 SQL/탭을 누락 저장하지 않는다. 현재 권한·기대 리비전·필수 참조를 재검증하고 전체 현재값과 HIST(변경 이력)를 원자 저장한다.

### 3-2. 고정 조건 · 기본 정렬

- 항상 현재 메뉴·액션과 대상 열람 범위를 서버에서 검사한다. 최종 적용본만 표시한다.
- 기본 정렬·페이지 방식·조회 기간/상한·보존 기간·대량 반출 한도는 소유 계약 미정이다. 운영값을 추정하지 않는다.
- 빈 결과·권한 제외·조회 실패·미확인을 구분한다. 명령과 연계 조회의 권한을 자동 승계하지 않는다.

내부 자동 번호와 참조값은 [REQ-601의 자동 식별자 규칙](../../../../spec/10-requirements/011-reference-integration.yaml)을 따른다. 읽기 전용 번호는 입력하지 않는다. 신규 행에는 저장 전 번호가 없고 저장 성공 후 표시된다. 대상 선택은 이름으로 하며 저장되는 참조는 같은 숫자 식별자다. 업무 코드·설정 키·순번·리비전과 구분한다.

### 편집 가능 판단

현재 변경 권한과 허용 상태가 모두 맞을 때만 소유 입력을 편집한다. 과거 이력은 읽기 전용이며 현재 적용본은 현재 변경 권한으로 다시 편집한다. 저장/판정/결과 불명 중 입력과 원 키를 보존하고 새 명령을 잠근다.

### 값 변경 후 연쇄 · 재계산

참조 선택은 안정 ID와 표시명을 함께 유지한다. 검색 문자열은 선택값을 바꾸지 않는다. 다른 대상 선택 시 기존 상세를 섞지 않는다. 외부 리비전 상승에 따른 자동 매핑/내용 동기화는 없다.

### 행 추가 기본값

상위 대상 문맥만 계승한다. ID·처리 상태·실제 수행자/시각은 서버가 정하며 임의로 입력하지 않는다. 업무 판단값은 비워 둔다. 목업 예시는 기본값이 아니다.

### 비노출 저장 컬럼

원 명령 식별자·소유 안정 ID·자기 기준 리비전과 전체 소유 자식 집합을 보존한다. 공개 필드명은 후속 상세 설계이며 내부 대리키 발급 형식은 REQ-601.surrogate_identifier를 따른다. 외부 상세를 소유 저장에 복사하지 않는다.

## 10. 미결 · 확인 필요

- SQL별 추출·현재 입력 구성·길이/개수 상한·SQL 검증 공개 계약·이력 보관 기간은 REQ-302.open 및 소유 상세 설계 후속이다.
- @defer 화면 합의 후 소유 상세 설계 — DB 물리명·와이어 필드·API·공통코드·메시지 키·길이/개수/기간/보존·운영값을 확정한다. 화면 작업은 해당 계약을 추정하지 않는다.

- 사용자 매뉴얼 작성 시 상위 제목 선택 → SQL 추가/행 선택 → 위 설명·아래 SQL 편집 → 다른 SQL과 탭 왕복 → 참조 검증 → 상단 저장·새 사유 → 이력 확인 순서를 포함한다. SQL별 삭제/원복·순번과 안정 ID 구분·예시값 재판단을 안내한다.
