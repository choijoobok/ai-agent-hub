# 스키마 카탈로그

> 업무에서 조회할 테이블·뷰를 등록하고 컬럼 의미와 인덱스 구성을 관리합니다.

**메뉴 위치** AI Agent Hub 관리 › 연동 관리 › 스키마 카탈로그

[카탈로그 전체 화면](./mockup.html#main)

## 1. 준비와 찾기

데이터소스를 먼저 등록하고 업무 설명을 보완합니다. 이번 원천 객체 확인은 PostgreSQL을 지원합니다. 실제 연결 주소와 인증 정보는 서버 설정에서 관리합니다.

데이터소스·업무명·객체 유형으로 [조회]한 뒤 한 행을 선택합니다. 선택한 카탈로그의 전체 구성을 불러오면 편집할 수 있습니다. 상단 행과 하단 탭을 함께 보면서 작업하며, 탭 이동은 입력을 지우지 않습니다.

## 2. 신규 카탈로그 등록

1. [신규 카탈로그]를 누릅니다.
2. 데이터소스와 DB·카탈로그, DB 스키마, 객체명을 입력합니다. 정확한 대소문자를 쓰며 기본 스키마를 자동 추정하지 않습니다.
3. 테이블·뷰를 구분하고 업무명·상세 설명을 보완합니다. 아직 확인하지 못한 내용은 미확인으로 남깁니다.
4. 필요하면 [객체 확인]으로 원천 컬럼과 인덱스 정의를 조회합니다. 이 결과는 참고 자료이며 자동 등록하거나 검수 완료로 바꾸지 않습니다.
5. 상단 [저장]을 누르고 새 변경 사유를 입력합니다. 저장에 성공하면 카탈로그 번호가 발급되고 하단 구성 편집이 열립니다.

[신규 등록](./mockup.html#new)

## 3. 컬럼 정의 보완

[컬럼 정의]에서 행을 추가하고 컬럼명·업무명·자료형·그룹 코드·상세 설명을 입력합니다. 자료형 목록은 선택한 데이터소스의 종류에 맞게 제공됩니다. 기존 값이 목록에 없거나 목록 조회에 실패하면 원문을 보존하고 확인합니다.

사이즈 셀을 두 번 클릭하면 원천 치수를 확인 상태와 함께 입력할 수 있습니다. 문자 길이와 바이트 길이, 숫자 정밀도와 소수 자릿수를 구분하며, 미확인이나 해당 없음을 0으로 입력하지 않습니다. 복합 기본키의 순서는 전체 구성에서 연속되게 입력합니다. 일반 뷰의 기본키는 해당 없음으로 표시합니다.

개인·민감정보 여부와 정보주체 식별 여부도 미확인을 별도로 관리합니다. 마스킹 유형을 확인할 수 없으면 임의 유형을 입력하지 않습니다. 추가 검수·값 해석·시간대·단위 항목은 그리드의 열 설정에서 표시할 수 있습니다.

컬럼 영역의 [저장]은 컬럼 정의만 반영합니다. 상단 마스터나 다른 탭에서 고치던 값은 유지됩니다.

[컬럼 정의](./mockup.html#columns)

## 4. 인덱스 구성

[인덱스]에서 새 정의를 추가하고 정의 종류·이름·유일 여부를 입력합니다. 같은 인덱스에 컬럼을 더하려면 행을 선택하고 [선택 인덱스 구성 추가]를 누릅니다. 저장된 컬럼에서 구성 컬럼을 고르고 순서와 방향을 입력합니다. 유일키는 유일 여부가 예로 고정되며 정렬 방향은 해당 없음입니다.

인덱스 영역의 [저장]으로 전체 인덱스 구성을 반영합니다. 중복 컬럼이나 겹치는 순서는 저장할 수 없습니다. 함수·부분·포함 컬럼이 있는 원천 인덱스는 [객체 확인]에서 원문을 참고하며, 실제 데이터베이스의 인덱스를 만들거나 변경하지 않습니다.

[인덱스](./mockup.html#indexes)

[사용자 그룹]에서 데이터소스에 허용된 그룹을 선택하고, [컬럼 그룹 예외]에서 등록 컬럼을 숨길 그룹과 사유를 입력합니다. 카탈로그 저장 권한으로 두 탭도 저장합니다. 그룹 제거 시 해당 그룹의 컬럼 예외도 함께 정리되며, 저장 전에 대상 그룹과 예외 건수를 확인합니다. 그룹을 사용 중지한 경우에는 예외가 보존됩니다. 예외만 제거하면 그룹의 기본 열람 설정으로 돌아갑니다. 마스킹 기능이 연결되지 않은 동안에는 숨김만 등록할 수 있습니다. 예외의 등록자·등록일시는 최초 저장 때 서버가 기록하고 수정 후에도 유지합니다. 미저장 행과 과거 등록 근거가 없는 행은 공란으로 표시합니다.

## 5. 저장과 복구

각 [저장]은 표시된 영역 전체를 저장하며 새 사유가 필요합니다. 저장한 영역의 변경 표시만 정리되고 다른 영역의 입력은 남습니다. 조회·다른 카탈로그 선택·신규 등록 전에 입력 폐기를 취소하면 현재 편집을 유지합니다.

응답이 끊겨 저장 결과를 알 수 없으면 [결과 확인]을 사용합니다. 원래의 명령과 사유로 결과를 확인하고 필요할 때 같은 입력을 다시 보냅니다. 결과 확인 중에는 새 저장이나 대상 변경을 할 수 없습니다.

## 6. 안 될 때

| 화면 상황 | 조치 |
|---|---|
| 필수 입력과 오류가 있는 셀을 확인하세요. | 표시된 입력과 구성 순서·참조 컬럼을 확인합니다. |
| 기준 정보가 변경되었습니다. 다시 조회해 주세요. | 입력을 보존한 채 최신 구성을 확인하고 변경 내용을 다시 검토합니다. |
| 저장은 반영됐지만 최신 구성을 불러오지 못했습니다. | 다시 조회 버튼으로 저장 결과를 불러옵니다. 같은 변경을 새로 저장하지 않습니다. |
| 마스킹 유형을 확인할 수 없습니다. | 운영 담당자에게 현재 지원 유형을 확인합니다. 기존 값은 유지합니다. |
| 연관 지식 원천을 아직 확인할 수 없습니다. | 연결 기능의 준비 상태를 확인합니다. 지식 참조가 없다는 뜻은 아닙니다. |

## 7. 다른 메뉴와의 관계

데이터소스의 업무 설명·시간대·조회 가이드는 [데이터소스]에서 관리합니다. 이 화면의 [사용 여부]와 검수는 카탈로그 관리값이며 실제 SQL 조회 허용을 대신하지 않습니다. 연관 지식은 원천 연결 상태가 확인되는 범위에서 조회합니다.

조회·저장·엑셀 반출은 부여된 권한을 따릅니다. 엑셀 다운로드는 현재 조회된 페이지의 내용을 받으며, 읽기 전용 사용자는 정의를 바꿀 수 없습니다.

테이블을 선택하면 관계 건수를 읽기 전용으로 확인할 수 있습니다. [테이블 관계 열기]는 해당 테이블이 포함된 관계를 새 브라우저 탭에 표시하며 현재 카탈로그의 미저장 입력은 유지됩니다.
