# 요건 정의서 — 데이터소스

## 개요

- **무엇을 하는 화면인가**: 배포된 DB/DW 연결을 Hub의 안정된 데이터소스 식별자와 연결하고 별칭·파서·업무 메타데이터·적용 가능 그룹을 관리한다.
- **프로세스상 위치**: (선행) 운영 배포에 연결 정의 → **이 화면** → (후행) 카탈로그에서 공개 객체 등록·정책 설정·조회.
- **이 데이터를 누가 쓰나**: 카탈로그·신원 매핑·지식·agent의 SQL 조회. 등록만으로 원천 데이터 접근을 허용하지 않는다.
- **바꾸면 어디가 흔들리나**: 하위 객체·그룹 매핑과 연결 해석. 연결 참조 정정은 동일 대상 근거를 남기며 Hub 식별자는 유지한다.

> 신규 설계 초안이다. 제품 화면·서버·시드는 미구현이다. 기능은 [FEAT-002](../../../../spec/31-features/002-admin.yaml), 별칭·파서·정정·그룹 및 공통 저장은 [공개 계약](../../../../spec/50-api/003-admin-integration-contracts.yaml)이 정본이다.

## 1. 화면 구성

```text
[조회조건 / 조회·신규·저장·삭제]
[데이터소스 — 1:1 현재값 편집 그리드, 전체 폭]
[상하 스플리터]
[적용 가능 그룹·연결 관측·코드 조회 정의·조회 파라미터·코드 조회 결과·컬럼 불일치·인덱스 불일치·사용처]
[선택한 탭의 그리드 — 전체 폭]
```

- 목록 진입 시 자동 조회하며 행은 자동 선택하지 않는다. 상단에는 1:1 현재값을 모아 셀 편집한다. 별도 기본정보 편집 폼은 없다.
- 하단에는 연결 관측·적용 가능 그룹·코드 조회 정의/파라미터/결과·원천 비교·사용처을 둔다. 장문 현재값은 그리드 컬럼과 공통 장문 셀 편집/뷰어로 다룬다.
- 중요한 열을 기본 표시하고 드문 열은 그리드 설정에서 켠다. 엑셀은 표시된 열과 순서를 따르며 숨긴 열까지 자동 포함하지 않는다.
- 저장·삭제 시 사유, 연결 참조 정정 시 동일 대상 근거는 명령 파라미터 창에서 입력한다. 기존 관리값을 수정하는 별도 폼을 만들지 않는다.

행 추가 탭: 적용 가능 그룹·코드 조회 정의·조회 파라미터

- 코드 조회 정의는 데이터소스 기본정보와 저장 단위를 구분한다. 선택 정의의 SQL·결과 매핑·파라미터·조회 정책 전체를 한 버전으로 저장/검증/활성화한다. 기본정보 저장은 정의를 반영하지 않는다. 각 탭은 그리드 하나이며 선택 조회명·버전 문맥을 유지한다.
- 다른 정의·버전·데이터소스 전환 전에 미저장 정의 변경을 확인하고 이전 조회 결과를 비운다. 시험 바인딩 값은 임시이며 카탈로그 운영 바인딩이나 SQL 기본값으로 저장하지 않는다. VERIFIED 이후 정의는 불변이며 복사하여 새 초안으로 수정한다.

### 1-1. 마스터-디테일 연동

- 상단 id로 상세를 읽어 전체 구성·version을 확보한 뒤 한 행을 편집한다. 하단 집합과 상단 셀을 하나의 편집본에 모으고 한 자산 전체를 저장한다. 여러 행 일괄 저장으로 계약을 바꾸지 않는다.
- 미저장 변경 중 행 전환·재조회·이탈은 MSG.ADMIN_ASSET_DISCARD_CONFIRM으로 확인한다. 탭 이동은 입력을 유지한다. 저장/결과 불명 중 편집·신규·행 전환·삭제를 잠그고 원 키 확인/재시도만 제공한다.
- 삭제 후 관리 목록을 다시 조회한다. 보존된 이력은 별도 SCR-041 메뉴에서 원 ID로 조회하며 현재 행을 요구하지 않는다.
- 후보/관측 실패로 저장된 참조를 삭제하지 않는다. 전체 구성을 읽지 못했으면 저장하지 않으며, 읽기 실패 시 이전 대상 값이 새 대상처럼 남지 않는다.

- 과거 구성 직접 진입은 `/admin/hub/data-source/history?targetId={원ID}&historyNo={세트번호}`다. 별도 이력 메뉴의 현재 READ·대상 범위를 검사하며 원 관리 화면의 탭을 열지 않는다.

### 별도 변경 이력 메뉴

- [SCR-041](../../../../spec/60-screens/010-change-history.yaml)는 이 관리 화면의 조회조건·마스터 컬럼·하단 탭을 읽기 전용으로 상속한다. 상단 변경 요약과 이력 저장일시 범위만 추가하며 독립 요건서/목업은 만들지 않는다.
- 저장/추가/삭제·실행·복원 버튼은 제공하지 않는다. 원본별 `_HIST`의 같은 `HISTORY_NO`로 과거 세트를 읽고 원 `REG_DTM`/`MOD_DTM`과 세트 공통 `HIST_DTM`을 구분한다. 현재 연결 관측/사용처/실행 결과는 당시 값으로 대신 채우지 않는다.
- 저장 대상·요약·동시성·별도 메뉴 권한과 보존은 [REQ-601.change_history](../../../../spec/10-requirements/011-reference-integration.yaml), 데이터/조회 계약은 [공통 이력 계약](../../../../spec/50-api/003-admin-integration-contracts.yaml)을 따른다. API-016 목록·API-017 상세는 원 관리 메뉴가 아니라 이 별도 이력 메뉴에서 사용한다.

행별 변경 취소는 [공통 그리드 표준](../../../../../aidd-guide/standard/frontend/grid.md)의 상태 컬럼 되돌리기를 사용한다. 툴바의 편집 취소 버튼은 두지 않는다.

### 4-2. 편집 가능 판단 — 조건부

- READ·SAVE가 있고 선택한 한 자산의 전체 구성/버전을 읽었을 때만 상단과 편집 가능한 하단 집합을 편집한다. READ만 있으면 모두 읽기 전용이다. 관측·사용처·이력은 언제나 읽기 전용이다.
- MISSING 상태도 새 연결 후보와 동일 대상 근거를 확인할 수 있으면 정정 가능하다. UNAVAILABLE이면 검증을 생략하지 않는다. 그룹 후보 계약이 미확정/조회 실패이면 기존 집합을 보존하고 변경하지 않는다.

### 4-3. 값 변경 후 연쇄 · 재계산

- 별칭 비교는 FEAT-002.alias_contract를 따른다. 연결/DBMS 변경으로 기존 파서가 호환되지 않으면 오류를 표시하고 재선택/미지정을 요구한다. 시간대·기준 시각 미지정을 서버 시각으로 채우지 않는다.

### 4-4. 팝업 · 모달 선택 결과 매핑

- 장문 셀 편집은 해당 행의 description·dataBasis만 바꾼다. 저장/삭제 명령 모달의 reason은 새 명령 사유이며 lastChangeReason을 자동 재사용하지 않는다. 배포 참조 정정 모달은 correctionEvidence를 받고, lastCorrectionEvidence와 구분한다.

### 4-5. 행 추가 기본값

- id/expectedVersion=null, 적용 가능 그룹=[], parserId/timeZoneId/dataBasis/description=null. 연결·별칭·DBMS·DB/DW 유형·명령 사유는 사용자가 정한다.

### 4-6. 비노출 저장 컬럼

- id/expectedVersion/commandKey를 원 명령 봉투로 보내고 전체 values는 상단 현재값·하단 집합에서 구성한다. 주체·처리 시각·aliasKey·관측·이력 결과는 서버 근거이며 편집 입력이 아니다.

## 6. 규칙 — 저장 · 실행

### 6-1. 검증

- 코드 조회 정의/바인딩 정본은 REQ-301.value_domain이다. 데이터소스에 여러 조회 정의/버전을 등록한다. 허용 원천만 참조하는 단일 읽기 전용 SQL을 검수하고 변경 함수·다중 문장·식별자 치환을 거부한다. 파라미터·현재 권한·시간/건수 제한을 서버가 검사한다.
- 기본 실시간, 캐시는 명시된 유효기간과 데이터소스/연결 세대·정확 정의 버전·타입 포함 바인딩·언어/회사/현재 권한 문맥별 격리다. 만료/권한 변경/비활성 시 재사용하지 않는다. 실패 시 오래된 값을 자동 제공하지 않는다.
- SQL/선언/바인딩과 결과 매핑을 대조한다. NULL 코드·상충 명칭·잘못된 타입·결과/프롬프트 상한 초과를 정상 목록으로 취급하지 않는다. 일부만 잘라 전체 목록처럼 전달하지 않는다. 대규모 코드 검색 계약 확정 전 해당 요청은 값 확보 불가다.
- VERIFIED 이후 정의 내용은 불변이고 변경은 새 DRAFT다. 새 버전 활성화는 기존 컬럼 pin을 바꾸지 않는다. 이전 활성 버전은 명시 비활성화 전까지 사용 가능하다. 사용처 영향을 확인하고 비활성화하면 연결 실행을 중지한다. 사용/역사 참조 정의는 물리 삭제하지 않는다. 원천 데이터 갱신은 카탈로그 버전을 만들지 않는다.
- 실행 근거에는 실제 정의 버전·바인딩·관측 시각·사용 코드 목록을 감사·민감정보·보존/파기 정책에 맞춰 연결한다. 무제한 원문 로그를 만들지 않는다. 기본정보 이력과 코드 조회 정의/실행 이력은 구분한다.
- 등록 뷰의 출력 컬럼도 비교한다. 타입/길이/정밀도는 제공 범위만 확인하고 NULL 미확인은 유지한다. 일반 뷰 물리 PK는 해당 없음이며 원본 PK 미승계다. DBMS 특수 뷰 인덱스는 지원 범위에서 비교하고 미지원/권한 부족을 없음으로 바꾸지 않는다. 구조 비교만으로 내부 조인/필터 의미까지 검증했다고 표시하지 않는다.


- DBMS·버전은 `REQ-603.dbms_context`와 `FEAT-002.dbms_contract`를 따른다. DBMS는 활성 공통코드 `DBMS`에서 선택하고 버전은 실제 버전 문자열을 관리한다. 연결 관측값은 제안/대조용이며 명시 저장 전 관리값을 덮어쓰지 않는다. 확인 불가를 정상으로 만들지 않고 불일치 해소 전 SQL 생성·실행을 차단한다. DBMS/버전·관리 버전 참조는 소속 테이블/컬럼과 함께 LLM에 전달한다.
- 자료형 후보는 `REQ-301.source_type_catalog`의 DBMS별 목록이며 버전별로 나누지 않는다. DBMS 변경 시 하위 자료형 불일치와 재검수 대상을 안내하고 임의 타입으로 자동 치환하지 않는다. DBMS 버전 변경 이력도 원본별 _HIST 동형 행에 보존하며 이전 이력에 값이 없으면 현재 버전으로 채우지 않는다.

### 6-3. 상태 전이

## 8. 시드 · 데이터 전제

- 메뉴 HUB_DATA_SOURCE, 상위 HUB_INTEGRATION, 위 경로와 EXPORT_YN=Y(export: true)는 설계값이다. 제품 시드는 구현 시 생성한다.
- DB/DW·관측 상태는 계약 상수다. DBMS는 공통코드 `DBMS`와 실행 지원 목록을 대조하고 파서는 소유 지원 목록을 사용한다. 버전은 관리 문자열이며 실제 코드/시드는 구현 단계에서 등록한다.
- 시간대는 배포 JVM의 ZoneId 목록에서 공통 Timezones 유틸로 조회한다. 시간대용 코드 시드/DB 테이블은 없다. 목록 첫 값은 데이터소스의 자동 기본값이 아니다.
- `MSG.ADMIN_DS_*`와 `MSG.ADMIN_ASSET_*`는 미등록 제안 키다. 표의 라벨·§5 버튼명·§1-2 안내를 문구로 사용한다. 공통 확인 문구/서버 오류 매핑은 [대상 시스템 §8](../target-system/requirements.md#8-시드--데이터-전제)과 같은 키를 사용하며 구현 시 한 번 등록한다. 별칭 중복 안내도 값에 원 입력을 반사하지 않는다.
- `SYS_CONFIG` 신규 키 없음. 후보 조회 실패는 빈 성공 응답으로 치환하지 않는다.

## 10. 미결 · 확인 필요

- 코드 조회 정의는 ENT-041~043·API-063~069의 planned 계약이다. 물리 스키마·실행 상한 수치·액션 키·결과 확인/잠금·캐시 무효화 구현은 FEAT-002.code_lookup_contract.pending을 따른다. 목업 버튼은 제품 실행/저장 기능이 아니다.

- @defer P3 integration_assets·integration — FEAT-003.batch_comparison_contract와 ENT-039/040의 물리/API·실행 권한·한도·재시작/결과 불명·보존 계약을 완성한다. 현재 목업의 버튼은 예시 이동이며 제품 실행 구현이 아니다.

- @defer P3 access_policy — 그룹 후보 조회의 API·현재 이름·유일 ID·삭제 경합·과거 표시 계약. FEAT-006/007·ENT-018 pending이 정본이며 미확정 그룹 선택을 구현 승인하지 않는다.
- @defer P3 integration·agent — 연결/DBMS/파서 지원 생산 계약과 실제 SQL의 동일 원천·이름 해석 검증. FEAT-002·ARCH-030의 pending을 따른다.

- @defer G3 — 서술형 관측/사용처의 구체 응답 필드·별칭 충돌의 메시지 코드를 공개 계약과 일치시키고 메시지 등록·화면 검토를 마친다.
