# 요건 정의서 — 데이터소스

## 개요

- **무엇을 하는 화면인가**: 서버 기동 시 YAML(서버 설정 파일)의 외부 DB(데이터베이스)/DW(데이터웨어하우스) 연결에서 등록된 데이터소스의 업무 메타데이터·접근 가능 사용자 그룹·데이터 조회 가이드를 관리한다.
- **프로세스상 위치**: (선행) 운영자가 외부 연결 설정 배포·서버 기동 → **이 화면** → (후행) 카탈로그 등록·그룹 매핑·권한 내 데이터 조회.
- **이 데이터를 누가 쓰나**: 카탈로그·신원 매핑·지식 검색·agent의 SQL(데이터 조회문) 작성과 실행. 연결 등록이나 가이드 추가만으로 원천 접근 권한을 부여하지 않는다.
- **바꾸면 어디가 흔들리나**: 가이드와 관리 메타데이터는 후속 조회의 문맥이며 하위 객체는 안정 식별자를 참조한다. 표시 별칭 변경은 그 참조를 바꾸지 않는다.

> 미구현 상세 설계다. 제품 화면·서버·시드는 변경하지 않는다. 기능은 [FEAT-002](../../../../spec/31-features/002-admin.yaml), 저장·공개 경계는 [공통 계약](../../../../spec/50-api/003-admin-integration-contracts.yaml)이 정본이다.

## 1. 화면 구성

```text
[조회조건]
[데이터소스 — 1:1 현재값 편집 그리드, 조회·저장·원천 구조 비교·엑셀]
[상하 스플리터]
[사용자 그룹 · 사용 스키마 카탈로그 · 컬럼 불일치 · 인덱스 불일치 · 데이터 조회 가이드]
[선택 탭의 그리드 — 전체 폭]
```

- 일반 진입 시 목록을 자동 조회하며 행을 자동 선택하지 않는다. 아래 main 그림은 데이터소스 선택 후 편집 예시다. 대시보드에서 정확한 dataSourceKey로 진입하면 현재 권한의 해당 행을 조회·선택한다. 연결 key·별칭·도출 DBMS와 서버 설정 불일치는 상단 읽기 전용이다. 연결 관측은 상단 컬럼/장문 뷰어에서 확인하며 별도 탭을 만들지 않는다.
- 상단 SQL 파서·최근 비교 컬럼은 제거한다. 읽기 전용 **불일치 검사 요약** 한 컬럼에서 저장된 컬럼·인덱스 불일치 건수와 확인 상태를 표시한다. 스케줄 배치와 수동 비교가 같은 결과를 생성하며 탭 진입·조회로 원천에 접속하지 않는다.
- 하단 탭은 위 순서의 **5개**다. 마스터 신규·삭제·연결 ID 정정은 제공하지 않는다. YAML에서 빠진 행도 참조와 과거 이력을 보존하고 서버 설정 불일치로 표시한다.
- 수동 관리값·그룹·가이드는 한 편집본이며 선택한 데이터소스 한 건 전체를 저장한다. 가이드 전용 저장·독립 버전·검수/활성화·독립 승인은 없다.
- 그리드 제목은 `MSG.ADMIN_DS_LIST`·`MSG.ADMIN_DS_GROUPS`·`MSG.ADMIN_DS_CATALOGS`·`MSG.ADMIN_DS_COLUMN_DIFFS`·`MSG.ADMIN_DS_INDEX_DIFFS`·`MSG.ADMIN_DS_QUERY_GUIDES`를 사용한다. 제안 메시지 키이며 구현 시 등록한다.

목록 연동: 데이터소스 키

행 추가 탭: 사용자 그룹·데이터 조회 가이드

### 1-1. 마스터-디테일 연동

- 안정 `id`로 상세의 전체 수동 메타데이터·그룹·가이드와 `version`을 확보한다. 탭 조회 결과가 일부 페이지뿐이면 저장하지 않는다. 탭 이동은 입력을 유지한다.
- 미저장 상태의 행 전환·재조회·이탈은 `MSG.ADMIN_ASSET_DISCARD_CONFIRM`으로 확인한다. 취소하면 모든 탭 입력을 보존한다.
- 상세 조회 실패 때 이전 데이터가 새 대상처럼 남지 않는다. 그룹/가이드 조회 실패는 빈 집합으로 바꾸거나 기존 행 제거로 해석하지 않는다.
- 저장 중·결과 불명 중 편집·행 전환·새 명령·반출을 잠그고 원 명령의 결과 확인/같은 입력 재시도만 제공한다.
- 사용 스키마 카탈로그·불일치·연결 관측은 소유 원천의 현재 조회 결과이며 편집본·데이터소스 전체 구성 이력에 복제하지 않는다.

### 별도 변경 이력 메뉴

- [SCR-041](../../../../spec/60-screens/010-change-history.yaml)은 원 화면의 조회조건·상단 컬럼·5개 하단 탭을 읽기 전용으로 상속하고 변경 요약·이력 저장일시 범위만 더한다.
- `/admin/hub/data-source/history?targetId={원ID}&historyNo={세트번호}`로 당시 메타데이터·전체 그룹·전체 가이드를 조회한다. 가이드 행의 원 등록/수정 감사값도 보존한다.
- 사용 카탈로그·비교 목록·연결 관측은 당시 전체 구성 이력으로 합성하지 않는다. 현재 관측을 조회하면 현재 정보임을 구분하고 당시 값이 없으면 재현 불가를 표시한다.
- 보존과 동시성은 [REQ-601.change_history](../../../../spec/10-requirements/011-reference-integration.yaml)·공통 이력 계약을 따른다. 현재 행이 불일치여도 별도 이력 메뉴의 현재 READ·대상 범위를 검사해 과거를 조회한다.

### 3-2. 고정 조건 · 기본 정렬

- 메뉴 READ와 현재 대상 범위를 적용한다. 접근 가능 사용자 그룹을 이 화면의 사용자별 추가 인가 게이트로 만들지 않는다.
- 목록 `alias ASC, id ASC`, 허용 정렬 `alias/id/modifiedAt`; 이력 `histStoredAt DESC, historyNo DESC`. 페이지 크기·상한은 공통 SearchRequest를 따른다.
- YAML 누락 행을 목록에서 삭제하거나 참조 카탈로그를 끊지 않는다. 상태 배지로 구분하며 진단·과거 이력 확인을 허용한다.

내부 자동 번호와 참조값은 [REQ-601의 자동 식별자 규칙](../../../../spec/10-requirements/011-reference-integration.yaml)을 따른다. 읽기 전용 번호는 입력하지 않는다. 신규 행에는 저장 전 번호가 없고 저장 성공 후 표시된다. 대상 선택은 이름으로 하며 저장되는 참조는 같은 숫자 식별자다. 업무 코드·설정 키·순번·리비전과 구분한다.

## 4. 컬럼

- `id`와 `version`은 안정 참조/낙관 잠금 봉투다. 상단 목록은 1:1 현재값과 공개 가능한 관측을 내려주며 선택 후 상세에서 전체 그룹·가이드를 확보한다.

### 4-2. 편집 가능 판단 — 조건부

- READ·SAVE와 현재 대상 범위, 선택 데이터소스의 전체 구성·기대 버전을 확보한 경우 수동 메타데이터·그룹·가이드만 편집한다. READ만 있으면 전체 읽기 전용이다.
- key·별칭·도출 DBMS·서버 설정 불일치·관측·사용 카탈로그·불일치 목록·감사값은 항상 읽기 전용이다.
- YAML 누락만으로 설명·가이드 등 모든 보완 저장을 막지 않는다. 기존 ID·현재 권한·전체 편집본/기대 버전·변경 필드/참조·경합을 검증할 수 있으면 전체 저장을 허용하되 업무 실행 차단은 유지한다.
- DBMS 버전 등 변경 필드의 현재 기준을 검증할 수 없으면 해당 전체 명령을 거부하며 일부만 저장하지 않는다. 로드 실패로 현재 기준 버전/경합 검증 자체가 불가능하면 저장을 잠근다.
- 그룹 후보 계약 미확정/조회 실패 시 기존 집합을 유지하며 그룹 추가·제거를 잠근다. 가이드 전체 조회 실패 때도 빈 배열 덮어쓰기를 금지한다.

### 4-3. 값 변경 후 연쇄 · 재계산

- 기동 시 도출 DBMS가 달라져 서버 SQL 지원 정책/하위 자료형과 호환되지 않으면 확인 필요와 재검수 대상을 표시한다. 임의 파서·자료형·버전으로 치환하지 않는다.
- 동기화 방식은 DW일 때만 편집한다. DB로 바꾸면 읽기 전용으로 전환하며 기존/편집 중 메모를 지우지 않는다. 다시 DW로 바꾸면 같은 메모를 편집한다. 빈 값도 허용하고 유형 전환/메모 저장으로 배치·실제 동기화·SQL 실행·최신성 판정을 수행하지 않는다.
- 수동 시간대·데이터 기준 시각 미지정을 서버 시각이나 첫 후보로 채우지 않는다. 저장 전 타이핑한 시간대 검색어는 선택값이 아니다.
- 가이드 변경은 현재 편집본만 바꾸며 저장 전 agent에 적용하지 않는다. 저장 후 후속 조회는 적용한 전체 구성 리비전을 추적하고 과거 턴을 현재 가이드로 재구성하지 않는다.

### 4-4. 팝업 · 모달 선택 결과 매핑

- 장문 셀 편집은 해당 수동값 또는 선택 가이드의 상세 설명만 바꾼다. 가이드 제목·본문을 서버 설정이나 정책 입력으로 해석하지 않는다.
- 저장 명령 창은 새 변경 사유 `reason`을 받으며 기존 `lastChangeReason`을 자동 재사용하지 않는다. 연결 ID 정정/계정 입력 창은 없다.

### 4-5. 행 추가 기본값

- 마스터 행 추가 없음. 그룹 추가는 선택한 데이터소스 ID를 고정하고 유효 후보만 선택한다. 중복/취소/빈 선택은 행을 만들지 않는다.
- 가이드 추가는 현재 데이터소스 ID를 고정하고 새 안정 가이드 ID는 서버가 부여한다. 제목·상세 설명은 빈 입력이며 감사값은 미등록이다. 기존 가이드 제거는 저장 전 표시하며 전체 저장에 반영하고 새 미저장 행 제거는 즉시 처리한다.
- 기동으로 처음 추가된 데이터소스의 수동 관리값은 미지정 상태로 관리자가 보완한다. 기동/재기동은 기존 수동값·그룹·가이드를 초기화하지 않는다.

### 4-6. 비노출 저장 컬럼

- `id/expectedVersion/commandKey`와 전체 수동 `values`·전체 `applicableGroups[{groupId,mappingActive}]`·전체 `queryGuides`를 저장한다. 기존 가이드의 안정 ID와 기대 소유를 검사한다.
- `dataSourceKey/alias/dbmsCode`는 서버가 현 YAML에서 확보하는 읽기 전용 정보다. 클라이언트가 보낸 값을 변경 입력으로 반영하지 않는다. 주체·감사·정규화 키·관측·진단도 서버 근거다.

## 6. 규칙 — 저장 · 실행

### 6-1. 검증

- 기동 입력은 `app.external-datasources.{dataSourceKey}` 전체다. Hub 자체 `spring.datasource`는 대상에서 제외한다. key·정규화 별칭·필수 연결 구성·비밀 참조를 전체 검증한 뒤 같은 key의 메타데이터를 추가/갱신한다. 잘못된 일부만 먼저 반영하지 않으며 상세 원자성/기동 실패 정책은 FEAT-002 정본을 따른다.
- 연결 key·표시 별칭·JDBC URL·접속 계정/비밀 참조는 YAML 소유다. 도출 DBMS는 URL 인식 결과이며 인식 불가이면 확인 필요·SQL 조회 차단이다. URL·계정·비밀 원문은 화면에 노출하지 않는다.
- DBMS 버전·DB/DW 유형·DW 동기화 방식 메모·시간대·데이터 기준 시각·설명은 수동 관리한다. 기동/재기동/연결 관측으로 기존 값을 덮어쓰지 않는다. URL 종류와 실제 관측·수동 버전의 근거를 구분하고 미확인·불일치를 정상으로 보지 않는다.
- YAML에서 사라진 key의 DB 행·안정 ID·하위 참조·이력은 보존한다. 같은 key의 별칭 변경은 같은 안정 ID에 갱신하며 하위 참조를 재연결하지 않는다. key 변경은 화면 정정으로 처리하지 않는다.
- REQ-601.configuration_diagnosis에 따라 기동/검증된 비교 대상 변경 때 비밀 없는 속성을 대조해 ENT-098에 판정을 저장한다. 조회·사용은 해당 적용 설정 버전의 판정을 참조하며 전체 YAML/DB를 매번 재대조하지 않는다. 비밀번호·토큰 등은 비교/버전 계산에서 제외하지만 해당 기동의 비밀 해석·연결 준비 검사는 유지한다.
- `configurationMismatch`는 일치/불일치/확인 필요의 읽기 전용 배지다. 누락·충돌·검증 불가를정상으로 저장할 수 없다. 해당 연결의 현재 SQL 조회·저장 정의 및 워크플로우 신규/재개/재시도 호출을 차단하고 대시보드 경고로 연결한다. 진단용 관리자 목록·정확 연결 관측·이력과 §4-2의 검증 가능한 관리 보완 저장은 별개다.
- 접근 가능 사용자 그룹은 ENT-018의 기존 적용 가능 그룹 집합이다. 하위 카탈로그/컬럼 매핑 후보 경계이며 실제 원천 접근 허가가 아니다. 그룹 축소와 하위 매핑 추가 경합은 서버가 현재 참조·버전을 검사해 유효 참조 단절을 막는다.
- 가이드는 ENT-096의 데이터소스 소유 자식이다. 제목·상세 설명 여러 건과 감사 네 컬럼을 관리하고 현재 메타데이터·전체 그룹·전체 가이드 및 전체 구성 이력을 한 성공 단위로 저장한다. 가이드 단독 버전·독립 승인·코드 조회 SQL 저장소를 만들지 않는다.
- 소비 순서는 지식 검색 → 선택 카탈로그의 그룹 코드/상세 설명과 데이터소스별 가이드를 문맥 주입 → 공통 코드면 groupCode를 가이드 조회 조건에 바인딩해 허용된 원천 읽기 조회 → 확보한 값/의미로 업무 SQL 작성이다. 그룹 코드가 null인 하드 코딩 값은 상세 설명의 명확한 의미를 해석하고 코드 조회를 강제하지 않는다. 동일 데이터소스 가이드를 카탈로그 수만큼 반복 주입하지 않는다.
- 가이드 본문은 인가 정책을 재정의하거나 LLM(대규모 언어 모델)의 권한을 늘리지 못한다. 가이드가 지시해도 현재 사용자·카탈로그·컬럼/행 범위·읽기 전용 SQL 검증과 실행 한도를 우회하지 않는다. 관리자 가이드 API 권한을 agent 내부 소비에 강요하지 않으며 내부 공개 조회는 FEAT-002 별도 논리 계약으로 정의한다.
- 코드/참조 조회가 실패하거나 값/명칭/관계가 미확인이면 추정·이전 성공값 대체·빈 정상 목록 치환을 금지한다. 필요한 근거를 확보하지 못한 업무 SQL을 완성/실행하지 않는다. 실제 조회 결과는 턴 근거 이력에 연결하고 적용 가이드의 전체 구성 리비전도 추적한다.
- 비교 제외된 물리/운영 속성은 미지원·확인 불가와 구분한다. 이 속성의 미수집/차이가 SQL 관련 비교의 전체 일치를 막거나 미해결 목록을 만들지 않는다.
- 구조 비교의 기준·관측·부분 실패·해소·경합은 REQ-304.batch_structure_comparison을 따른다. 등록 TABLE/VIEW만 비교하고 저장된 현재 유효 카탈로그 판을 기준으로 한다. 성공 확인한 해소만 현재 목록에서 제거하며 원천 권한 부족/부분/실패는 기존 차이를 유지한다. DB 전체 탐색·자동 등록/수정·원천 DDL(구조 변경문) 실행·데이터값 샘플 조회는 하지 않는다.
- 컬럼 이름·원천 타입/의미·치수/단위·NULL·PK/전체 순서와 인덱스 전체 키·정렬·포함 컬럼·필터/표현식을 비교한다. 한쪽 존재와 확인 불가를 구분한다. 뷰의 NULL 미확인·일반 뷰 물리 PK 해당 없음·특수 뷰 지원 범위를 보존하며 내부 조인/필터 의미까지 검증했다고 표시하지 않는다.
- SQL 파서 선택은 제공하지 않는다. 서버의 검증된 DBMS/버전 지원 정책은 REQ-603.parser_policy를, 동기화 방식 메모의 저장/참고 경계는 REQ-603.dw_sync_note를 따른다. 메모는 관리용 참고이며 agent 실행 지시로 제공하지 않는다.
- 자료형 후보는 REQ-301.source_type_catalog의 DBMS별 목록이며 버전별로 분할하지 않는다. DBMS·수동 버전·현재 메타데이터 리비전은 해당 카탈로그/컬럼과 함께 SQL 문맥에 제공하고 과거 이력에 없는 값을 현재값으로 채우지 않는다.

### 불일치 검사 요약과 스케줄

- 업무 배치 정본은 [JOB-003](../../../../spec/65-batches/003-schema-comparison.yaml)이다. 운영자가 공통 스케줄 관리에서 주기·시간대·사용 여부를 정하며 DW 동기화 방식 메모는 스케줄에 영향을 주지 않는다.
- 집계·권한 없음/부분/실패·해소 규칙은 REQ-304.batch_structure_comparison.summary가 정본이다. 한 컬럼의 여러 속성 차이는 1건, 한 인덱스의 여러 구성 차이도 1건으로 센다. 임시 검색/페이지 전 같은 탭 전체 건수를 사용한다.
- 일부 권한/관측 실패면 이전 차이를 포함한 건수와 일부 확인을 표시한다. 전 대상 권한 부재는 해당 없음, 전 범위 실패는 확인 불가이며 탭의 과거 차이는 이전 결과로 유지한다. 빈 메타데이터 목록을 권한 없음으로 추정하지 않는다.
- 대시보드는 같은 현재 결과를 읽고 정확 dataSourceKey로 이 화면을 연다. 결과의 기준 시각·제외/실패 범위는 요약 셀 상세와 각 탭 최근 확인에서 확인한다. 현재 결과를 데이터소스 관리 이력에 복제하지 않는다.

### 6-3. 상태 전이

- 관리 사용여부나 정상 처리 스위치는 없다. YAML 소유/서버 진단은 읽기 전용이고 가이드는 별도 DRAFT/VERIFIED/ACTIVE 상태를 갖지 않는다.
- 편집 → 저장 중 → 성공 또는 명시 거부. 응답 유실/접수 불명은 UNKNOWN(결과 불명)으로 유지하고 원 키로 확인/재시도한다. APPLIED(반영 완료) 이후만 완료 표시·재조회한다. 충돌은 자동 병합하지 않는다.

### 6-4. LLM 입력 준비

[REQ-610](../../../../spec/10-requirements/012-reference-business.yaml)의 `prompt_contract.admin_input_preparation.sources.data_source`가 이 화면의 **프롬프트 포함 후보 / 서버 집행 / 관리·감사 항목**, 해석 가이드 및 제공 단계·조건을 정의한다. §4의 실제 컬럼과 대응하며 공통 해석 규칙은 같은 절의 `guides`·`conditions`·`stages`를 따른다.

화면 목록/상세 응답을 그대로 모델에 전달하지 않는다. 기존 관리 값을 사용하고 입력 분류용 컬럼·탭을 추가하지 않는다. 실제 조합·전송과 최종 JSON/CLI·API 계약은 업무 지식 관리·전체 흐름 합의 뒤 소유 작업흐름에서 구체화한다. 아래 검수는 설계 대조이며 목업에서 LLM 호출을 시연하거나 제품 실행 검증을 완료한 것으로 표시하지 않는다.

## 7. API

정본 [데이터소스 API](../../../../spec/50-api/004-admin-integration-apis.yaml)를 참조한다. 아래는 endpoints.ts용 경로이며 모두 POST다.

## 8. 시드 · 데이터 전제

- 메뉴 HUB_DATA_SOURCE·상위 HUB_INTEGRATION·EXPORT_YN=Y는 설계값이다. 제품 메뉴·메시지·API 시드는 구현 단계 생성 태스크로 반영한다.
- DBMS는 URL 인식 결과와 공통코드 DBMS/실행 지원 목록을 대조한다. 파서는 서버 지원 정책으로 결정하며 화면의 수동 선택 목록은 없다. 시간대는 공통 Timezones 유틸이 제공한다. 미판별·빈 후보·실패에 첫 값을 자동 선택하지 않는다.
- `MSG.ADMIN_DS_*`·`MSG.ADMIN_ASSET_*`는 제안 키다. 화면 label()·서버 MsgKey/SYS_MESSAGE 규약을 따르고 원 비밀이나 원 입력을 오류에 반사하지 않는다.
- `SYS_CONFIG` 신규 키·시간대 코드 테이블·가이드별 캐시 설정은 없다. 외부 접속 설정은 YAML 소유이며 서버 설정 예시는 운영 가이드 소유다.
