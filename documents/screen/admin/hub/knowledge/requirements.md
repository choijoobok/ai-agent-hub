# 요건 정의서 — 지식

## 개요

- **무엇을 하는 화면인가**: 업무 지식의 최종 적용본을 찾고 본문·허용 그룹·안정 ID 매핑·매핑별 사용 설명을 하나의 지식 변경으로 작성한다.
- **프로세스상 위치**: 검색 태그와 공개 자산 준비 → 지식 작성 → 현재 변경 권한 검증·직접 저장 → 허용 사용자 검색·컨텍스트 주입
- **이 데이터를 누가 쓰나**: 권한 있는 관리자와 연결 업무의 담당자가 현재 적용값 또는 업무 처리 근거로 사용한다.
- **바꾸면 어디가 흔들리나**: 소유 기능의 저장·권한·참조 및 이력/감사 연결을 함께 확인한다.

> 미구현 화면 초안이며 사용자 화면 합의·제품 구현·G3(설계 승인 게이트) 승인이 아니다. [화면 정본](../../../../spec/60-screens/_index.yaml)과 [기능 정본](../../../../spec/31-features/002-admin.yaml)을 따른다. 표시 예시는 실제 데이터·물리명·운영 기본값이 아니다.

## 1. 화면 구성

상단 조회조건 → 지식 목록 → 지식 내용 · 사용자 그룹 · 태그 매핑 · 인증 예제 매핑 · 직접 카탈로그 매핑 · 카탈로그 합산 · 업무 API 매핑 · 업무 도구 매핑 순서다. 제목·건수는 왼쪽, 작업 버튼은 상단·그리드 툴바·모달 하단에서 우측 정렬한다. 초기 화면의 모든 탭은 실제 전환하며 같은 상위 대상의 입력·선택·추가/제거 행을 유지한다.

관리 화면은 최종 적용본만 조회하고 변경 입력은 임시값으로 분리한다. 변경 권한을 부여받은 소수의 업무 전문가와 관리자만 소유 범위의 전체 구성을 직접 저장한다. 메뉴 표시뿐 아니라 서버가 저장 직전 현재 액션·대상 범위 권한, 자기 기준 리비전, 필수 참조와 기술 검증을 확인한다. 검증된 전체 변경과 변경 전후 이력·변경자·시각·사유는 같은 트랜잭션으로 반영한다. 일반 admin 계정이나 조회 권한만으로 변경할 수 없다. 별도 승인 요청·검토자/승인자 판정·전결/승인 사용 설정은 제공하지 않는다.

### 1-3. 마스터-디테일·이력 경계

- 선택 변경·조회·이탈 때 미저장 변경을 확인하고 취소하면 선택·입력을 보존한다. 결과 불명에는 새 명령 없이 원 처리 결과를 확인한다.
- SCR-048는 원 화면의 저장 구성을 읽기 전용 상속하고 변경 요약·변경 사유·복원 원본 리비전·이력 저장일시 범위를 추가한다. 복원 버튼은 선택한 과거 이력에서 이 화면의 새 편집으로 인계할 뿐 이력을 수정하지 않는다. REQ-303.restore_contract를 따른다.
- 소유 구성의 전체 집합을 확보하며 미열람 탭을 누락 저장하지 않는다. 관측/사용처·외부 원천 상세는 저장에서 제외한다.

셀 편집은 [공통 그리드 표준](../../../../../aidd-guide/standard/frontend/grid.md)을 따른다. 현재 권한과 컬럼별 편집 조건을 만족하면 셀을 더블 클릭해 바로 입력하고, 저장 전까지는 로컬 변경으로 유지한다. 별도 수정 버튼은 두지 않는다.

행별 변경 취소는 [공통 그리드 표준](../../../../../aidd-guide/standard/frontend/grid.md)의 상태 컬럼 되돌리기를 사용한다. 툴바의 편집 취소 버튼은 두지 않는다.

내부 자동 번호와 참조값은 [REQ-601의 자동 식별자 규칙](../../../../spec/10-requirements/011-reference-integration.yaml)을 따른다. 읽기 전용 번호는 입력하지 않는다. 신규 행에는 저장 전 번호가 없고 저장 성공 후 표시된다. 대상 선택은 이름으로 하며 저장되는 참조는 같은 숫자 식별자다. 업무 코드·설정 키·순번·리비전과 구분한다.

### 편집 가능 판단

현재 변경 권한과 허용 상태가 모두 맞을 때만 소유 입력을 편집한다. 과거 이력은 읽기 전용이며 현재 적용본은 현재 변경 권한으로 다시 편집한다. 저장/판정/결과 불명 중 입력과 원 키를 보존하고 새 명령을 잠근다.

### 값 변경 후 연쇄 · 재계산

참조 선택은 안정 ID와 표시명을 함께 유지한다. 검색 문자열은 선택값을 바꾸지 않는다. 다른 대상 선택 시 기존 상세를 섞지 않는다. 외부 리비전 상승에 따른 자동 매핑/내용 동기화는 없다.

### 행 추가 기본값

상위 대상 문맥만 계승한다. ID·처리 상태·실제 수행자/시각은 서버가 정하며 임의로 입력하지 않는다. 업무 판단값은 비워 둔다. 목업 예시는 기본값이 아니다.

### 비노출 저장 컬럼

원 명령 식별자·소유 안정 ID·자기 기준 리비전과 전체 소유 자식 집합을 보존한다. 공개 필드명은 후속 상세 설계이며 내부 대리키 발급 형식은 REQ-601.surrogate_identifier를 따른다. 외부 상세를 소유 저장에 복사하지 않는다.

### 6-3. 상태 전이

적용본 열람 → 임시 변경 입력 → 현재 변경 권한·기준 리비전·전체 구성 검증 → 현재값과 이력 원자 저장 → 최신 적용본. 저장 실패에는 현재값과 이력을 모두 유지한다. 결과 불명은 원 명령 키로 확인한다.

### 6-4. 복원·임베딩 경계

[REQ-303.restore_contract](../../../../spec/10-requirements/007-knowledge-catalog.yaml)이 복원 대상·권한·리비전·이력 원자성의 정본이다. 복원은 본문·제목·태그/예제/직접 카탈로그/API/도구 소유 매핑과 용도·사용 조건을 불러오며 현재 사용 여부·접근 그룹을 유지한다. 미저장 편집이 있으면 확인하고 취소 시 그대로 보존한다. 소유 본문과 외부 자산 상세·임베딩 결과를 혼합하지 않는다.

[REQ-303.embedding_observation](../../../../spec/10-requirements/007-knowledge-catalog.yaml)에 따라 상단 세 컬럼은 조회 전용 관측이다. 임베딩 탭 없이 마지막 실행/적용 모델의 전체 내용 보기에서 세부 정보를 확인한다. 이력에는 현재 관측값을 채우지 않는다. 태그 검색은 기존 사용/권한 조건으로 유지한다.

## 10. 미결 · 확인 필요

- 본문 SQL/물리명 안내의 상세 방식·길이 제한은 REQ-303.open 후속이다. 자동 의미 검수/승인 단계를 추가하지 않는다.
- A 공통 후속: SCR-015 임베딩 설정 소비·FEAT-014 임베딩/전체 재임베딩 작업 결과/재처리·동시 작업 계약과 전역 TC 연결을 확정한다. B는 모델 설정·실제 작업 API를 만들지 않는다.
- @defer 화면 합의 후 소유 상세 설계 — DB 물리명·와이어 필드·API·공통코드·메시지 키·길이/개수/기간/보존·운영값을 확정한다. 화면 작업은 해당 계약을 추정하지 않는다.
- 사용자 매뉴얼 작성 시 이력 선택→복원→원 지식 편집 확인→사유 입력→저장, 리비전 3→4→5와 취소/충돌/미저장 보존, 임베딩 상태 상세 확인 순서를 포함한다.
