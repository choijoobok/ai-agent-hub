# 요건 정의서 — 업무 API

## 개요

- **무엇을 하는 화면인가**: REQ-608의 API 계약과 입력 필드별 자료형·필수 여부·허용값·값의 출처·채우기 가이드·검증 조건을 관리한다. 고정값·기본값과 허용 조회 참조·결과 추출/변환 안내를 구분하고 해당 지식-API 매핑 건의 사용 설명·업무별 절차를 참조한다. API 자체 저장과 지식 매핑 저장의 경계는 REQ-608을 따른다. 실제 필드 배치·화면 요건서·목업은 P3에서 정한다 REQ-608.result_handling_guide의 API 공통 결과 안내·질문/선택별 후속 처리 가이드를 자연어로 관리하고 계약 원천을 참조한다. 구체 필드·배치·목업은 P3에서 정한다.
- **프로세스상 위치**: 관련 자산·정책 확인 → 이 화면의 조회·입력 → 소유 업무의 검증·직접 저장·변경 이력 기록.
- **이 데이터를 누가 쓰나**: 연결된 관리 업무와 agent의 현재 권한 검증 및 실행 기록.
- **바꾸면 어디가 흔들리나**: REQ-608·REQ-601·REQ-111와 연결된 참조·변경 권한·이력. 정본은 documents/spec이며 이 문서는 화면 검토 초안이다.

## 1. 화면 구성

조회조건 → 상단 업무 API 목록 → 상하 스플리터 → 하단 API 사용 가이드·경로 변수·쿼리 파라미터·헤더 파라미터·바디 JSON 스키마·응답 JSON 스키마·필드값 의미 매핑·사용자 그룹·응답 데이터 접근 제한 설정·연결 지식.
API 사용 가이드는 자유 작성 textarea를 넓게 표시하고 멱등성 보장 여부의 선택 설명과 재실행·결과 확인 안내를 함께 작성한다. 연결 지식은 열 번째 조회 전용 탭이다. 본문은 JSON 전용이며 본문 없는 정상 계약은 허용한다. 같은 API의 탭/팝업 입력과 선택을 보존하고 전체 저장한다. 대응 도구는 탭·버튼·숨김 열에도 두지 않는다.
상태별 버튼: 허용 목록
필드값 의미 매핑 탭은 왼쪽 필드 목록과 오른쪽 값 설정을 좌우로 배치하고 가운데 세로 스플리터를 둔다. 초기 너비는 1:1이며 드래그 또는 좌우 방향키로 조절한다. 참조 가이드/직접 등록 전환은 오른쪽 영역에서 이루어지고 필드 선택·입력·너비를 보존한다.

### 1-1. 마스터-디테일 연동


- 대상 안정 식별자와 읽은 문맥/기준 버전으로 전체 구성을 확보한다. 탭의 행과 상위 대상을 섞지 않는다.
- 다른 대상 선택·재조회·화면 이탈은 미저장 입력 확인 후 수행하며 같은 대상 탭 이동은 입력을 유지한다.
- 조회 실패·부분 목록·접힌 탭을 삭제나 빈 전체 집합으로 해석하지 않는다. 처리 중 중복 명령을 막고 결과 불명은 원 키로 확인한다.

| 신규 | edit |

셀 편집은 [공통 그리드 표준](../../../../../aidd-guide/standard/frontend/grid.md)을 따른다. 현재 권한과 컬럼별 편집 조건을 만족하면 셀을 더블 클릭해 바로 입력하고, 저장 전까지는 로컬 변경으로 유지한다. 별도 수정 버튼은 두지 않는다.

행별 변경 취소는 [공통 그리드 표준](../../../../../aidd-guide/standard/frontend/grid.md)의 상태 컬럼 되돌리기를 사용한다. 툴바의 편집 취소 버튼은 두지 않는다.

연결 선택·표시는 연결 정보 컬럼 하나로 제공하며 적용 연결은 숨김 선택 열에도 두지 않는다. 수동 사용/연결 선택 입력은 저장 전 편집본이며 서버 설정 불일치는 현재 적용본의 선택 연결이 참조한 저장 판정이다. 배지 설명에 “저장된 연결 기준”을 안내한다. 미저장 연결 변경은 기존 배지를 유지하고 기존 행 상태의 수정 표시·되돌리기를 사용한다. 저장 실패는 입력과 기존 진단을 보존하고, 되돌리기는 저장된 연결 선택을 복원한다. 저장 성공 후 응답/재조회로 새 연결의 판정을 표시하며 판정을 받지 못하면 이전 연결의 진단을 재사용하지 않고 확인 필요로 표시한다. 진단은 일치/불일치/확인 필요 배지 하나와 안전한 사유 설명/경고로 제공하고 기존 연결 설정 유효 여부·사용 가능 여부·사용 불가 사유 컬럼은 숨김 선택 열에도 두지 않는다. 시스템 변경은 하위 연결을 재선택하고 저장 전 기본값으로 자동 대체하지 않는다.

신원 필요 컬럼은 숨김 선택 열에도 두지 않는다. 신원 생성·전달 위치·검증 방식은 [REQ-609.identity_verification](../../../../spec/10-requirements/012-reference-business.yaml)의 선택 연결/검수 계약에서 결정한다. 계약 미설정을 신원 불필요로 처리하거나 업무 입력으로 검사를 해제하지 않는다. 권장 난수 토큰은 서버 실행 시점에만 발급·검증·소비하며 이 화면에 원문/해시·발급/소비 조작을 추가하지 않는다.

### 멱등성과 후속 결과 확인

멱등성은 해당 API·도구 자체의 보장 여부만 설정하며 기본값은 false다. 기간·키 조건 입력/검증은 두지 않는다. true도 실행 승인·재전송 제한을 면제하지 않는다. 결과 확인에 사용할 등록 API는 사용 가이드에서 안내한다. 구체적인 입력값 확보와 응답 해석은 그 조회 API의 자체 가이드·입력/응답 명세를 사용한다. 원 실행의 requestId 등 실제 근거와 연결은 보존하며 부족한 값을 추측하지 않는다. 결과 판정 창은 현재 API·도구 자신의 응답에 대한 판정만 관리한다. 자동 폴링과 결과 불명 원 실행의 자동 재전송은 허용하지 않는다.

### 입력값 확보용 API 선택

값 출처에서 API 조회를 선택하면 조회 API 검색 선택 셀이 활성화된다. API명·대상 시스템·안정 ID로 식별해 선택하고 apiId만 저장한다. 입력 매핑·결과 필드 선택·판 고정 설정은 제공하지 않는다. 값 확보 가이드에 업무 목적과 주의사항을 작성하면 LLM이 선택 API의 현재 명세/가이드로 파라미터를 구성하고 실제 응답을 해석한다. 예를 들어 주문 식별값이 필요하면 주문 조회 API만 지정하고 찾을 주문의 조건은 가이드와 대화 문맥으로 판단한다. 부족/모호한 값은 질문하며 현재 권한·필수·자료형은 서버가 검증한다. 대상 API 필드 변경만으로 연결 설정 재저장을 요구하지 않는다. 원천·명세 변경 후 현재 호출 검증 실패는 추정 대체하지 않는다. API 조회에서 다른 유형으로 바꾸면 로컬 조회 API 선택을 해제하며 행 되돌리기로 원래 선택을 복원한다. 다른 유형에는 null로 저장한다. 보충 설정 복사에는 조회 API 안정 ID와 가이드를 함께 포함하고 현재 대상 허용 여부를 다시 검사한다.

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

현재 적용된 최종 관리 구성과 현재 권한 범위를 조회한다. 미저장 편집본을 운영 목록에 섞지 않는다.
물리 테이블·결합 키의 신규 상세 설계는 후속이다. 다른 소유의 관측·역참조는 읽기 전용이며 저장 사본에 포함하지 않는다.

### 3-2. 고정 조건 · 기본 정렬

현재 유효 조회 권한과 대상 범위를 적용한다. 표시명과 안정 식별자로 동일 이름을 구별한다. 정확 정렬/페이징 계약은 후속 상세 설계한다.

내부 자동 번호와 참조값은 [REQ-601의 자동 식별자 규칙](../../../../spec/10-requirements/011-reference-integration.yaml)을 따른다. 읽기 전용 번호는 입력하지 않는다. 신규 행에는 저장 전 번호가 없고 저장 성공 후 표시된다. 대상 선택은 이름으로 하며 저장되는 참조는 같은 숫자 식별자다. 업무 코드·설정 키·순번·리비전과 구분한다.

## 6. 규칙 — 저장 · 실행

### 6-1. 검증

- REQ-608.field_value_mapping이 필드값 의미의 정본이다. 경로/쿼리/헤더/바디/응답의 등록 필드를 안정 식별자로 연결하며 같은 필드의 중복 매핑·미등록/삭제 필드·객체/배열 컨테이너를 거부한다. 경로 변수는 순서·설명으로 선택한다. 조회 실패/미상은 빈 정상 목록이 아니다.
- 참조 가이드는 프롬프트 안내이며 허용된 조회의 실제 결과를 근거로 해석한다. 직접 등록은 코드값·명칭·의미/사용 조건을 소유 API에 저장하고 프롬프트로 제공한다. 코드의 자료형/앞자리 0을 보존하고 중복 값·타입 불일치를 거부한다. 동일 명칭의 복수 코드가 남으면 확인 질문하며 새 코드를 만들지 않는다. 명칭/가이드가 허용값·권한·신원/마스킹·실행 승인을 바꾸지 않는다.
- 필드 행/탭/방식 전환 중 가이드와 코드표의 편집을 각 매핑에 보존한다. 현재 선택 방식만 소비하며 미완성 방식은 저장 검증한다. 행 추가/삭제/원복은 소유 필드 문맥을 유지한다. 전체 저장과 이력은 같은 API 단위이며 참조 가이드의 조회 결과 원문을 직접 등록 코드표로 복제하지 않는다.
- 결과 판정은 응답의 실행 결과 관련 필드와 그 직접 등록 코드 항목만 참조한다. 코드 원값/명칭/의미는 정본을 읽고 판정 상태만 별도로 관리한다. 참조 가이드 방식만 있는 응답 필드에 동적 결과 판정을 만들지 않는다. 판정에서 참조 중인 코드/필드의 실제 삭제·방식 변경은 참조를 함께 정리하기 전 저장할 수 없다. 원천에서 사라져 보존한 불일치 필드와 기존 참조는 오류 상태로 저장 가능하며 정상 실행 계약은 차단한다. 주문 상태 취소가 API 호출 실패를 뜻하지 않는다.

- REQ-608.api_workspace가 10탭·JSON 전용·경로 변수 순서/템플릿 바인딩·샘플 가져오기·메모의 정본이다. 경로 변수의 정렬은 순서 키를 바꾸지 않으며 자리 수/키 중복/빈 값·템플릿 변경은 재검증한다. 원본 스키마의 필수/NULL은 도출하되 샘플에서는 추정하지 않는다. 개인정보·업무 보충 설정은 새 필드에서 확인한다. 기존 경로의 설명·가이드·개인정보·마스킹은 유지한다.
- 샘플의 중복 객체 키·잘못된 JSON·혼합 타입 충돌은 반영하지 않는다. 배열의 모든 항목을 합치고 객체/배열 컨테이너·루트 배열/스칼라·점/대괄호가 든 키를 구별한다. 삭제는 별도 명시 동작이다. 원 샘플 값을 이력/모델용 예시로 자동 저장하지 않는다.
- REQ-608.response_access를 적용한다. 예외 없는 개인/민감 필드는 이력과 같은 수준, 비민감은 원문. 활성 소속×활성 API 허용 그룹만 결합하고 원문 > 같은 유형의 덜 엄격한 마스킹 수준 > 미전송 순이다. 미지원·다른 유형·비교 불가는 해당 값 비노출 오류다. Portal 예외로 이력 마스킹이나 모델 전송 동의를 해제하지 않는다.
- 결과 체크·자유 설명만으로 업무 성공을 판정하지 않는다. 등록 결과 필드/값 매핑과 HTTP 계약을 검증하고 접수·처리 중·완료·실패·불명을 구별한다. 비JSON/검증 실패를 미실행으로 단정하지 않는다.
- 검수 근거는 상단 메모로 통합하며 메모 파싱·별도 필수 근거 양식·미래 적용일 자동 오픈을 만들지 않는다. 호출 계약의 멱등성 보장 여부의 선택 설명과 재실행·결과 확인 설명은 API 사용 가이드에 통합한다. 별도 호출 계약 창/입력 항목은 두지 않는다. 자유문을 파싱해 실행 조건을 바꾸지 않으며 REQ-105의 서버 검증·실행 승인·재시도 제한은 유지한다. 연결 지식 탭은 원 소유 매핑을 읽기 전용으로 조회하며 같은 API의 가이드/입력을 보존한다.

- 서버 설정 불일치는 REQ-601.configuration_diagnosis의 기동/비교 대상 변경 후 DB 저장 판정을 참조한다. 일반 목록 조회나 각 호출에서 전체 YAML/DB를 재대조하지 않는다. API별 판정 사본은 없으며 현재 적용본의 제공 시스템/명시 연결을 참조한다. 부모 자체 누락은 차단하되 다른 자식 연결의 누락은 전파하지 않는다.
- 신원 확인은 REQ-609.identity_verification·UC-044를 따른다. 이 화면은 검수된 계약을 참조하고 실제 난수 발급·보호된 콜백·DB 일회 소비·대상 권한 확인을 실행하지 않는다. 적용 계약 미확인/필수 매핑 중지·회수는 호출을 차단하며 사용자 입력으로 우회하지 못한다.
- 불일치·확인 필요·저장 판정 없음·버전 불일치와 해당 기동 준비 미완료는 실제 전송 전에 차단한다. 일치도 수동 사용 OFF·권한/신원·계약/검수 오류를 허용하지 않는다. 비밀값은 비교/지문에서 제외하되 비밀 누락·복호화/인증 오류 검증은 유지한다.

- FEAT-008의 그룹/응답 예외 편집은 이 화면에서만 제공한다. 정책 영역 변경 권한과 API 정의 변경 권한은 별도로 검사한다. 정책만 변경 가능한 관리자는 API 기본/필드 정의를 수정하지 못하고 정의 변경 권한만으로 정책을 수정하지 못한다. 서버는 현재 허용된 영역/필드만 수락하고 다른 영역의 현재값을 보존한 전체 API 구성과 이력을 같은 성공 단위로 저장한다. 별도 그룹 매핑 저장소/리비전은 만들지 않는다. 그룹 변경 사유도 소유 API의 변경 사유/이력에 보존한다.
- 응답 예외의 경로는 응답 필드에 등록된 경로만, 그룹은 해당 API 허용 그룹만 선택한다. 중복 예외·미등록 경로·허용 그룹 밖 대상을 거부한다. 개인정보/마스킹 정보 유형의 원천은 응답 필드이며 별도 마스킹 수준은 REQ-608.response_access·REQ-611.masking_utility.api_levels의 지원 코드/자료형/순위로 검사한다. 그룹별 임의 알고리즘을 만들지 않는다. 그룹 열람과 전송 동의는 독립 검사하며 동의를 우회하지 않는다.

- 변경 권한을 부여받은 소수의 업무 전문가와 관리자만 소유 범위의 전체 구성을 직접 저장한다. 메뉴 표시뿐 아니라 서버가 저장 직전 현재 액션·대상 범위 권한, 자기 기준 리비전, 필수 참조와 기술 검증을 확인한다. 검증된 전체 변경과 변경 전후 이력·변경자·시각·사유는 같은 트랜잭션으로 반영한다. 일반 admin 계정이나 조회 권한만으로 변경할 수 없다. 별도 승인 요청·검토자/승인자 판정·전결/승인 사용 설정은 제공하지 않는다.
- 자기 기준 리비전 충돌·현재 권한·필수 참조 유효성·SQL/API 기술 검증은 유지한다. 저장 전에는 현재 적용본을 바꾸지 않는다.
- 지식은 외부 자산의 안정 ID를 매핑한다. 외부 리비전 상승만으로 지식 매핑·내용을 자동 변경하지 않는다.
- 현재 열람 권한 안의 사용처 식별자·이름·종류·리비전·참조 경로만 조회한다. 지식 본문을 모아 업무 의미의 영향이나 보완 필요성을 판정하지 않는다. 내용 적합성 검토는 운영·유지보수 조직의 자체 절차이며 이 화면에 검토 작업을 만들거나 저장의 필수 단계로 요구하지 않는다. 조회 실패·열람 제한을 참조 없음으로 처리하지 않으며 현재 참조 무결성과 기술 계약 검증은 유지한다.
- 실제 실행에 사용한 정확 계약·가이드 버전은 실행 당시 기록한다. 관리자 저장과 사용자의 실제 업무 실행 확인은 별개다.
- 코드명 조회 실패는 원 업무 성공·접수·불명과 별개다. 원 실행을 재전송하거나 다른 원천·LLM 추정 이름으로 대체하지 않는다.
- API 저장만으로 대응 도구를 생성·노출하지 않는다. 코드 조회 참조가 호출 권한·행 스코프·마스킹을 확대하지 않는다.


### 배열 원소의 의미 매핑

`states[]`처럼 문자열·숫자·불리언 배열인 경우 해당 경로의 각 원소에 코드 의미 매핑을 적용한다. 컨테이너의 배열 자료형을 바꾸지 않고 배열 항목 자료형으로 직접 코드값을 검증한다. 객체 배열은 `items[].status` 같은 스칼라 속성을 선택한다. 배열 전체·객체 자체에는 코드 하나를 매핑하지 않는다. 원소별 의미 해석은 전체 실행 성공 판정이 아니며 배열을 단일 결과 코드로 자동 승격하지 않는다.

### 조건부 보충 설정

고정/기본값·마스킹·식별 용도·형식/시간대/단위·별도 검증 조건은 §4의 적용 조건이 성립할 때만 필수다. 적용 대상이 아닌 값은 null로 저장한다. 출처/분류 변경으로 기존 설정이 불필요해지면 삭제될 설정을 확인하고 같은 전체 저장에서 정리하며 다른 영역의 값을 임의 초기화하지 않는다. 보호값·개인정보 미검수는 이 예외로 우회하지 않는다.

### 스키마 원천·필드 동기화

- 바디·응답 JSON 스키마 원본은 상단 목록 한 행의 현재 내용 마스터 ENT-012에 각각 저장하고 ENT-061에 동형 보존한다. 각 탭의 JSON 스키마 편집은 이 두 속성을 편집하며 필드별 행에 원본을 중복 저장하지 않는다. JSON 샘플은 편집 창 안에서 구조 초안을 만드는 보조 수단이고 실제 샘플 값은 저장하지 않는다.
- 저장 원본은 type/properties/items/required 등의 구조 정의(JSON Schema)다. 기본 정적 객체·배열·스칼라와 null 허용을 다루며 목업이 지원하지 않는 참조/조건/동적 구조는 오류로 알린다. 제품 지원 범위는 상세 설계에서 명시한다. 빈 문자열·실패·부분 조회·미해석 구조를 빈 스키마로 대체하지 않는다. 본문 없음은 명시 선택으로 미리보기/확인한다.
- 필드는 방향/영역과 정적 경로 토큰으로 대조한다. 현재 원천의 새 필드만 자동 추가하며 수동 추가·경로/형/필수 편집과 행별 삭제 컬럼은 제공하지 않는다. 같은 경로는 안정 필드 식별자와 보충 설정을 유지한다. 원천에 없어진 필드는 스키마 일치 여부=false로 표시하고 기존 설정을 보존한다. 자료형/필수 변경은 경로가 있으므로 true인 채 설정 재확인을 요구한다. null/대조 실패는 삭제 대상이 아니다.
- 필드 설정 이관 조작 순서는 **원본 필드 한 행 선택 → 필드 설정 복사 버튼 → 같은 API/같은 탭의 붙여넣을 대상 필드 한 행 선택 → 필드 설정 붙여넣기 버튼 → 원본/대상 경로와 덮어쓸 설정 확인 → 설정 덮어쓰기 버튼**이다. 붙여넣기는 로컬 편집이며 상단 저장으로 확정한다. 확인 창을 취소하면 대상 설정을 바꾸지 않는다.
- 설명·값 확보/해석 가이드·고정/기본값·개인정보/마스킹·결과 설명 같은 보충 설정만 옮긴다. 경로·자료형·필수·ID·스키마 판정·원천 버전은 복사하지 않는다. 기존 대상값 덮어쓰기는 명시 확인하며 다른 대상/탭·자료형 불일치·정책 변경 권한 없음은 거부한다. 별도 필드값 의미 매핑·결과 판정·다른 필드 참조는 자동 복제/이동하지 않고 명시 재연결한다.
- 각 탭의 스키마 불일치 필드 일괄 삭제는 현재 탭 전체 목록 중 false인 행만 대상으로 건수/경로를 확인한다. 일치·미확인 행은 제외한다. 의미 매핑·코드·결과 판정·값 출처·응답 접근 예외 등의 현재 참조가 있으면 전체 삭제를 막고 해소할 참조를 표시한다. 확인 후 로컬 삭제 표시하며 실제 삭제는 전체 저장에서 서버가 원천·기대 버전·대상/참조·권한을 재검증한 뒤 수행한다. 과거 이력과 실행 근거는 지우지 않는다.
- 불일치 필드는 정리 전 저장하여 설정 이관에 사용할 수 있지만 현재 실행 명세·프롬프트·신규 의미/결과 후보에서 제외한다. 현재 유효 참조가 불일치 필드를 가리키거나 구조 변경의 보충 설정 검증이 끝나지 않으면 정상 실행 계약으로 사용하지 못한다.
- 원천·도출 필드·불일치 판정/대조 근거·보충 설정·명시 정리 결과·전체 이력은 하나의 원자 저장 단위다. 클라이언트가 보낸 일치 플래그만 믿고 삭제하지 않는다. 저장 실패·미리보기 취소는 기존 편집값을 보존한다. 필드 보충 설정의 행 원복은 현재 원천의 구조/일치 판정을 과거 값으로 돌리지 않는다.

### 6-2. 영향 테이블

물리 테이블을 새로 확정하지 않는다. 소유 업무 구성·처리 근거·적용 이력을 기존 정본의 같은 반영 단위로 다룬다. 실패 시 부분 반영·부분 권한 변경을 남기지 않는다. 조회 전용 동작은 변경 없음.

### 6-3. 상태 전이

현재 적용본 → 로컬 변경 입력 → 현재 변경 권한·기준 리비전·전체 구성 검증 → 직접 저장과 이력 원자 반영 → 새 적용본. 저장 전에는 기존 적용본을 유지한다.

### 6-4. LLM 입력 준비

[REQ-610](../../../../spec/10-requirements/012-reference-business.yaml)의 `prompt_contract.admin_input_preparation.sources.business_api`가 이 화면의 **프롬프트 포함 후보 / 서버 집행 / 관리·감사 항목**, 해석 가이드 및 제공 단계·조건을 정의한다. §4의 실제 컬럼과 대응하며 공통 해석 규칙은 같은 절의 `guides`·`conditions`·`stages`를 따른다.

화면 목록/상세 응답을 그대로 모델에 전달하지 않는다. 기존 관리 값을 사용하고 입력 분류용 컬럼·탭을 추가하지 않는다. 실제 조합·전송과 최종 JSON/CLI·API 계약은 업무 지식 관리·전체 흐름 합의 뒤 소유 작업흐름에서 구체화한다. 아래 검수는 설계 대조이며 목업에서 LLM 호출을 시연하거나 제품 실행 검증을 완료한 것으로 표시하지 않는다.

## 7. API

신규 물리/API 상세 설계는 후속이다. 이미 정해진 기능·화면·공통 직접 저장 계약을 참조하고 새로운 경로·메서드·요청 DTO는 정하지 않는다. 실행 당시 정확 버전 기록과 현재 권한 검사는 유지한다.

## 8. 시드 · 데이터 전제

메뉴/경로는 화면 정본의 검토안이다. 이번 작업에서 메뉴·메시지·공통코드 시드나 제품 sources/를 변경하지 않는다. 미정 코드/메시지 키는 화면 합의 후 상세 설계한다.
