# 요건 정의서 — 월별 사용자 쿼터 현황

## 개요

- **무엇을 하는 화면인가**: 한 달의 사용자별 실제 쿼터 지급·사용 현황과 선택 사용자의 같은 월 추가 토큰 사용 신청 내역을 함께 조회한다.
- **프로세스상 위치**: 월별 개인 쿼터 기준의 사용자 배정·당월 추가 승인·호출 계량 → 월별 지급/사용 현황 조회. 원 기준 편집과 신청 판정은 각 소유 화면에서 수행한다.
- **문서 범위**: 미구현 관리자 설계 초안이다. 기존 기록의 비저장 투영이며 새 배정/신청/사용 원장·물리 테이블/API·게이트 승인을 만들지 않는다.

## 1. 화면 구성

기준년월·사용자 조회조건 → 상단 사용자별 쿼터 목록 → 상하 스플리터 → 하단 추가 토큰 사용 신청 내역 그리드. 한 달은 필수로 선택하며 초기값은 업무 시간대의 현재 월이다. 실제 조회 후 행을 자동 선택하지 않는다. 제목·건수는 왼쪽, 조회/엑셀은 그리드 상단 오른쪽이다. 별도 수정·저장·승인 버튼은 없다.

## 3. 조회 — 원천과 범위

정본은 REQ-116.monthly_status_view다. 선택 월의 일반/일할 배정·추가 신청·개인 사용 중 하나라도 존재하는 안정 사용자 ID를 기준 집합으로 삼아 SCR-021 사용자 배정의 해당 월 유효 실지급 기록과 SCR-022 원 신청/처리·한도 반영 기록과 NFR-010·016의 개인 귀속 사용을 읽는다. 전체 사용자 배정/추가 신청/호출 원행을 한 번에 조인해 합산하지 않는다. 월×사용자별 각 집합을 먼저 비중복 집계한 뒤 같은 키로 연결한다. 신청이 없어도 배정 사용자는 남긴다. 신청 또는 개인 사용만 있으나 배정 확인이 안 되는 원천 불일치는 누락시키거나 0 지급으로 확정하지 않고 확인 필요로 표시한다.

같은 월·사용자의 유효 지급만 한 번 사용하며 교체/폐기된 예정본과 대체된 세트는 제외하고 선택 과거월의 최종 유효 지급 세트는 한 번 채택한다. 승인 처리 재수신은 중복 합산하지 않는다. 대기/반려/취소/미처리만료 신청은 지급에 포함하지 않는다. 과거 승인 만료는 당시에 지급된 사실을 지우지 않는다. 과거 월 잔여는 이월 가능한 잔액이 아니다. 현재 설정으로 과거 등급/배정/사용을 재계산하지 않는다.

SCR-066은 사용자 중심의 여러 월·모델/용도 상세, SCR-067은 월 전체 비용/계량 통계다. 이 화면은 한 달의 사용자별 지급·사용과 원 추가 신청 대조만 담당하며 원 배정·승인·실사용 기록을 복제/수정하지 않는다. 상세 물리 원천/조인/공개 API는 각 소유 기능 상세 설계에서 함께 닫는다.

## 4. 컬럼

필드명은 화면 논리 식별자이며 물리/공개 DTO(데이터 전달 객체) 필드명은 후속 설계한다. 모든 결과 컬럼은 신규 행 추가/편집이 없다. 숫자 null·조회 실패/미상은 0으로 바꾸지 않는다. 값 원천·계산 참조는 각 셀의 설명과 목업 상세 설명에 표시한다. 장문은 읽기 전용 셀 뷰어로 전체 내용을 확인한다.

## 6. 규칙 — 조회와 계산

- 지급/사용/잔여 산식과 중복 제거·과거 월/월말 만료는 REQ-116.monthly_status_view를 따른다. 이 화면에서 배정·승인·한도·사용 원장을 쓰거나 초과를 보정하지 않는다. 예약/선차감량은 제공하지 않는다(NFR-012).
- 부분 승인량만 지급에 반영하고 원 신청량·실제 초과 사용량과 구분한다. 동일 사용자 여러 원 신청이 있어도 일반 배정과 사용을 신청 건수만큼 곱하지 않는다.
- 계량 미상/지연·추가 승인 반영 결과 불명·배정 미확보면 해당 값과 파생 총액/잔여를 확인 필요로 표시한다. 성공한 조회의 실제 0과 null을 구분한다.
- 현재 월·사용자·원천/반출 권한을 서버에서 다시 검사한다. 이름 일치로 다른 사용자의 신청을 연결하지 않는다. 조회 권한으로 승인 권한을 얻지 않는다. 운영용 사용은 개인 쿼터 사용에 넣지 않는다.
- 월/사용자 변경 중 이전 하단 결과를 노출하지 않는다. 조회 시점 이후 도착한 승인/계량은 다음 명시 조회에 반영하며 한 결과에서 서로 다른 기준 시각을 섞지 않는다.

## 7. API

신규 공개 API/DTO·물리 테이블은 화면/전체 업무 흐름 합의 후 상세 설계한다. 기존 소유 배정/추가 신청/계량의 읽기 전용 조합으로 구현하며 별도 복제 저장소를 만들지 않는다. 논리 필드명은 화면 설명용이다.

## 8. 시드 · 데이터 전제

메뉴·메시지 키/시드는 제품 구현 시 반영한다. 이번 변경은 설계/목업이며 제품 sources·DB/시드 변경이 없다. 실제 데이터가 없는 목업 예시를 운영 성공 근거로 삼지 않는다.
