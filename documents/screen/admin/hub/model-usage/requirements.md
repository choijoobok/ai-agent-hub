# 요건 정의서 — 모델 용도·우선순위 설정

## 개요

- **무엇을 하는 화면인가**: 등록된 외부 모델·지원 effort를 선택해 용도·우선순위·설명을 정한다. 호출 코드는 외부 모델 등록 화면에서 가져온다.
- **프로세스상 위치**: SCR-015 외부 모델 표시명/코드·지원 조합 등록 → 모델 용도/우선순위 지정 → 사용자 선택 또는 자동 작업에서 사용.
- **이 데이터를 누가 쓰나**: Portal 사용자는 유효한 텍스트 생성 조합 전체를 주 추론으로 선택한다. 보조 작업·시스템 운영·임베딩은 관리자 지정만 사용한다.
- **바꾸면 어디가 흔들리나**: 새 질의의 선택지, 보조 작업의 장애 대체 순서, 시스템 운영과 임베딩. 이미 시작한 작업의 고정 설정과 토큰 배분은 바꾸지 않는다.

## 1. 화면 구성

조회조건 → **모델 용도 설정** 한 목록. 외부 모델 등록(SCR-015)을 선행 기능으로 연결한다.
제목·건수는 왼쪽, 작업 버튼은 오른쪽에 둔다. 초기 화면은 저장된 적용 조합이다.
외부 모델은 그리드 셀 안의 일반 콤보박스이며 공급사 / 모델 표시명 / effort 표시명을 표시한다. 선택 팝업 레이어나 별도 적용 버튼을 두지 않는다. 용도도 일반 셀 콤보이며 설명은 셀 안의 텍스트 입력이다. 저장값은 외부 모델 식별값 하나다. 용도·순위·설명을 지정하며 코드는 직접 입력하지 않는다.
주 추론 용도 한 행이 정상 최초 미선택의 기본값이다. 사용자 선택지는 용도 미지정도 포함한 등록 화면의 전체 유효 텍스트 조합이다.
상태별 버튼: 허용 목록
행 추가 탭: 모델 용도 설정

조회조건에는 초기화만 두며 조회·행 추가·저장·업무 버튼은 이 그리드 상단 우측에 모은다. 편집 그리드에 상태·삭제 컬럼을 두고 삭제는 저장 전 상태로 표시한다.

### 그리드 선택

| 그리드 선택 | 선택 방식 |
|---|---|
| 모델 용도 설정 | 단일 |

번호 → 상태(편집 가능) → 업무 컬럼 → 삭제(삭제 가능) 순이다. 번호·상태는 왼쪽, 삭제는 맨 오른쪽에 고정한다. 행 선택 체크박스는 두지 않는다.
행 클릭으로 한 행을 선택한다. 저장은 선택 행만이 아니라 같은 저장 단위의 전체 변경 행을 대상으로 한다.

### 1-1. 마스터-디테일 연동

없음. 편집본 전체의 입력과 추가/제외 행을 유지한다. 조회조건 변경·재조회·화면 이탈은 미저장 입력 확인 후 수행한다.
저장은 조회 필터로 가려진 조합을 삭제하지 않는다. 편집에 필요한 전체 구성을 확보하지 못하면 저장하지 않는다.

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

현재 적용 용도 설정(비활성/보완 필요 참조 포함)과 후보로 고를 SCR-015의 활성·검증된 외부 모델 조합을 조회한다. 등록 코드와 설명의 원천을 복제해 편집하지 않는다. 물리 테이블·결합 키는 후속 설계다.
공급사 연결은 실제 호출 서비스이며 모델 제작사와 다를 수 있다. Amazon Bedrock을 통해 호출하는 모델은 해당 경로·단가·동의 범위를 유지한다.

### 3-2. 고정 조건 · 기본 정렬

용도 업무 순서 → 같은 보조 용도의 우선순위 → 외부 모델 조합 순이다. 사용자 그룹·쿼터 등급별 필터는 없다.
용도 행을 제거해도 등록 조합 자체가 유효하면 사용자 주 추론 선택지는 유지한다. 등록 원천에서 제거/비활성/미지원으로 바뀐 조합만 사용자 선택지에서 제외하며, 이미 시작한 실행의 고정 조합과 이력은 보존한다. 실행 때 현재 권한·전송 동의·연결 유효성은 별도로 검사한다.

### 편집·선택·기본값

- 외부 모델 식별값이 가리키는 공급사·모델·effort 지원 조합과 현재 등록 리비전을 검사한다. 모델과 effort를 분리 선택하거나 표시명에서 코드를 생성하지 않는다. 선택 취소·조회 실패는 입력을 보존한다.
- 용도 후보와 저장 유효성은 agent 소스의 스텝 유형/LLM 통신 계약을 정본으로 삼는다. 운영 공통코드 그룹으로 등록하지 않으며 admin이 별도 목록을 하드코딩하거나 임의 용도를 추가하지 않는다. 현재 목업의 한글 후보는 업무 표시명 예시이고 실제 소스 코드값은 개발 단계에 연결한다.
- 같은 용도 안의 동일 조합은 중복 등록하지 않는다. 여러 용도에 쓰는 동일 텍스트 조합은 Portal 선택지에서 하나로 보인다.
- 기본 지정·안정 식별자·편집 기준 버전·후보 설정 버전은 관리/실행 근거로 유지하지만 관리 컬럼을 추가하지 않는다. API·물리명은 후속이다.

## 6. 규칙 — 저장 · 실행

### 6-1. 검증

- 용도 참조가 남은 외부 모델 조합는 등록 화면에서 삭제할 수 없다. 이 화면에서 다른 유효 조합으로 옮기거나 허용되는 용도 행을 제거해 저장한 뒤에만 삭제 가능하다. 저장 직전에 현재 등록 상태/코드 리비전을 다시 검사해 삭제·변경과 경합한 낡은 선택을 거부한다.

- REQ-602.screen_contract: 등록된 유효 텍스트 생성 조합 전체를 모든 사용자에게 제공한다. 보조/운영용 행도 포함하고 임베딩은 제외한다. 그룹·쿼터 등급·system 역할로 모델을 제한하지 않는다. 토큰 한도·실제 사용량 집행은 REQ-116·NFR-012에서 유지한다.
- 보조 판정 각 용도는 1~3개 후보이며 확인된 일시 공급 장애에만 다음 순위를 사용한다. 미동의·인증/안전 거부·입력/지원 오류·결과 불명·시간/예산 소진은 대체 사유가 아니다. REQ-602.auxiliary_fallback의 검사·전체 예산·기록을 유지한다.
- 주 추론·시스템 운영·임베딩은 자동 대체하지 않는다. 주 추론 실패 시 질의를 보존하고 사용자 재선택·명시 전송을 기다린다. 사용 불가 이후 목록에 조합이 하나 남아도 자동 선택하지 않는다.
- 관리자 지정 용도의 필수 1순위 또는 기본 조합이 없어지는 변경은 저장하지 않는다. 임베딩 교체는 본문/질의의 같은 모델·설정과 벡터 재생성 준비를 확인하며 저장만으로 전환 완료를 표시하지 않는다.
- 공급사 연결·지원 모델·effort의 유효성, 현재 변경 권한, 동일 용도 중복·순위와 자기 기준본을 서버에서 재검사한다. 저장 실패는 기존 적용본과 이력을 유지한다.
- 새 경로가 포함되면 기존 데이터 전송 동의가 자동 확대되지 않는다(REQ-106). 접속/인증 비밀은 배포 설정에 두고 화면·반출에 노출하지 않는다(REQ-403).

### 6-2. 영향 테이블

신규 물리명을 확정하지 않는다. 조합·용도별 순서·기본 지정과 적용 이력의 소유 단위를 후속 설계한다. 자산 변경 요청 원장으로 합치지 않는다.

### 6-3. 상태 전이

적용본 조회 → 편집 → 검증 후 저장 또는 취소. 검증 실패는 입력 유지, 자기 기준본 충돌은 비교/재조회, 결과 불명은 원 명령 결과 확인이다.
관리 목록은 저장 성공한 적용본만 보여준다. 별도 변경 이력 메뉴 SCR-063은 이 네 업무 컬럼과 공통 이력 패턴을 상속하며 독립 목업을 복제하지 않는다.

## 7. API

물리/API 상세는 전체 화면·업무 흐름 합의 후 설계한다. 기존 공급사 연결/지원 정보 조회와 소유 모델 관리 계약을 사용하며 임의 URL·필드명을 추가하지 않는다.

## 8. 시드 · 데이터 전제

SCR-015의 외부 모델 조합별 표시명/코드·단일 식별값 등록과 검증이 선행한다. 화면의 예시 이름과 수준은 실제 지원 계약/초기 운영값이 아니다. 제품 sources/·DB·시드 변경은 이번 작업에서 하지 않는다.

| 외부 모델 | SCR-015의 현재 등록 조합을 조회해 안정 식별값과 표시명 조합으로 후보를 만든다. 입력 가능한 후보는 현재 유효 조합이며 기존 미사용/보완 필요 참조는 원래 값으로 남긴다. | 기존 DataGrid의 일반 select 셀 편집기에 후보를 공급한다. 표시문자열은 공급사 / 모델 표시명 / effort 표시명, 값은 외부 모델 식별값이다. 선택 팝업/확인 레이어를 만들지 않는다. |
| 용도 | agent가 정의한 스텝 유형·LLM 통신 계약 소스에서 읽기 전용 후보 목록을 제공한다. 안정 코드·표시명을 같은 정본에서 가져오며 REQ-610·ADR-020의 소스 계약 경계를 따른다. | 소스 계약 목록을 일반 select 셀 편집기의 후보로 변환하고 값은 계약 코드, 표시는 해당 코드의 표시명을 사용한다. SYS 공통코드 그룹·관리자 자유 입력·admin의 중복 상수 목록으로 대체하지 않는다. |
| 설명 | 사용자가 작성한 해당 용도 설정의 설명 | 일반 text 셀 편집기로 그리드 셀 안에서 입력한다. 별도 팝업/장문 입력 레이어가 아니다. |

- 외부 모델 조회와 소스 계약 목록을 기존 셀 콤보 옵션으로 바꾸는 공통 후보 공급 어댑터/훅을 개발 단계에 마련한다. 기존 DataGrid·옵션 계약을 재사용하고, 공유할 수 있는 후보 조회·상태 처리를 화면마다 복제하지 않는다. 현재는 요건/목업이며 제품 컴포넌트는 구현하지 않는다.
- 최초 조회·후보 갱신의 로딩/조회 실패/0건을 구분한다. 실패를 정상 빈 후보로 바꾸거나 기존 선택을 임의 첫 항목으로 교체하지 않는다. 서버 저장에서도 현재 등록 모델/계약 코드·권한·기준본을 재검증한다. 코드 목록·전달 형식·조회 경로·실제 컴포넌트 이름은 전체 화면/업무 흐름 합의 뒤 확정한다.
- 기존 구현 참고: [배치 스케줄의 조회→후보 변환](../../../../../sources/frontend/src/modules/system/features/batchschedule/pages/BatchSchedulePage.tsx), [메뉴 액션 소스 상수→후보 변환](../../../../../sources/frontend/src/modules/system/features/menu/components/MenuDetailTabs.tsx), [사용자 화면의 소스 상수 콤보](../../../../../sources/frontend/src/modules/system/features/user/pages/UserMgmtPage.tsx), [공통 ColumnDef의 options 계약](../../../../../sources/frontend/src/shared/grid/types.ts). 참고용이며 system 소스를 변경하지 않는다.

- @defer 전체 화면·업무 흐름 합의 후 — 물리명·공개 API·메시지 키·동시성·페이징과 공급사 지원 목록의 실제 연결을 설계한다. 같은 공급사 복수 연결은 등록 연결명으로 식별하고 임의 이름/식별값을 확정하지 않는다.
