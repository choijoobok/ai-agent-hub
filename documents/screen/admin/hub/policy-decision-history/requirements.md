# 요건 정의서 — 정책 판정 이력

## 개요

- **무엇을 하는 화면인가**: 업무 연관성·정책·동의 전송·차단/마스킹 판정의 원 근거를 검색하고 별도 관리자 검토 의견을 남긴다.
- **프로세스상 위치**: 턴/스텝 정책 원판정·동의/전송 → 서버 전체 필터 조회 → 원판정/별도 검토 → 필요한 조사 연결
- **이 데이터를 누가 쓰나**: 권한 있는 관리자와 연결 업무의 담당자가 현재 적용값 또는 업무 처리 근거로 사용한다.
- **바꾸면 어디가 흔들리나**: 소유 기능의 요청·권한·참조 및 이력/감사 연결을 함께 확인한다.

> 미구현 화면 초안이며 사용자 화면 합의·제품 구현·G3(설계 승인 게이트) 승인이 아니다. [화면 정본](../../../../spec/60-screens/_index.yaml)과 [기능 정본](../../../../spec/31-features/002-admin.yaml)을 따른다. 표시 예시는 실제 데이터·물리명·운영 기본값이 아니다.

## 1. 화면 구성

상단 조회조건 → 정책 판정 이력 목록 → 판정 상세 · 당시 버전·근거 · 보존·열람 상태 · 관리자 검토 순서다. 제목·건수는 왼쪽, 작업 버튼은 상단·그리드 툴바·모달 하단에서 우측 정렬한다. 초기 화면의 모든 탭은 실제 전환하며 같은 상위 대상의 입력·선택·추가/제거 행을 유지한다.

### 1-3. 마스터-디테일·이력 경계

- 선택 변경·조회·이탈 때 미저장 변경을 확인하고 취소하면 선택·입력을 보존한다. 결과 불명에는 새 명령 없이 원 처리 결과를 확인한다.
- 업무 원장·로그의 자체 기록을 조회한다. 이 화면 자체를 관리 구성 이력으로 복제하지 않는다.
- 원 사건은 읽기 전용. 현재 권한으로 추가한 관리자 검토/보정 의견·조사 연결 사건만 별도 저장

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

| 테이블 | 역할 | 결합 기준 |
|---|---|---|
| 미정 — 논리: 정책 판정 이력 | 소유 업무 기록/원장 | 안정 식별자 + 해당 조회 문맥. 물리 테이블·컬럼·조인/API는 소유 상세 설계 후속 |

### 3-2. 고정 조건 · 기본 정렬

- 항상 현재 메뉴·액션과 대상 열람 범위를 서버에서 검사한다. 선택한 업무 기록의 당시 내용과 현재 관측을 구분한다.
- 기본 정렬·페이지 방식·조회 기간/상한·보존 기간·대량 반출 한도는 소유 계약 미정이다. 운영값을 추정하지 않는다.
- 모든 필터는 현재 페이지가 아니라 서버 전체 허용 이력에서 적용한다. 조건 일치 스텝이 여러 개여도 턴은 한 번 표시하고 상세에 일치 스텝 근거를 구분한다.

## 10. 미결 · 확인 필요

- A 공통 후속: 대용량 로그 페이징·기간 기본값/상한·원천 시각 기본 정렬과 동률키·전체 반출 상한은 화면 합의 후 확정한다. 현재 목업 공통 푸터의 총 1건·1페이지는 예시이며 offset 계약 확정이 아니다.
- @defer 화면 합의 후 소유 상세 설계 — DB 물리명·와이어 필드·API·공통코드·메시지 키·길이/개수/기간/보존·운영값을 확정한다. 화면 작업은 해당 계약을 추정하지 않는다.
- A 공통 변경 필요: 소유 FEAT의 공개 계약·전역 TC에서 본 화면 사례 연결과 메시지 키를 확정한다. 공통 spec·메뉴·상태·생성기·스타일은 이 B 작업에서 수정하지 않는다.
