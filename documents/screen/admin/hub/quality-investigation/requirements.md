# 요건 정의서 — 오류·품질 조사

## 개요

- **무엇을 하는 화면인가**: 채팅 오류와 품질 문제의 사후 조사를 관리하고 원본별 연결·당시 근거·진단·실제 조치·검증 및 증거 보호를 추적한다.
- **프로세스상 위치**: 오류 발생/신고/개별 실행 실패/감사 검토 → 조사 → 진단·소유 자산 직접 수정 → 실제 조치 검증·종결/재개
- **이 데이터를 누가 쓰나**: 권한 있는 관리자와 연결 업무의 담당자가 현재 적용값 또는 업무 처리 근거로 사용한다.
- **바꾸면 어디가 흔들리나**: 소유 기능의 저장·권한·참조 및 이력/감사 연결을 함께 확인한다.

> 미구현 화면 초안이며 사용자 화면 합의·제품 구현·G3(설계 승인 게이트) 승인이 아니다. [화면 정본](../../../../spec/60-screens/_index.yaml)과 [기능 정본](../../../../spec/31-features/002-admin.yaml)을 따른다. 표시 예시는 실제 데이터·물리명·운영 기본값이 아니다.

## 1. 화면 구성

상단 조회조건 → 오류·품질 조사 목록 → 원본 발생·연결 · 진단·조치·검증 · 당시 증거 · 보호 대상 · 조사 연결 기록 · 관련 자산 순서다. 제목·건수는 왼쪽, 작업 버튼은 상단·그리드 툴바·모달 하단에서 우측 정렬한다. 초기 화면의 모든 탭은 실제 전환하며 같은 상위 대상의 입력·선택·추가/제거 행을 유지한다.

## 8. 시드 · 데이터 전제

- 코드그룹·메시지 키·물리 테이블·필드·신규 API 경로는 미정이다. A 담당 공통 정본 확정 후 연결하며 이번 작업에서 시드·제품 소스를 변경하지 않는다.
