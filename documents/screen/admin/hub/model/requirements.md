# 요건 정의서 — 외부 모델 등록

## 개요

- **무엇을 하는 화면인가**: 공급사 / 모델 표시명 / effort 표시명 지원 조합을 한 행씩 등록하고 외부 모델 식별값 하나로 식별한다. 각 표시명과 실제 호출 코드를 구분한다. 하단에서 같은 공급 경로·모델의 적용 시작일별 입력·캐시·출력 단가를 관리한다. effort가 달라도 가격 이력은 공유한다.
- **프로세스상 위치**: 배포 연결/어댑터 준비 → **공급사·모델·effort 등록과 기간별 단가 관리** → SCR-062 모델 용도·우선순위 설정 → 실행 시 코드 해석.
- **이 데이터를 누가 쓰나**: 토큰 풀 기준 단가 화면은 대상 월 1일 유효 가격을 자동 참조한다. 용도 설정은 등록 모델/effort를 콤보로 선택한다. Portal은 사용 여부가 켜진 유효 텍스트 조합을 사용자 주 추론 선택지로 제공한다. 내부 용도·우선순위 사용 여부와는 별도다.
- **바꾸면 어디가 흔들리나**: 모델 용도 참조·최초 기본값·사용자 선택지·호출/계량 근거. 표시명 변경과 호출 코드 변경은 영향이 다르다.

## 1. 화면 구성

조회조건 → 상단 외부 모델 조합 목록 → 가운데 스플리터 → 하단 기간별 단가 그리드다. 하단 그리드가 하나이므로 탭을 두지 않는다. 모델 표시명/모델 코드와 effort 표시명/effort 코드는 각각 나란한 기본 표시 컬럼이며 별도 셀로 편집한다. 코드 컬럼을 기본 숨김으로 두지 않는다. 외부 모델 식별값·effort 전송 방식 등 보조 정보는 그리드 설정에서 펼쳐 확인한다. 한 행은 공급사·호출 경로·모델·effort의 유효한 조합이며 외부 모델 식별값 하나를 갖는다.
개발 가이드의 공통 그리드 크롬을 사용한다. 조회조건에는 초기화만, 조회·행 추가·저장·업무 버튼은 그리드 상단 우측에 둔다. 편집 그리드의 상태·삭제 컬럼은 저장 전 변경을 표시한다.
상태별 버튼: 허용 목록
행 추가 탭: 외부 모델 조합·기간별 단가
목록 연동: 단가 기준
대상 편집 조건: 가격 편집 가능=Y
행 제거 보호: 삭제 보호 근거

### 그리드 선택

| 그리드 선택 | 선택 방식 |
|---|---|
| 외부 모델 조합 | 단일 |

번호 → 상태(편집 가능) → 업무 컬럼 → 삭제(삭제 가능) 순이다. 단일 행 선택이므로 선택 체크박스를 두지 않는다. 번호·상태는 왼쪽, 삭제는 맨 오른쪽에 고정한다.
행 클릭으로 한 행을 선택한다. 저장은 선택 행만이 아니라 같은 저장 단위의 전체 변경 행을 대상으로 한다.

### 1-1. 연동·편집 단위

상단 행을 고르면 같은 실제 공급 경로·모델의 기간별 단가를 하단에 조회한다. 상단의 단가 기준은 안정된 공유 가격 키를 뜻하며 표시 문자열에서 추론하지 않는다. 같은 가격 키의 effort 행을 왕복해도 단가 입력본을 공유·유지하고 중복 저장하지 않는다. 등록 편집본과 변경한 가격 구성을 함께 저장하며 하단 저장도 같은 단위다. 신규 미저장 조합은 먼저 등록한 뒤 단가를 추가한다. 표시명/코드·지원 여부를 상단 한 행에서 확인한다. 용도 설정은 모델 용도 화면이 소유하며 등록 그리드에는 사용 용도 컬럼을 두지 않는다. 조회 필터 밖의 조합을 삭제로 보지 않으며 전체 편집본과 입력을 유지한다.

### 3-1. 사용 테이블 · 결합

공급사·모델·지원 effort의 안정 참조와 등록 리비전, 배포 연결 참조 및 현재 용도 사용처·공유 가격 이력과 월 산정 참조를 조회한다. 물리 테이블·결합 키는 미정이다.

공급사명/코드, 모델명/호출 코드, 모델별 effort명 순이다. 텍스트 생성/임베딩과 Portal 선택 허용/제외를 구분한다.

## 6. 규칙 — 저장 · 실행

### 6-1. 검증

- 공급사→모델→지원 effort의 실제 조합만 등록한다. 등록명과 코드를 분리하며 대소문자·별칭·숫자 단계 등을 임의 정규화/변환하지 않는다. 값 전송 시 코드 필수, 미전송 시 코드 비움이다.
- 모델 용도에서 참조 중이면 외부 모델 조합 행 삭제를 차단한다. 사용 용도는 해당 외부 모델 식별값을 참조하는 모든 현재 용도를 합해 확인한다. 참조가 미사용/보완 필요여도 남아 있으면 사용 중이다. 용도에서 참조하는 외부 모델 조합을 우회 제거할 수 없다. 사용처를 확인하지 못하면 삭제 가능으로 처리하지 않는다.
- 표시명 변경은 안정 참조를 유지한다. 현재 용도에서 쓰는 호출 모델 코드·effort 코드·전송 방식·연결 교체는 참조 해소 전 거부하고 새 조합 등록 후 용도 이동을 안내한다. 과거 실행/이력의 코드를 덮어쓰지 않는다.
- 사용 여부는 Portal 사용자의 주 추론 선택 허용 여부다. 켜짐이어도 텍스트 유형·현재 연결/지원 조합의 유효성을 만족해야 한다. 임베딩은 꺼짐이며 Portal 후보에 포함하지 않는다.
- 꺼짐은 Portal 신규 선택에서 제외할 뿐 내부 용도·보조 후보·가격 이력/참조를 삭제하거나 해당 모델 호출을 일괄 차단하지 않는다. 저장된 사용자 선택이 이후 꺼짐/무효가 되면 다음 새 턴 전에 재선택하도록 안내하고 다른 모델로 조용히 바꾸지 않는다. 진행 중인 턴의 고정 등록/용도 버전과 코드는 유지한다.
- 삭제 저장과 용도 저장이 경합하면 현재 전체 참조를 일관되게 검사한다. 먼저 생성된 참조를 무시한 삭제나 삭제된 모델/effort를 참조하는 설정은 모두 허용하지 않는다. 삭제 확인 뒤 화면에 남은 오래된 참조로 호출하지 않는다.
- 자기 기준 리비전·현재 변경 권한·실제 연결/어댑터 지원을 서버에서 재검사한다. 코드만 등록해 실제 지원 확인이 끝난 것으로 보지 않는다. 실제 호출·동의/쿼터 집행은 실행 소유 기능이다.
- 시작된 작업은 당시 등록/용도 버전과 실제 전송 코드·전송 여부를 고정 기록한다. 현재 권한·참조/연결·동의 검사는 호출 당시 다시 수행한다. 등록/용도 변경으로 기존 작업을 다른 코드로 호출하지 않는다.
- 접속 주소·API 키·비밀번호는 REQ-403의 배포 설정을 참조한다. 등록으로 전송 동의 범위를 확대하지 않는다(REQ-106). 보조 판정만 기존 자동 대체 범위를 유지한다.

- 가격의 키·기간·검증·잠금·변경 이력은 [REQ-613.price_history_contract](../../../../spec/10-requirements/013-reference-operations.yaml)가 정본이다. 미래 가격은 초안 참조 여부와 무관하게 새 리비전으로 정정/예약 취소하고 이미 적용된 가격은 새 시작일 행으로 변경한다. 기존 초안의 가격 사본·원 리비전은 보존하며 명시 재생성/재선택으로만 갱신한다. 모델/연결 변경과 삭제는 같은 가격 키의 다른 effort·월 산정 참조도 보호한다. 단가 조회 실패를 빈 이력으로 처리하지 않는다.

### 6-2. 영향 테이블

물리명은 미정. 외부 모델 등록 편집본과 변경한 공유 가격 이력의 전체 적용본을 원자 반영한다. 같은 가격 키는 한 번만 저장하며 단가 오류가 있으면 상단 변경도 부분 적용하지 않는다. 용도 참조는 읽고 검증하며 이 화면에서 편집하지 않는다.

### 6-3. 상태 전이

현재 적용본 조회 → 셀 더블 클릭으로 로컬 변경 → 검증 성공 저장 또는 행 원복. 참조 중 삭제·코드 오류·충돌은 미적용/입력 보존, 결과 불명은 원 명령 결과 확인이다.
변경 이력 SCR-051은 상단 등록 목록과 하단 기간별 단가를 당시 전체 구성으로 읽기 전용 상속한다. 독립 이력 요건/목업을 복제하지 않는다.

## 7. API

등록·지원 근거·현재 용도 사용처 조회 및 전체 저장의 공개 계약은 화면/업무 흐름 합의 후 상세 설계한다. URL·DTO·물리명은 확정하지 않는다.

## 8. 시드 · 데이터 전제

배포 연결·어댑터 지원 근거가 선행한다. 화면의 모든 demo 코드는 설명용이며 실제 공급사 지원값이나 초기 운영값이 아니다. 제품 sources/·DB·시드 변경 없음.

- @defer 전체 화면·업무 흐름 합의 후 — 물리명·API·메시지·안정 식별/버전·지원 근거/사용처 계약·삭제/용도 저장 경합과 코드별 실제 어댑터 매핑을 상세 설계한다.
- @defer 전체 화면·업무 흐름 합의 후 — FEAT-015·FEAT-016에서 유지시간별 캐시 쓰기 등 추가 계량 단위의 행 기반 입력/선택을 상세화한다(TRM-088). 현재 입력·캐시·출력 컬럼은 세부 가격 행의 기본 표시이며 물리 컬럼 고정이 아니다. 여러 쓰기 단위를 하나의 가격에 합치지 않고 현재 화면에서 구분 등록할 수 없는 단위는 산정 미완료로 차단한다.
- @defer 제품 구현 후 — 실제 API/개발 CLI 전송값·생략·숨은 재시도/계량·동의/삭제 경합을 검증한다. 목업 조작은 제품 검증이 아니다.
