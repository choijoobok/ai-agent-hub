# 요건 정의서 — 토큰 풀 기준 단가

## 개요

- **무엇을 하는 화면인가**: 월별 USD/100만 토큰 기준 단가를 산정하고, 해당 월의 턴 가정 또는 대상 월 직전 월 실적 스냅샷·단가·수량·메모·쿼터 기준 저장에 따른 고정 기록을 확인한다.
- **프로세스상 위치**: SCR-015 모델 조합·기간별 단가/소스 용도 확인 → 수동 턴 가정 또는 대상 월 직전 월 실적 초안 → USD 기준 단가 작성·저장 → SCR-021 월 기준 저장 시 단가 고정 → 쿼터 배분 실행.
- **이 데이터를 누가 쓰나**: 다음 달 토큰 풀 계획 담당자. 저장된 유효 단가를 같은 년월 쿼터 기준에서 참조한다.
- **바꾸면 어디가 흔들리나**: 고정 전 대상 월의 USD 기준 단가와 다음 달 풀 미리보기. 고정된 단가·배정·사용량은 소급 변경하지 않는다.

## 1. 화면 구성

상단 월 목록에 년월·총 예상 비용·비중복 토큰 합계·USD/100만 토큰 기준 단가·초안 생성자·생성일시·메모·단가 상태를 함께 표시한다. 산정 요약과 산정 근거 탭은 두지 않는다. 하단은 산정 항목·실적 스냅샷 두 탭이다. 생성자/일시는 서버가 최초 생성 당시 기록하며 메모만 셀에서 편집한다. 같은 월의 메모와 산정 항목 전체를 한 번 저장한다. 다음 달 초안 생성은 직전 월 실적 스냅샷과 대상 월 1일 유효 모델 가격을 결합해 상단 월 요약·하단 두 탭을 함께 만든다. 같은 월 재생성은 기존 보완과 비교·명시 반영한다.

목록 연동: 년월
대상 편집 조건: 고정 여부=N
선택 무관 버튼: 다음 달 초안 생성
산정 검증 버튼: 저장
행 추가 탭: 산정 항목
상태별 버튼: 허용 목록

### 3-1. 사용 테이블 · 결합

소유 월의 산정 기록·확정 기준과 당시 소비 구성/요금 근거 및 대상 월 직전 월 실적 스냅샷을 조회한다. 모델은 SCR-015 안정 식별값과 당시 호출 구성을, 용도 후보는 agent 소스 스텝 유형/LLM 통신 계약을 참조한다. 물리명·조인·API 상세는 후속이다.

## 6. 규칙 — 저장 · 실행

### 6-1. 산식과 집계

산식·미상 처리·용도/귀속·스냅샷·고정 경계는 [REQ-613.calculation_contract](../../../../spec/10-requirements/013-reference-operations.yaml)가 정본이다.

- 수동 턴 가정과 대상 월 직전 월 실적 월 합계를 같은 산식으로 계산한다. 월 합계를 용도별 서로 다른 호출수/턴수로 나눠 구성비를 바꾸지 않는다.
- 입력에 캐시가 포함되면 비캐시 입력을 분리한다. 캐시 세부 과금 단위의 비용과 쿼터 토큰 중첩을 구분하며 미지원/미상 단위는 보완 전 유효 단가로 저장/참조하지 않는다. 추론량이 출력에 포함되면 중복 가산하지 않는다.
- 실제 계량의 현재 유효값을 스냅샷 상한 시각까지 합산한다. 동일 실행 누적 재수신 중복을 제거하고 실패/중단/재시도/대체의 실제 소비는 남긴다. 현재 용도 미지정 모델의 사용자 주 추론·질의 임베딩 등 사용자 귀속 개인 쿼터 차감 대상은 모두 포함하며 시스템 운영/지식 재임베딩은 분리한다.
- USD 가격은 SCR-015의 기간별 단가가 원천이며 [REQ-613.price_history_contract](../../../../spec/10-requirements/013-reference-operations.yaml)에 따라 대상 월 1일 유효 가격 한 세트를 선택한다. effort는 같은 경로/모델의 가격을 공유한다. 등록된 할인·프로모션·인상 가격을 사용하고 월중 변경은 가중하지 않는다. 가격·원 시작일·기준일·리비전·출처/확인일을 산정 항목에 복사 보존하며 이 화면에서 단가를 직접 입력하지 않는다. 가격 보완은 모델 화면 저장 후 명시 재생성/재선택으로 반영한다.
- 공급사 계량·Hub 추정·미상/누락을 구분한다. 분모0·비용0·미보완 미상/환산·단가·정규화 근거 미비는 유효 저장/쿼터 기준 참조 불가다. 추정 보완은 원 미상 자료와 사유를 보존하며0으로 숨기지 않는다.

### 6-2. 저장·참조 범위

선택 고정 전 월의 메모·산정 항목·실제 원 스냅샷·가격 스냅샷과 보완값/사유를 함께 저장한다. 원천 조회 실패 시 기존 초안을 유지하고 일부만 갱신하지 않는다. 대상 월 가격이 없으면 원 실적은 보존하되 산정 미완료·유효 저장/고정 불가다. 상세 재생성·가격 보존 규칙은 REQ-613.calculation_contract를 따른다. 생성자/일시는 최초 생성 기록에서 조회한다. 실적 원장·다른 월·모델 등록을 바꾸지 않는다. SCR-021은 같은 년월의 저장된 유효 단가를 행 추가 때 참조하며 화면의 표시 문자열로 조합/월 기록을 추정하지 않는다. 물리명/API 상세는 미정이다.

### 6-3. 쿼터 기준 저장에 따른 단가 고정

작성·저장 → 같은 년월 SCR-021 월 기준 저장 성공과 함께 고정. 이때 현재 권한·단가 유효성·추가 당시 기준본과 현재본을 재검사한다. 실적과 대상 월1일 유효 가격을 함께 재대조한다. 실적 재대조는 고정 요청의 서버 상한 시각으로 수행하고 차이가 있으면 비교·명시 재확인하며 재확인 중 상한을 계속 이동하지 않는다. 월 기준 저장과 단가 고정은 함께 성공하거나 함께 실패한다.

고정된 월의 메모·요금/수량·원 스냅샷은 수정/재생성할 수 없다. 수동 실행은 미래 예정 생성이고 최종 효력 사용자/등급·인원/개인 한도는 월말 배치의 대상 월 시작 마감으로 고정한다. 최초 저장된 USD 단가는 이때도 교체하지 않는다. 지연 계량은 원 사용 월에 정정하되 잠긴 단가/과거 배정은 바꾸지 않는다. 배분 미실행 월의 월말 승계와 원 저장 기준/실제 적용 기준 구분은 REQ-118이 소유한다.

### 6-4. LLM 입력 준비

[REQ-610](../../../../spec/10-requirements/012-reference-business.yaml)의 `prompt_contract.admin_input_preparation.sources.token_rate`가 이 화면의 **프롬프트 포함 후보 / 서버 집행 / 관리·감사 항목**, 해석 가이드 및 제공 단계·조건을 정의한다. §4의 실제 컬럼과 대응하며 공통 해석 규칙은 같은 절의 `guides`·`conditions`·`stages`를 따른다.

화면 목록/상세 응답을 그대로 모델에 전달하지 않는다. 기존 관리 값을 사용하고 입력 분류용 컬럼·탭을 추가하지 않는다. 실제 조합·전송과 최종 JSON/CLI·API 계약은 업무 지식 관리·전체 흐름 합의 뒤 소유 작업흐름에서 구체화한다. 아래 검수는 설계 대조이며 목업에서 LLM 호출을 시연하거나 제품 실행 검증을 완료한 것으로 표시하지 않는다.

## 7. API

기존 공통 조회/저장/명령·스냅샷 보존 계약의 소유 상세 설계 후속이다. 새 API 경로·와이어 속성·가격/계량 자동 수집 수단을 확정하지 않는다.

## 8. 엑셀

현재 표시 열·선택 월·반출 권한을 적용한다. 확정 기록은 당시 값으로 내보내며 미상/추정·근거 기준 시각을 감추지 않는다.

## 10. 미결 · 확인 필요

- @defer 전체 화면/업무 흐름 합의 후 — 실제 집계/자동 초안 스케줄·전달 계약·메시지 키·물리 구조·API 상세·금액 정밀도/반올림·기간/대량 처리 한도를 설계한다. 산식의 토큰/비용 반올림을 임의로 선행 적용하지 않는다.
- @defer 개발 단계 — SCR-015 등록 데이터와 agent 소스 계약 목록을 기존 일반 셀 콤보 options에 공급한다. 목업의 모델/용도/가격은 정적 예시이며 제품 조회/집계 완료로 표시하지 않는다. 미상 단위·캐시 정규화·최종 유효 계량 선택은 실제 공급 경로별 계약 시험을 수행한다.
- 고객 제출 HTML은 이 요건서와 정본에서 재생성한다. 목업 계산은 JS 수치 시연이며 제품 금액 정밀도 계약을 대신하지 않는다.
