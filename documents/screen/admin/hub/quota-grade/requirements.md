# 요건 정의서 — 쿼터 등급 관리

## 개요

- **무엇을 하는 화면인가**: 시작월별 등급·순위·배분 가중치를 한 번 등록하고 변경 전까지 계속 적용한다. 상단은 기준 시작월·메모·등록자/등록일시, 하단은 해당 기준의 전체 등급이다.
- **프로세스상 위치**: 등급 기준 등록 → 월별 개인 쿼터 기준에서 적용 기준 조회 → 월말 배치의 다음 달 사용자 배분
- **문서 범위**: 2026-11-14 승인된 admin G3 및 CR-043 범위 구현. 기준 관리·전체 이력·연결 포트를 제공하며 실제 사용자 이전/예정 배정/마감 연결은005/017/045에서 검증한다. 목업 수치는 예시다.

## 1. 화면 구성

시작월별 등급·순위·배분 가중치를 한 번 등록하고 변경 전까지 계속 적용한다. 상단은 기준 시작월·메모·등록자/등록일시, 하단은 해당 기준의 전체 등급이다. 제목·건수는 왼쪽, 작업 버튼은 각 그리드 상단 오른쪽이다. 하단 그리드가 하나이므로 탭 없이 가운데 스플리터 아래에 쿼터 등급 그리드를 직접 표시한다. 기준을 왕복해도 입력·선택을 유지한다.

목록 연동: 등급 기준 시작월
대상 편집 조건: 편집 가능=Y
선택 무관 버튼: 상단 행 추가. 기준 복사는 유효한 시작월의 신규 행 선택 필요
행 추가 탭: 등급 기준·쿼터 등급
상태별 버튼: 허용 목록

## 3. 조회 — 테이블과 범위

현재값은 AI_ADMIN_QUOTA_GRADE_SET·AI_ADMIN_QUOTA_GRADE_ITEM, 안정 식별은 AI_ADMIN_QUOTA_GRADE, 전체 이력은 부모/자식 _HIST다. 물리 정본은 ENT-105/115/116/205/210이다. 현재 메뉴/대상별 권한과 반출 범위를 각각 검사하며 실패·미상·0건을 구분한다. 원 명령/자기 기준본·안정 참조는 비표시로 보존한다.

## 6. 규칙 — 저장 · 실행

- 등급 기준은 시작월별 전체 등급 세트다. 대상 월 이하인 시작월 중 가장 최근 기준 하나를 사용하며 다음 기준 시작 전까지 계속 적용한다. 매월 복제/재등록하지 않는다. 적용 가능한 기준이 없으면 임의 기본 가중치로 배분하지 않는다.
- 새 기준은 미래 시작월로 작성하고 직전 기준의 전체 등급을 편집용으로 복사할 수 있다. 시작월은 저장 후 변경하지 않는다. 현재/과거에 적용된 기준은 수정/삭제하지 않고 변경은 새 미래 기준으로 등록한다.
- 등급은 안정 참조로 연결한다. 이름 변경이나 새 기준 복사가 사용자/승인/과거 배정의 참조를 새 이름 파싱으로 바꾸지 않는다. 신규 기본 등급은 해당 효력 월 기준의 최하위 등급이다.
- 배분율은 기존 상대 가중치다. 0보다 큰 수·소수 둘째 자리이며 순위가 높은 등급의 값은 낮은 등급 이상이다. 등급별 전체 풀의 백분율이나 합계100 조건을 만들지 않는다. 개인 기본 한도 산식은 REQ-116이 정본이다.
- 등급명·순위는 같은 기준 안에서 중복하지 않는다. 빈 세트/누락 가중치·순위 역전은 저장을 거부한다. 사용 중인 등급을 제거/통합할 때는 같은 미래 기준에 남는 이전 등급과 영향 대상을 확인하고 전체를 함께 저장한다. 등급 이전 효력은 해당 변경 기준 시작월 S부터이고 S 이전 월은 바꾸지 않는다. 원 승인/효력 이력은 수정하지 않고 별도 이전 근거를 남기며 후속 기준에서 대응 등급이 빠지면 보완 전 반영하지 않는다. 미래 기준 삭제 시 그 기준에서 파생한 미발효 이전 예약도 함께 대조하고 필요한 취소/대체 예약을 별도 이력으로 반영한다. 이미 발효한 사용자 등급/승인 이력은 삭제하지 않는다.
- 미래 기준의 수정/삭제는 그 시작월부터 다음 기준 직전월의 기준 영향과 이전된 사용자 효력 예약이 이어지는 후속 기준까지 검사한다. 해당 구간의 수동 예정 배분은 낡음으로 표시하고 월말 배치는 다음 달 유효 기준의 최신 저장본으로 최종 산정한다. 월 시작 후 실제 적용본을 변경하지 않는다.
- 등록자/등록일시는 최초 저장의 서버 기록이다. 메모는 기존 largeText 셀 위 textarea로 편집한다. 같은 기준의 메모와 등급 전체를 저장하며 등록 정보는 수정하지 않는다.
- 현재 권한·자기 기준본 충돌·전체 참조 유효성을 저장 시 다시 검사한다. 등급 변경으로 사용자 그룹/모델 선택 권한을 바꾸지 않는다. 변경 이력은 원 화면을 상속하는 별도 메뉴이며 독립 목업을 복제하지 않는다.

### 현재 구현의 저장·삭제 범위

- 상단 한 행의 메모와 하단 전체 등급은 함께 저장한다. 하단에는 독립 저장 버튼이 없다. 여러 시작월은 독립 성공 단위이며 실패한 기준만 남긴다. 원 키·본문을 탭 저장소에 보존하고 재시도는 원 결과 확인부터 한다.
- 신규 기준의 유효 시작월을 입력하면 직전 기준을 읽어 복사를 준비한다. **직전 기준 복사**는 조회된 편집본을 하단에 넣으며 저장 전에는 DB 효과가 없다. 복사한 안정 등급 ID를 유지하고 등록자/시각은 새 기준의 서버 기록이다.
- 마스터의 기존 행 삭제는 기본 잠금이며 상세 조회 후 열린다. **소유 전체 구성 삭제 예외**: 하단 등급은 기준과 함께 저장·삭제하는 직접 소유 구성으로, 외부 사용자/예약/배정 참조와 구별한다. 미래 기준이고 전체 외부 참조 없음이 확인되면 하단 등급이 존재해도 기준 삭제를 허용한다. 안정 등급 식별·과거 HIST와 기존 사용자/배정 관계는 자동 삭제하지 않는다.
- 원장 전체 미설치는 NOT_INSTALLED로 표시하며 참조 사용자 수를0명으로 표기하지 않는다. 일부 설치·검사 누락·실패는 UNAVAILABLE이며 저장/삭제를 막는다. 서버는 같은 잠금/트랜잭션에서 현재 상태를 다시 검증한다.
- GRADE_SET_ID·GRADE_ID·REVISION은 비표시 십진 문자열이다. 신규 자식은 clientKey로 구별해 서버가 안정 ID를 발급한다. 가중치는 API에서 정확한 십진 문자열로 전달한다.

### 6-4. LLM 입력 준비

[REQ-610](../../../../spec/10-requirements/012-reference-business.yaml)의 `prompt_contract.admin_input_preparation.sources.quota_grade`가 이 화면의 **프롬프트 포함 후보 / 서버 집행 / 관리·감사 항목**, 해석 가이드 및 제공 단계·조건을 정의한다. §4의 실제 컬럼과 대응하며 공통 해석 규칙은 같은 절의 `guides`·`conditions`·`stages`를 따른다.

화면 목록/상세 응답을 그대로 모델에 전달하지 않는다. 기존 관리 값을 사용하고 입력 분류용 컬럼·탭을 추가하지 않는다. 실제 조합·전송과 최종 JSON/CLI·API 계약은 업무 지식 관리·전체 흐름 합의 뒤 소유 작업흐름에서 구체화한다. 아래 검수는 설계 대조이며 목업에서 LLM 호출을 시연하거나 제품 실행 검증을 완료한 것으로 표시하지 않는다.

## 10. 미결 · 확인 필요

- SLICE-005에서 실제 사용자 효력/예약과 참조 수·명시 등급 이전을 연결했다. 새 등급도 같은 저장의 clientKey로 이전 대상으로 지정할 수 있다. 사용자별 현재값/부모 판/전체 이력은 기준 변경과 같은 트랜잭션이다. @defer SLICE-017/045 — 예정본 낡음·월말 배정 경합은 생산 연결로 검증한다.
- 별도 이력 조회 메뉴는 후속 공통 이력 화면에서 제공한다. 현재값·전체 HIST 저장은 구현됐다.
