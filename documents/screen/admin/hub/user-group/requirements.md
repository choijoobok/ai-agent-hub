# 요건 정의서 — 사용자 그룹

## 개요

- **무엇을 하는 화면인가**: 그룹 정의를 관리하고 선택 그룹의 사용자·지식·스키마 카탈로그·API·커스텀 도구 매핑을 다섯 탭에서 확인·편집한다.
- **프로세스상 위치**: 그룹 선택 → 탭의 현재 매핑/제약 확인 → 활성 스위치·사유 편집 → 해당 소유 업무의 직접 저장 처리 → 현재 적용본 재조회.
- **이 데이터를 누가 쓰나**: 사용자 접근·자산 권한 관리 담당자가 그룹 관점에서 현재 허용 범위와 변경 후보를 확인한다.
- **바꾸면 어디가 흔들리나**: 소속 부여/회수와 각 자산 편집본·저장·이력. 정본은 REQ-605.mapping_workbench와 각 소유 계약이다.

## 1. 화면 구성

조회조건 → 상단 사용자 그룹 목록 → 상하 스플리터 → 사용자·지식·스키마 카탈로그·API·커스텀 도구 다섯 탭이다.
각 탭은 현재 활성 매핑과 현재 조회 권한 안의 비활성/미매핑 후보를 구분해 표시한다. 스위치 값은 저장 전 편집본이며 현재 접근 상태와 별도다. 지식 탭에는 인증 예제도 자산 종류로 구분하고, 커스텀 도구 탭에는 등록 업무 도구를 내부 빈/API 기반 유형으로 구분한다.
제목·건수는 왼쪽, 작업 버튼은 오른쪽이다. 스위치는 한 번 눌러 변경하고 사유는 셀에서 입력한다. 새 대상 등록/계약·컬럼 예외 편집은 원 소유 화면의 업무다.

목록 연동: 그룹 식별자
대상 편집 조건: 대상 선택됨=Y
상태별 버튼: 허용 목록

행 클릭으로 선택하고 선택 체크박스는 두지 않는다. 탭의 저장은 선택 행만이 아니라 선택 그룹·해당 탭의 전체 변경 후보를 대상으로 하며 다른 그룹/탭의 미저장 변경을 포함하지 않는다.

### 1-1. 마스터-디테일 연동

- 안정 그룹 식별자로 다섯 탭을 함께 조회한다. 그룹명 변경으로 매핑을 다시 식별하지 않는다.
- 그룹/탭을 왕복해도 각 편집본·입력·선택을 유지한다. 재조회·이탈은 미저장 변경 확인 후 처리한다. 아직 저장되지 않은 신규 그룹은 매핑 편집을 잠근다.
- 원천의 일부 목록·열람 제한·조회 실패를 빈 전체 매핑으로 간주하지 않는다. 화면에 보이지 않은 다른 그룹/자산 매핑을 삭제하거나 후보에서 누락하지 않는다.

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

그룹 정의와 각 원 소유의 현재 사용자 소속·지식/인증 예제·테이블·업무 API·도구 그룹 매핑을 안정 참조로 역조회한다. 실제 테이블·결합·페이징 계약은 후속이다. 조회자는 그룹 화면과 각 원천의 현재 열람 범위를 함께 만족해야 한다.

### 3-2. 고정 조건 · 기본 정렬

선택 그룹의 활성 매핑과 비활성/미매핑 후보를 구분한다. 현재 접근은 현재 적용본에서만 판정하고 편집값과 섞지 않는다. 그룹 하나만으로 다른 소속 그룹·사용자 대상 매핑·컬럼/행·계약·노출·원 시스템 권한까지 확정했다고 표시하지 않는다.

스위치 클릭은 입력 변경이다. 각 탭의 저장은 선택 그룹·해당 탭의 전체 변경을 현재 권한으로 검증하고 원 소유 구성과 이력을 함께 반영한다. 원천 불명·권한 없음·저장 중에는 이유와 잠금을 표시한다.

## 6. 규칙 — 저장 · 실행

### 6-1. 검증

- 변경 권한을 부여받은 소수의 업무 전문가와 관리자만 직접 저장한다. 서버는 저장 직전 현재 액션·대상 범위 권한과 자기 기준 리비전·필수 참조·기술 검증을 확인한다. 전체 변경과 변경 전후 이력·변경자·시각·사유를 원자적으로 반영한다. 조회 권한이나 일반 admin 계정만으로 변경할 수 없으며 별도 승인 요청·전결·승인 사용 설정은 제공하지 않는다.
- 그룹 정의 저장은 하단 매핑 변경을 포함하지 않는다. 하단 저장은 선택 그룹·현재 탭의 변경 대상에 대해 원 소유의 전체 구성과 기준 리비전을 검증한다. 화면에 없는 다른 그룹·자산 본문·컬럼 예외를 보존한다. 부분 조회를 전체 집합으로 저장하지 않는다.
- 사용자 소속 추가·재부여·회수도 직접 저장이며, 마지막 활성 그룹의 회수는 Portal 이용자 비활성화와 원자 처리한다. 물리 삭제 없이 원 부여/회수 이력을 보존한다.
- 지식·카탈로그·API·도구에 대한 그룹 매핑은 서로 별개다. 매핑만으로 다른 자산·신원·행 스코프·실행 권한을 자동 부여하지 않는다.
- 상태 미상·현재 권한 없음·대상 비활성은 편집을 잠근다. 실패·기준본 충돌에는 현재 적용본/이력을 유지하고 입력은 보존한다. 결과 불명은 원 명령 키로 확인한다.

### 6-2. 영향 테이블 · 저장 범위

원 소유 계약의 현재 매핑·전체 구성을 저장하며 같은 원자 단위로 변경 전후·변경자·시각·사유와 전체 세트 이력을 남긴다. 별도 승인 원장·사본 매핑을 새로 만들지 않는다. 과거 승인 근거가 있다면 읽기 전용으로 보존하고 철회된 대기 요청은 자동 반영하지 않는다.

### 6-3. 상태 전이

현재값 조회 → 탭별 임시 편집 → 현재 변경 권한·전체 구성 검증 → 직접 저장과 이력 기록 → 현재값 재조회. 스위치 클릭만으로 현재 접근을 바꾸지 않는다.

## 7. API

그룹 관점의 매핑 조회·후보 전달은 기존 소유 기능을 재사용하는 진입 계약으로 상세화한다. URL·DTO·물리명은 화면/전체 업무 흐름 합의 후다. 실제 접근 판정·실행을 목업 저장이 대신하지 않는다.

## 8. 시드 · 데이터 전제

메뉴·메시지·권한 시드와 제품 소스는 이번 화면 검토에서 구현하지 않는다. 기존 그룹·대상 안정 식별자와 현재 적용본·현재 변경 권한을 조회할 수 있어야 한다. 예시 데이터는 모두 가상이다.
