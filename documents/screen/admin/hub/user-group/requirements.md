# 요건 정의서 — 사용자 그룹

## 현재 구현 범위 — CR-040

그룹 정의 생성·조회·수정, 공통 전체 이력, 독립 행별 저장 결과와 다섯 탭의 연결 상태를 제공한다.
사용자 소속 편집·선택 팝업은 `@defer SLICE-005`, 자산 실원천 조회·권한 소비는 `@defer SLICE-002/003/004/011/020`이다. 아래 소속/자산 업무 규칙은 후속 연결의 기준이며 현재 제공 기능으로 읽지 않는다.

현재는 그룹명 부분 일치로 명시 조회한다. 사용 상태는 USED/UNUSED/UNKNOWN의 읽기 전용 표시이고 원천이 연결되기 전 상태 검색은 제공하지 않는다. 다섯 탭은 미연결·장애·권한 제한을 0건과 구분한다. 전체 참조 없음이 확인되지 않으면 삭제를 막는다. 자산 탭은 쓰기/다운로드를 열지 않으며 그룹 정의는 현재 페이지 내보내기만 제공한다.

그룹 정의 저장은 상단 변경 사유와 각 행의 안정 ID/기준 리비전을 사용한다. 독립 행은 부분 성공하며 실패 행만 남는다. 통신 실패로 미확정인 명령은 같은 관리자·브라우저 탭의 저장소에 원 입력을 보존하고 편집/신규 추가를 잠근다. 다시 저장하면 원 결과부터 확인하며 새 키로 자동 재실행하지 않는다. 다른 브라우저에서 중복 신규 등록하지 않는다.

좌측 최상위 메뉴의 초기 표시 순서는 대시보드 → 시스템 → AI Agent Hub 관리다. 하단 다섯 탭은 각 버튼 최소 너비 80px와 남는 높이를 사용하는 공통 DetailTabs를 적용한다.

## 개요

- **무엇을 하는 화면인가**: 그룹 정의와 사용자 소속을 관리하고, 지식·스키마 카탈로그·API·커스텀 도구의 현재 매핑을 조회한다.
- **프로세스상 위치**: 그룹 선택 → 사용자 소속 관리 또는 자산 네 탭의 현재 매핑/제약 조회. 자산 매핑 변경은 각 자산 관리 화면에서 전체 구성과 함께 저장한다.
- **이 데이터를 누가 쓰나**: 사용자 접근·자산 권한 관리 담당자가 그룹 관점에서 현재 허용 범위를 확인한다. 사용자 소속 변경만 이 화면에서 처리한다.
- **바꾸면 어디가 흔들리나**: 그룹 정의·사용자 소속 부여/회수의 이력. 자산 매핑은 각 자산 전체 저장·이력에 포함되며 이 화면의 조회로 변경되지 않는다. 정본은 REQ-605.mapping_workbench와 각 소유 계약이다.

## 1. 화면 구성

조회조건 → 상단 사용자 그룹 목록 → 상하 스플리터 → 사용자·지식·스키마 카탈로그·API·커스텀 도구 다섯 탭이다.
사용자 탭은 현재 소속과 부여/회수 후보를 구분한다. 자산 네 탭은 선택 그룹의 현재 매핑의 식별·명칭·활성 결과를 조회하며 매핑 활성 여부은 읽기 전용 스위치로 표시한다. 지식 탭에는 지식만 표시하며 인증 예제는 지식에만 연결한다. 커스텀 도구 탭은 도구 식별자·도구명·매핑 활성 여부만 조회한다. 실행 구현 유형은 도구 관리 소유다.
제목·건수는 왼쪽, 작업 버튼은 오른쪽이다. 사용자 소속 스위치와 메모만 편집한다. 자산 탭에는 행 추가·저장·삭제·변경 사유 입력을 두지 않는다. 자산의 매핑·계약·컬럼 예외 변경은 원 소유 화면에서 전체 구성과 함께 처리한다.

### 1-1. 마스터-디테일 연동

- 안정 그룹 식별자로 다섯 탭을 함께 조회한다. 그룹명 변경으로 매핑을 다시 식별하지 않는다.
- 그룹/탭을 왕복해도 사용자 탭 편집본과 각 탭 선택을 유지한다. 재조회·이탈은 그룹 정의·사용자 소속의 미저장 변경을 확인한다. 저장되지 않은 신규 그룹은 하단 조회·사용자 소속 편집을 잠근다.
- 원천의 일부 목록·열람 제한·조회 실패를 빈 전체 매핑으로 간주하지 않는다. 화면에 보이지 않은 다른 그룹/자산 매핑을 삭제하거나 후보에서 누락하지 않는다.

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

그룹 정의와 각 원 소유의 현재 사용자 소속·지식·테이블·업무 API·도구 그룹 매핑을 안정 참조로 역조회한다. 실제 테이블·결합·페이징 계약은 후속이다. 조회자는 그룹 화면과 각 원천의 현재 열람 범위를 함께 만족해야 한다.

### 3-2. 고정 조건 · 기본 정렬

사용자 탭의 소속/부여 후보와 자산 네 탭의 현재 매핑 조회를 구분한다. 현재 접근은 현재 적용본에서만 판정하고 사용자 소속 편집값과 섞지 않는다. 그룹 하나만으로 다른 소속 그룹·사용자 대상 매핑·컬럼/행·계약·노출·원 시스템 권한까지 확정했다고 표시하지 않는다.

내부 자동 번호와 참조값은 [REQ-601의 자동 식별자 규칙](../../../../spec/10-requirements/011-reference-integration.yaml)을 따른다. 읽기 전용 번호는 입력하지 않는다. 신규 행에는 저장 전 번호가 없고 저장 성공 후 표시된다. 대상 선택은 이름으로 하며 저장되는 참조는 같은 숫자 식별자다. 업무 코드·설정 키·순번·리비전과 구분한다.

## 6. 규칙 — 저장 · 실행

### 6-1. 검증

- 변경 권한을 부여받은 소수의 업무 전문가와 관리자만 직접 저장한다. 서버는 저장 직전 현재 액션·대상 범위 권한과 자기 기준 리비전·필수 참조·기술 검증을 확인한다. 전체 변경과 변경 전후 이력·변경자·시각·사유를 원자적으로 반영한다. 조회 권한이나 일반 admin 계정만으로 변경할 수 없으며 별도 승인 요청·전결·승인 사용 설정은 제공하지 않는다.
- 그룹 정의 저장은 하단 매핑을 포함하지 않는다. 사용자 탭 저장은 선택 그룹의 소속 부여/회수만 처리한다. 자산 네 탭에는 변경 명령·행 추가·저장·삭제·사유 입력을 제공하지 않으며 조회/행 선택으로 자산 이력이나 리비전을 만들지 않는다.
- 자산의 그룹 매핑 변경은 각 자산 관리 화면에서 본문·계약·다른 매핑을 포함한 전체 구성을 확보해 저장한다. 변경 전후 전체 이력 사본(HIST)에 그룹 매핑도 같은 자산 리비전으로 포함한다. 그룹 화면 전용 자산 매핑 저장·부분 이력은 만들지 않는다.
- 사용자 소속 추가·재부여·회수도 직접 저장이며, 마지막 활성 그룹의 회수는 Portal 이용자 비활성화와 원자 처리한다. 물리 삭제 없이 원 부여/회수 이력을 보존한다.
- 지식·카탈로그·API·도구에 대한 그룹 매핑은 서로 별개다. 매핑만으로 다른 자산·신원·행 스코프·실행 권한을 자동 부여하지 않는다.
- 상태 미상·현재 권한 없음·대상 비활성은 편집을 잠근다. 실패·기준본 충돌에는 현재 적용본/이력을 유지하고 입력은 보존한다. 결과 불명은 원 명령 키로 확인한다.

두 탭의 소속 데이터 항목·복합 식별·감사 의미는 REQ-609.membership_record를 따른다. 같은 사용자/그룹 조합의 중복 행을 만들지 않고 재부여는 기존 소속을 활성화하며 최초 등록 감사값을 보존한다. 어느 화면에서 저장하든 동일한 현재값·변경 이력과 기대 버전을 사용한다. 사용자/그룹 이름은 참조 정보이며 별도 소속 저장 컬럼으로 복제하지 않는다.

### 6-2. 영향 테이블 · 저장 범위

그룹 정의와 사용자 소속 변경만 각각의 소유 계약으로 저장·기록한다. 자산 네 탭은 원 소유의 현재 매핑을 역조회하며 쓰기를 수행하지 않는다. 자산 변경과 전체 매핑의 이력 사본은 각 자산 화면의 전체 저장 단위에 속한다. 별도 승인 원장·사본 매핑을 새로 만들지 않는다. 과거 승인 근거가 있다면 읽기 전용으로 보존하고 철회된 대기 요청은 자동 반영하지 않는다.

### 6-3. 상태 전이

사용자 소속: 현재값 조회 → 임시 편집 → 현재 변경 권한·기준본 검증 → 직접 저장과 소속 이력 기록 → 재조회. 자산 네 탭: 그룹 선택 → 현재 매핑 조회 → 필요 시 원 자산 화면에서 전체 구성 변경·저장 → 재조회.

추가 후보의 원천과 선택 결과는 REQ-609.membership_record.candidates를 따른다. 추가 버튼은 이 탭에 하나만 두며 표시명은 추가다. Portal 사용자 조회 팝업의 선택은 저장된 선택 그룹을 고정한 편집 행만 만든다. 닫기·조회 실패·선택 없음에는 변경 행을 만들지 않는다. 현재·미저장 소속의 중복을 검사하고 저장 시 현재 권한·대상 유효성·기대 버전을 다시 검증한다.

### 6-4. LLM 입력 준비

[REQ-610](../../../../spec/10-requirements/012-reference-business.yaml)의 `prompt_contract.admin_input_preparation.sources.user_group`가 이 화면의 **프롬프트 포함 후보 / 서버 집행 / 관리·감사 항목**, 해석 가이드 및 제공 단계·조건을 정의한다. §4의 실제 컬럼과 대응하며 공통 해석 규칙은 같은 절의 `guides`·`conditions`·`stages`를 따른다.

화면 목록/상세 응답을 그대로 모델에 전달하지 않는다. 기존 관리 값을 사용하고 입력 분류용 컬럼·탭을 추가하지 않는다. 실제 조합·전송과 최종 JSON/CLI·API 계약은 업무 지식 관리·전체 흐름 합의 뒤 소유 작업흐름에서 구체화한다. 아래 검수는 설계 대조이며 목업에서 LLM 호출을 시연하거나 제품 실행 검증을 완료한 것으로 표시하지 않는다.

현재 정의 물리 매핑은 ENT-102/202, API-085/105/106/109를 따른다. 그룹명은 공백 제거 후 필수·최대100자, 설명·변경 사유는 공백 불가이며 감사 값·번호·리비전·사용 상태·소속을 입력하면 거부한다. 그룹 정의 감사 넷은 공통 합성한다. 메시지는 `group.*`, 메뉴는 `HUB_USER_GROUP`, 경로는 `/admin/hub/user-group`이다.

## 7. API

그룹 관점의 자산 매핑 API는 조회만 제공한다. 사용자 소속의 부여/회수는 기존 소유 기능을 재사용한다. 자산 매핑 쓰기 API·후보 전달 계약은 이 화면에 제공하지 않는다. URL·DTO·물리명은 화면/전체 업무 흐름 합의 후다. 실제 접근 판정·실행을 목업 저장이 대신하지 않는다.

## 8. 시드 · 데이터 전제

메뉴·메시지·권한 시드와 제품 소스는 이번 화면 검토에서 구현하지 않는다. 기존 그룹·대상 안정 식별자와 현재 적용본·현재 변경 권한을 조회할 수 있어야 한다. 예시 데이터는 모두 가상이다.

현재 실행 검수 TC-00611: 그룹 신규·수정의 번호/전체 이력/등록 감사 보존, 중복 원 명령 재수신, 낡은 리비전/현재 SAVE 부재/위조 하단 거부, HIST 실패 전체 롤백, 독립 행 부분 성공, 미연결 삭제 차단, 완전 무참조 삭제의 직전 이력 및 SQL rollback/reapply. 소속/자산 실연결 사례는 CR-040 후속 소유자가 검증한다.
