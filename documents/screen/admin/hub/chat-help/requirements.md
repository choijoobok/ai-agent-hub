# 요건 정의서 — 채팅 도움말·주의사항

## 개요

- **무엇을 하는 화면인가**: Portal(사용자 채팅 화면)에 정해진 위치·시점에 표시할 세 종류의 콘텐츠를 선택하고 본문 형식을 지정해 작성·미리보기·저장한다.
- **프로세스상 위치**: 구분 선택 → 형식/본문 편집·미리보기 → 선택 구분 저장·불변 버전/이력 → agent 제공 계약 → Portal 표시·제출 근거 연결.
- **이 데이터를 누가 쓰나**: 관리자는 콘텐츠를 작성하고 agent는 저장된 정확 버전과 현재 전송 정보를 제공한다. Portal은 형식에 맞게 렌더링한다.
- **바꾸면 어디가 흔들리나**: 도움말·초기 안내·제출 전 개인정보/전송 안내와 당시 안내 버전 재현. 업무 지식 검색과 모델의 권한·실행 계약은 별도다.

> 사용자 권장안 반영 설계 검토본이다. 제품 구현·화면 전체 승인·G3(설계 완료 게이트) 승인을 뜻하지 않는다. 제품 사실은 [REQ-308.portal_content](../../../../spec/10-requirements/007-knowledge-catalog.yaml), 실제 전송 동의는 [REQ-106](../../../../spec/10-requirements/003-security.yaml)을 따른다.

## 1. 화면 구성

상단에 **구분 선택과 작성 형식 선택**, 아래에 **큰 본문 textarea(여러 줄 입력창)**를 둔다. 구분 콤보는 코드·명칭을 함께 표시한다. 선택 구분의 코드·명칭·Portal 노출 위치·시점·현재 적용 버전을 읽기 전용으로 안내한다. 조회·저장·본문 크게 편집·미리보기 버튼을 제공한다.

콘텐츠 목록 그리드와 지식의 본문/그룹/태그/예제/카탈로그/API/도구 매핑 탭은 두지 않는다. 세 구분은 소스의 고정 계약이며 임의 추가·삭제·코드/명칭/노출 조건 변경·사용 중지 기능은 없다. 안내 버전은 구분이 아니라 각 콘텐츠의 공통 메타데이터다.

### 1-1. 구분과 Portal 표시

| 구분 코드 | 명칭 | 노출 위치 | 노출 시점 |
| --- | --- | --- | --- |
| USAGE_HELP | 사용 도움말 | Portal 도움말 영역 | 도움말 열기 |
| CHAT_START | 새 대화 초기 안내 | 새 대화 시작 영역 | 새 대화 시작 |
| INPUT_NOTICE | 개인정보·전송 주의사항 | 입력창 주변 | 요청 제출 전 |

코드·명칭·표시 조건의 정본은 REQ-308.portal_content.types다. 관리 화면의 구분 선택은 편집 대상을 바꾸며, 저장 대상 코드를 수정하는 동작이 아니다. Portal은 제목 문자열로 구분을 추측하지 않는다.

### 1-4. 큰 편집창·미리보기·저장

본문 크게 편집은 같은 원문의 임시 버퍼를 연다. 모달 오른쪽 아래 모서리를 마우스로 끌어 가로·세로 크기를 조절하며 본문 영역이 함께 변한다. 입력을 보존하고 화면 범위 안에서 반영·취소 버튼에 접근할 수 있어야 한다. 반영만 현재 구분 본문에 옮기고 취소·닫기·Esc는 원문을 유지한다.

미리보기는 현재 구분의 미저장 원문을 선택 형식으로 표시한다. 원문 자동 변환·모델 재작성·자동 저장은 없다. 관리자 미리보기와 Portal은 같은 허용 형식/렌더링 정책을 사용한다. 실제 전송 대상·범위·공급 경로는 서버 동적 정보이며 본문에 변수 치환식으로 삽입하지 않는다. 목업의 전송 정보는 예시임을 구분하고 실제 동의 기록을 만들지 않는다.

## 2. 조회조건

없음 — 목록 검색/페이징을 두지 않는다. 상단 구분 선택은 §4의 고정 편집 대상 선택이다. 진입 시 현재 권한으로 받은 적용본만 사용하며 실패·미설정과 정상 빈 결과를 구분한다.

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

| 테이블 | 역할 | 결합 기준 |
|---|---|---|

### 3-2. 고정 조건 · 기본 정렬

현재 READ(조회) 권한과 허용된 세 코드만 조회한다. 구분 순서는 사용 도움말 → 새 대화 초기 안내 → 개인정보·전송 주의사항이다. 표시명·코드·배치/시점은 서버 계약 값을 표시한다. 현재 적용 버전은 서버가 발급하며 textarea 편집·미리보기·취소로 바뀌지 않는다.

## 6. 규칙 — 저장 · 실행

### 6-1. 입력·표시 검증

REQ-308.portal_content를 따른다. 형식과 비공백 본문 및 안전 렌더링 후의 표시 내용을 검사한다. HTML의 script·이벤트 속성·위험 링크·외부 미디어·임의 스타일/네트워크 요청은 실행하지 않는다. 미리보기에서 제거되는 표현을 저장 원문과 구별하고, 관리자 미리보기와 Portal의 허용 정책이 달라지지 않게 한다. 입력 문자열을 권한·실행 명령·템플릿 치환식으로 사용하지 않는다.

### 6-2. 직접 저장·동시성·이력

선택 코드의 형식·원문·기대 버전·새 사유를 현재 SAVE 권한으로 검증한다. 저장 중 다른 코드/본문으로 바뀌거나 같은 코드의 다른 관리자 저장으로 기준이 낡으면 자동 덮어쓰기/재시도하지 않는다. 선택 코드의 현재값·불변 리비전·변경 전후 전체 이력·명령 성공 결과를 같은 성공 단위로 확정한다. 다른 코드의 편집본·지식 리비전을 바꾸지 않는다.

SCR-069(채팅 도움말·주의사항 변경 이력)은 원 화면을 읽기 전용 상속하고 코드·선택 이력 버전의 형식/본문·변경 사유/시각을 조회한다. SCR-048 지식 이력에 합치거나 최신 본문으로 과거 안내를 대체하지 않는다. 독립 이력 요건서/목업을 복제하지 않는다. 실제 물리 테이블/API는 소유 상세 설계 후속이다.

### 6-3. Portal 계약·제출 근거

admin은 콘텐츠 원천을 관리하고 agent가 현재 저장본을 Portal 표시 계약으로 제공한다. Portal은 admin 관리 API를 직접 읽거나 문구를 재작성/모델 생성/자체 업무 문구로 대체하지 않는다. code/name/format/body/revision은 같은 콘텐츠 판에 묶으며, 계약/렌더링 정책의 버전은 콘텐츠 리비전과 구분한다. 위치·시점은 고정 코드 계약으로 정한다.

INPUT_NOTICE는 요청 제출 전에 입력창 주변에서 확인 가능해야 하며 도움말 안에만 숨기지 않는다. 본문과 별도로 서버가 검증한 실제 처리 목적·자료 범위·후보 공급 경로 및 설정 버전을 함께 표시한다. 임의 변수 치환이나 관리자 고정 문자열이 현재 전송 정보를 대신하지 않는다.

제출 시 실제 표시한 INPUT_NOTICE 버전과 동적 전송 정보의 근거를 원 요청에 연결한다. 안내 누락·표시 실패·형식 미지원·버전/범위 불일치이면 전송을 시작하지 않고 안내를 다시 확인하게 한다. 실제 본문이 뒤에 바뀌어도 당시 판을 재현한다. 재표시·조회·미리보기는 새 턴/모델 호출/자동 재제출을 만들지 않는다. 구체 재접속·계약 주 버전 정책은 ARCH-019를 유지한다.

### 6-4. 지식·프롬프트와 경계

정적 도움말·초기 안내·주의사항은 이 화면 소유다. 사용자가 채팅으로 사용법을 질문하면 기존 REQ-308의 허용 활성 지식 검색으로 답한다. 표시 콘텐츠를 지식으로 자동 복제·임베딩·검색 주입하거나 지식 변경으로 이 콘텐츠를 자동 갱신하지 않는다. 업무 지식·자산 매핑·대화형 답변 원천은 SCR-011, 모델 공통 응답 지침은 SCR-013이 소유한다. 정책·권한·동의·실행 승인을 안내 본문으로 바꾸지 않는다.

## 7. API

API(응용 프로그램 인터페이스) URL·메서드·물리/와이어 세부 필드는 소유 상세 설계 후속이다. REQ-308.portal_content.delivery의 논리 계약을 FEAT-010(관리 저장/조회)·FEAT-107(Portal 표시)·REQ-009/ARCH-019(agent 제공)에 연결한다. 최소 계약 항목은 코드·명칭·형식·원문·콘텐츠 버전이며 실제 전송 정보는 별도 서버 값이다. 관리 저장과 Portal 읽기/제출 검증을 분리한다.

## 8. 시드 · 데이터 전제

세 코드·명칭·위치/시점과 형식 코드가 고정 계약이다. 코드 변경은 소비자와 함께 검증·배포하는 계약 변경이며 관리자가 추가/삭제하지 않는다. 제품 초기 본문·메시지·DB(데이터베이스) 물리 모델·시드는 화면/작업흐름 승인 뒤 구현한다. 본문 미설정 상태를 목업 예시나 임의 기본 문구로 정상 운영하지 않는다.
