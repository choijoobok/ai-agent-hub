# 사용자 관리

> **설계 변경 안내(CR-033, 아직 미구현):** 비활성화 저장 성공 뒤 다음 보호 요청부터 차단하는 방식으로 변경할 예정입니다. 현재 제품에서는 아래의 재검사/강제 종료 동작을 기준으로 운영하며, 구현 후 이 안내를 현행화합니다.

> 시스템을 쓸 사람을 등록하고, 계정을 쓸 수 있게 하거나 막고, 잠긴 계정을 풀고, 역할·접속 IP·접속 중인 세션을 관리합니다.

**메뉴 위치** 시스템 › 사용자 › 사용자 관리

[사용자 관리 화면 — 위는 사용자 목록, 아래는 고른 사람의 탭 다섯](./mockup.html#main)

---

## 1. 먼저 알아 둘 것

- 역할을 부여하려면 **[역할 관리]에서 역할이 먼저 등록**되어 있어야 합니다.
- **계정은 지울 수 없습니다.** 더 이상 쓰지 않는 계정은 `사용 여부`를 꺼서 막습니다. 지난 이력이 누구의 것인지 남아야 하기 때문입니다.
- **관리자는 비밀번호를 정하지 않습니다.** 계정을 새로 만들거나 비밀번호를 초기화하면 시스템이 **임시 비밀번호를 만들어** 화면에 한 번 보여 줍니다. 그 창을 닫으면 다시 볼 수 없습니다.
- 계정을 못 쓰게 만드는 사유는 **넷**이고 서로 다른 것입니다 — `미사용`(관리자가 껐다) · `기간 만료`(사용 기간이 지났다) · `잠김`(로그인을 여러 번 틀렸다) · `휴면`(오래 안 들어왔다). 하나를 풀어도 다른 것이 걸려 있을 수 있습니다.

---

## 2. 찾기

1. 위쪽 조회조건에 찾을 값을 넣습니다. **아무것도 넣지 않으면 전체가 나옵니다** — 조건은 모두 선택입니다.
2. `[조회]` 를 누릅니다.
3. 화면에 들어오기만 해서는 목록이 나오지 않습니다. 반드시 `[조회]` 를 눌러야 합니다.

**자주 쓰는 조건**

| 이렇게 찾고 싶다 | 이렇게 넣습니다 |
|---|---|
| 지금 못 들어오는 계정만 | `계정 상태`에서 *잠김* · *휴면* · *기간 만료* 를 고릅니다 |
| 그만둔 사람 계정 확인 | `계정 상태`에서 *미사용* 을 고릅니다 |
| 특정 역할을 가진 사람 전부 | `보유 역할`에서 역할을 고릅니다 — **기간이 지난 부여도 함께 나옵니다** |
| 곧 역할이 끝나는 사람 | `역할 만료 예정`에서 *30일 이내* 처럼 고릅니다 |
| 한 번도 안 들어온 사람 | `최종 로그인`의 연산을 *이하* 로 바꾸고 오늘 날짜를 넣습니다 |

- 목록에는 **다섯 칸만** 보입니다. `잠금` · `실패 횟수` · `휴면` · `언어` 같은 칸은 그리드 설정(`[⚙]`)에서 켜면 보입니다 — 켜지 않았을 뿐 값은 이미 와 있습니다.
- `상태` 칸은 **먼저 걸린 사유 하나**만 보여 줍니다. 넷이 동시에 걸려 있을 수 있으므로, 자세히 볼 때는 원래 칸들을 켜서 봅니다.
- `상태` 칸은 정렬되지 않습니다. 계산해서 만든 값이기 때문입니다.

## 3. 하기

### 3-1. 계정 새로 만들기

1. `[행 추가]` 를 누르면 맨 위에 빈 줄이 생깁니다.
2. **로그인 ID · 이름 · 이메일**을 채웁니다. 셋은 필수입니다.
   - **로그인 ID 는 나중에 바꿀 수 없습니다.** 계정은 지울 수도 없으므로 한 번 정하면 끝입니다.
   - 이메일이 필수인 이유는 **임시 비밀번호를 전할 곳**이기 때문입니다.
3. 필요하면 `사용 시작일` · `사용 종료일`을 넣습니다. 비워 두면 기간 제한이 없습니다. **시작일과 종료일 당일도 포함**됩니다.
4. `[저장]` 을 누릅니다. 여러 줄을 한꺼번에 만들 수 있습니다.
5. 저장하면 **임시 비밀번호 창**이 뜹니다 — 값을 사용자에게 전하고 닫습니다.

> **신규 계정에 역할을 주는 것은 두 단계입니다.** 저장하기 전에는 아래 탭이 잠겨 있습니다. 먼저 저장하고, 그 줄을 다시 골라 [보유 역할] 탭에서 역할을 줍니다.

### 3-2. 고치기

1. 고칠 칸을 두 번 누르면 편집됩니다. 바꾼 줄에는 왼쪽에 표시가 붙습니다.
2. `[저장]` 을 누릅니다.

**고칠 수 있는 칸** — 이름 · 이메일 · 사용 여부 · 사용 시작일 · 사용 종료일 · 언어.

**고칠 수 없는 칸** — `잠금` · `잠금 시각` · `실패 횟수` · `휴면` · `임시 비밀번호` · `최종 로그인` · `상태`. 이 값들은 **시스템이 스스로 거는 것**이고, 푸는 방법은 위쪽 버튼들입니다(3-4). 칸을 직접 고치게 두면 여러 사유가 뒤섞입니다.

### 3-3. 계정을 못 쓰게 하기

- **지우는 것이 아니라 끄는 것입니다.** `사용 여부`를 끄고 `[저장]` 합니다.
- 현재 저장 안내는 다음 로그인 차단을 설명합니다. 실제로는 권한 재계산·날짜 경과 시에도 계정 상태를 검사하지만 저장 직후 차단은 보장하지 않습니다. **즉시 세션을 종료하려면** [활성 세션] 탭에서 `[강제 종료]`를 함께 해야 합니다.
- **자기 계정은 끌 수 없습니다.** 그 칸을 누르면 *자기 계정은 사용 중지할 수 없습니다.* 라고 뜹니다.
- 기간을 정해서 막으려면 `사용 종료일`을 넣습니다. 그날까지는 들어올 수 있습니다.

### 3-4. 잠긴 계정 풀기 · 휴면 풀기 · 비밀번호 초기화

줄을 고르고 위쪽 버튼을 누릅니다. **셋은 서로 다른 것을 풉니다.**

| 버튼 | 무엇을 하나 | 무엇을 하지 않나 |
|---|---|---|
| `[잠금 해제]` | 로그인 실패로 걸린 잠금을 풀고 실패 횟수를 0으로 되돌립니다 | 비밀번호는 그대로입니다 |
| `[휴면 해제]` | 오래 안 들어와 걸린 휴면을 풉니다 | **잠금은 풀리지 않습니다** |
| `[비밀번호 초기화]` | 임시 비밀번호를 새로 발급하고 다음 로그인에서 바꾸도록 표시합니다 | **잠금은 풀리지 않습니다** |

- 이미 풀려 있는 계정에 눌러도 **오류가 아닙니다.** 원하던 결과가 이미 이뤄져 있는 것입니다.
- 비밀번호를 못 쓰게 된 사람이 **잠기기까지 했다면** `[잠금 해제]` 와 `[비밀번호 초기화]` 를 **둘 다** 눌러야 합니다.
- 여러 줄을 골라 한 번에 할 수 있습니다. 초기화는 발급된 값들을 표로 한 번에 보여 줍니다.

> **임시 비밀번호 창은 다시 열 수 없습니다.** 창을 닫은 뒤 값을 잊었다면 다시 초기화하는 수밖에 없고, 그러면 **방금 전한 값이 그 자리에서 못 쓰게 됩니다.** 전하기 전에는 닫지 마십시오.
> 이 값은 오래 살지 않습니다 — 사용자는 다음 로그인에서 반드시 비밀번호를 바꿔야 하고, 정해진 시간이 지나면 그 값으로는 아예 들어올 수 없습니다.

### 3-5. 아래쪽 탭 다섯

목록에서 **저장된 줄 하나를 고르면** 아래쪽 탭이 그 사람의 것으로 채워집니다. 탭은 처음 열 때 조회됩니다.

[보유 역할 탭](./mockup.html#tab-role)

**[보유 역할]** — 이 사람이 가진 역할입니다.
- 주기: `[행 추가]` → `역할`을 고르고 필요하면 기간을 넣습니다 → `[저장]`. 기간을 비우면 무기한입니다.
- 회수: **종료일을 어제로 바꿉니다.** 그러면 언제까지 그 역할이었는지가 남습니다. `[행 삭제]`는 **잘못 등록한 줄을 정리할 때**만 쓰십시오 — 지우면 기록이 남지 않습니다.
- 역할 변경은 세션 권한 재계산을 예약하며 다음 보호 요청에서 회수된 액션을 거부합니다.
- `역할 사용`이 꺼져 있으면 **부여 상태가 *유효* 여도 아무 권한도 주지 않습니다.** 역할 자체를 켜는 곳은 [역할 관리]입니다.

[개인 예외 탭](./mockup.html#tab-grant)

**[개인 예외]** — 역할과 별개로 이 사람에게 직접 준 권한입니다. **여기서는 보기만 합니다** — 주고 거두는 것은 [개인 예외 권한] 메뉴입니다.

[접속 IP 탭](./mockup.html#tab-ip)

**[접속 IP]** — 이 계정이 들어올 수 있는 IP 대역입니다.
- **줄이 하나도 없으면 제한이 없습니다.** 어디서든 들어올 수 있다는 뜻입니다.
- **첫 줄을 등록하는 순간부터 나머지 모든 IP 가 막힙니다.** 저장 전에 그 안내가 뜹니다 — 사무실 대역을 빠뜨리면 본인이 못 들어옵니다.
- 파견·출장처럼 기한이 있으면 `허용 시작` · `허용 종료`를 넣습니다. 비우면 무기한입니다.
- 잠시 막을 때는 `사용`을 끄고, 아주 안 쓰면 줄을 지웁니다.

[활성 세션 탭](./mockup.html#tab-session)

**[활성 세션]** — 지금 접속 중인 세션입니다.
- 모르는 곳에서 들어온 세션이 보이면 고르고 `[강제 종료]`.
- **계정은 바뀌지 않습니다** — 그 사람은 다시 로그인할 수 있습니다. 아예 막으려면 `사용 여부`를 꺼야 합니다(3-3).
- **자기 계정의 세션은 종료할 수 없습니다.** 그때는 버튼이 눌리지 않고 사유가 표시됩니다.
- 고른 수보다 적게 끊길 수 있습니다 — 이미 만료된 세션은 그냥 넘어갑니다.
- `접속 IP` · `브라우저`가 비어 있을 수 있습니다. 로그인 이력에서 찾아 붙이는 값이라 이력이 없으면 비어 있습니다.

[유효 권한 탭](./mockup.html#tab-effective)

**[유효 권한]** — *이 사람이 지금 실제로 무엇을 할 수 있나* 를 한 화면에서 봅니다. **문의가 왔을 때 여기부터 봅니다.**
- 액션 네 칸은 `●` 준다 · `·` 안 준다 · `—` **그 메뉴에는 그런 기능이 아예 없다** 입니다.
- `출처`가 어느 역할 때문인지 또는 *개인 예외* 인지 말합니다. 같은 메뉴가 두 줄이면 경로가 둘이라는 뜻입니다.
- `표시 범위`를 *전체 메뉴* 로 바꾸면 **못 가진 메뉴까지** 함께 보여 어디가 비었는지 알 수 있습니다.
- 줄은 있는데 회색이면 이유가 둘 중 하나입니다 — 부여 기간 밖이거나, **메뉴가 꺼져 있거나 화면이 없거나**.
- 아무 권한도 없으면 *유효 권한이 공집합입니다 — 이 계정은 다음 로그인부터 차단됩니다.* 라고 알려 줍니다.

### 3-6. 엑셀로 받기

- `[⤓]` — 현재 페이지와 전체 중에서 고릅니다. **지금 보이는 컬럼만** 나갑니다. 아래 탭들도 각각 받을 수 있습니다.
- 엑셀 올리기는 이 화면에 없습니다.
- **임시 비밀번호 창은 엑셀로 받을 수 없습니다.** 값이 파일로 남으면 안 되기 때문입니다.

## 4. 안 될 때

| 이런 일이 생기면 | 이유 | 어떻게 하나 |
|---|---|---|
| *이미 있는 로그인 ID 입니다.* | 그 ID 의 계정이 이미 있습니다. 껐던 계정도 남아 있습니다 | `계정 상태`를 비우고 그 ID 로 조회해 보십시오 |
| *같은 로그인 ID 가 두 번 있습니다.* | 지금 저장하려는 줄 안에 같은 ID 가 둘입니다 | 한 줄을 지우고 저장합니다 |
| *이메일은 필수입니다.* | 임시 비밀번호를 전할 곳이 없습니다 | 이메일을 채웁니다 |
| *사용 기간의 시작이 종료보다 늦습니다.* | 시작일과 종료일이 뒤집혔습니다 | 날짜를 바로잡습니다. 같은 날은 괜찮습니다 |
| *자기 계정은 사용 중지할 수 없습니다.* | 자기 계정을 끄면 그 자리에서 밀려납니다 | 다른 관리자에게 요청합니다 |
| *계정은 삭제할 수 없습니다. 사용 여부를 끄십시오.* | 계정은 지우지 않습니다 | `사용 여부`를 끕니다 |
| *임시 비밀번호 발급이 꺼져 있습니다.* | 이 시스템에서 관리자 발급 기능을 꺼 두었습니다 | 사용자가 로그인 화면의 비밀번호 재설정을 쓰게 합니다 |
| *IP 주소 또는 CIDR 형식이 아닙니다.* | 오타이거나 형식이 맞지 않습니다 | `192.168.0.10` 또는 `192.168.0.0/24` 형태로 넣습니다 |
| 잠금을 풀었는데 여전히 못 들어옵니다 | 사유가 여럿이었습니다 | 상태 칸을 다시 보고 `휴면` · `미사용` · `기간 만료` 를 확인합니다 |
| 역할을 줬는데 메뉴가 안 보인다고 합니다 | 회수·부여는 다음 보호 요청의 재계산에서 반영됩니다 | 다시 로그인하게 합니다. 그래도 안 되면 [유효 권한] 탭을 봅니다 |
| 역할이 *유효* 인데 아무것도 안 됩니다 | **역할 자체가 꺼져 있습니다** | [역할 관리]에서 그 역할을 켭니다 |
| 아래 탭이 눌러지지 않습니다 | 사용자를 고르지 않았거나, 아직 저장하지 않은 새 줄입니다 | 먼저 저장하고 그 줄을 다시 고릅니다 |
| 버튼이 눌리지 않습니다 | 권한이 없거나 대상을 고르지 않았습니다 | 대상을 고르고, 그래도 안 되면 권한을 요청합니다 |

## 5. 다른 메뉴와의 관계

**먼저 해야 하는 것**

| 무엇을 | 어디서 | 왜 |
|---|---|---|
| 역할 등록 | 역할 관리 | 여기서 부여할 역할이 있어야 합니다 |
| 역할에 권한 주기 | 역할별 권한 | 역할이 있어도 권한이 없으면 아무것도 열리지 않습니다 |
| 메뉴 등록 | 메뉴 관리 | 메뉴가 꺼져 있으면 권한을 줘도 열리지 않습니다 |

**여기서 저장하면 바뀌는 곳**

| 어디가 | 어떻게 |
|---|---|
| 그 사람의 로그인 | 사용 여부 · 사용 기간 · 잠금 · 휴면이 로그인을 막거나 엽니다. 현재는 재로그인 또는 계정 상태 재검사 시 적용되며 저장 직후는 보장하지 않습니다 |
| 그 사람의 메뉴 | 역할 변경 후 권한 재계산 결과를 받아 메뉴가 달라집니다 |
| 그 사람의 접속 경로 | 접속 IP 를 등록하면 그 대역 밖에서는 들어오지 못합니다 |
| 사용 이력 | 누가 언제 무엇을 했는지 남습니다 |

**같이 보는 화면**

- 로그인이 안 된다는 문의 → **[로그인 이력]** 에서 실패 사유를 함께 봅니다. 여기 `상태` 칸과 같은 순서로 기록됩니다.
- 권한이 이상하다는 문의 → 이 화면의 **[유효 권한]** 탭을 먼저 보고, 고칠 곳이 역할이면 [역할별 권한], 이 사람만이면 [개인 예외 권한]입니다.

## 6. 자주 묻는 것

- **계정을 지우고 싶습니다** — 지울 수 없습니다. `사용 여부`를 끄면 못 들어옵니다. 지난 이력에 그 사람이 남아 있어야 하기 때문입니다.
- **같은 사람이 ID 를 바꾸고 싶어 합니다** — 로그인 ID 는 바꿀 수 없습니다. 새 계정을 만들고 옛 계정을 끕니다. 역할은 새 계정에 다시 줘야 합니다.
- **임시 비밀번호를 잃어버렸습니다** — 다시 초기화하면 됩니다. 다만 **먼저 발급한 값은 그 순간 못 쓰게 됩니다.**
- **비밀번호를 관리자가 정해 줄 수 있나요** — 없습니다. 발급만 할 수 있습니다.
- **끈 계정도 목록에 나오나요** — 나옵니다. 조회조건에 기본값이 없어서 **처음 조회하면 전부** 나옵니다.
