# 요건 정의서 — 공통 코드 관리

## 개요

- **무엇을 하는 화면인가**: 화면의 셀렉트 후보가 되는 **코드 그룹**과 그 안의 **코드**를 등록·수정하고, 코드마다 붙는 **참조 속성**(그룹별로 다른 부가 값)을 관리한다. 코드명은 여기서 입력하며 값은 다국어 테이블로 간다.
- **프로세스상 위치**: (선행) 소스가 코드그룹 이름을 지목한다 — **그룹은 개발이 먼저 정한다** → **이 화면** → (후행) 여기서 만든 코드가 모든 업무 화면의 셀렉트 후보이자 배지 글자가 된다. 다른 언어의 이름은 `MESSAGE_MGMT` 에서 채운다.
- **이 데이터를 누가 쓰나**: 코드 셀렉트를 쓰는 **모든 화면**(`type: 'code'` 컬럼과 `grpCd` 조회조건), 배지의 글자, `LOGIN_LOG` 의 결과 이름 등.
- **바꾸면 어디가 흔들리나**: **코드 하나를 끄면 그것을 쓰는 화면의 콤보 후보가 사라진다** — 이미 그 값을 가진 기존 행은 그대로 남아 *후보에 없는 값* 이 된다. 코드를 지우면 참조값이 함께 사라진다. 저장은 **코드 캐시**를 올리고, **코드명이 바뀐 저장은 메시지 캐시까지** 올려 다른 사용자 화면의 글자가 함께 바뀐다.

> **단계가 둘이 아니라 셋이고, 셋째는 컬럼이다.**
> ```
> 그룹 → 코드 → 참조 ┬ 정의(어떤 속성을 쓰는가) : 모달
>                    └ 값(그 속성의 값)          : 하단 그리드의 동적 컬럼
> ```
> 참조 값이 pane 도 탭도 아닌 것은 본질이 **매트릭스**(코드 × 속성)이기 때문이다. 값을 모달에 담으면 **한 코드씩만 보여** *"어느 코드가 아직 안 채워졌나"* 에 답할 수 없다. 펼쳐 놓으면 **빈 칸 자체가 할 일**이 된다 — 별도 배지도, *값 없는 것 우선* 정렬도 두지 않는 이유다.

> **이 문서는 구현된 소스에서 역으로 작성했다**(2026-09-03).

## 1. 화면 구성

```
[조회조건 — 넷. 앞 둘은 마스터, 뒤 둘은 하단(마스터도 거른다)]
[그리드 A: 코드 그룹]                        ← 마스터
[━━ 스플리터(상하 · 양쪽 접기 가능) ━━]
[그리드 B: 코드]  ⓐ [참조 코드 관리]         ← 디테일. 오른쪽 끝이 동적 컬럼
[모달: 참조 코드 정의]
```

- 진입 시 자동 조회: **안 함.**
- 모달: **참조 코드 정의** 하나(§6-4).
- 그리드 개인화 키가 `master` · `detail` 로 갈린다 — 같으면 위아래 설정이 서로를 덮는다.

### 1-1. 마스터-디테일 연동

- 연동 기준: 마스터의 `GRP_CD` 로 코드와 참조 정의를 조회한다.
- **조회가 둘이고 둘 다 도착한 뒤에 그린다.** 컬럼(정의) 없이 행을 그리면 값이 갈 자리가 없고, 행 없이 컬럼만 그리면 **빈 그리드가 한 번 깜빡인다.**
- **미저장 신규 그룹 행을 선택한 동안**: 하단은 **잠긴 빈 상태**(`MSG.CODE_DETAIL_LOCKED`). 하단이 **DB 에 붙어 있어 FK 가 걸리므로** 부모가 저장되기 전에는 자식을 만들 수 없다 — `MESSAGE_MGMT` 와 갈리는 자리다(거기 하단은 마스터 응답의 컬럼이라 잠기지 않는다).
- **선택 없음**: `MSG.CODE_DETAIL_EMPTY`. **두 문구를 합치지 않는다** — 같은 빈 판이지만 **다음에 할 일이 다르다.**
- 하단에 미저장 편집이 있는 상태에서 다른 마스터 행 선택: **확인 후 폐기.** 거부하면 **선택 자체가 일어나지 않는다** — 거부권이 없으면 *보고 있는 것* 과 *고른 것* 이 갈리고, 그 상태로 저장하면 **A 그룹의 행이 B 그룹으로 나간다.**
- 마스터 [조회]: **하단을 리셋하고 자동 선택하지 않는다.** 조회는 목록을 통째로 바꾸므로 이전에 보던 행이 결과에 없을 수 있고, 하단이 남아 있으면 **다른 그룹의 데이터를 그 그룹 것으로 보게 된다.**
- 저장 단위: **마스터와 디테일이 각각 따로.** 참조 정의도 모달 안에서 따로 닫힌다.
- 모달을 닫으면 **하단을 재조회한다**(저장 여부와 무관하게). 컬럼 집합이 바뀌었을 수 있다 — 저장했는지를 모달이 바깥에 알려 주는 것보다 **닫힘 하나를 신호로 두는 편**이 어긋날 자리가 없다.

## 2. 조회조건

| 조건 | 대상 컬럼 | 입력방식 | 연산 | 필수 | 기본값 | 무엇을 거르나 | 라벨 키 |
|---|---|---|---|---|---|---|---|
| 그룹 코드 | `GRP_CD` | 텍스트 | `contains`(기본) · `eq` · `startsWith` · `endsWith` | 선택 | — | 마스터 | `MSG.CODE_SEARCH_GRP_CD` |
| 그룹명 | `GRP_NM` | 텍스트 | 〃 | 선택 | — | 마스터 | `MSG.CODE_SEARCH_GRP_NM` |
| 코드 | `DTL_CD` | 텍스트 | 〃 | 선택 | — | **마스터 + 하단** | `MSG.CODE_SEARCH_DTL_CD` |
| 코드명 | **파생** — `SYS_MESSAGE` | 텍스트 | 〃 | 선택 | — | **마스터 + 하단** | `MSG.CODE_SEARCH_CODE_NM` |

- **넷이 두 쌍으로 읽힌다** — 앞 둘은 마스터, 뒤 둘은 하단이며 **뒤 둘이 마스터도 거른다.** *"이 코드값이 어느 그룹에 있더라"* 가 실제로 자주 묻는 것이며, 마스터만 거르면 답할 수 없다. 고르면 하단이 그 조건으로 **미리 걸려 있다.**
- 마스터에서 `dtlCd` · `codeNm` 은 **파생 조건**이다(`EXISTS`) — 그래서 서버가 문자열 비교만 편다. 없는 연산자를 열면 400 이다.
- **참조값 조건이 없다.** 컬럼이 그룹마다 다르므로 폼도 그룹에 따라 바뀌어야 하고, 그러면 *"그룹을 고르기 전에는 검색할 수 없는 조건"* 이 생긴다 — 참조값은 **컬럼 필터**로 거른다. 하단이 전량이라 그 범위가 곧 전부다.
- **`사용 여부` · `시스템 여부` 조건도 없다**(2026-08-30 개정). 같은 이름의 컬럼이 **위아래 두 그리드에 다 있어서** 폼의 라벨만으로는 *어느 쪽을 거르는가* 를 말할 수 없었다 — 바로 아래 *코드*·*코드명* 은 하단의 것인데 그 둘은 마스터의 것이었다. 값 집합이 둘뿐이라 **컬럼 필터**로 충분하고, 거기서는 **어느 그리드의 것인지가 자리로 드러난다.**

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

| 테이블 | 역할 | 결합 기준 |
|---|---|---|
| `SYS_CODE_GROUP` | 마스터 | — |
| `SYS_CODE` | 하단 | `GRP_CD` |
| `SYS_CODE_GRP_REF` | 참조 **정의**(모달 · 컬럼 집합) | `GRP_CD` |
| `SYS_CODE_REF` | 참조 **값**(동적 컬럼의 셀) | `GRP_CD` + `DTL_CD` + `REF_CD` |
| `SYS_MESSAGE` | **코드명** | `MSG_KEY = SYS_CODE.DTL_NM` |
| `SYS_CACHE_VERSION` | 저장 후 캐시 무효화 | — |

- **`SYS_CODE.DTL_NM` 은 코드명이 아니라 그 코드의 메시지 키**(`code.{GRP_CD}.{DTL_CD}`)다. 실제 이름은 `SYS_MESSAGE` 의 값이며 언어마다 한 행이다.
- **`GRP_NM` 은 다국어가 아니다** — 관리 화면 전용 명칭이라 컬럼 값 그대로다. 그룹은 사용자에게 보이지 않는다.

### 3-2. 고정 조건 · 기본 정렬

- 항상 적용되는 필터: **없음.**
- 기본 정렬: 마스터 `SORT_NO` 오름차 · 하단 `SORT_NO` 오름차 · 정의 `REF_CD` 오름차.
- 조회 상한: 없음. **하단과 정의는 전량**이다.
- 페이징: 마스터 offset.

- **행 식별키**: 마스터 `GRP_CD` · 하단 `GRP_CD + DTL_CD`(복합) · 정의 `GRP_CD + REF_CD`(복합).

- **그룹에 `사용 여부` 컬럼이 없다.** 코드 쪽에는 있다 — **이름이 같다고 같은 것이 아니다.** 코드의 `USE_YN` 은 *콤보 후보에서 뺀다* 는 뜻이라 읽는 쪽이 있지만, 그룹은 콤보의 후보가 아니라 **소스가 이름으로 지목하는 것**이라 끄는 것의 뜻이 정의되지 않는다 — 끄면 콤보가 통째로 비어 화면이 못 쓰거나, 무시되어 스위치가 아무 일도 안 한다.
- **`GRP_CD` 는 신규 행에서만 열린다.** 고치려면 지우고 다시 만든다.
- **`시스템` 은 편집 선언이 없다.** 켤 수 있게 하면 관리자가 아무 그룹이나 잠글 수 있고, 끌 수 있게 하면 보호가 한 번의 클릭으로 사라진다 — 서버가 거부한다고 한 것을 화면은 **입력 수단을 없애는 것**으로 갚는다.
- **시스템 그룹에는 삭제 체크박스가 아예 없다** — 비활성이 아니라 **없는 것**이며, 사유는 `그룹 코드` 옆의 `시스템` 배지가 이미 말한다.

- **참조 컬럼은 선언의 맨 뒤다**(2026-08-31). 가운데에 끼우면 그룹을 옮길 때마다 **선언 컬럼들 한가운데가 늘었다 줄었다** 한다 — 오른쪽 끝에 모여 있으면 *여기서부터가 이 그룹의 속성* 이라는 경계가 자리로 드러난다. **개인화 값과도 여기서 맞는다**: 저장된 컬럼 설정은 동적 컬럼을 담지 않으므로 *남은 것* 으로 맨 뒤에 붙는데, 선언이 가운데면 **저장한 사람과 아닌 사람의 컬럼 순서가 갈린다.**
- **참조 컬럼의 헤더는 메시지 키가 아니라 정의 행의 `REF_NM` 값이다** — 컬럼 헤더 계약의 유일한 예외다. 같은 `REF_CD` 를 그룹마다 다르게 부르는 것이 이 값의 존재 이유라 전역 코드명이 대신할 수 없다.

### 4-1b. 코드명 — 다국어로 간다

- 값이 `SYS_MESSAGE` 로 가며 채우는 것은 **지금 세션 언어 하나**다. 다른 언어는 `MESSAGE_MGMT` 로 간다 — 언어를 컬럼으로 늘리면 지원 언어를 하나 켤 때마다 그리드가 옆으로 자라고 **저장된 컬럼 목록이 어긋난다.**
- **필수가 아니다.** 비우면 **그 언어의 행을 지우는 것**이 규약이고(빈 문자열이 아니다), 지운 뒤 셀에 보이는 **키 문자열**(`code.ORDER_KIND.B2B`)이 *아직 안 채웠다* 는 사실을 그대로 드러낸다.
- 폴백: 세션 언어 → 기본 언어 → **키 문자열 그대로**. 셀에 키가 보이면 그것이 **진단**이다.

- 후보 콤보의 글자는 `참조코드 · 이름` 이며 **꺼진 코드는 후보에서 뺀다.**
- 후보를 **전용 API 로 가져오지 않는다** — 이 화면은 이미 *한 그룹의 코드* 를 읽는 경로를 갖고 있고 화이트리스트도 그 하나다. 새 경로를 내면 같은 질의가 두 벌이 된다. 캐시는 무기한이며 **바뀌는 자리가 이 화면 자신**이다(`CODE_REF_KEY` 그룹을 골라 코드를 더하면 그때 다시 받는다).

### 4-2. 편집 가능 판단 — 조건부

| 범위 | 대상 | 조건 → 편집 가능 |
|---|---|---|
| 셀 | 하단 `USE_YN` | **`SYS_YN='Y'` 면 불가.** 사유 문구는 `MSG.CODE_SYSTEM_BADGE` |
| 셀 | `GRP_CD` · `DTL_CD` · `REF_CD` | 신규 행에서만(PK) |
| 그리드 | 하단 전체 | 마스터에 **저장된** 행이 선택되어 있을 때만 |
| 버튼 | ⓐ [참조 코드 관리] | 저장된 그룹 선택 **AND** 하단에 미저장 편집이 없을 때 |
| 셀 | **참조값 컬럼** | **`SYS_YN='Y'` 인 행에서도 열린다** |

- **`SYS_YN` 이 지키는 것은 코드의 존재이지 그 속성값이 아니다** — 참조값은 운영 데이터다.
- ⓐ 가 미저장 편집에서 **비활성**인 이유: 정의가 바뀌면 컬럼 집합이 바뀌고 하단 재조회가 편집을 버린다. 열고 나서 묻는 것보다 **누를 수 없는 것이 먼저 보이는 편**이 낫다. **왜 눌리지 않는가를 말한다** — 회색 버튼만 두면 버그로 읽힌다(`MSG.CODE_REF_DEF_NO_GROUP` · `MSG.CODE_REF_DEF_DIRTY`).
- ⓐ 는 `SAVE` 액션에 매인다 — **`READ` 만 가진 사용자에게는 버튼이 없다.** 정의는 컬럼 헤더로 이미 보인다.

### 4-3. 값 변경 후 연쇄 · 재계산

- **참조값 셀은 맵의 한 칸이다.** 읽기는 `refs[refCd]`, 쓰기는 그 맵을 갈아 끼운다.
- **비운 칸은 키를 지운다** — 빈 문자열을 남기면 *없음* 의 표현이 둘이 된다. 그래서 정의는 있는데 값이 없는 속성은 **키가 아예 없고**, 화면이 정의 목록과 아우터 조인해 **빈 셀**을 그린다.
- 셀 편집기가 내는 것이 문자열이 아니면 **빈 칸으로 접는다** — `String(value)` 로 두면 객체가 `[object Object]` 로 저장된다.

### 4-4. 팝업 · 모달 선택 결과 매핑

- 정의 모달은 값을 돌려주지 않는다 — **컬럼 집합을 바꾼다.** 닫히면 하단을 재조회한다.

### 4-5. 행 추가 기본값

- **그룹**: `GRP_CD=''` · `GRP_NM=''` · `SORT_NO=0` · `codeCount=0` · **`SYS_YN=false`**(화면이 만드는 그룹은 언제나 업무 그룹이며 서버도 이 값을 받지 않는다).
- **코드**: `DTL_CD=''` · `codeNm=''` · `USE_YN=true` · `SORT_NO=0` · `SYS_YN=false` · `refs={}`.
- **하단 행 추가는 그룹이 선택돼 있어야 한다** — 아니면 `MSG.CODE_DETAIL_EMPTY` 를 말하고 거부한다.

### 4-6. 비노출 저장 컬럼

- **삭제 행은 키만 보낸다.** 나머지를 보내면 **서버가 쓰지 않을 값을 검증하게 된다.**
- `SYS_YN` 은 저장 요청에 실리지만 서버가 받지 않는다.

## 6. 규칙 — 저장 · 실행

### 6-1. 삭제 — **게이트는 하나고 나머지 둘은 확인이다**

| 무엇을 지우나 | 게이트인가 | 왜 |
|---|---|---|
| **그룹** | **게이트** — `codeCount > 0` 이면 체크박스가 꺼진다. 사유 `MSG.CODE_GROUP_HAS_CODE` | **DB 가 거부한다**(FK). 막을 수 있으면 막는다 |
| **코드** | **확인** — 참조값이 있으면 건수를 말한다(`MSG.CODE_DELETE_REF_WARN`) | **DB 가 거부하지 않는다** — 참조값은 그 행의 파생이라 서비스가 먼저 지운다. 게이트를 두면 **아무것도 지울 수 없다**(정의를 쓰는 그룹의 코드는 대개 참조 1건 이상이다) |
| **정의** | **확인** — 그 정의로 입력된 값의 건수를 말한다(`MSG.CODE_REF_DEF_DELETE_WARN`) | **값 → 정의 순서로 지우면 FK 가 막을 것이 없다.** 막을 것이 없으면 **묻는다** |
| **시스템 그룹·시스템 코드** | **체크박스가 없다** | 배지가 사유를 이미 말한다 |

- **그룹의 삭제 게이트는 코드 수를 읽는다.** 마스터 응답이 그 수를 갖고 있으므로 **행마다** 답할 수 있다 — 하단을 조회해야만 아는 것이 아니다.
- 코드 삭제의 확인은 **건수보다 먼저** *참조값이 함께 사라진다* 는 것을 말한다.

  사용자가 같은 값을 넣을 수 있고, 그것은 화면이 원리적으로 막을 수 없다.

| | |
|---|---|
| **서버는 첫 실패에서 멈추지 않는다** | 세 저장(그룹 · 코드 · 정의) 다 **행을 끝까지 돌며 모아서** 한 번 거절한다. 하나씩 던지면 사용자가 저장을 N 번 눌러 오류를 하나씩 발견한다 |
| **틀린 행의 키 셀이 붉어진다** | 서버가 *요청 배열의 몇 번째* 로 행을 짚어 준다 |
| **표가 `컬럼 · 값 · 사유`** 를 낸다 | 중복은 값이 행마다 달라 **행마다 한 줄**로 펴지고, 필수값 누락은 값이 비어 **한 줄로 접힌다** |
| **경합은 409 다** | 제약이 막은 것은 입력이 틀린 것이 아니라 세상이 바뀐 것이다 — 답은 *다시 조회* 다 |

### 6-3. 영향 테이블

| 트리거 | 테이블 | 작업 | 조건 · 내용 |
|---|---|---|---|
| 그룹 저장 | `SYS_CODE_GROUP` | INSERT · UPDATE · DELETE | `GRP_NM` · `GRP_DESC` · `SORT_NO` 만 수정된다 |
| 코드 저장 | `SYS_CODE` | INSERT · UPDATE · DELETE | 신규는 `DTL_NM` 을 `code.{GRP_CD}.{DTL_CD}` 로 **자동 생성**한다 |
| 코드 저장 | `SYS_MESSAGE` | INSERT · UPDATE · **DELETE** | **세션 언어 한 행만.** 코드명을 비우면 **그 행을 지운다** |
| 코드 저장 | `SYS_CODE_REF` | INSERT · UPDATE · DELETE | `refs` 맵의 차이. 코드 삭제 시 **함께 지운다** |
| 정의 저장 | `SYS_CODE_GRP_REF` | INSERT · UPDATE · DELETE | 정의 삭제 시 그 정의의 **값도 함께** 지운다 |
| 어느 저장이든 | `SYS_CACHE_VERSION` | UPDATE | **`CODE` 버전을 올린다** |
| 코드명이 바뀐 저장 | `SYS_CACHE_VERSION` | UPDATE | **`MESSAGE` 버전도 올리고 캐시를 비운다**(커밋 뒤) |

- 저장은 **한 트랜잭션**이다.
- **캐시는 커밋 뒤에 비운다.** 커밋 전에 비우면 다른 스레드가 아직 옛 값인 DB 를 읽어 캐시를 다시 채우고, 그 뒤에 커밋이 앉아 **TTL 만큼 옛 문구가 나간다.**
- **`DTL_NM` 은 수정 대상이 아니다** — PK 가 바뀌지 않으므로 바뀔 일이 없다.

### 6-4. 참조 — 정의와 값

```
정의 (SYS_CODE_GRP_REF)   : 이 그룹이 어떤 속성을 쓰는가   → 모달 · 하단의 컬럼 집합
값   (SYS_CODE_REF)       : 그 코드의 그 속성값             → 하단의 동적 컬럼 셀
```

- **`REF_CD` 는 아무 값이나 쓸 수 없다** — 공통코드 `CODE_REF_KEY` 가 화이트리스트다. 그 그룹을 이 화면에서 골라 코드를 더하면 후보가 는다.
- **정의는 자주 열지 않는 관리 행위**라 상시 자리를 줄 값이 없다. 값은 매트릭스라 상시 자리를 준다.
- 모달 안은 **그냥 그리드 하나**이며 화면의 크롬과 색을 그대로 쓴다 — 여기만의 어휘를 만들면 같은 화면 안에 규약이 둘이 된다.
- **저장이 모달 안에서 닫힌다** — 바깥 그리드의 미저장 편집과 섞이지 않는다.

- 없음.

## 7. API

| 용도 | `endpoints.ts` 키 | 경로 | 메서드 | 액션 | 페이징 |
|---|---|---|---|---|---|
| 그룹 목록 | `getGroupList` | `/service/system/code/getGroupList` | POST | R | offset |
| 그룹 저장 | `saveGroup` | `/service/system/code/saveGroup` | POST | S | — |
| 코드 목록 | `getList` | `/service/system/code/getList` | POST | R | 전량 |
| 코드 저장 | `save` | `/service/system/code/save` | POST | S | — |
| 정의 목록 | `getRefDefList` | `/service/system/code/getRefDefList` | POST | R | 전량 |
| 정의 저장 | `saveRefDef` | `/service/system/code/saveRefDef` | POST | S | — |

- **여섯인 것이 이 화면의 모양이다** — 그리드가 셋이고 각각 조회와 저장을 갖는다.
- **`getRefDefList` 를 두 자리에서 부른다** — 정의 모달의 조회와, 하단 조회에 **함께** 나가는 쪽. 같은 응답을 쓰므로 정의가 바뀌면 **컬럼 집합과 모달 목록이 같은 순간에 같아진다.**
- **참조 코드 후보도 `getList` 로 받는다**(그룹 `CODE_REF_KEY`) — 전용 경로를 내지 않는다.
- `exportExcel` 없음 — 프론트 생성.
- 별개로 **`POST /api/common/system/code/getList`** 가 있다 — 이 화면의 것이 아니라 **모든 화면의 코드 셀렉트**가 쓰는 공통 경로다.

## 8. 시드 · 데이터 전제

- **코드그룹 `CODE_REF_KEY`** — 참조 코드의 화이트리스트다. 이 그룹 자체도 이 화면에서 관리한다.
- 메시지 키: 화면 `MSG.CODE_*` · 서버 `MsgKey.ERR_CODE_*` 열.
- **코드명의 메시지 키는 시드가 아니라 저장이 만든다** — `code.{GRP_CD}.{DTL_CD}`.
- 메뉴 시드: `menu-tree.yaml` — `code: CODE_MGMT` · `parent: MASTER` · `url: /admin/system/code` · `export: true`.
- 초기 데이터 전제: **소스가 이름으로 지목하는 그룹은 미리 있어야 한다**(예: `LOGIN_RSLT_CD`). 없으면 그 화면의 셀렉트가 비고 배지 글자가 키로 보인다.
- 설정: 메시지 캐시 TTL(`sys-config.message.cache-ttl-minutes`).

## 10. 미결 · 확인 필요

- **그룹을 끄는 수단이 없다.** 쓰지 않게 된 그룹은 코드를 다 지운 뒤 그룹째 지우는 길뿐이다 — *현재 답은 "끄는 것의 뜻이 정의되지 않았다" 이며 이것이 결정이다.*
- **참조값으로 조회할 수 없다.** 컬럼 필터가 하단 전량 안에서 답하지만, 그룹을 넘나드는 *"이 속성값을 가진 코드 전부"* 는 물을 수 없다.
