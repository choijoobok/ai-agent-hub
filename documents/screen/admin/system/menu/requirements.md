# 요건 정의서 — 메뉴 트리

## 개요

- **무엇을 하는 화면인가**: 좌측 메뉴의 **구조를 정리한다** — 폴더를 만들고, 순서와 부모를 바꾸고, 아이콘과 사용 여부를 정한다. 그 메뉴가 **무엇을 쓰고 누가 닿는지**를 함께 보여준다.
- **프로세스상 위치**: (선행) 화면(리프)은 **배포가 만든다** — 라우트가 없으면 붙여도 열리지 않는다 → **이 화면** → (후행) `ROLE_AUTH_MGMT` · `USER_AUTH_MGMT` 가 이 트리 위에 권한을 준다.
- **이 데이터를 누가 쓰나**: 좌측 사이더의 메뉴 트리, 권한 트리 둘, `API_CATALOG` 의 매핑, 인가 판정의 **최종 게이트**(`USE_YN`).
- **바꾸면 어디가 흔들리나**: **메뉴를 끄면 그 아래 전부가 함께 꺼지고**, 권한이 있어도 열리지 않는다. 순서·부모를 바꾸면 모든 사용자의 사이더가 바뀐다.

> **통째로 즉시 저장이다.** 이 화면의 절반이 그 한 줄에서 나온다 — 위치 변경은 **즉시일 수밖에 없고**(형제 전체가 다시 쓰이며 잠금으로 직렬화된다), 한 그리드 안에서 일괄과 즉시를 섞지 않으므로 **전부 즉시**가 됐다.
>
> | 즉시 저장이 지우는 것 | 대신 |
> |---|---|
> | 행 상태 컬럼 | **없다** — 미저장 상태가 존재하지 않는다 |
> | 저장 버튼 | 없다 |
> | 삭제 컬럼 | 버튼 + 확인 |
> | 미저장 신규 행 | 추가 버튼 둘 + 모달 |
> | 되돌리기 | 셀은 다시 고치고 스위치는 다시 누른다. **드래그만 그것으로 부족해 놓기 전에 묻는다** |

> **리프를 만드는 곳이 아니다.** 프론트 라우트는 **정적 맵이고 배포로만 바뀐다** — 화면에서 리프를 새로 만들어도 그 URL 에 컴포넌트가 없다. 자주 하는 일은 **구조 정리**(폴더 추가 · 순서 · 부모)와 **아이콘 · 사용 여부**이며, 리프 추가는 **배포 뒤에** 트리에 붙이는 드문 일이다.

> **이 문서는 구현된 소스에서 역으로 작성했다**(2026-09-03).

## 1. 화면 구성

```
[트리 그리드: 메뉴]                      ← 조회조건 폼이 없다. 검색 칸은 트리 헤더에
[━━ 스플리터(상하) ━━]
[탭 셋: 사용 API · 접근 가능 사용자 · 권한 역할]
[모달: 메뉴 추가 — 칸이 하나]
```

- **진입 시 스스로 조회한다.** 트리가 곧 목록이라 빈 판으로 시작할 이유가 없고, **조건이 거르지 않으므로 조회가 언제나 전건이라 누르기 전과 뒤가 같다** — 조회 버튼을 기다리는 다른 화면들과 갈리는 자리다.
- **조회조건 폼이 없다.** 브레드크럼 슬롯이 **빈다** — 이 화면에 있던 검색 칸 셋과 이동 버튼 둘이 전부 트리 헤더로 옮겨 갔다.
- **그리드 컨트롤러가 아니라 단순 질의를 쓴다** — 조건·정렬·페이징·저장이 **하나도 없다.** 쓰면 절반이 죽은 채로 붙어 있게 되고, 다음 사람이 *왜 여기서만 안 되나* 를 묻는다.

### 1-1. 마스터-디테일 연동

- **고른 메뉴를 행이 아니라 코드로 든다.** 즉시 저장이라 셀 하나를 고칠 때마다 트리를 다시 읽는데, 행 객체를 들고 있으면 그 뒤로 **낡은 객체**를 가리킨다 — 하단 탭이 방금 바꾼 값을 못 보고, 삭제 게이트가 옛 건수로 판정한다. **코드로 들면 매번 지금 트리에서 다시 찾는다.**
- **조회 둘이 갈린다.**

| 무엇 | 선택 | 왜 |
|---|---|---|
| **사람이 [조회]를 누름** | **놓는다** | 목록이 통째로 바뀌었을 수 있다 — 하단이 남아 있으면 **다른 메뉴의 권한을 이 메뉴 것으로** 보게 된다 |
| **저장 뒤 다시 읽기** | **유지한다** | 자기가 방금 고친 한 행을 다시 읽는 것이라 그 경우가 아니다. 놓으면 **아이콘 하나 바꿨다고 읽던 하단이 사라진다**(2026-08-30 실물) |

- 고른 코드가 트리에 없으면(지워진 메뉴를 가리켰다) **고른 것이 없다** 로 다룬다.
- **하단은 선택을 prop 으로 받는다** — 핸들이 아니다. 이유가 둘이다: 디테일 셋이 **조회 전용이라 거부할 일이 없고**(그 거부권이 핸들의 존재 이유였다), 선택이 바뀌는 자리가 **다섯**(행 클릭 · 조회 · 노드 추가 · 넘겨받기 · 첫 진입)이라 **한 곳을 빠뜨려도 조용하다.**

### 1-2. 검색 — **거르지 않고 찾아간다**

- 조건에 맞는 노드만 남기면 **부모가 사라져 트리가 아니게 된다.** 강조 · 경로 펼침 · **첫 일치로 스크롤.**
- **칸 셋이 하나가 됐다**(2026-08-31). 이름·코드·URL 을 각각 받고 `AND` 로 좁히던 것을 **`OR` 로 잇는 칸 하나**로 합쳤다 — 사람은 **손에 있는 것**으로 찾고, *어느 칸에 넣을지* 를 먼저 정해야 하는 것이 곧 마찰이다.
- **`AND` → `OR` 로 바뀐 것이 요점이다.** 칸이 셋일 때는 좁히는 뜻이었지만 칸이 하나면 **넣은 글자가 어디서든 걸려야** 한다.
- **자리도 브레드크럼에서 트리 헤더로 내려왔다** — 슬롯은 값이 한 커밋 늦게 도착해 **한글이 두 번 입력됐다.** 이동 버튼 둘은 뺐다.

- **메뉴명에 아이콘이 붙고 사이더와 같은 것을 쓴다** — **폴백까지 공유**하므로 아이콘을 비워 둔 메뉴가 여기서는 폴더로, 사이더에서는 다른 모양으로 보이던 일이 없다.
- **꺼진 메뉴는 이름이 흐리다** — 최종 게이트에서 걸린다.
- **`고아` 태그**(`MSG.MENU_ORPHAN`) — **선언에서 사라진 메뉴**다. 화면이 없어져 눌러도 열리지 않으며 **시드는 그것을 지우지 않고 표시만 한다**: 그 행에 역할 권한과 개인 예외가 딸려 있고, **배포가 그것을 지우는 것은 운영 결정을 배포가 되돌리는 일**이다. `API_CATALOG` 의 *미매핑* · `MESSAGE_MGMT` 의 *미사용* 과 **같은 자리**이며, 셋 다 막지 않고 표시하고 **사람이 판단한다.**
- **`미연결` 태그**(`MSG.MENU_UNLINKED`) — URL 은 있는데 **라우트 맵에 없다.** **프론트만 아는 사실이라 서버가 판정할 수 없다.** 콤보로 고르므로 만드는 순간에는 생기지 않지만, **배포로 라우트가 사라지거나 시드로 직접 넣으면 생긴다.** 저장을 막지는 않는다.
- **URL 은 고르는 것이다.** 손으로 치게 두면 오타가 곧 404 이고 그 값은 **저장은 되지만 열리지 않는다.** 후보는 **라우트 목록에서 다른 메뉴가 이미 쓰는 URL 을 뺀 것**이며, 첫 항목이 *(없음)* 으로 **URL 을 비워 폴더로 되돌리는 유일한 경로**다. 동시 저장·직접 요청도 서버 검증과 DB 유니크 제약이 막아, 이미 다른 메뉴가 가진 URL은 **409으로 거부**한다(CR-002).
- **평소에는 값만 보이고 더블 클릭해야 콤보가 뜬다**(2026-08-31). 콤보가 늘 서 있으면 옆 그리드와 이질적이고, 무엇보다 **구조를 보는 화면이 입력 화면처럼 읽힌다.** 열리면서 **드롭다운도 함께 열린다** — 더블 클릭 뒤에 한 번 더 눌러야 하면 제스처가 둘이 된다. **포커스를 잃으면 고르지 않은 것**이라 값은 그대로 두고 칸만 닫는다.
- **폴더의 URL 은 `—` 다** — 비어 있는 것이 아니라 **없는 것**이다.
- **아이콘은 코드와 모양을 함께** 보여야 한다 — 코드만으로는 무엇인지 모른다.
- **스위치는 셀이 곧 편집기다.** 더블 클릭이 열 것이 없지만 **잠긴 칸이 아니므로** 편집 가능으로 선언한다 — 안 하면 읽기 전용 색조가 깔린다.
- **`사용자 수` 는 리프만 값이 있다**(구조 노드는 `—`) — 권한 대상이 아니라 **세는 것이 정의되지 않는다.**
- **컬럼에 글자 크기를 적지 않는다** — 설정 창의 *그리드 글자 크기* 를 트리가 행에 걸고 셀이 물려받는다. 여기서 한 번 더 적으면 **설정이 이 컬럼만 비껴간다.**

### 4-2. 편집 가능 판단 — 조건부

| 대상 | 조건 |
|---|---|
| `MENU_URL` | **자식이 없을 때만.** URL 과 자식은 **배타**이며 그 사이가 없다 |
| `ICON_CD` · `USE_YN` | `SAVE` 권한이 있을 때 |
| 전부 | `SAVE` 권한이 없으면 잠긴다 |

- **화면이 미리 막고 저장 서비스가 다시 막는다** — 화면의 방어는 UX 이지 방어가 아니다.
- **그 잠금이 색으로도 보인다** — 열리지 않는 칸에 읽기 전용 색조가 깔린다.

### 4-3. 즉시 저장 — **셀 하나에 요청 하나**

- **응답을 받고 값을 바꾼다.** 즉시 저장은 **낙관적 반영이 아니다** — 되돌리기 수단이 없는 화면에서 화면과 DB 가 어긋나면 고칠 방법이 없으므로, 실패하면 **조회로 되돌린다**(셀이 제자리로 간다).
- 저장 뒤 **선택을 유지한 채** 트리를 다시 읽는다.

### 4-4. 팝업 — 메뉴 추가 모달

- **칸이 `MENU_CD` 하나뿐이다.** *행을 편집하는 폼* 이 아니라 **한 연산의 인자**를 받는 모달이며, **칸이 하나뿐인 것이 그 증거**다.

| 나머지 여섯 | 어떻게 정해지나 |
|---|---|
| 부모 | 선택 노드(또는 최상위) |
| 순서 | 형제의 **맨 끝** |
| 이름 | `menu.{MENU_CD}` 키 — **값은 `MESSAGE_MGMT` 에서 채운다** |
| 사용 여부 | 켬 |
| URL · 아이콘 | **만든 뒤 셀에서** 채운다 |

- **중복은 화면이 막지 않는다** — 다른 사람이 방금 만든 것을 알 수 없다. **서버 검증**이며 실패는 이 모달의 칸으로 되돌아온다.
- 코드는 **최대 30자.**
- **열려 있을 때만 마운트된다** — 그래서 *열 때 칸을 비우는* 코드가 없다. 직전에 만든 코드가 남아 있으면 **그대로 눌러 중복**이 나고, 그것은 서버까지 갔다 오는 실패다.
- **추가 직후 그 행을 선택하고 검색어 칸에도 넣는다** — 맨 끝이라 화면 밖에 생길 수 있고, 만든 사람은 곧바로 URL·아이콘을 채운다.

### 4-5. 행 추가 기본값 · 비노출 저장 컬럼

- §4-4 의 표가 기본값이다.
- **저장 요청에 `UP_MENU_CD` 가 없다**(§4 단서) — 위치는 드래그의 전용 경로로만 바뀐다.

## 5. 버튼 · 액션

| 버튼 | 라벨 키 | 액션 | 활성 조건 | 동작 |
|---|---|---|---|---|
| 조회 | (공통) | `R` | 항상 | 트리를 다시 읽고 **선택을 놓는다** |
| 모두 접기 / 펼치기 | `MSG.MENU_COLLAPSE_ALL` · `MSG.MENU_EXPAND_ALL` | **없음** | 항상 | 표시만 |
| 최상위 추가 | `MSG.MENU_ADD_ROOT` | `S` | 항상 | 모달을 연다 |
| 하위 추가 | `MSG.MENU_ADD_CHILD` | `S` | **§5-1** | 모달을 연다 |
| 삭제 | `MSG.MENU_DELETE` | `S` | **§6-1** | 확인 후 삭제 |
| (드래그) | — | `S` | `SAVE` 권한 | **놓으면 묻는다**(§5-2) |

- **접기/펼치기는 액션을 선언하지 않는다.** **토글 하나로 두지 않는 것**은 일부만 펼친 중간 상태에서 토글이 무엇을 가리키는지 말할 수 없기 때문이다.
- **저장 버튼이 없다**(즉시 저장).
- 엑셀 다운로드: **사용**(`EXPORT_YN='Y'`) — **프론트 생성**이며 트리를 표로 편다.
- 진행률 창: 없음.

### 5-1. 하위 추가가 막히는 이유 셋

| 조건 | 문구 키 |
|---|---|
| 아무것도 안 골랐다 | `MSG.MENU_ADD_CHILD_NO_SELECTION` |
| 고른 것이 **화면(리프)** 이다 | `MSG.MENU_ADD_CHILD_LEAF` |
| **깊이 상한(5단)** 에 닿았다 | `MSG.MENU_ADD_CHILD_DEPTH` |

- **회색 버튼만 두지 않는다** — 왜 눌리지 않는지 말한다.

### 5-2. 드롭 확인 — **놓으면 묻는다**

- 즉시 저장이라 **드롭이 곧 저장**이다. 셀 편집은 다시 고치면 되고 스위치는 다시 누르면 되지만, **드래그는 원래 자리를 사람이 기억해야** 되돌릴 수 있다 — **형제가 스무 개인 폴더에서 *몇 번째였는지* 를 기억하는 사람은 없다.**
- ***지금* 과 *이동* 을 나란히 낸다**(`MSG.MENU_MOVE_FROM` · `MSG.MENU_MOVE_TO`). 목적지만 말하면 취소한 뒤 원래 자리를 찾지 못한다 — 확인 문구가 **되돌릴 근거**를 함께 준다.
- **기본 포커스가 취소**다 — 되돌릴 수 없는 확인의 기본은 안전한 쪽이다.
- **놓기 전에 막는 것들**: 자기 자신·자손 아래로(순환), 깊이 상한 초과, 리프 아래로.
- 저장하는 것은 **형제 목록 전체**다.

### 5-3. 사용 여부 확인 — **무엇을 바꾸는지 전부 말한다**

| 방향 | 무엇을 말하나 | 문구 키 |
|---|---|---|
| **끈다** | 자손 수 | `MSG.MENU_USE_OFF_DESCENDANTS` |
| **끈다** | **접근할 수 있던 인원**(자기 + 자손 합) | `MSG.MENU_USE_OFF_USERS` |
| **켠다** | 자손 수 + **그중 개별로 꺼 두었던 수** | `MSG.MENU_USE_ON_DESCENDANTS` |

- **켜는 방향에도 경고가 있다** — `ROLE_MGMT` 와 갈리는 자리이며, 이유는 **전파가 이전 상태를 기억하지 않기** 때문이다. **개별로 꺼 두었던 것까지 켜진다.** 기억하려면 컬럼이 하나 더 필요한데 *컬럼 둘이 한 일을 하면 어느 것을 봐야 하는지 알 수 없다* 가 그대로 걸린다.
- **자손 수가 0이면 그 줄을 내지 않는다** — 항상 보이면 읽히지 않는다.
- **인원은 리프만 센다** — 구조 노드는 권한 대상이 아니다.
- **취소하면 스위치가 제자리로 돌아간다**(조회를 부르지 않으므로 값이 그대로다).

### 5-4. 화면 넘겨주기 — 받는 쪽

| 어디서 | 무엇을 | 무슨 일이 |
|---|---|---|
| `API_CATALOG` 하단 행 더블 클릭 | `MENU_CD` | **그 메뉴가 선택되고 검색어 칸에 코드가 들어가** 경로가 펼쳐지며 스크롤된다 |

- **넘겨주기는 사건이지 상태가 아니다** — 마운트할 때 한 번 읽고 **지운다.** 남겨 두면 이 화면을 다음에 열 때도 같은 곳으로 튄다.
- 값이 **효과가 아니라 초기값**으로 들어간다 — 효과로 읽으면 *첫 렌더는 빈 화면, 두 번째 렌더에서 이동* 이 되어 사람이 그 깜빡임을 본다.
- **이미 열려 있는 탭에도 도착한다**(구독).
- **접힌 폴더 안에 있을 수 있는데, 경로를 펼치고 스크롤하는 수단이 이미 검색이다** — 같은 일을 하는 길을 둘로 만들지 않는다.

## 6. 규칙 — 저장 · 실행

### 6-1. 삭제 게이트 — **FK 자식이 다섯이고 넷은 막고 하나는 함께 지운다**

```
지울 수 있다 = 자식 없음  AND  API 수 = 0  AND  역할 수 = 0
```

| 무엇이 | 어떻게 |
|---|---|
| 하위 메뉴 | **막는다** |
| `SYS_MENU_API` | **막는다** |
| `SYS_ROLE_MENU_AUTH` | **막는다** |
| `SYS_USER_AUTH` | **막는다**(서버) |
| **`SYS_FAVORITE`** | **함께 지운다** — 즐겨찾기는 개인의 편의이지 운영 결정이 아니다 |

- **어느 쪽이 막는지 말한다** — 버튼 힌트가 막는 항목의 이름을 나열한다(`MSG.MENU_DELETE_BLOCKED`).
- 삭제 확인의 **기본 포커스도 취소**다.
- 삭제 뒤에는 **선택을 놓고** 다시 읽는다.

### 6-2. 검증

| # | 시점 | 위치 | 검사 | 위반 시 메시지 |
|---|---|---|---|---|
| 1 | 위치 저장 | 서버 | **트리가 그 사이에 바뀌었나** | `MsgKey.ERR_MENU_TREE_CHANGED` |
| 2 | 위치 저장 | 화면+서버 | **자기 자신·자손 아래로 이동 금지** | `MsgKey.ERR_MENU_CYCLE` |
| 3 | 위치 저장 | 화면+서버 | 깊이 상한(5단) | `MsgKey.ERR_MENU_DEPTH` |
| 4 | 속성 저장 | 화면+서버 | **하위가 있으면 URL 을 가질 수 없다** | `MsgKey.ERR_MENU_URL_ON_PARENT` |
| 5 | 위치 저장 | 화면+서버 | **화면이 있는 메뉴에는 하위를 둘 수 없다** | `MsgKey.ERR_MENU_CHILD_UNDER_LEAF` |
| 6 | 속성 저장 | 서버 | **권한이 부여된 메뉴는 URL 을 비울 수 없다** | `MsgKey.ERR_MENU_URL_REQUIRED` |
| 7 | 노드 추가 | 서버 | 이미 있는 `MENU_CD` | `MsgKey.ERR_MENU_DUPLICATE` |
| 8 | 삭제 | 서버 | 게이트 넷 | `MsgKey.ERR_MENU_NOT_DELETABLE` |
| 9 | 어느 저장이든 | 서버 | 대상 메뉴가 있는가 | `MsgKey.ERR_MENU_NOT_FOUND` |
| 10 | 속성 저장 | 서버+DB | 다른 메뉴가 같은 URL을 쓰는가 | `MsgKey.ERR_MENU_URL_DUPLICATE` |

- **`URL 과 자식은 배타`가 규칙의 뼈대다** — 4·5 가 그 두 방향이다.
- **위치 저장은 형제 전체를 다시 쓰며 잠금으로 직렬화된다** — 그래서 그 사이 트리가 바뀌었으면 거부한다.

## 8. 하단 탭 셋 — **셋이 서로 다른 것을 본다**

```
탭 1  사용 API          이 메뉴가 무엇을 쓰는가
탭 2  접근 가능 사용자   누가 닿는가
탭 3  권한 역할          누가 줬는가
```

- **셋 다 조회 전용이다.** 매핑은 시드로만 바뀌고, 권한 편집은 `ROLE_AUTH_MGMT` 와 `USER_AUTH_MGMT` 의 일이다 — 여기서 고칠 수 있게 하면 **같은 사실을 고치는 화면이 둘**이 된다.
- **탭을 열 때 부른다.** 셋을 한꺼번에 부르면 보지도 않을 계산 둘이 매번 딸려 오고, 그중 *접근 가능 사용자* 는 **두 경로의 합집합이라 가장 비싸다.**
- **한 번 부른 탭은 메뉴가 바뀔 때까지 다시 부르지 않는다.** 탭을 오가는 것은 조회가 아니라 *보는 각도를 바꾸는 것* 이다. **`USER_MGMT` 의 *저장하면 나머지를 잊는다* 규칙이 여기에는 없다** — 셋 다 조회 전용이라 **서로의 답을 바꿀 저장이 없다.**
- **판이 공통 그리드다**(2026-08-31 교체). 그 전에는 라이브러리의 표를 직접 써서 이 화면의 하단만 **다른 세계**였다 — 컬럼 폭을 기억하지 않고, 필터도 정렬도 엑셀도 없고, **무엇보다 버튼 줄이 없어** *고르기 전에는 잠긴다* 를 그릴 크롬이 아예 없었다. **서버는 그대로다.**
- **즉시 저장이 셀마다 트리를 다시 읽지만 선택이 유지되므로 하단은 조용하다** — 아이콘 하나 바꿨다고 하단이 세 번 깜빡이지 않는다.

## 9. 시드 · 데이터 전제

- 코드그룹: **없음.** 아이콘 코드는 프론트 상수 목록에서 고른다.
- 메시지 키: 화면 `MSG.MENU_*` · 서버 `MsgKey.ERR_MENU_*` 아홉. **메뉴 이름 키는 `menu.{MENU_CD}`**.

## 11. 미결 · 확인 필요

- **메뉴 이름을 여기서 고칠 수 없다.** `MESSAGE_MGMT` 로 가야 한다 — *현재 답은 "이름의 원본은 하나" 이며 이것이 결정이다.* 다만 새 메뉴를 만들면 이름이 키 문자열로 보이는 구간이 생긴다.
- **고아 메뉴의 일괄 정리가 없다.** 하나씩 게이트를 통과시켜 지운다.
- **`미연결` 을 서버가 판정할 수 없다** — 라우트 맵은 프론트만 안다. 시드로 직접 넣은 URL 은 화면을 열어야 발견된다.
