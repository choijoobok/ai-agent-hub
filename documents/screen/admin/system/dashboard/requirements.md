# 요건 정의서 — 관리 대시보드

## 개요

- **무엇을 하는 화면인가**: 로그인 인사말·메뉴/권한 수와 함께, 현재 열람 가능한 연결 설정 오류를 관리자에게 알린다. 오류 원인과 영향 API·도구·워크플로우 범위를 확인하고 관련 화면으로 이동한다.
- **프로세스상 위치**: 로그인/대시보드 진입 → 연결 설정 오류 확인 → 대상 시스템/API에서 원인 정정 → 서버 검사로 해소 확인.
- **이 데이터를 누가 쓰나**: 해당 대상·메뉴의 현재 조회 권한을 가진 운영 담당자. 수신/화면 권한은 실제 호출 권한을 부여하지 않는다.

> 현재 제품 소스는 인사말·사용 가능 메뉴 수·보유 권한 수만 보여 주고 이 화면 전용 API를 호출하지 않는다. 아래 연결 설정 오류 위젯·조회·이동은 **2026-11-01 사용자 승인 목표 설계**이며 제품 구현 완료 표시가 아니다. 기존 system 공통 대시보드가 admin의 경고 판정을 소유하지 않는다.

## 1. 화면 구성

인사말과 기존 사용 가능 메뉴·보유 권한 요약 카드 → 연결 설정 오류 안내 → 현재 경고 그리드다. 하나의 하단 그리드이므로 탭은 없다. 항상 열리는 고정 탭의 기존 성격은 유지한다. 오류 판정·영향 집계·발생/해소 이력은 admin이 소유하고 system 대시보드는 권한을 검사한 투영을 표시한다.

## 2. 조회조건

별도 검색 폼은 없다. 현재 권한 범위의 미해결 경고가 기본이며 관련 메뉴에서 상세 조건으로 좁힌다. 원인별 같은 환경·설정 세대의 중복을 묶는다.

## 3. 조회 — 테이블과 범위

기존 이름/메뉴/권한 수는 로그인 응답을 사용한다. 새 경고 요약/목록은 admin 공개 API-071을 조회하며 원장 ENT-094(현재 경고)와 ENT-095(발생/해소 이벤트)의 소유는 admin이다. system이 해당 테이블에 직접 접근하거나 판정을 복제하지 않는다. 전체 조회 실패·영향 집계 일부 실패·미지원 관계를 정상 0건과 구분한다. 권한 회수/조회 실패 때 이전 세부정보를 현행 값으로 유지하지 않는다.

## 6. 규칙 — 저장 · 실행

### 6-1. 경고 판정과 해소

- REQ-601.asset_availability가 자동 유효성·영향 참조·경고 생명주기의 정본이다. YAML 동기화 후 및 현재 검사에서 알려진 누락을 원인별로 등록한다. 같은 원인을 여러 API가 사용해도 알림을 무제한 증식하지 않는다.
- 경고 해소는 같은 원인과 현재 설정의 복구를 확인했을 때만 반영한다. 운영자가 봤다는 사실이나 자산 사용 OFF는 연결 자체가 정상이라는 근거가 아니다. 복구도 수동 사용 OFF를 ON으로 바꾸지 않는다.
- 영향은 등록된 식별자·참조 관계로 계산한다. 지식 본문 전체를 수집하거나 LLM의 업무 의미 판단을 요구하지 않는다. 검사 불완전/미지원/후속 차수 관계는 null·확인 필요로 표시하고 검사 범위를 함께 설명한다.

### 6-2. 현재 구현과 목표 설계의 경계

현재 소스에는 경고 조회/실시간 알림이 없으며 기존 카드 수는 로그인 때 정해진 값이다. 새 위젯의 API·주체별 권한·탭 재활성 조회와 실패/늦은 응답 처리는 소유 구현 슬라이스에서 적용한다. 고정 탭에서 무제한 폴링하지 않는다. 화면 경고는 서버의 호출 직전 검사를 대신하지 않는다.

### 6-3. 저장·반출

이 화면에서 경고/연결/사용 여부를 직접 수정하지 않는다. 원인 정정은 대상 시스템/API 소유 화면에서 현재 권한·기대 버전·이력으로 처리한다. DASHBOARD의 기존 READ 경계를 유지하고 이 요약 위젯에는 EXPORT를 선언하지 않는다. 상세 반출은 각 소유 관리 메뉴의 READ+EXPORT와 반출 정책을 사용한다.
