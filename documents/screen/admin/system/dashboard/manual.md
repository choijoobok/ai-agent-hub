## 1. 먼저 알아 둘 것

대시보드는 로그인 후 열리는 고정 탭입니다. 인사말과 사용 가능 메뉴·보유 권한 수는 로그인 때의 값입니다. 숫자가 실제와 다르면 다시 로그인해 확인합니다. 연결 설정 오류는 현재 열람 권한 범위의 별도 운영 정보입니다.

## 2. 연결 설정 오류 확인

1. 연결 설정 오류 안내와 현재 경고 목록을 확인합니다.
2. 대상 시스템·연결 식별자·오류 사유와 영향을 받는 API·도구 수를 확인합니다. 검사하지 못했거나 아직 지원하지 않는 관계는 0건 대신 확인 필요로 보입니다.
3. 관련 API 또는 설정 확인을 눌러 같은 원인의 관리 화면으로 이동합니다. 이 화면에서 연결이나 사용 여부를 직접 바꾸지는 않습니다.
4. 운영 설정이나 API 참조를 정정한 뒤 조회하여 원인 복구 확인 상태를 확인합니다.

데이터소스 YAML 누락/판별 실패 경고는 설정 확인을 눌러 해당 데이터소스 키의 화면으로 이동합니다. 가이드 수정으로 실제 연결 오류가 복구되었다고 판단하지 않습니다.

## 3. 복구 상태의 의미

미해결은 현재 원인을 바로잡아야 함을, 확인 필요는 최신 검사/영향 집계를 확정하지 못했음을 뜻합니다. 해소는 해당 원인을 서버가 다시 검사해 복구를 확인한 경우입니다. 단순 열람이나 자산 사용 중지만으로 해소되지 않으며 연결이 복구되어도 수동 사용 중지한 자산이 자동으로 사용 상태가 되지 않습니다.

## 4. 안 될 때

| 상황 | 확인할 것 |
|---|---|
| 경고를 조회할 수 없음 | 조회 권한과 현재 서버 검사 상태를 확인하고 다시 조회합니다. 이전 정상 화면을 현재 결과로 보지 않습니다. |
| 관련 화면으로 이동할 수 없음 | 해당 관리 메뉴의 현재 조회 권한을 확인합니다. |
| 워크플로우 영향 수가 확인 필요임 | 후속 차수의 실제 검사 범위가 아직 제공되지 않은 상태일 수 있습니다. 0건이나 영향 없음이 아닙니다. |
| 설정을 복구했는데 API가 사용 중지임 | 자산 사용 여부는 관리자의 별도 설정입니다. 해당 API/도구 관리에서 확인합니다. |

경고 목록은 실제 업무 재실행 명령이 아닙니다. 실패한 워크플로우의 선행 성공 작업이나 결과 불명 작업을 경고 확인만으로 다시 실행하지 않습니다.
