# 요건 정의서 — 개인 예외 권한

## 개요

- **무엇을 하는 화면인가**: 역할과 별개로 **한 사람에게 직접** 권한을 준다. **기간과 사유가 필수**이며, 회수는 삭제가 아니라 **종료일을 어제로 두는 것**이다.
- **프로세스상 위치**: (선행) `USER_MGMT` 에 계정이 있어야 하고 `MENU_TREE` 에 메뉴가 있어야 한다 → **이 화면** → (후행) 그 사람의 유효 권한에 합집합으로 더해진다.
- **이 데이터를 누가 쓰나**: 유효 권한 계산(역할과 **합집합**), `USER_MGMT` 의 **개인 예외 탭**(조회 전용)과 **유효 권한 탭**.
- **바꾸면 어디가 흔들리나**: 그 사람의 권한이 즉시 바뀐다. `ROLE_MGMT` · `ROLE_AUTH_MGMT` 의 **차단 경고가 이 값을 읽는다** — 개인 예외가 있는 사람은 역할을 잃어도 차단되지 않는다.

> **목록이 원본이고 트리는 그 투영이다.** *같은 데이터의 두 표시* 이지만 **대칭이 아니다** — 기간과 사유가 들어가는 곳이 목록뿐이므로 **데이터는 목록에 있고, 트리는 그것을 읽어 그린다.** 이 화면의 모든 상태(스위치의 켜짐 · 폴더의 3-state · `✎`)가 **하단 그리드의 행에서 계산된다.** 트리가 자기 상태를 따로 들면 *"지웠는데 위에는 그대로다"* 가 된다.

> **회수는 삭제가 아니다.** 스위치를 끄면 **종료일이 어제가 되고 행은 남는다.** 지우는 것은 목록의 `✕` 이며 **잘못 등록한 행 정리**다 — 둘을 같은 제스처로 두면 *누구에게 왜 무엇을 언제까지 줬는가* 가 사라진다.

> **이 문서는 구현된 소스에서 역으로 작성했다**(2026-09-03).

## 1. 화면 구성

```
[조회조건 — 사용자 한 칸]
┌──────────────────────────────────────────────┐
│ [좌: 사용자 목록] │  [우: 권한 트리]           │   ← 좌우
└──────────────────────────────────────────────┘
[하: 예외 목록]                                    ← 상하. **저장 버튼이 여기 있다**
```

- 진입 시 자동 조회: **안 함.**
- 모달: **재부여 확인** 하나(§4-4).
- **스플리터가 둘**이고 `ROLE_AUTH_MGMT` 와 같은 배치다 — 사용자 목록은 컬럼이 넷이라 위아래로 두면 가로가 대부분 빈다.
- **저장 단위는 하단이다.** 행 상태(`＋` · `✎` · `✕`)가 거기 있으므로 저장 버튼도 거기 있다. 트리의 버튼은 **조회와 접기·펼치기**뿐이며, 트리가 말하는 미저장은 메뉴명 옆의 `✎` 하나다.

### 1-1. 마스터-디테일 연동

- 연동 기준: 좌측에서 고른 `USER_ID` 로 트리와 하단을 **한 번에** 조회한다(같은 응답).
- **미저장 신규 부모가 생길 수 없다** — 계정 생성은 `USER_MGMT` 의 일이라 좌측이 읽기 전용이다. 그래서 **잠긴 상태가 없다**(`ROLE_AUTH_MGMT`·`CODE_MGMT` 와 갈리는 자리).
- **고른 사용자가 없으면 트리와 하단이 함께 잠긴다.** 트리의 조회 버튼이 그 실물이었다 — 눌러도 조용했고 사용자가 보는 것은 **아무 일도 일어나지 않는 클릭**이다.
- **미저장 편집이 있는 상태에서 다른 사용자 선택: 묻는다.** 거부하면 선택이 되돌아간다 — 그 상태로 저장하면 **A 의 예외가 B 에게 나간다.**
- **좌측 [조회]는 선택을 풀고 검색어까지 비운다** — 잠긴 칸에 남은 글자는 잡음이다. **미저장이 있으면 조회 전에 묻는다.**
- **트리 [조회]와 하단 [조회]가 같은 함수를 부른다**(2026-09-01). 둘은 조회 하나의 **두 표시**이므로 한쪽만 다시 읽을 수 없다 — 읽으면 **같은 데이터가 화면에서 갈린다.** 컨트롤러의 조회를 거치지 않으므로 **미저장 확인을 화면이 직접 한다.**
- 제목 뒤에 **이름 / ID** 가 붙는다. 둘 다인 이유는 각자 부족하기 때문이다 — ID 만으로는 **누구인지** 를 모르고(`u10293`), 이름만으로는 **동명이인**이 갈리지 않는다. **여기서는 그것이 안전 장치다**: 좌 pane 이 스크롤되면 고른 행이 화면에서 벗어나는데, 그 상태로 트리의 스위치를 켜는 것은 **누군지 모르는 사람에게 권한을 주는** 일이다.

## 2. 조회조건

| 조건 | 대상 컬럼 | 입력방식 | 연산 | 필수 | 기본값 | 라벨 키 |
|---|---|---|---|---|---|---|
| 사용자 | **`USER_ID` + `USER_NM` 한 칸** | 텍스트 | `contains`(기본) · `eq` · `startsWith` · `endsWith` | 선택 | — | `MSG.USER_AUTH_SEARCH_USER` |

- **하나뿐이다.**
- **ID 와 이름을 한 칸이 함께 본다.** 사람을 찾을 때 손에 있는 것은 *ID 이거나 이름* 이고 **어느 쪽인지는 대개 상관없다** — `USER_MGMT` 와 갈리는 자리이며, 그쪽은 **목록 자체가 일**이라 칸이 여덟이다.
- **`부여 상태` 조건이 없다** — 트리는 만료 배지를 그려야 하므로 전건을 보고, 목록만 걸러져 있으면 *"같은 데이터의 두 표시"* 라는 원칙이 성립하지 않는다.
- **`예외 건수` 로도 거르지 않는다** — 거르면 *예외가 없는 사람에게 처음 주는* 동선이 막힌다. 좁히는 데 쓰는 것은 정렬이 아니라 **눈**이다.
- **못 쓰는 계정도 나온다** — 계정 상태는 컬럼이 말한다(§4-1).

### 2-1. 메뉴 검색 — **거르지 않고 찾아간다**

- 트리 헤더의 검색 칸(`MSG.USER_AUTH_SEARCH_MENU`). 강조 · 경로 펼침 · **첫 일치로 스크롤**. 서버로 나가지 않는다.
- **칸 하나다**(2026-08-31) — 건수와 이동 버튼 둘을 뺐다. 트리가 강조와 함께 경로를 펼치므로 나머지 일치도 같은 화면 안에 있고, *다음* 을 눌러 옮겨 다닐 거리가 아니다.
- **브레드크럼 슬롯이 아니라 트리 헤더에 있다**(2026-08-31 이동). 슬롯에서는 둘이 어긋났다.

| 무엇이 | 왜 |
|---|---|
| **자리** | 줄 오른쪽 끝의 *조회조건 숨기기* 옆이라 **무엇을 검색하는지가 화면 어디에도 없었다** — 이 화면은 검색 칸이 둘이다(사용자는 조회조건, 메뉴는 트리) |
| **입력** | 한 글자가 **두 번 들어갔다.** 슬롯은 셸이 그리는 것이라 값이 **한 커밋 늦게** 도착하고, 그 사이 DOM 이 *아직 옛 props* 로 되돌아간다 — 라틴 글자에서는 깜빡임이지만 **한글은 매 타가 조합 중**이라 그 되돌림이 조합을 깬다 |

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

| 테이블 | 역할 | 결합 기준 |
|---|---|---|
| `SYS_USER` | 좌 — 사용자 목록 | — |
| `SYS_MENU` | 우 — **메뉴 계층 전건** | — |
| `SYS_USER_MENU_AUTH` | 개인 예외(기간 · 사유) | `USER_ID` + `MENU_CD` + `ACTION_CD` |
| `SYS_MENU_API` · `SYS_API` | 정의된 액션 | `MENU_CD` |
| `SYS_USER_ROLE` · `SYS_ROLE_MENU_AUTH` · `SYS_ROLE` | **역할 경유 배지** | `USER_ID` → `ROLE_ID` |
| `SYS_MESSAGE` | 메뉴명 | 서버가 세션 언어로 푼다 |

- **`getMenuTree` 하나가 트리와 목록을 함께 먹인다.** 표시가 둘이라고 원본이 둘이 되면 **같은 질문에 답이 둘**이 되고, 그 둘이 갈리는 순간 *"트리에는 있는데 목록에 없다"* 가 된다.

### 3-2. 고정 조건 · 기본 정렬

- 좌: offset 페이징.
- 우·하: **페이징도 조건도 없다.** 하단의 순서는 **트리 그대로**(전위 순회)다 — 다시 정렬하면 **목록에서 찾은 행이 트리의 어디인지** 를 눈으로 잇기 어려워진다.

- **넷뿐이고 고르기만 하는 목록이다.** 행 추가 버튼도 삭제 컬럼도 없다.

- **`예외 건수` 는 지금 유효한 것만 센다**(2026-08-31 추가). 하단 그리드의 *상태* 컬럼과 **같은 규칙**이어야 눈으로 센 수와 맞는다 — 전건을 세면 만료가 쌓인 계정이 **영영 큰 수**로 남아 화면의 어느 수와도 맞지 않는다. 세지 않는 것이 무엇인지는 **툴팁**이 말한다. **배지를 붙이지 않는다**: 0 은 *결함이 아니라 정상* 이다.
- **파생 둘 다 정렬을 켜지 않는다** — 서버 화이트리스트에 없다.

### 4-2. 우 — 권한 트리 (**셀 상태 일곱** — 이쪽이 원본이다)

| 상태 | 언제 | 스위치 |
|---|---|---|
| **부여 없음** | 개인 예외가 없다 | 꺼짐 |
| **유효** | 오늘이 기간 안 | **켜짐** |
| **예정** | 시작일이 미래 | **꺼진 채 배지** |
| **만료** | 종료일이 지났다 | **꺼진 채 배지** |
| **역할 경유** | 그 액션을 **지금 유효한 역할이** 준다 | 배지 |
| **액션 미정의(`—`)** | 그 메뉴에 그 액션의 API 가 없다 | 없음 |
| **구조 노드** | `MENU_URL` 이 `null` | 없음 — 파생 3-state |

- **스위치가 켜지는 것은 *유효* 하나뿐이다.** 예정·만료는 **꺼진 채 배지**다.
- **역할 경유 배지는 막지 않고 알려만 준다.** 중복은 무해하고(합집합), 막으면 **역할 부여가 곧 만료되는 경우**를 처리할 수 없다. 만료된 역할 부여와 꺼진 역할은 이 배지에 오지 않는다.
- **꺼진 메뉴에도 예외는 줄 수 있다** — 메뉴의 `USE_YN` 은 최종 게이트다. 화면은 **이름을 흐리게** 그린다.
- 아이콘 코드는 **사이더와 같은 것**이다.
- **`✎` 는 하단이 말한다** — 상태가 있는 행의 메뉴에 붙는다. **구조 노드에는 붙지 않는다.**
- **폴더의 3-state 는 액션 열마다 따로 요약하며 표시뿐이다.** 일괄 토글은 어느 화면에도 없다.

- **메뉴와 액션이 읽기 전용이다.** 그 둘은 PK 의 일부이고 고치는 것은 *다른 행을 만드는 일* 이며, 만드는 자리는 트리다 — 목록에서 메뉴 코드를 고칠 수 있게 하면 **트리를 둔 이유가 사라진다.**
- **`행 추가` 버튼이 없다.** 부여는 **트리에서 켜는 것**이며, 목록에 빈 행을 만들 수 있게 하면 *메뉴 코드를 손으로 적는* 경로가 열린다.
- **메뉴명에 조상 경로를 붙인다** — 목록만 보면 **메뉴 코드로 무엇인지 알 수 없다.**
- **`종료일` 이 필수다.** **무기한이라는 선택지가 없다** — 역할 부여(`null` = 무기한)와 갈리는 자리이며 그 차이가 의도다.
- **`부여 사유` 가 필수다.** 역할 부여에는 없는 컬럼이며 **변경 이력 테이블이 없으므로 이 칸이 곧 감사 기록**이다.
- **`상태` 는 값에서 다시 계산한다** — 조회 시점의 판정을 붙잡아 두지 않는다. 종료일을 어제로 바꾼 순간 그 행은 *만료* 이며 트리의 스위치도 같은 계산을 보고 **함께 꺼진다.**
- **종료일이 비어 있으면 만료가 아니다.** 방금 켠 신규 행이 그 상태이고 *유효* 로 보인다 — 스위치를 켠 사람이 기대하는 그림이며, **저장은 검증에서 막힌다.**
- **고아 배지**(`MSG.USER_AUTH_ORPHAN`) — API 가 사라져 그 액션이 미정의가 된 부여다. 트리에서는 `—` 로 보여 켜고 끌 수 없고, **목록에서만 지울 수 있다.** 일괄 정리는 두지 않는다: 몇 건 되지 않고 **한 건씩 보고 지우는 것이 그 판단의 본체**다.
- **기간은 양끝 포함**이라 같은 날은 통과다.

### 4-4. 스위치 하나가 하는 일 — **목록에 행을 만들라는 지시**

| 지금 상태 | 조작 | 무엇이 일어나나 |
|---|---|---|
| 부여 없음 | **켬** | 목록에 **추가(`＋`) 행**. 시작일 = 오늘, **종료일과 사유는 빈칸** |
| 만료 | **켬** | **이전 값을 보여주고 대체를 확인한 뒤** 그 행을 되살린다 — 새 행이 아니다(PK 가 하나다) |
| 예정 | **켬** | **아무것도 하지 않는다** — 사람이 정해 둔 기간이 이미 들어 있다. 안내만 낸다 |
| 삭제 표시 | **켬** | 삭제를 **되돌린다** |
| 유효 | **끔** | **회수** — 종료일을 어제로. **행은 남는다** |
| 미저장 신규 | **끔** | **즉시 제거** — 서버에 없는 행이다 |

- **되살릴 때 종료일을 지우는 것이 아니라 다시 받는다** — 기간이 필수라 비워 두면 검증에 걸린다. **무기한이라는 선택지가 없으므로** 되살리려면 새 종료일을 받는 수밖에 없다.
- **즉시 회수는 어제다.** 오늘로 두면 양끝 포함이라 **오늘까지 유효하다.**

| 조작 | 무엇이 함께 | 알리는가 |
|---|---|---|
| 다른 액션을 **켠다** | **`READ` 행도 만들거나 되살린다** | `MSG.USER_AUTH_READ_ON` |
| 다른 액션을 켜는데 **역할이 `READ` 를 준다** | **만들지 않는다** — 합집합이라 그것으로 충분하고, 굳이 하나 더 만들면 **회수할 것이 둘**이 된다 | `MSG.USER_AUTH_READ_VIA_ROLE` |
| `READ` 를 **끈다** | **그 메뉴의 유효한 나머지도 함께 회수** | `MSG.USER_AUTH_READ_OFF`(건수) |
| `READ` 를 끄는데 **역할이 `READ` 를 준다** | **연쇄하지 않는다** — 그 사람은 여전히 화면에 들어갈 수 있어 나머지가 도달 가능하다 | — |

- **전에는 *새 행을 만드는 길* 하나에만 걸려 있었다**(2026-09-01 수정). 삭제 표시를 되돌리거나 만료를 되살려 켜면 **조회 없는 저장**이 조용히 남았고, 그 부여는 도달할 수 없어 **인가 데이터가 거짓말을 한다.**
- **갱신을 한 번에 모은다**(2026-09-01 실물). 누른 액션과 `READ` 를 각각 넣었더니 둘이 **같은 스냅샷**에서 다음 배열을 만들어 **뒤엣것이 앞엣것을 덮었다** — 조회만 켜지고 **정작 누른 스위치는 꺼진 채로** 남았다.
  - `ROLE_AUTH_MGMT` 에는 없던 사고다: 그쪽은 한 메뉴의 부여가 집합 하나라 둘을 더해도 갱신이 **한 번**이고, 여기는 부여마다 **행**이라 둘을 더하는 것이 **갱신 둘**이 된다.
  - **순서가 규칙이다** — **통째로 넣는 갱신이 먼저, 이어 붙는 갱신이 나중.** 거꾸로 두면 통째로 넣는 쪽이 **앞의 것을 지운다.**

### 4-6. 행 추가 기본값

- **트리에서 켤 때만 생긴다**: `VALID_FROM_DT` = **오늘**(브라우저의 오늘) · `VALID_TO_DT` = 빈칸 · `GRANT_RSN` = 빈칸.
- **시작일은 거의 항상 오늘이고 종료일과 사유는 새 판단이라 빈칸이다.**

### 4-7. 비노출 저장 컬럼

- **삭제 행은 `MENU_CD` + `ACTION_CD` 만 보낸다.**
- 저장이 보는 사용자는 **상태가 아니라 참조로 든다** — 저장 페이로드를 만드는 콜백이 만들어진 시점의 상태를 붙잡고 있으면 **A 사용자의 예외가 B 사용자에게 나간다.**

## 5. 버튼 · 액션

| 버튼 | 라벨 키 | 액션 | 활성 조건 | 동작 |
|---|---|---|---|---|
| 조회(좌) | (공통) | `R` | 항상 | 사용자 목록. **선택이 풀린다** · 미저장이면 묻는다 |
| 조회(트리 · 하단) | (공통) | `R` | 사용자 선택 | **같은 함수** — 트리와 목록을 함께 다시 읽는다 |
| 저장(하단) | (공통) | `S` | 변경 있음 | 예외 추가·수정·삭제 일괄 |
| 행 삭제(하단) | (공통) | `S` | 행 선택 | **잘못 등록한 행 정리** |
| 모두 접기 / 펼치기 | `MSG.MENU_COLLAPSE_ALL` · `MSG.MENU_EXPAND_ALL` | 없음 | 항상 | 표시만 |

- **하단에 `행 추가` 가 없다**(§4-3).
- 엑셀 다운로드: **사용**(`EXPORT_YN='Y'`) — **프론트 생성**이라 서버 경로가 없다.
- 진행률 창: 없음.
- **저장 뒤에 트리를 다시 읽는다** — 서버가 정리한 결과와 화면을 맞춘다. 하단은 **자기 조회 경로가 없으므로** 그 재조회가 목록까지 채운다.

### 5-1. 저장 확인 **앞**에 서는 배너

| 트리거 | 문구 키 | 무엇을 말하나 |
|---|---|---|
| **새로 준 예외가 10건 이상** | `MSG.USER_AUTH_THRESHOLD` | *역할 신설을 검토하세요* |

- **막지 않고 묻기만 한다.** 진짜로 10개가 필요한 예외가 실재하며, 막으면 사용자는 **저장을 두 번 나눠** 규칙을 피한다.
- **새로 준 것만 센다.** 기간을 고치거나 회수하는 것은 예외를 *늘리는* 일이 아니므로 여기 세면 **정리하는 저장에서 신설을 권하게** 된다.
- **10은 상수이고 실측이 미결이다**(§10).

### 6-2. 영향 테이블

| 트리거 | 테이블 | 작업 | 조건 · 내용 |
|---|---|---|---|
| 저장 | `SYS_USER_MENU_AUTH` | INSERT · UPDATE · DELETE | 기간·사유가 함께 간다 |
| **세션** | — | **무효화** | 그 사용자의 유효 권한이 바뀌면 |

- 저장은 **한 트랜잭션**이다.
- **고아 부여는 저장이 지우지 않는다** — 지우는 것은 목록에서 사람이 한다.

### 6-3. 상태 전이 — 기간에서 파생

- 상태 컬럼이 **없다.** `SCHEDULED` · `ACTIVE` · `EXPIRED` 는 **기간에서 조회 시 계산**한다 — 컬럼으로 두면 배치가 그것을 갱신해야 하고, **배치가 실패한 동안 화면과 판정이 갈린다.**

| 지금 | 동작 | 다음 |
|---|---|---|
| 부여 없음 | 트리에서 켠다 | 신규 행(오늘 시작) |
| `ACTIVE` | 트리에서 끈다 | `EXPIRED`(종료일 = 어제) |
| `EXPIRED` | 트리에서 켠다 | **확인 후** `ACTIVE`(같은 행을 되살린다) |
| `SCHEDULED` | 시작일 도래 | `ACTIVE` (자동) |
| 어느 상태든 | 목록에서 `✕` | 행이 사라진다 — **기록도 사라진다** |

## 7. API

| 용도 | `endpoints.ts` 키 | 경로 | 메서드 | 액션 | 페이징 |
|---|---|---|---|---|---|
| 좌 — 사용자 목록 | `getList` | `/service/system/userAuth/getList` | POST | R | offset |
| **우 + 하** | `getMenuTree` | `/service/system/userAuth/getMenuTree` | POST | R | **없음** |
| 저장 | `save` | `/service/system/userAuth/save` | POST | S | — |

- **셋인데 화면은 넷이다** — 우와 하가 **경로 하나**를 나눠 쓴다. 표시가 둘이라고 원본이 둘이 되면 **같은 질문에 답이 둘**이 된다.
- **`USER_MGMT` 의 개인 예외 탭과 경로를 나눈다.** 거기는 *"이 사람이 무슨 예외를 갖고 있나"* 이고 여기는 *"이 사람에게 예외를 준다"* 다 — 편집을 탭에 두지 않는 이유는 **사용자 관리 권한이 있다고 예외 권한 부여 권한이 따라오면 안 되기** 때문이다. 반환 형태도 다르다(저쪽은 납작한 목록, 여기는 메뉴 전건).
- `exportExcel` 없음 — 프론트 생성.

## 8. 시드 · 데이터 전제

- 코드그룹: **없음.** 액션 넷과 상태 셋은 상수다.
- 메시지 키: 화면 `MSG.USER_AUTH_*` · `MSG.AUTHZ_ACTION_*` · 서버 `MsgKey.ERR_USER_AUTH_*` 아홉.
- 메뉴 시드: `menu-tree.yaml` — `code: USER_AUTH_MGMT` · `parent: USER` · `url: /admin/system/user-auth` · `export: true`.

| `UA-29d` | 목록에서 **기간·사유만** 고친다 | **스위치는 그대로.** 트리 행에 **`✎` 미저장 표시**만 붙는다 |
| `UA-29e` | 미저장 변경이 있는 채로 **목록을 접는다** | 트리의 `✎` 표시가 **남는다** — 접기는 표시일 뿐이다 |
| `UA-35` | 저장 API 를 대조 | **트리와 목록이 같은 하나**다 — 나누면 한쪽만 저장하는 경로가 열린다 |

### 예외 목록

| # | 조작 · 상황 | 기대 |
|---|---|---|
| `UA-36` | 기간·사유를 비운 채 저장 | **셋 다 거부**된다 — 전부 필수다 |
| `UA-37` | 역할 부여(`user.html` 탭 1)와 대조 | **거기는 기간이 선택**이고 **여기는 필수**다 |
| `UA-38` | 즉시 회수 | **종료일을 어제로** 한다 — 행을 지우지 않는다 |
| `UA-39` | 행을 지운다 | **오등록 정정**용이다 — 회수 수단이 아니다 |
| `UA-40` | 상태 컬럼 | **조회 시 계산**된다. 배치가 갱신하지 않으며 **정렬도 끈다** |
| `UA-41` | API 가 사라져 미정의가 된 부여 | **행이 남고 고아로 표시**된다 — 배포가 운영 결정을 지우지 않는다 |

### 배치와 연동

| # | 조작 · 상황 | 기대 |
|---|---|---|
| `UA-42` | 하단의 탭 | **없다** — 역할 후보 리포트는 **기능 제외**다 |
| `UA-43` | 사용자 미선택 상태 | 트리·목록이 **빈 상태 + 버튼 비활성** |
| `UA-44` | **잠긴 상태**를 만들려 한다 | **만들 수 없다** — 사용자 목록에서 행을 추가할 수 없다 |
| `UA-45` | 사용자 목록의 삭제 컬럼 | **없다** — 고르기만 하는 목록이다 **(되면 안 되는 것)** |
| `UA-46` | 미저장 편집 상태로 다른 사용자를 클릭 | **확인 다이얼로그.** 트리와 목록이 **함께** 버려진다 |
| `UA-47` | 스플리터 | **둘이다** — 좌우(사용자↔트리) + 상하(위↔예외 목록) |
| `UA-48` | `◀` 를 누른다 | **막대가 맨 왼쪽으로** 가고 **사용자 목록이 접힌다** |

### 버튼 → 액션

| # | 조작 · 상황 | 기대 |
|---|---|---|
| `UA-49` | 이 화면의 액션 집합 | `R` `S` `E` — **`EXECUTE` 가 없다** |
| `UA-50` | 트리 조회의 응답 | 메뉴 계층 + **역할 보유분**을 함께 준다 |
| `UA-51` | `S` 권한이 없는 사용자 | **저장 버튼과 함께 트리의 스위치도 비활성**이다 **(되면 안 되는 것)** |
| `UA-52` | 엑셀 다운로드 | 트리는 **계층을 들여쓰기로 편다** |

## 10. 미결 · 확인 필요

- **역할 신설 권고의 기준(10건)이 실측 미결이다.** 상수로 둔 것은 **설정으로 빼려면 그 값을 무엇으로 정할지 먼저 알아야 하기** 때문이며, 지금은 아무도 그 답을 갖고 있지 않다 — **운영에서 이 배너가 얼마나 자주 뜨는지가 그 답이 된다.**
- **고아 부여의 일괄 정리가 없다** — 한 건씩 지운다. *현재 답은 "한 건씩 보고 지우는 것이 판단의 본체" 이며 이것이 결정이다.*
- **시작일 기본값이 브라우저의 오늘이다** — 업무 시간대는 서버의 것인데 화면이 만드는 기본값은 브라우저의 것이라, 시차가 큰 환경에서 하루가 어긋날 수 있다.
