# 요건 정의서 — 로그인 이력

> **CR-028 목표 경계(2026-10-29):** 이 문서의 기존 소스 역작성은 현재 구현 근거다. system 계정·인증·세션·SYS_USER 참조는 관리자 영역에 한정한다. Portal 계정/인증은 ARCH-050의 별도 계약과 SCR-113~115를 사용하며 같은 문자열 ID로 관리자 이름·이력·개인 설정을 연결하지 않는다. 통합 감사의 영역 구분·이행 및 상세 화면 변경은 소유 P3 후속이고 현재 소스에서 구현됐다는 뜻이 아니다.


## 개요

- **무엇을 하는 화면인가**: 로그인 성공·실패와 **세션이 끝난 사건**(로그아웃 · 만료 · 강제 종료 · 밀려남)을 시각 순으로 보여준다. 용도가 둘이다 — *이 사람이 왜 못 들어오나* 와 **없는 계정으로의 연속 시도 탐지**.
- **프로세스상 위치**: (선행) 없음 — 인증 체인이 판정할 때마다 행을 남긴다 → **이 화면** → (후행) 사유가 계정 상태면 `USER_MGMT` 에서 잠금·휴면을 풀고, 허용 IP 문제면 같은 화면의 접속 IP 탭으로 간다.
- **이 데이터를 누가 쓰나**: `USER_MGMT` 의 **활성 세션** 탭이 접속 IP·브라우저를 여기서 찾아 붙인다. 그 밖에는 사람만 쓴다.
- **바꾸면 어디가 흔들리나**: `LOGIN_RSLT_CD` 에 코드를 더하면 **묶음(실패/종료/성공)을 함께 정해야 기동한다** — 정하지 않은 코드가 있으면 서버가 뜨지 않는다. 배지 색 셋과 조회조건 `결과 묶음` 이 같은 축이라 한쪽만 고치면 색과 거르기가 갈린다.

> **이름보다 담는 것이 넓다.** `SYS_LO_LOGIN` 은 실제로 **세션 이력**이다. 이름을 바꾸지 않는 것은 **로그인 실패를 찾는 사람이 메뉴에서 그것을 찾기** 때문이다 — 담는 것이 넓은 것보다 찾는 이름으로 있는 편이 낫다.

> **이 문서는 구현된 소스에서 역으로 작성했다**(2026-09-03).

## 2. 조회조건

| 조건 | 대상 컬럼 | 입력방식 | 연산 | 필수 | 기본값 | 선택 출처 | 라벨 키 |
|---|---|---|---|---|---|---|---|
| 조회 기간 | `CRE_DTM` | 날짜(기간) | `between` | **필수**(§2 단서) | 시스템 값 **7일** · 상한 **92일** | — | `MSG.LOGIN_LOG_SEARCH_PERIOD` |
| 사용자 아이디 | `USER_ID` | 텍스트 | `eq`(기본) · `startsWith` · `contains` · `endsWith` | 선택 | — | — | `MSG.LOGIN_LOG_SEARCH_USER_ID` |
| 사용자명 | `SYS_USER.USER_NM` | 텍스트 | `contains`(기본) · 나머지 셋 | 선택 | — | — | `MSG.LOGIN_LOG_SEARCH_USER_NM` |
| 결과 | `LOGIN_RSLT_CD` | 셀렉트(다중) | `in` | 선택 | — | **코드그룹 `LOGIN_RSLT_CD`** | `MSG.LOGIN_LOG_SEARCH_RESULT` |
| 결과 묶음 | **파생** — 코드 집합 | 셀렉트 | `eq` | 선택 | — | 상수 `FAILED`·`CLOSED` | `MSG.LOGIN_LOG_SEARCH_RSLT_GROUP` |
| 접속 IP | `CLIENT_IP` | 텍스트 | **`eq` 만** | 선택 | — | — | `MSG.LOGIN_LOG_SEARCH_CLIENT_IP` |
| 추적 ID | `TRACE_ID` | 텍스트 | **`eq` 만** | 선택 | — | — | `MSG.LOGIN_LOG_SEARCH_TRACE_ID` |

- **기간 상한을 화면이 덮지 않는다** — 이력 셋 중 유일하다. 사용 이력이 1·31 로 좁힌 것은 행마다 `nclob` 이 달려 있어서인데, 여기는 행이 가볍다. 그 결과 **보존(365일)보다 창(92일)이 짧은 유일한 화면**이 되는데, 1년치가 필요하면 엑셀을 네 번 내린다.
- **`추적 ID` 를 넣으면 기간이 선택이 된다** — 사용 이력과 같은 규칙이며 판정도 같게 서버가 한다.
- **`결과` 와 `결과 묶음` 이 따로인 것이 의도다.** 묶음은 **훑기**(코드 열다섯을 하나씩 고르면 *"실패 전부"* 에 열 번을 누른다)이고 결과는 **좁히기**다. 한 콤보에 15 + 2 를 섞으면 목록에서 무엇이 묶음인지 알 수 없다. **둘을 함께 채우면 교집합**이다 — *실패만* + `FAIL_PWD` = `FAIL_PWD`.
- **`결과 묶음` 후보에 *성공만* 이 없다.** 성공은 코드 하나라 접을 것이 없고 `결과` 콤보가 한 번의 선택으로 이미 답한다 — 두면 같은 조회를 내는 길이 둘이 되고, 함께 채워졌을 때 교집합 규칙만 복잡해진다. (서버의 묶음 맵에는 `SUCCESS` 가 있으나 **화면이 후보로 내지 않는다.**)
- **`결과` 는 후보를 공통코드에서 받고 `결과 묶음` 은 상수다.** 갈리는 기준이 분명하다 — 결과 코드의 *이름* 은 데이터가 정하지만, 묶음은 **값에 따라 서버의 갈래가 갈리므로** 소스가 값을 가져야 한다. `grpCd` 로 열면 관리 화면에서 항목을 더할 수 있는데 서버에는 그 묶음이 없다.
- **IP 는 완전 일치만.** 인덱스가 `CRE_DTM` · `TRACE_ID` 둘뿐이라 대역 검색은 **완전 일치와 비용이 같은데 결과만 넓어진다.** 실패 행에서 IP 를 복사해 그 IP 로 다시 조회하는 것이 침입 시도 탐지의 동선이다.
- **사람 칸 둘은 그 예외다.** 부분 이름은 **다른 답**을 낸다 — `admin` 으로 **끝나는** 아이디로의 시도를 모아 보는 것 자체가 물음이다.
- **이름으로 물으면 없는 계정의 시도가 빠진다.** 그 행에는 이름이 없기 때문이며, 그것이 맞다 — *"홍길동의 로그인 실패"* 를 묻는 사람이 찾는 것은 **그 사람의 행**이고, 없는 계정의 시도는 아이디나 결과 코드로 찾는다.

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

| 테이블 | 역할 | 결합 기준 |
|---|---|---|
| `SYS_LO_LOGIN` | 메인 | — |
| `SYS_USER` | 사용자명 | `USER_ID` — **`LEFT JOIN`** |

- **`LEFT JOIN` 이라야 하는 것이 이 화면에서 가장 분명하다.** FK 를 걸지 않은 이유가 *"존재하지 않는 주체의 기록도 남아야 한다"* 였고 **이 테이블이 그 대표 사례**다. `JOIN` 으로 두면 **없는 계정으로의 시도가 통째로 사라지고**, 그것은 이 화면의 두 번째 용도를 없애는 것이다.
- **두 번째 질의가 없다.** 이름이 컬럼 그대로라 번역도 폴백도 없다 — 사용 이력이 메뉴명 때문에 질의를 하나 더 도는 것과 갈리는 자리다.
- `MENU_CD` 컬럼이 **테이블에 없다.** 사용 이력이 `NULL` 로 푼 것을 이 테이블은 **컬럼을 두지 않는 것으로** 풀었고, 둘이 어긋나지 않는다.

### 3-2. 고정 조건 · 기본 정렬

- 항상 적용되는 필터: **없음.**
- 기본 정렬: `CRE_DTM` 내림차 → `LOGIN_LOG_SEQ`(동률만). PK 순서가 시간 순서가 아니다(`allocationSize=1000`).
- 조회 상한: **기간 92일**(시스템 값).
- 페이징: **커서**.
- 보존: **365일**(`sys-config.retention.login-log-days`).

`○` = 기본 숨김.

- **편집 선언이 한 줄도 없다.** 정렬은 `일시` 하나만 열린다(커서의 기준점).
- **`사용자 아이디` 는 값이 *시도한 ID* 다** — `SYS_USER` 에 없는 값이 들어온다. 헤더는 이력 셋과 같은 이름을 쓰고, 그 사실은 **헤더 툴팁**(`MSG.LOGIN_LOG_USER_ID_ATTEMPTED`)**과 옆 칸의 배지**가 말한다. *시도 ID* 라는 이름으로 걱정을 표현하는 것보다 **칸이 스스로 말하는 편**이 낫다.
- 아이디의 빈 값은 `(입력 없음)`(`MSG.LOGIN_LOG_NO_USER_ID`). 판정을 `??` 가 아니라 `||` 로 하는 것은 **오라클이 빈 문자열을 `NULL` 로 저장하기** 때문이다 — `??` 로 두면 *같은 행이 PostgreSQL 에서는 빈칸, 오라클에서는 `(입력 없음)`* 이 된다.
- **`사용자명` 이 비면 `없는 계정` 배지가 붙는다.** 이 칸이 비는 것은 이 테이블에서 **예외가 아니라 흔한 일**이라, 빈칸으로 두면 *"조회가 덜 됐다"* 로 읽힌다.
  - **값 대신 그리는 배지가 아니라 값 옆에 붙는 배지다.** 값 대신 그리면 **이름이 있는 행에서 이름이 사라진다.**
  - **글자와 색이 결과 컬럼의 `FAIL_NO_USER` 에서 온다** — 같은 공통코드 행을 읽고 색도 같은 `err` 다. 문구를 따로 두면 관리 화면에서 이름을 고쳤을 때 **한 행의 두 칸이 갈린다.**
  - **아이디가 없는 행에는 붙이지 않는다.** 입력조차 없었으면 *없는 계정* 이 아니라 *계정을 말하지 않은 것* 이고, 왼쪽 칸이 이미 `(입력 없음)` 이라고 말한다.
  - **지워진 계정의 예전 로그인도 같은 배지다** — *"지금 이 아이디로 들어올 계정이 없다"* 가 두 경우에 다 참이다.
- **결과 배지는 색 셋 · 글자 열다섯이다.** 15색을 쓰지 않는다 — 운영자가 색 열다섯을 외우지 않는다. 배지 안의 라벨은 코드마다 다르므로 **구분은 잃지 않고 훑기만 빨라진다.** 맵이다(값 집합이 닫혀 있다 — 열거형).

| 색 | 코드 |
|---|---|
| `ok` | `SUCCESS` |
| `err` | `FAIL_NO_USER` · `FAIL_PWD` · `FAIL_DISABLED` · `FAIL_EXPIRED` · `FAIL_LOCKED` · `FAIL_DORMANT` · `FAIL_IP` · `FAIL_NO_AUTHORITY` · `FAIL_TEMP_EXPIRED` · `FAIL_CONCURRENT` |
| `muted` | `LOGOUT` · `SESSION_TIMEOUT` · `FORCED_LOGOUT` · `SESSION_EVICTED` |

- **종료 넷이 회색인 것이 의도다.** 만료도 밀려남도 사용자에게는 *"갑자기 로그아웃됨"* 이지만 시스템으로서는 정상 동작이며, 빨강에 두면 문의를 받은 운영자가 **장애로 읽는다.**
- **결과의 이름은 소스가 아니라 공통코드가 갖는다.** 코드를 소스가 열거형으로 갖는데도 이름을 공통코드에 두는 것은 **값과 이름의 소유가 다르기** 때문이다 — 갈래는 소스가 정하고 글자는 데이터가 정한다. 화면에 `options` 를 상수로 적으면 언어를 늘릴 때 이 파일이 함께 는다.
- **`브라우저` 는 기본 숨김이고 툴팁으로 읽는다.** 한 줄이 200자를 넘어 켜는 순간 다른 컬럼이 전부 밀린다. **`[보기]` 를 쓰지 않는다** — `nclob` 이 아니라 `VARCHAR(500)` 이라 값이 이미 목록에 실려 있어 눌러서 가져올 것이 없다(사용 이력의 전문과 정반대다). **파싱하지 않는다** — *Chrome 131 / Windows* 로 접어 보여주려면 매달 갱신되는 의존성이 들어온다. 500자에서 잘린 채 저장되며 **`…` 를 붙이지 않는다.**

### 5-1. 0건 문구가 조건에 따라 갈린다

| 무엇을 물었나 | 문구 키 |
|---|---|
| `결과 묶음` = *실패만* 이 조건에 있다 | `MSG.LOGIN_LOG_EMPTY_FAILED` |
| 그 밖 | `MSG.LOGIN_LOG_EMPTY` |

- *실패만* 으로 물어 0건이면 그것은 빈 결과가 아니라 **진단**이다. 같은 문구를 쓰면 *"이 기간에 로그인 실패가 없다"* 라는 답이 *"조회 결과가 없다"* 로 읽힌다.
- **문구는 조회 직전에 정한다.** 응답이 0건인지 알았을 때는 이미 *무엇을 물었는지* 가 폼에만 남아 있고, 그 사이 사용자가 조건을 고쳐 놓으면 문구가 **묻지 않은 것**을 말한다.
- **`결과` 로 실패 코드만 골라도 여기 걸리지 않는다.** `FAIL_PWD` 하나를 고른 것은 *"비밀번호 실패를 찾는다"* 이지 *"실패가 있나"* 가 아니며, 그 0건에 *실패가 없다* 고 답하면 **묻지 않은 것**을 말하는 셈이다.
- `emptyNotice` 를 켠다 — 0건을 모달로도 알린다.

### 6-4. 결과 코드 열다섯

> **`뜻` 칸은 코드가 무엇을 가리키는지의 설명이지 화면에 뜨는 글자가 아니다.** 화면 글자는
> `SYS_MESSAGE` 의 `code.LOGIN_RSLT_CD.{코드}` 가 갖고, 두 자리가 다를 수 있다 —
> `FAIL_NO_USER` 는 여기서 *존재하지 않는 ID* 이고 화면에서는 **`없는 계정`** 이다
> (`SYS_CODE.CD_NM` 과 `SYS_MESSAGE` 가 각자의 소유를 갖는다).

| 코드 | 뜻 | 묶음 |
|---|---|---|
| `SUCCESS` | 성공 | 성공 |
| `FAIL_NO_USER` | 존재하지 않는 ID | 실패 |
| `FAIL_PWD` | 비밀번호 불일치 | 실패 |
| `FAIL_DISABLED` | 사용 중지 계정 | 실패 |
| `FAIL_EXPIRED` | 사용 기간 만료 | 실패 |
| `FAIL_LOCKED` | 잠긴 계정 | 실패 |
| `FAIL_DORMANT` | 휴면 계정 — 본인 재인증이 필요하다 | 실패 |
| `FAIL_IP` | 허용 IP 가 아니다 | 실패 |
| `FAIL_NO_AUTHORITY` | 유효 권한이 공집합이다 | 실패 |
| `FAIL_TEMP_EXPIRED` | 임시 비밀번호가 유효 시간을 넘겼다 | 실패 |
| `FAIL_CONCURRENT` | 기존 세션이 살아 있어 신규 로그인이 거부됐다 | 실패 |
| `LOGOUT` | 정상 로그아웃 | 종료 |
| `SESSION_TIMEOUT` | 세션 만료 — **기록 시점은 첫 401 이다** | 종료 |
| `FORCED_LOGOUT` | 관리자 강제 로그아웃 | 종료 |
| `SESSION_EVICTED` | 동시 접속 제어로 밀려났다 | 종료 |

- **묶음이 열거형 전부를 덮는다.** 코드를 더하면서 묶음을 정하지 않으면 **기동이 실패한다** — 조용히 두면 새 코드는 *실패만* 에도 *종료만* 에도 걸리지 않아, 그 조회를 하는 사람의 목록에서 **말없이 빠진다.**
- **묶음을 접두(`FAIL_`)로 판정하지 않는다.** 접두로 두면 열거형에 이름을 더하는 순간 **묶음이 조용히 바뀐다.**
- **실패 순서가 계정 상태 체인의 순서와 같다** — `USER_MGMT` 의 `계정 상태` 파생값과 같은 순서를 본다(미사용 → 기간 만료 → 잠김 → 휴면).
