# 요건 정의서 — API 카탈로그

## 개요

- **무엇을 하는 화면인가**: 시스템에 **등록된 API 전부**와 그 API 가 **어느 메뉴에 붙어 있는지**를 보여준다. 목적은 하나 — **403 을 진단한다.**
- **프로세스상 위치**: (선행) `ACCESS_LOG` · `ERROR_LOG` 에서 URL 하나를 얻는다 → **이 화면** → (후행) 권한 문제로 좁혀지면 `MENU_TREE` 로 넘어가고, 거기서 `ROLE_AUTH_MGMT` · `USER_AUTH_MGMT` 로 간다.
- **이 데이터를 누가 쓰나**: 사람만 쓴다. 원본인 `SYS_API` · `SYS_MENU_API` 는 인가 판정이 읽는다.
- **바꾸면 어디가 흔들리나**: **이 화면은 아무것도 바꾸지 않는다.** 원본이 시드이고 시드는 생성물이다.

> **403 은 세 갈래로 갈리고, 그 셋이 이 화면의 설계를 전부 정한다.**
> ```
> 로그에서 URL 하나를 얻어 여기서 찾는다
>   ├ 목록에 없다      → 미등록   : 컨트롤러 + 시드 재생성      ← 빈 상태가 답한다
>   ├ 있는데 매핑 0    → 미매핑   : endpoints.ts + 시드 재생성  ← 배지와 하단이 답한다
>   └ 있고 매핑이 있다 → 권한 문제 : 역할 권한 또는 개인 예외    ← 하단이 넘겨준다
> ```
> **첫째 갈래는 화면이 보여줄 수 없다** — 없는 행을 목록에 낼 방법이 없기 때문이며, 그래서 **0건의 빈 상태가 곧 진단**이 된다. 이 화면에서 가장 공들인 자리가 데이터가 아니라 **데이터 없음**인 이유다.

> **이 파일이 이 화면의 소재이기도 하다.** *미매핑* 을 고치는 곳이 프론트의 `endpoints.ts` 이고, 이 화면 자신의 그 파일도 같은 규칙을 받는다 — **화면이 진단하는 결함의 원인이 화면 자신의 이웃 파일에 있다.**

> **이 문서는 구현된 소스에서 역으로 작성했다**(2026-09-03).

## 1. 화면 구성

```
[조회조건 — 넷. 넷째가 진단의 입구다]
[그리드 A: API]                         ← 마스터
[━━ 스플리터(상하) ━━]
[그리드 B: 이 API 를 쓰는 메뉴]           ← 하단. 행 더블 클릭이 MENU_TREE 로 간다
```

- 진입 시 자동 조회: **안 함.** **다만 다른 화면에서 URL 을 건네받아 열렸으면 스스로 한 번 조회한다**(§5-1).
- 모달: **없음.**
- 그리드 개인화 키: `master` · `menu`.
- **하단의 설정 창을 끈다** — 컬럼이 넷이고 **넷 다 봐야 한다.** 끄면 저장된 설정을 읽지도 않으므로 왕복 하나가 준다.

### 1-1. 마스터-디테일 연동

- 연동 기준: 마스터의 `API_URL` 로 매핑 메뉴를 조회한다.
- **거부하지 않는다.** 하단에 **잃을 것이 없다** — 편집이 없는 화면에서 확인 모달은 순수한 마찰이다.
- 고르는 순간 하단의 빈 상태를 **미매핑 진단**으로 바꿔 둔다. 0건으로 돌아오면 그 문구가 그대로 서고, 1건이라도 오면 판이 행을 그리므로 빈 상태는 보이지 않는다.
- **하단은 조회조건 폼을 나눠 갖지 않는다.** `CODE_MGMT` 와 갈리는 자리다 — 거기서는 *"이 코드값이 어느 그룹에 있더라"* 가 실제 질문이었지만, 여기 하단에 있는 것은 **메뉴 경로 · 사용 여부 · 인원**뿐이고 **그 셋으로 API 를 거꾸로 찾는 동선은 이 화면의 것이 아니다** — 그것을 묻는 자리는 `MENU_TREE` 다.
- **마스터 [조회]는 하단을 리셋한다** — 남아 있으면 **다른 API 의 매핑을 이 API 것으로** 보게 된다.
- 선택된 API 를 **참조로도 든다** — 행을 고른 **바로 그 순간**에 조회가 나가야 하므로 상태 갱신을 기다릴 수 없다.

## 2. 조회조건

| 조건 | 대상 컬럼 | 입력방식 | 연산 | 필수 | 기본값 | 선택 출처 | 라벨 키 |
|---|---|---|---|---|---|---|---|
| API URL | `API_URL` | 텍스트 | **`contains`(기본)** · `eq` · `startsWith` · `endsWith` | 선택 | **건네받은 URL** | — | `MSG.API_CATALOG_SEARCH_API_URL` |
| API 이름 | `API_NM` | 텍스트 | `contains`(기본) · 나머지 셋 | 선택 | — | — | `MSG.API_CATALOG_SEARCH_API_NM` |
| 액션 | `ACTION_CD` | 셀렉트 | **`eq` 만** | 선택 | — | **상수 넷** | `MSG.API_CATALOG_SEARCH_ACTION` |
| **매핑 상태** | **파생** — 매핑 행의 존재 | 셀렉트 | **`eq` 만** | 선택 | **없음(전체)** | 상수 `Y`·`N` | `MSG.API_CATALOG_SEARCH_MAPPED` |

- **넷째가 진단의 입구다.** 컬럼 필터로 두면 **현재 페이지 안에서만** 걸리는데, 미매핑만 골라 보는 것이 이 화면에서 가장 자주 하는 일이고 그 답은 **전량에 대한 것**이라야 한다 — 그래서 **서버 조건**이다. §5 의 *결함 목록이 그대로 파일이 된다* 도 이 조건 없이는 성립하지 않는다.
- **매핑 상태에 기본값을 두지 않는다.** 미매핑을 기본으로 걸면 **이 화면이 결함 목록이 되고**, 403 하나를 들고 온 사람이 *자기 URL 이 목록에 없다* 를 **미등록으로 잘못 읽는다.**
- **URL 의 기본 연산자가 `contains` 다.** 로그에서 들고 오는 것은 대개 전체 URL 이라 완전 일치가 맞을 것 같지만, *뒷마디로 찾고 싶으면 여기서 URL 을 확정해 오는 것이 맞는 동선* 이며 **그 동선의 입구가 이 칸이다.**
- **액션은 공통코드가 아니다** — **API 의 속성**이며 값에 따라 프로세스가 갈리므로 소스가 값을 갖는다.
- **`값 없음`·`값 있음` 연산자가 없다** — URL 은 PK 라 `NOT NULL` 이고, API 이름은 빌드가 필수로 강제해 언제나 값이 있다.

`○` = 기본 숨김.

- **편집 선언이 하나도 없다** — 그것이 곧 전 컬럼 읽기 전용이다.
- **`API_URL` 에 PK 표시를 붙이지 않는다.** PK 표시는 *신규 행에서만 열린다* 를 뜻하는데 **이 화면에는 신규 행이 없다** — 채울 수 없는 칸에 필수 표시를 붙이면 *왜 안 되나* 를 묻게 된다.
- **`API_NM` 은 빌 수 없다.** 원본이 컨트롤러의 요약 문구이고 **빌드 게이트가 없는 핸들러에서 빌드를 깨므로** *이름 없는 행* 을 화면이 어떻게 보일지 정할 필요가 없다 — **검증을 사람에서 장치로 옮긴다는 원칙이 이 화면의 빈 칸 하나를 없앴다.**
- **`API_DESC` 는 빌 수 있다** — 선택이므로 컨트롤러가 안 적을 수 있다. 500자라 한 줄로 못 읽으니 **펼쳐 읽는다**(편집기가 아니다).
- **`매핑 메뉴 수` 의 `0` 이 곧 진단이다.** 매핑 행이 없으면 유효 권한의 원소가 되는 쌍이 만들어지지 않아 **아무도 이 API 를 부를 수 없다.** 배지는 값이 `0` 일 때 **오류색**이며(`MSG.API_CATALOG_UNMAPPED`), *대개 결함* 인 것은 **배포 예정 화면의 API 가 먼저 들어오는 정상 경로가 있어서** — **그래서 막지는 않는다.**
- **`매핑 메뉴 수` 는 정렬도 필터도 없다** — 두 번째 질의가 세는 값이라 `ORDER BY` 에 넣을 컬럼이 없다. 전량을 물어야 하므로 **`매핑 상태` 를 서버 조건으로 두었다.**
- **`최종 시드 반영` 은 등록일이 아니다.** *등록일* 로 보여주면 거짓말이 된다. **감출 수는 있어도 켤 수 없게 두지는 않았다** — *"어제 배포했는데 왜 아직 미등록인가"* 를 물을 자리가 실제로 있다.

### 5-1. 화면 넘겨주기

**받는 쪽**

| 어디서 | 무엇을 | 무슨 일이 |
|---|---|---|
| `ACCESS_LOG` · `ERROR_LOG` 의 `요청 URI` 더블 클릭 | URL | **칸이 채워진 채로 열리고 스스로 조회까지 한다** |

- **조회까지 해 준다.** 칸만 채우고 멈추면 사람이 조회를 한 번 더 눌러야 하는데, **더블 클릭은 *가서 보겠다* 는 제스처이지 *조건을 옮겨 적겠다* 가 아니다.**
- **완전 일치로 박지 않는다.** 로그의 URL 에 쿼리스트링이 붙어 있으면 0건이 되고, **그 0건은 미등록으로 읽힌다.**
- 값이 **효과가 아니라 초기값**으로 들어간다 — 효과로 읽으면 *첫 렌더는 빈 칸, 두 번째 렌더에서 채워짐* 이 되어 사람이 그 깜빡임을 본다.
- **이미 열려 있는 탭에도 도착한다.** 같은 메뉴를 다시 열면 새 탭이 아니라 있는 탭이 활성화되고 이 화면은 다시 마운트되지 않으므로, 초기값 하나로 두면 **탭만 바뀌고 목록은 그대로다.**

**주는 쪽**

| 제스처 | 어디로 | 무엇을 | 조건 |
|---|---|---|---|
| 하단 행 더블 클릭 | `MENU_TREE` | `MENU_CD` | **`MENU_TREE` 의 `READ` 권한이 있을 때만** |

- **권한이 없으면 아무 일도 일어나지 않는다** — 열어 놓고 403 을 보여주는 것보다 낫다.
- 이 화면은 **넘겨주기까지가 자기 일이다.**

### 5-2. 빈 상태가 곧 진단이다

**마스터** — 문구가 둘로 갈린다.

| 조건 | 문구 키 | 무엇을 말하나 |
|---|---|---|
| **URL 칸에만 값이 있고 0건** | `MSG.API_CATALOG_NOT_REGISTERED` | **미등록** — 컨트롤러를 만들고 시드를 다시 생성해야 한다 |
| 그 밖에 0건 | `MSG.API_CATALOG_EMPTY` | 보통의 빈 결과 |

- **하나로 합치면** 조건을 잘못 준 사람에게 *"컨트롤러를 추가하라"* 고 말하게 되고, 반대로 보통 문구로 정하면 **이 화면의 세 갈래 중 하나가 사라진다.**
- 판정은 **조건이 URL 하나뿐일 때**다.

**하단** — 문구가 둘로 갈린다.

| 조건 | 문구 키 | 무엇을 말하나 |
