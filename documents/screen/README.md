# `documents/screen/` — 화면 문서

화면 하나 = **정본 둘 + 파생 목업 + 선택 캡처**.

**이 문서가 정본이다** — 폴더 규칙 · 셋의 역할 · 현행화 시점을 여기가 갖는다(`AGENTS.md` §6 이
여기를 가리킨다). 곁의 둘은 다른 것을 갖는다: **형식**은
[`aidd-guide/artifact/template/`](../../aidd-guide/artifact/template/README.md), **순서**(①~⑥)는
[`aidd-guide/artifact/screen/screen.md`](../../aidd-guide/artifact/screen/screen.md).

```
documents/screen/{페이지경로}/
    requirements.md      개발 요건 정의서 + 테스트 케이스 — AI 가 읽고 구현한다   ← 정본
    manual.md            사용자 메뉴얼 — 원본                                    ← 정본
    mockup.html          목업 — `/mockup` 이 요건서에서 만든다                    ← 파생
    screen.png           (선택) 대표 화면 실제 캡처                               ← 인수 근거
    screen-{그림키}.png  (선택) 탭·모달·상태별 실제 캡처                          ← 인수 근거
    impl.md              (선택) 구현 기록 — 만든 파일과 요건서 대비 이탈
```

**파생 목업과 제출 사이트는 형상 관리에 없다**(`AGENTS.md` §4-5). 새로 클론한 트리에
목업과 `build/deliverables/`가 없는 것이 정상이다. 실제 캡처는 다시 만들기 어려운 인수 근거라
민감정보를 제거한 뒤 정본과 함께 커밋한다.

그래서 **`manual.md` 의 `./mockup.html#…` 링크는 클론 상태에서 열리지 않는다** — 깨진
링크가 아니라 **아직 만들지 않은 것**이며, `/mockup` 을 돌리면 살아난다. `/manual-site`는
그림 키가 같은 실제 PNG가 있으면 목업 대신 쓰고, 없으면 검토본에 목업과 기대 파일명을 표시한다.

## 독자가 다르다

| 문서 | 독자 | 무엇을 적나 | 무엇을 적지 않나 |
|---|---|---|---|
| `requirements.md` | **AI** | *무엇을* — 컬럼 · 조건 · 버튼 · 검증 · 상태 전이 · 영향 테이블 · **테스트 케이스**. **DB 컬럼 · 코드그룹 · 메시지 키는 명시** | *어떻게* — 컴포넌트 · prop · 함수명. 이미 표준인 공통 동작 |
| `manual.md` | **운영자** | 할 수 있는 일을 **순서대로**, **다른 메뉴와의 관계**, 안 될 때 | 테이블 · API · 코드값 · 권한 이름 |
| `mockup.html` | **설계자** | 배치와 **상태별 화면**. 요건서에서 생성된다 | 구현 코드 · 요건서에 없는 규칙 |

같은 사실을 세 번 적지 않는다 — **요건서는 화면의 표시·조작 규칙의 정본**이고, 업무 규칙은 REQ를 참조한다. 목업은 그것이 지켜졌는지 묻고,
메뉴얼은 그것을 사용자의 말로 옮긴다. **목업에만 있는 규칙은 유실된 것으로 친다** — 목업이
다시 생성되기 때문이다. 그래서 테스트 케이스도 요건서가 갖는다.

## 공통 그리드 표현

요건서의 업무 컬럼·명령 표는 [그리드 표준](../../aidd-guide/standard/frontend/grid.md) §2~5 위에 얹는다. 조회조건은 초기화만, 제목·건수는 왼쪽, 조회·행 추가·저장·업무 버튼·도구는 각 그리드 상단 오른쪽이다. 표의 `없음`은 별도 업무 명령/독립 API가 없다는 뜻이며 공통 크롬을 다른 위치에 복제하지 않는다.
시스템 컬럼 순서는 번호 → 다중 선택 체크박스 → 편집 상태 → 업무 컬럼 → 삭제다. 번호는 항상 맨 왼쪽, 삭제는 허용되는 경우에만 맨 오른쪽에 고정하며 단일 선택에는 체크박스가 없다. 편집 그리드는 행 상태와 삭제 표시를 제공하되 권한·요청 상태·참조 보호를 적용한다. 조회 전용, 고정 행의 수정 전용, 신규 전용 식별자 등 실제 소스/요건의 제한을 풀지 않는다. 행 추가 선언이 없으면 추가 동작을 만들지 않는다. 하위 탭의 조회/저장 버튼도 소유 전체 조회/저장 단위를 유지하며 독립 계약을 추정하지 않는다.
목업의 로컬 편집·삭제 표시는 서버 처리 성공을 의미하지 않는다. 신규·수정·삭제·되돌리기와 제출 스냅샷 불변을 같은 공통 동작으로 검수한다.
여부형 스위치와 감사 컬럼 기본 합성은 [공통 컬럼 표준](../../aidd-guide/standard/frontend/grid-columns.md) §2~3을 따른다. 사용자가 업무 컬럼만 지정해도 감사 컬럼을 생략하지 않으며 사용자 명시 제외만 허용한다.

## 새 화면을 시작할 때

```bash
cp aidd-guide/artifact/template/02-requirements.md documents/screen/{페이지경로}/requirements.md
```

순서와 대조 방법은 `/menu-doc` 이 갖는다 — 어느 화면이 문서를 갖췄는지는
`node .claude/skills/menu-doc/screens.mjs` 가 센다.

1. `requirements.md` 를 쓰고 **`/mockup` 으로 목업을 만들어 함께 사용자 승인을 받는다.**
   승인 전 BE/FE/시드 착수 금지 — 승인은 *둘을 함께* 보는 판단이라, 요건서만 승인받고
   목업에서 뒤집히면 그 승인이 무효가 된다(`AGENTS.md` §6.3 ①·②·③).
2. 승인 뒤 구현하면서 `manual.md` 를 만든다(같은 §6.3 ④). **화면이 서기 전의 사용법은
   추측이고, 추측한 메뉴얼은 고칠 곳을 알려 주지 않는다.**
3. `/manual-site`가 좌측 실제 메뉴 트리 + 중앙 본문인
   `build/deliverables/user/index.html`을 만든다. 화면별 HTML을 중복 생성하지 않는다.
   개발 중에는 목업을 쓰고, P6 인수 전에는 그림 키별 실제 PNG를 넣어 `--release`를 통과시킨다.
   일반 사용자에게는 `user --release --standalone`으로 만든 `build/deliverables-user/`만 전달한다.
   이 독립본에는 설계 산출물과 운영·개발 안내가 들어가지 않는다.

## 폴더 이름은 페이지 경로다

**페이지 경로는 소스가 소유한다.** 주소창에 보이는 그것이며, 바꾸는 주체가 개발이다.
`sources/frontend/src/shared/routes/screenRegistry.ts` 의 키를 그대로 미러링한다 — `/log/access` → `documents/screen/admin/system/log/access/`.

- **대상은 `screenRegistry.ts` 의 경로 전부**다. 그 목록은 `menu-tree.yaml` 의 `url` 과 1:1 이며 생성기가 그것을 지킨다 — 한쪽에만 있으면 시드 생성이 막힌다.
- **경로를 바꾸면 폴더도 같은 커밋에서 `git mv` 한다.** `screenRegistry` 의 키를 고치는 것과 폴더를 옮기는 것은 **한 작업**이다. 메뉴 트리(`menu-tree.yaml` 의 위치)는 운영 중에 옮겨질 수 있으므로 폴더 기준이 아니다.
- **`_standalone/{소유모듈}/{화면이름}/`**은 메뉴 없는 공통·독립 화면의 정본 자리다. 같은 SCR 체계를 쓰고 `current_doc`·`sources`와 호출 화면의 `uses_screens`를 연결한다.
- 공통 화면은 입력·반환·검증·취소·오류를 한 번 정의한다. 호출 화면은 여는 위치·전달 조건·결과 매핑·후속 처리만 정의한다. 전용 탭/모달은 부모 문서의 절로 둔다.
- 메뉴가 없다는 사실은 무권한 접근을 뜻하지 않는다. 참조 팝업은 호출 메뉴 권한을, 자기 서비스는 인증·본인 범위를 검사한다. 독립 매뉴얼이 필요 없는 경우 호출 화면 매뉴얼이 사용 순서를 설명한다.
- 상세 연결·테스트 번호 정책은 [spec-schema.md](../../aidd-guide/artifact/spec-schema.md)의 「설계 문서의 책임과 연결」을 따른다.

## 현행화

| 시점 | 해야 하는 것 |
|---|---|
| **소스가 바뀔 때마다** | 그 화면의 셋을 **즉시** 대조한다. 컬럼·버튼·API·조회조건·검증·문구가 달라졌으면 문서를 고친다. **일치하면 고치지 않는다** |
| **페이지 경로가 바뀔 때** | 폴더를 같은 커밋에서 옮긴다(위 「폴더 이름은 페이지 경로다」) |
| **요건서를 고쳤을 때** | `/mockup` 으로 목업을 다시 만든다 — **손으로 맞추지 않는다** |
| **커밋** | 소스와 문서를 **같은 커밋**에 담는다 — 나누면 그 사이의 커밋이 거짓말을 한다 |

**선언된 영향 화면을 훅이 계산한다** — `doc-drift`가 바뀐 파일의 명세 연결과 등록된 페이지를 찾아
가리킨다. **가리키기만 하고 막지 않는다**: *고쳐야 하는가* 는 판단이고, 위 표의 첫 줄대로
일치하면 고치지 않는다. 사슬은
[`aidd-guide/harness/hooks.md`](../../aidd-guide/harness/hooks.md) 가 갖는다.
