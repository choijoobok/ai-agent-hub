## CR-030 — YAML 대상 시스템과 자산 유효성·관리 경고

**접수/판정**: 2026-11-01 사용자가 제시된 권장안의 요구사항·목업·관련 문서 반영을 명시 승인했다. A 지금 설계에 반영(선택), B 후속 보완(기존 기본 연결/설정 잔재 누락·자산 수동 설정 차이 유지), C 기존안 유지(화면과 YAML 소유권 혼재) 중 A를 적용하며 재확인하지 않는다. 결정은 [ADR-038](ADR-038-YAML-대상-시스템과-자산-사용-유효성-분리.md)에 기록한다.

**직접 영향**: REQ-601·604·608·301·303·304·612·404·405·510, FEAT-001·003·004·005·014·021·510, UC-015·018·510, ARCH-028, 대상 시스템/연결과 자산/이력 모델, API-001~005·070·071, SCR-001·003·004·011·019·525 및 상속 이력, 계획 시험. 대상 시스템 삭제 API-006과 기본 연결 계획은 철회한다. 기존 DataSource 직접 CRUD, Portal 계정 매핑·실행 사용자 확인은 유지한다.

**경계/규모**: admin P3는 미승인 상세 보완이고, system의 이미 구현된 대시보드 위젯 슬롯에 admin 공개 경고 소비를 추가하는 변경만 이 CR로 기록한다. 현재 system 슬롯/개인 상태 소스와 DB는 유지하며 수정 설계·목업을 구현 완료로 표시하지 않는다. FEAT 증가 없이 대상 정보·자산/실행 소비·대시보드 연결의 설계 작업 세 묶음이며 제품 슬라이스 재작업 수는 각 소유 G3에서 산정한다. 기존 게이트 상태를 넘기지 않는다.

**이행/복구**: 실제 제품 반영은 후속이다. 기본 연결에 의존하는 기존 데이터가 있으면 그때 해석된 정확 연결 ID로 명시 전환하고 미확인은 보완 대상으로 남긴다. 관리자 표시 재정의·수동 OFF·원본/이력 감사·비밀 비노출을 보존한다. 설계 단계 복구는 관련 정본을 함께 되돌리며 구현 뒤에는 동기화 메타/재정의·명시 연결·사용 설정·경고의 데이터 이행을 새로 검토한다.

**접수/판정**: 2026-10-29 사용자가 공통 계정 등록 요구를 철회하고 각각 사용자 등록·로그인 인증을 분리하도록 명시했다. A 지금 설계에 반영(선택), B 상세 분리를 후속으로 미룸(공통 인증 의존 잔존), C 공통 계정 유지(사용자 철회 요구와 불일치) 중 사용자 요청으로 A를 적용한다. 재확인은 요구하지 않는다.

**결정 근거**: [ADR-034](ADR-034-관리자와-Portal-계정-인증-분리.md). ITO 관리 운영과 일반 업무 이용자의 신원 원천·인증 요구가 다르다. 관리자 겸임자도 별도 Portal 계정을 발급받는다. 공통 Hub 사용자 관리 메뉴·원장을 두지 않는다.

**직접 영향**: REQ-501·510·616, UC-501·023·510, FEAT-501·005·301·305·510, ARCH-011·012·021·022·024·025·050, AUTHZ-090, IF-006·007, SCR-005·501·502 및 Portal의 SCR-113~115 사용 연결, TC-5017~5019와 영역 분리 시험 8건. 관리 처리자·Portal 대상의 식별과 기존 SYS_USER FK·이름 조인의 경계도 대조한다.

**재작업**: SLICE-501·504는 P3/todo를 유지하고 관리자 전용 경계로 재설계한다. 별도 Portal 계정 원장·admin 관리/portal 인증·세션과 통합 전달 계약의 슬라이스 수는 해당 P3에서 산정한다. 역할/메뉴 인가·자기 서비스·알림·UI 상태·이력의 관련 기존 슬라이스는 회귀 범위이며 완료된 기존 구현 전체를 폐기하지 않는다. FEAT +0, Portal 인증 SCR +3, TC +8이며 기존 TC 3건의 기준을 교체한다. G3 기준 대비 증가율은 같은 범위의 FEAT 기준선이 아직 없으므로 임의 산출하지 않는다.

**대체/유지**: CR-027과 ADR-007의 공통 인증·인증 부팅 재사용만 대체한다. 네 모듈·단일 배포/SPA·PostgreSQL 공유·/ 및 /portal/**와 /admin 영역·Portal PC/모바일·SSO/대상 인증과 자체 모드는 유지한다. 현재 관리자 자체 계정·비밀번호·물리 삭제 금지와 기존 데이터도 유지한다.

**게이트**: 전역 G2는 진행 중이며 공통 보안 불변식 변경 재검증을 추가한다. system/admin의 기존 G2 중 계정·인증/인가·진입 부분만 재개방하고 그 외 이전 승인 근거는 보존한다. 변경 방향 승인과 G2/G3 재승인·제품 구현 승인을 구분한다.

**이행/복구**: 현재 공통 계정 통합 소스/저장 구조는 구현되지 않았다. 관리자 원장·비밀번호를 Portal로 복제/자동 연결하지 않고 Portal은 별도 발급·검증한다. 쿠키/세션·현재 주체 캐시·API 수락 전환, 기존 세션 처리와 롤백은 소유 P3에서 명세하고 그 계약 없이 배포하지 않는다. 되돌려도 두 원장을 이메일/ID로 자동 통합하지 않는다. 고객 배포·DB 변경·외부 계정 생성·사용자 공지는 이번 작업에서 실행하지 않았다.

**검증 범위**: 정본·추적성·생성물·HTML 및 독립 의미 검토로 현재 설계의 연결을 확인한다. 양방향 자격증명/세션 거부, 한쪽 상태·회수의 비전파, 외부 주체 충돌/재요청, 같은 문자열 ID의 이력·알림·개인 상태 혼동은 미구현 계약 시험 명세이며 실제 인증/DB/모바일 시험 완료로 세지 않는다.

## CR-029 — admin 관리 변경 이력 저장·조회 공통화

**범위**: 2026-10-30 사용자 정정으로 admin 모듈만 적용한다. system은 새 변경 이력 저장·메뉴·이번 목업 재정리에서 제외한다. system에 잘못 추가한 적용 계획과 슬라이스 재개방은 철회한다.

**문제와 결정**: 화면마다 다른 이력 표시에 대해 A 원본명_HIST 동형 복사·전체 구성·별도 상속 조회(선택), B 후속 이행, C 기존 표시 유지 중 사용자 요청으로 A를 채택했다. 단일 그리드는 성공한 변경 행 전체, 마스터·탭은 전체 소유 구성으로 저장한다. 세부 규칙은 REQ-601.change_history·approval_storage와 ADR-035가 소유한다.

**직접 영향**: admin 소유 기능/화면과 _SNP/_HIST 저장·조회 계약, 공통 검증·수락 시험이다. 현재 적용본/요청/과거 적용본, BASE_REVISION/APPLIED_REVISION과 마스터 단위 증가·원자 반영을 구분한다. 자식 이력의 시각은 부모를 참조하고 실행 중 과거 리비전은 HIST 참조 보호를 따른다.

**재작업**: admin 메뉴53개(원 화면37개·상속 이력16개)의 요건/목업과 전체 흐름을 먼저 검토한다. 메뉴별 소유·상속 연결은 60-screens의 menu_tree와 각 화면 history_view를 따른다. 상속 이력의 독립 요건서/목업은 작성하지 않는다. 화면 합의 후 저장/조회 물리·공개 계약·시험과 관련 슬라이스를 상세화한다.

**이행/복구**: admin 이력 구현 때 원본·SNP·HIST 타입/키·세트 원자성·권한·재수신을 검증한다. 현재 원본 삭제에 이력을 연쇄 삭제하지 않으며 과거 미기록 값을 소급 생성하지 않는다. 실제 배포 이행/복구는 소유 구현 범위에서 정한다.

**게이트/규모**: admin의 새 물리 상세는 화면 합의 후 G3 전에 확정한다. 방향 합의·목업 검토와 G3/구현 승인은 구분한다. 기존 7영역은 화면 합의 뒤 기술 설계 담당 묶음으로 유지한다. 당시 CR-029 자체로는 system의 별도 변경을 철회하지 않았다. CR-026은 위 2026-10-30 후속 결정으로 철회했고 CR-028의 별도 계정 계약은 유지한다.
