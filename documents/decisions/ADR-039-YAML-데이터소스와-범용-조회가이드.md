# ADR-039 — YAML 데이터소스와 범용 데이터 조회 가이드

| 항목 | 내용 |
|---|---|
| 일자·상태 | 2026-11-01 · accepted · 사용자가 권장안의 요구·관련 문서 반영을 승인하고 가이드를 범용화함 |
| 등급 | High — 연결 원천과 관리 이력·LLM의 동적 데이터 확인 경계를 변경 |
| 범위 | REQ-603·301, FEAT-002·003, SCR-002·003·525, CR-031. 제품 구현·게이트 승인은 별도 |

## 1. 맥락

데이터소스를 화면에서 등록·삭제하거나 연결 참조를 정정하면 배포 YAML과 관리 DB의 소유가 겹친다. 기존 코드 조회 정의의 SQL·정확 버전·파라미터·결과 대응은 사용자가 요청한 조회 방법 안내보다 복잡하다. 실제 코드값을 컬럼 설명에 고정하면 원천 변경을 따라가지 못한다.

## 2. 대안

- 화면 데이터소스 CRUD와 구조화 코드 조회 정의 유지: 기계 검증·정확 바인딩을 제공하지만 별도 SQL 자산·파라미터·버전/상태 관리가 필요하다.
- **YAML 연결 원천과 수동 메타·범용 데이터 조회 가이드(선택)**: 접속과 업무 보완의 소유를 나누고 여러 제목/설명으로 조회 방법을 안내한다. 동적 값은 권한 있는 원천에서 실제 확인한다.
- 컬럼 설명에 현재 코드값을 열거: 단순하지만 원천 변경·추가를 반영하기 어려워 선택하지 않는다. 고정된 INLINE 값 도메인은 별개로 유지한다.

## 3. 결정

Hub DB의 `spring.datasource`와 별개인 `app.external-datasources.{dataSourceKey}`를 기동 시 전체 검증하고 안정 키로 메타를 추가·갱신한다. YAML 키·별칭·접속/비밀 정의와 JDBC URL로 판별한 DBMS 종류는 읽기 전용이다. DBMS 버전·파서·업무 메타·그룹·가이드는 수동 관리하며 재기동이 덮지 않는다.

하단은 접근 가능 사용자 그룹·사용 스키마 카탈로그·컬럼 불일치·인덱스 불일치·데이터 조회 가이드 다섯 탭이다. 가이드는 데이터소스별 여러 제목·상세 설명과 감사 넷으로 관리한다. 메타·그룹·가이드는 같은 전체 저장/이력 세트이며 가이드 독립 SQL 정의·버전·검수/활성화는 없다.

실제 선택 카탈로그의 데이터소스별 가이드를 중복 제거해 제공하고, 필요한 코드·참조값은 현재 권한 안에서 읽어 확인한 뒤 업무 SQL에 사용한다. 권한 적용 가이드는 서버 인가·신원·행 필터·마스킹·SQL 통제의 대체물이 아니다. 실패·빈 결과·미확정 값은 추정 실행하지 않는다.

YAML에서 제거된 데이터소스는 참조/이력을 보존하고 서버 불일치 배지·공통 연동 경고·새 업무 호출 차단으로 드러낸다. 실제 검증 가능한 관리 보완과 업무 호출 가능 상태는 분리한다.

## 4. 포기한 것과 검증

구조화 조회 정의/typed 바인딩의 자동 검증 편의와 자유서술만으로 선행 조회 준수를 보장한다는 주장을 포기한다. 가이드 길이/프롬프트 예산·공개 조회/도구와 턴 근거 저장은 소유 상세 설계/제품 시험에서 완성한다. 변경된 가이드는 전체 관리 이력, 사용한 본문/리비전·조회 SQL/결과/시각은 보호된 턴 근거로 구분한다.

## 5. 되돌리기

구조화 실행이 필요해지면 별도 사용자 결정으로 모델·카탈로그 참조·관리 화면·공개 계약을 다시 설계한다. 자유서술 본문을 자동 SQL/파라미터 정의로 변환하지 않는다. 아직 미구현 단계라 현재 재작업은 문서·목업이며 구현 후에는 데이터/참조 이행 비용이 커진다.
