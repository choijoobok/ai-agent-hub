## 1. 맥락

화면별 이력 탭·JSON 스냅샷 모달·내용 버전 조회의 표시가 달라 당시 구성을 일관되게 확인하기 어렵다.
사용자는 두 화면 유형의 저장 및 원 화면을 재사용하는 별도 이력 메뉴를 명시 요청했다.
단일 그리드는 성공한 변경 행의 전체 컬럼으로 답변했고 원본명 뒤 `_HIST`·서로게이트 PK·세트 동일 시각을 지정했다.

## 2. 대안

| 대안 | 장점 | 대가 |
|---|---|---|
| A. 동형 이력 테이블·전체 세트 복사·원 화면 재사용 | 타입/검색/탭 구성이 같고 이력 번호로 당시 전체 재현 | 복사량·테이블 수 증가, 원 스키마 변경 때 이력도 현행화 |
| B. 전체 JSON 한 열과 스냅샷 뷰어 유지 | 이력 테이블이 적음 | 화면별 뷰어·검색 계약과 해석이 다름 |
| C. 변경 필드만 저장하고 조회 때 재조립 | 저장량이 작음 | 전체 재현과 삭제/보존/버전 경계가 복잡 |

## 3. 사용자 결정

2026-10-30 사용자 요청과 답변으로 A를 채택했다. 제품 규칙은 [REQ-601.change_history](../spec/10-requirements/011-reference-integration.yaml),
재사용 절차는 [공통 이력 패턴](../../aidd-guide/artifact/screen/overlay/history-pattern.md)이 갖는다.

- 단일 그리드는 성공한 변경 행 전체를 추가한다. 전체 테이블/현재 검색 페이지를 복사하지 않는다.
- 마스터·하단 탭은 어느 소유 영역을 저장해도 마스터와 모든 소유 관리 자식의 당시 구성을 한 이력 번호로 복사한다.
- 테이블명은 원본명 + `_HIST`, 모든 이력 테이블 PK는 시퀀스 방식의 `HIST_ID` 단일 키다. `HISTORY_NO`는 별도 세트 연결 키다.
- 원본 `REG_DTM`·`MOD_DTM`은 그대로 복사한다. `HIST_DTM`은 이력 저장일시이며 주 저장 처리에서 한 번 확정해 마스터 이력에만 저장한다. 자식은 HISTORY_NO로 해당 시각을 참조한다.
- 조회는 별도 이력 메뉴에서 원 관리 화면을 읽기 전용으로 상속한다. 상단 변경 요약과 이력 저장일시 범위만 더하며 독립 이력 목업은 만들지 않는다.
- 요약은 서버가 대조한 `기준 정보`와 실제 변경 탭명을 정해진 순서로 열거한다. 현재값/이력/성공 결과는 원자적으로 확정하고 동일 명령 재전송은 같은 이력을 반환한다.
- 승인 대상은 승인 후 실제 반영 성공 때만 `_HIST`를 저장한다. 초안·요청 대기·반려/취소·반영 실패는 운영 이력을 만들지 않으며 반려 요청·제출본/버전·판정 근거는 승인 원장에 보존하고 새 요청과 연결한다.

## 4. 경계

2026-10-30 후속 검토·수정 요청에 따라 적용본/요청/이력을 분리한다. 원본별 `_SNP`와 대상별 기준/결과 리비전, 마스터 단위 증가·원자 반영은 REQ-601.approval_storage를 따른다. 과거 적용 내용은 `_HIST`가 제공하며 실행/자산 참조 중인 세트는 파기하지 않는다. 별도 불변 내용 저장소를 병행하는 대안은 같은 내용을 이중 보존·조회하는 비용 때문에 채택하지 않았다.
타 화면 소유 사용처·실시간 관측·원천 샘플·세션·캐시·실행 로그는 복사하지 않는다. 과거 조회에 현재값을 합성하지 않는다.
비밀 원문·암호문·비밀번호 해시·토큰을 넣지 않는다. 원 등록/수정일시와 이력 저장일시는 목적이 다르다.
이력 저장일시는 커밋 완료 시각이 아니라 해당 세트의 단일 저장 기준시각이다.

## 5. 비용과 되돌리기

미구현 admin 이력은 새 계약으로 교체한다. 이력 자식·키/제약·조회 API·권한·시험을 함께 현행화한다.
사용자 정정으로 적용 범위를 admin 모듈로 한정한다. system 모듈의 새 변경 이력 도입·영향 설계 계획은 철회하며 기존 로그/업무 이력 계약을 유지한다.
원본/이력 스키마를 함께 관리해야 하며 과거 이력을 추측해 소급 생성하지 않는다.
되돌리려면 저장·조회·메뉴·시험·데이터 형식 이행이 필요하므로 실제 이력 적재 이후 비용이 커진다.

## 6. 승인 범위

저장/조회 패턴·명명·키/시각 원칙의 명시 결정이다. G3(설계 승인 게이트) 재승인이나 제품 구현 승인을 대신하지 않는다.
일반 사용 로그·비밀번호 재사용 방지·배치 실행 이력은 구성 변경 스냅샷과 구분한다.

2026-11-05 후속: SCR-048의 복원은 REQ-303.restore_contract에 따라 원 지식 편집으로 인계하는 진입만 허용한다. 이력 읽기 전용·불변 복사 결정은 유지하고 실제 현재값 변경은 새 저장/새 리비전으로 남긴다.
