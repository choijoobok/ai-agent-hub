# ADR-040 — 연결 설정 판정 사전 저장과 비밀 제외 지문

| 항목 | 내용 |
|---|---|
| 일자·상태 | 2026-11-03 · accepted · 사용자가 기동 사전 판정/저장과 비밀번호 등 제외·나머지 권장안의 반영을 승인 |
| 등급 | Medium — 판정 생산·저장·소비 계약과 화면을 함께 변경하며 제품은 아직 미구현 |
| 범위 | REQ-601·603·604·608, ARCH-028·030, FEAT-001·002·004, SCR-001·002·004와 상속 이력 |

## 1. 맥락

현재 설계의 화면 진단은 현재 로드 정의를 대조한 비저장 투영이었다. 사용자는 기동 때 불일치를 판정해 DB에 저장하고 화면과 실제 사용 차단이 그 결과를 재사용하도록 요청했다. 업무 API 목록의 진단 세 컬럼도 선택 연결의 서버 설정 불일치 하나로 정리한다.

대상 시스템 상단은 자식 전체의 집계이므로 다른 연결 하나의 오류를 API에 전파하면 정상 연결까지 차단한다. 설정 버전 없는 정상값은 재기동/순차 배포에서 과거 판정을 잘못 재사용할 수 있다.

## 2. 고려한 대안

- A — 조회/사용 때마다 전체 설정과 등록 메타를 대조: 별도 판정 저장이 적지만 목록 검색·실행이 반복 대조에 의존하고 같은 상태의 재사용 경계가 분산된다.
- B — 기동/비교 대상 변경 때 판정하고 적용 설정 버전별 저장 결과를 재사용(선택): 목록·후보·실제 사용이 같은 근거를 사용한다. 동기화 원자성·버전별 결과·기동 준비 구분이 필요하다.
- C — 대상마다 단일 불일치 값만 저장: 단순하지만 서로 다른 설정으로 동작하는 노드가 값을 덮거나 오래된 정상값을 현재값으로 사용할 수 있어 선택하지 않는다.

## 3. 결정

REQ-601.configuration_diagnosis를 정본으로 기동 사전 판정과 버전별 저장·재사용을 적용한다. 서비스가 명시한 비교 속성/변환에서 비밀번호 등 비밀값을 제외하고, 최종 비밀 없는 연결 설정의 정규 지문을 적용 설정 버전으로 사용한다.

## 4. 근거

판정 생산과 소비를 분리하면 일반 조회가 상태를 수정하지 않고 실행도 전체 YAML/DB를 재대조하지 않는다. 정확 연결의 판정을 참조하므로 API별 사본 갱신이나 정상 형제 연결의 차단이 필요 없다. 정상 판정도 명시 저장해 경고 없음과 검증 성공을 구분한다.

기존 YAML 기술 정본·관리자 표시 보완·수동 사용의 독립성은 ADR-038·039를 유지한다. 해당 결정 전체를 대체하지 않으며 현재 비저장 진단의 생산/저장 방식을 보완한다. 새 system 환경설정 버전 원장이나 system 구현 변경을 추가하지 않는다.

## 5. 포기한 것

비밀값만 바뀌었는지는 적용 설정 버전으로 구분하지 않는다. 같은 지문을 자격증명 동일성·인증 성공·업무 승인 재사용의 근거로 쓰지 않는다. 비밀 해석·현재 실행 주체/목적지·실제 연결 준비는 기존 기동/호출 통제를 유지한다.

현재 관리 메타는 배포 제어가 선택한 한 세대만 갱신하고, 판정 당시 DB 메타의 필요한 비밀 없는 비교 기준을 버전별로 고정한다. 구 노드가 현재 메타를 옛값으로 다시 쓰지 않으며 비호환 변경은 기존 배출 후 전환을 따른다.

한 개 전역 정상 플래그만 읽는 단순함은 포기한다. 자기 설정 버전의 판정과 해당 기동의 준비를 확인해야 한다. 버전별 판정 저장은 원문 주소·비밀을 DB에 복사하는 근거가 아니다.

## 6. 되돌리기

구현 전에는 요구·연결 계약·논리 모델·화면·계획 시험을 함께 수정한다. 구현 후에는 ENT-098 소비를 다시 계산 방식으로 이행하고 진행/역사 참조와 경고 사건을 보존해야 한다. 빈번한 동적 설정 변경으로 기동/명시 동기화 경계가 성립하지 않거나 버전별 판정 유지 비용이 요구를 넘으면 재검토한다.

## 7. 영향과 후속

ENT-098(연결 설정 판정)과 TRM-290을 기존 도메인·용어 정본에 정의한다. 정상/불일치/미상과 비밀 제외·재기동 실패·서로 다른 설정 노드·정상 형제 연결·API 참조 변경을 계획 시험으로 검수한다.

정확 YAML 바인딩과 물리 컬럼별 비교표, 정규화·안전한 기술값 투영, 판정 저장/기동 준비의 원자성, 배포 버전 선택·보존/정리는 소유 상세 설계에서 완성한다. 제품 소스·DB 적용·G3 게이트 승인은 이번 결정에 포함하지 않는다.
