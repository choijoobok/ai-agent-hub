## 맥락

선행 admin 19화면이 사용하는 인증 공통부와 FEAT-126 디버그가 integration 한 게이트에 묶여 있었다. 관리자 비활성화는 현행 저장이 세션 무효화를 보장하지 않아 재로그인·dirty/날짜 재계산 전까지 접근이 남을 수 있다. Portal 서버 인증은 미구현이며 제품 인증 화면은 후행이다. 사용자는 OQ-036·037·038의 권장안 A를 모두 명시 선택했다. 이 결정은 단계 게이트 승인이 아니다.

## 대안과 결정

1. **승인 단위 A**: integration에는 FEAT-301~305와 태그 면제 공통 기반을 남기고, FEAT-126/SCR-112와 응답 계약 소비·호환성 시험은 integration-debug로 분리한다. B는 둘의 전체 상세 설계를 마친 뒤 같은 G3를 받는 안으로 공통 개발이 디버그 설계를 기다려 선택하지 않았다. 제품 모듈은 네 개 그대로이며 새 작업흐름의 게이트는 자동 승인하지 않는다.
2. **비활성화 A**: 관리자 비활성화 커밋 뒤 시작한 다음 보호 요청부터 차단한다. 진행 중 저장은 권한 회수와 같은 보호 경계에서 선후를 정한다. 먼저 확정된 저장이나 전송된 외부 효과를 소급 취소하지 않는다. B는 현행 지연 반영과 별도 강제 종료를 유지하는 안으로 운영 간극 때문에 선택하지 않았다. 이미 구현한 system의 의미 변경은 CR-033으로 관리한다.
3. **인증 개발 순서 A**: Portal LOCAL 실제 인증과 외부 신원 수락/실패 계약·시험 대역을 먼저 준비한다. 실제 고객사 SSO 어댑터 검증은 연동 정보 확보 후 별도 슬라이스로 수행한다. B는 실SSO까지 선행 완료 조건으로 삼는 안으로 고객 환경 대기를 늘려 선택하지 않았다. SSO 기본·LOCAL 병행 제품 요구는 유지하며 외부 인증 실패를 LOCAL로 자동 우회하지 않는다. 미검증 SSO를 완료로 집계하지 않는다.

## 상세 설계 근거와 대가

정본은 FEAT-301의 인증 선행 계약이다. 요청별 현재 계정 검사와 관리 쓰기의 authoritative 권한 판정을 도입하므로 기존 캐시만 사용하는 경로보다 DB 비용이 든다. 세션 dirty 갱신은 UI 갱신을 돕지만 보안 보장의 유일한 근거가 아니다. 초기 권한 보호는 PostgreSQL 트랜잭션 advisory lock의 공유/배타 모드로 단순화한다. 동일 트랜잭션의 커밋/롤백까지 유지되므로 임대 만료 뒤 원 작업이 살아 있는 경합을 만들지 않는다. 기존 SYS_DATA_LOCK의 만료형 작업 락과 역할을 구분한다. 근거: [PostgreSQL 트랜잭션 advisory lock](https://www.postgresql.org/docs/18/explicit-locking.html#ADVISORY-LOCKS).

공유 키는 보호 요청/관리 저장, 배타 키는 권한·계정 상태 변경이 사용한다. 처음부터 배타 변경인 요청은 공유→배타 승격을 하지 않는다. 전역 키의 처리량 한계는 실제 구현에서 계측하며 같은 경합 반례를 통과할 때만 세분한다. 다른 모듈 Entity/Repository 직접 참조와 잠금 중 네트워크 대기는 허용하지 않는다.

## 되돌리기와 영향

작업흐름 재통합은 기능·화면·시험·슬라이스 소유를 함께 이동해야 하므로 중간 비용이다. 비활성화 시점 변경은 관리자 운영 절차·REQ-501·UC-501·SCR-501·인증/인가 시험을 재검토하는 높은 비용이다. 자체/외부 인증 개발 순서 변경은 중간 비용이며 등록 계정이나 모드를 자동 전환하지 않는다.

ARCH-019/021/050, FEAT-301/126/501/502/503/005/006/040, 시스템 사용자 화면, 선행 계약·NFR 시험과 개발 계획을 갱신한다. Portal 세션 물리 저장/배포 설정과 외부 어댑터의 정확 프로토콜은 integration 소유 G3/후속 고객 연동 설계에서 검증한다. 이번 결정으로 admin·system·integration 또는 integration-debug의 게이트를 통과시키지 않는다.

## 2026-11-10 세부 결정 — 전환과 수동 배치

사용자는 전환·복구 때 관리자 재로그인을 허용하고 system 영향 G2를 명시 승인했다. 승인 상태와 검증은 project.state.yaml이 소유한다.

수동 배치 접수와 계정 중지 경합은 A(채택): 이미 접수·확정된 배치를 계속 처리하고 새 실행·중단 요청부터 현재 권한을 검사한다. 다른 권한 있는 관리자의 중단은 가능하다. B는 계정 중지 시 접수된 배치에도 중단을 요청하는 안이며, 요청자 연결·진행/대기 작업 탐색·부분 완료 정책이 추가되어 채택하지 않았다. 포기한 것은 계정 중지 한 번으로 과거 접수 작업까지 정지시키는 편의이며 변경 비용은 중간이다. 상세 확정점/인계/실패는 FEAT-508.manual_admission, TC-5086~5089가 소유한다. 이 정책 결정은 system G3와 배치 변경 화면 검수의 승인을 대신하지 않는다.
