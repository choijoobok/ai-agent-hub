# ADR-037 — 관리자 직접 변경과 업무 검토 경계

| 항목 | 내용 |
|---|---|
| 일자·상태 | 2026-10-31 · accepted · 사용자 명시 결정 |
| 등급 | High — 관리자 간 승인·업무 의미 영향 검토를 철회한다 |
| 대체 범위 | ADR-018·023·036의 관리자 간 권한/그룹·자산 변경 승인/전결 전부와 지식 영향 검토 제품 절차. Portal 사용자 신청 승인·실제 실행 사용자 확인·기술 검증은 유지 |

## 1. 맥락

관리 화면에서 자산 매핑이나 사용자 그룹 소속을 추가할 때도 요청·검토·승인을 반복하면 소수의 업무 전문가와 관리자가 같은 변경을 여러 단계로 처리해야 한다.
사용자는 관리자 간 모든 권한·자산 변경 승인 요구를 전면 철회하고, 소수의 변경 권한자가 직접 관리하되 변경 이력은 유지하도록 명시 결정했다.
이어 지식의 업무 의미 영향 검토는 제품 내부의 작업 배정/판단/종결 기능보다 운영·유지보수 조직의 자체 프로세스로 맡기도록 결정했다.

## 2. 대안

- 기존 승인과 영향 검토 유지: 사전 인적 확인 근거를 갖지만 반복 요청·검토·승인과 영향 작업 운영 비용이 크다.
- 승인 사용 설정만 해제: 절차 화면·요청 원장·후보 상태와 전결 기록이 남아 복잡성이 유지된다.
- 현재 변경 권한에 따른 직접 저장과 이력(선택): 관리자 승인/전결과 업무 의미 영향 검토 제품 절차를 철회하고, 최소 권한·기술 검증·전후 전체 이력으로 운영한다.

## 3. 결정

제품 사실은 [REQ-601](../spec/10-requirements/011-reference-integration.yaml)의 `direct_management`·`management_storage`와 [REQ-305·306](../spec/10-requirements/007-knowledge-catalog.yaml)이 정본이다.
관리자 사용자가 다른 관리자에게 요청하던 자산 등록/수정·접근 매핑·노출·중지/삭제와 Portal 사용자의 그룹 소속 추가/재부여/중지는 모두 해당 현재 변경 권한자의 직접 저장이다.
별도 관리자 요청·기술 검토 완료·최종 승인/반려·전결 단계와 승인 사용 설정, 새 요청 원장/SNP를 만들지 않는다.
변경 전후 전체 소유 구성·기대/결과 리비전·실제 행위자/시각·사유·검증 근거·멱등 결과와 HIST는 원 소유 성공 단위로 함께 확정한다.

지식 업무 의미 영향의 본문 자동 수집·판단/보완 요구·작업 배정/완료는 제품 요구에서 철회한다.
안정 ID의 현재 사용처·참조 경로 조회, SQL/API 기술 계약·필수 참조 무결성·현재 권한 검증과 실제 변경 이력은 유지한다.
업무 의미 적합성의 검토 책임은 고객사의 운영/유지보수 조직 자체 프로세스에 둔다.

Portal 사용자의 쿼터 승급·추가 토큰과 RM-P3 자동화 활성화 신청은 해당 관리자 승인 경로를 유지한다.
실제 상태 변경 실행의 사용자 명시 확인·고객사 외부 API 공동 오픈·코드 검수/배포 통제와 프로젝트 단계 게이트는 각각의 기존 소유 계약을 유지한다.

## 4. 근거와 포기한 것

사전 다른 관리자의 승인과 제품 내부 업무 의미 영향 판단/완료 원장을 포기하고 관리 절차와 구현 범위를 줄인다.
대신 소수의 업무 전문가/관리자에게만 대상별 변경 권한을 부여하고, 서버의 현재 메뉴/액션 권한·기대 버전·기술 검증·원자 이력으로 잘못된 변경을 추적한다.
조회·변경·반출 권한은 분리하며 역할명이나 화면 버튼 표시만으로 변경을 허용하지 않는다.

## 5. 과거 근거와 되돌리기

과거 요청·제출/검토·승인/반려 근거와 성공한 적용 이력은 보존한다. 과거 미반영 요청은 자동 승인/직접 저장으로 변환하지 않고 늦은 승인 콜백도 현재값을 변경하지 못한다.
현재는 미구현 설계이므로 철회한 현행 승인 전용 스펙은 Git 이력에 보존한다. 제품 DB의 기존 행을 삭제하거나 과거 승인 데이터를 파기하는 작업은 아니다.
다시 도입하려면 요구·화면/상태·요청 원장·공개 계약·테스트를 함께 재설계해야 하므로 구현 뒤 되돌리기 비용이 높다.

## 6. 영향·후속

REQ-601·103·301~306·605·607~609·612·614·616, 관리자 공통/자산·권한 유즈케이스·기능·화면, 승인 저장/공개 계약과 계획 테스트를 현행화한다.
지식 영향 검토의 REQ-307·UC-013·FEAT-036·SCR-034와 관리자 요청 전용 화면·원장/SNP는 철회하고 번호를 재사용하지 않는다.
현재 admin G3 전 상세 설계 변경이며 제품 구현·화면 최종 합의·게이트 승인을 대신하지 않는다.
