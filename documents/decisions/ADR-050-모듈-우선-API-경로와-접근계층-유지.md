status: accepted

사용자가 public/common/service의 의미를 확인한 뒤 A를 선택했다. API는 `/api/{모듈}/{계층}/{업무}/{동작}`으로 통일한다. 이후 integration 공통 경로 영향 G3도 명시 승인됐으며 상태/일자는 `project.state.yaml`을 따른다. 이 기록은 명명 정책과 이유이고 system 소비 영향 G3나 실제 구현 수락을 대신하지 않는다. 목표와 현재 구현의 구별, 정확 전환/복구는 `50-api`의 `path/current_path`와 `FEAT-301.api_path_transition`이 소유한다.

모듈을 앞에 두면 호출 경로에서 책임을 먼저 알 수 있다. `system`과 `sys`를 섞지 않고 현재 제품 모듈명을 사용한다. 페이지의 `/admin`은 관리자 화면 영역이며 API의 `system/admin`은 서버 기능 소유이므로 둘이 항상 같은 첫 단어일 필요는 없다. 페이지 경로 결정은 CR-037·ARCH-021을 따른다.

A는 기존 접근 계층을 유지한다. public은 정확히 허용한 인증 전/원천 검증 기능, common은 해당 영역의 공통·본인 범위 기능, service는 업무 권한을 추가 확인하는 기능이다. 경로 문자열만으로 인증/권한을 대체하지 않는다. 외부 인사 수신 integration과 local 참조 sample은 기존 기술 namespace이며 제품 모듈을 늘리지 않는다.

B는 계층을 제거하고 접근 정책을 별도 메타데이터로 선언하는 안이었다. URL은 짧아지지만 현재 보안 분류·시드 생산을 새 메타데이터 중심으로 바꿔야 한다. C는 현재 계층 우선 순서를 유지하는 안으로 변경 비용은 적지만 모듈별 경로 통일 요구를 만족하지 못한다. A는 한 마디를 유지하는 대신 접근 구분과 생성 모델을 보존한다.

현재 개발 단계의 구주소 호환 미유지 원칙을 적용한다. URL을 키로 쓰는 API/메뉴 연결과 모든 호출자를 같은 전환에서 바꾸고 검증한다. 기존 권한 연결을 버리고 CSV만 다시 적재하는 방식은 쓰지 않는다. 실제 고객 배포 뒤에 이 결정을 무조건 재사용하지 않는다. 저장소/회수 프로토콜과 기존 완료 검증은 보존하고 경로 영향만 재검토한다.
