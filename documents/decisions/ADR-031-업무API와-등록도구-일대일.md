## 1. 맥락

REQ-608의 API 계약과 REQ-612의 도구 등록은 별도 관리 승인 설정을 갖는다.
지식은 API를 연결하므로 같은 API에 여러 도구를 두면 어떤 노출·그룹 설정과 도구를
선택할지 추가 규칙이 필요하다. 업무별 질문·사용 방법은 이미 지식 매핑이 소유한다.
제품 규칙의 정본은 [REQ-612.api_tool_mapping](../spec/10-requirements/013-reference-operations.yaml)이다.

## 2. 대안

| 대안 | 장점 | 대가 |
|---|---|---|
| A. 업무 API 하나당 등록 도구 하나 | 지식 API 링크에서 호출할 도구가 명확하고 노출/그룹 설정 중복 방지 | 같은 API를 여러 도구 이름·설정으로 나누어 노출하지 못함 |
| B. 같은 API에 여러 등록 도구 허용 | 용도별 도구 이름·노출 설정을 별도로 구성 가능 | 지식에 추가 도구 선택 기준과 중복 노출·그룹 판정·검수 부담 발생 |

## 3. 결정과 근거

사용자가 2026-10-28 “API 하나당 도구 하나”를 선택했다.
업무별 용도·질문·후속 절차의 차이는 지식의 API 연결 설명에 둔다.
도구가 아직 없는 API 등록 단계와 동일 도구의 여러 내용 리비전은 중복 등록으로 보지 않는다.
신규 후보·세트·탭을 달리해도 동일 API의 별도 도구를 만들 수 없도록 서버에서 검증한다.

## 4. 포기한 것

하나의 API를 여러 도구로 포장하는 기능을 두지 않는다.
API와 도구의 독립 관리 설정·그룹/노출 조건·불변 참조 판은 유지한다.
자동 도구 생성이나 API 승인만으로 도구를 노출하는 동작은 이 결정에 포함되지 않는다.
내부 서비스 기반 커스텀 도구와 구현의 대응 수를 이 결정으로 제한하지 않는다.

## 5. 되돌리기

구현 후 비용은 높다. 다중 도구를 허용하려면 ENT-011·015·016의 유일성,
FEAT-004·021 및 지식의 API 연결에서 도구를 선택하는 계약·화면·시험을 바꿔야 한다.
같은 API를 서로 다른 독립 도구로 노출해야 하는 실제 운영 사례가 나오면 재검토한다.

## 6. 영향과 후속

REQ-612·FEAT-004·021·UC-019·ENT-011·015·016·SCR-004·019를 연결한다.
중복 후보 경합, 폐지 후 재등록/복원, API 참조 변경과 과거 리비전 보존의 물리 계약을 검증한다.
물리 설계·제품 구현·G3 승인은 별도다.
