# ADR-036 — 신원 아이디는 직접 설정하고 그룹 추가만 승인한다

> superseded_by: [ADR-037 — 관리자 직접 변경과 업무 검토 경계](ADR-037-관리자-직접변경과-업무검토-경계.md). 관리자 간 승인/전결은 전부 철회하며 아래 내용은 당시 결정 기록이다.


| 항목 | 내용 |
|---|---|
| 일자·상태 | 2026-10-31 · accepted · 사용자 명시 결정 |
| 등급 | High — 대상 신원 변경의 승인 경계를 분리한다 |
| 대체 범위 | ADR-018·ADR-023의 신원 매핑 승인/전결 범위만 대체. 그룹 추가·회수와 다른 자산 승인은 유지 |

## 1. 맥락

Portal 사용자 관리에서 기준정보의 데이터소스/대상 시스템 목록을 불러와 필요한 대상 사용자 아이디를 설정한다.
사용자는 신원 아이디까지 별도 승인을 요구하면 운영 절차가 복잡해진다며 그룹 추가만 승인하고 신원은 승인 없이 설정하도록 명시 결정했다.

## 2. 대안

- 기존 방식 유지: 신원 신규/교체도 요청·승인 또는 설정에 따른 전결로 처리한다. 단계와 후보 관리 비용이 남는다.
- 신원 직접 설정과 그룹 승인 분리(선택): 신원 신규/교체/중지는 승인·전결 없이 직접 저장한다. 그룹 추가만 기존 승인 정책을 따른다.

## 3. 결정

제품 사실은 [REQ-609.identity_management](../spec/10-requirements/012-reference-business.yaml)와 [REQ-616.screen_contract](../spec/10-requirements/013-reference-operations.yaml)가 정본이다.
Portal 두 신원 탭은 기준정보 후보와 현재 매핑을 함께 조회하고 필요한 행만 설정한다.
신원 저장은 현재 변경 권한·대상/아이디 근거·기대 버전을 검증하고 현재값과 변경 전후 감사를 함께 반영한다. 별도 승인/전결 기록을 만들지 않는다.
그룹 추가/재부여 요청은 SCR-037에서 기존 승인 설정에 따라 처리하며 그룹 회수는 승인 없이 한다.

## 4. 근거와 포기한 것

사용자의 명시 결정으로 신원 변경의 사전 승인 단계를 없애 운영 부담을 줄인다.
대신 오인 아이디 연결을 별도 승인자가 사전에 확인하는 통제를 포기한다. 현재 변경 권한·아이디 연결 근거·감사와 그룹/자산/행 스코프·대상 자체 권한 검사는 유지한다.

## 5. 되돌리기

다시 신원 승인을 도입하려면 Portal 입력/후보·승인 메뉴·상태/이력·공개 계약을 함께 수정해야 하므로 구현 후 비용이 높다.
과거 신원 요청은 이력으로 보존하고 새 직접 설정이나 그룹 승인으로 자동 전환하지 않으며 늦은 승인으로 현재값을 변경하지 않는다.

## 6. 영향·후속

REQ-601·609·616, REQ-103, ARCH-050·029, PRN-06, UC-024, FEAT-005·038, SCR-005·037, PRC-13의 신원/그룹 경계를 갱신한다.
현재 admin 작업흐름 G3 전의 설계 변경이며 제품 구현·화면/게이트 승인과 구분한다.
