## 1. 맥락

대상 시스템 연결은 YAML이 소유하고 관리 화면은 이름·설명만 보완한다. 일반 HTTP JSON 호출과 SAP OData 호출은 인증·CSRF 토큰·쿠키·쿼리 표현·응답 처리에 차이가 있다. 이 차이를 업무 API마다 중복 설정하면 화면과 실행 계약이 복잡해진다. 현재 업무 API 관리(SLICE-004)는 구현 전이며, ENT-011 공통 마스터와 ENT-012 공통 내용의 물리 명세가 있다. SAP 운영 연동 요구·버전·실제 서비스 계약은 아직 확보하지 않았다.

사용자는 2026-11-14 B안(연결별 호출 유틸 지정 구조를 먼저 반영하고 SAP OData 지원은 후속으로 유예)을 승인했다. 별도 SAP 메뉴를 만들더라도 공통 마스터를 공유하고 종류별 자식으로 확장하는 방향 및 향후 참고 문서 보존을 요청했다. 이는 SAP 실행·전용 메뉴·전체 OData 기능의 구현 승인이 아니다.

## 2. 고려한 대안

| 대안 | 장점 | 비용·포기한 것 |
|---|---|---|
| A. OData 지원까지 지금 통합 | 즉시 같은 관리 체계에서 정의·실행 가능 | 실제 고객 계약 없이 버전별 조건식·자료형·배치·편집 화면을 선행 설계해야 한다. 현재 범위가 크게 늘어난다. |
| B. 공통 호출 계약·연결별 빈 선택만 지금, SAP 구현은 후속 | 현재 REST JSON 범위를 유지하며 후속 구현을 연결할 수 있다 | 지금 SAP 지원을 보장하지 않는다. 후속의 실행·화면·고객 연동 검증이 필요하다. |
| C. Hub 직접 OData 지원 제외, 외부 JSON 중계 서비스 사용 | Hub의 프로토콜 복잡도가 낮다 | 고객이 중계 서비스를 개발·운영해야 하고 오류·감사의 책임 경계가 하나 늘어난다. |

## 3. 결정

B를 적용한다. YAML의 각 업무 API 연결은 공통 호출 인터페이스를 구현한 등록 Spring 빈을 명시한다. 공통 API 자산과 종류 구분을 유지하며 SAP 전용 실행·자식 테이블·편집 화면은 후속 설계한다.

### 연결별 호출 유틸

- `invoker-bean`은 등록된 공통 호출 인터페이스의 빈 이름이다. 임의 클래스·메서드·스크립트를 설정으로 실행하지 않는다. 빈 누락·중복·지원하지 않는 API 종류나 옵션은 검증 실패다. 무음 기본 유틸 대체는 없다.
- 구체 HTTP 라이브러리는 구현 빈 내부 선택이다. WebClient 빈 자체를 곧바로 업무 실행 권한으로 취급하지 않는다. 첫 구현은 기존 스택으로 일반 REST JSON을 지원하며 WebFlux 서버 전환을 요구하지 않는다.
- 연결별 인증·타임아웃·응답 상한과 안전한 테스트 설정은 YAML에 둔다. 비밀은 기존 FEAT-302 보호 참조로만 소비한다. 연결 소속·정확 설정 세대·실제 전송 대상은 검증한 불변 정의와 같아야 한다.
- 호출 전후의 현재 권한·업무 실행 승인·감사·전체 시간 제한·결과 불명·재시도 통제는 공통 실행 소유자가 지킨다. 유틸은 이를 생략하거나 다른 업무 요청으로 바꾸지 않는다.
- 연결 테스트는 설정에 명시한 GET/HEAD만 사용한다. 시험 성공은 SAP 또는 실제 업무 API의 공동 검수 완료가 아니다.

### 공통 마스터와 종류별 확장

- `AI_ADMIN_BUSINESS_API`(ENT-011)의 `API_ID`가 모든 종류의 안정 ID다. `API_KIND_CD`로 종류를 구분하고 원본과 ENT-059 이력에 같은 값을 보존한다. 현재 지원값은 `REST_JSON`뿐이다. OData 종류·버전 코드는 후속 SAP 설계에서 확정하고 그 전에는 등록·실행을 열지 않는다.
- 이름·제공 시스템·선택 연결·HTTP 기본 계약·공통 가이드·검수 정보는 ENT-012 공통 내용과 ENT-061 이력에 유지한다. OData도 HTTP 기반이므로 공통 필드를 재사용할 수 있으나, 모든 OData 형식을 현재 JSON 스키마로 처리할 수 있다고 보장하지 않는다.
- SAP 전용 속성은 후속 자식 테이블이 같은 `API_ID`를 참조한다. 정확 테이블명·컬럼·자식 개수는 현재 만들지 않는다. 버전별 엔티티/복합 키·함수/액션·조회식·메타데이터 등을 확인한 뒤 필요한 구조만 추가한다.
- 새 종류의 자식은 공통 마스터의 같은 버전·명령·전체 저장·HISTORY_NO 경계에 참여한다. 종류와 자식 구성의 일치, 타 종류 자식 혼입, 삭제 참조, 과거 재현을 검증한다. 기존 API의 종류를 단순 수정해 다른 자식 구조로 전환하지 않는다.
- 그룹·지식·워크플로우 등 외부 연결은 공통 `API_ID`를 계속 참조한다. 연결 목록은 공통 마스터/공통 내용에서 조회하고 종류별 자식과 무조건 내부 조인하지 않는다. 종류를 빠뜨리거나 별도 ID 공간으로 나누지 않는다.
- SAP 전용 메뉴는 후속 UX 선택이다. 별도 메뉴가 필요해도 공통 API 자산을 편집하는 전용 화면으로 구현할 수 있다. 다른 기준 정보의 API 연결 탭은 종류를 통합 조회하고 현재 권한을 적용한다. 필요 시 종류 표시·상세 화면 이동만 보완한다. 새 자산 종류를 별도로 도입하는 결정은 이 ADR의 후속 변경이다.

## 4. 후속 SAP 설계·개발 시 확인할 사항

아래는 후속 검토 항목이며 지금 모두 구현하기로 약속한 목록이 아니다.

1. 실제 SAP 제품·서비스와 OData V2/V4 버전, 인증 방식, 서비스 루트, 지원 읽기/쓰기 연산을 먼저 확보한다. 단순 지정 API 호출과 관리자용 범용 OData 등록 기능을 구분한다.
2. 서비스별 CSRF 필요 조건, 토큰 발급 요청, 쿠키와 토큰의 결합, 만료·갱신·동시 호출을 정의한다. 모든 API에 CSRF를 강제하지 않고 연결/인증 문맥 간 토큰·쿠키를 섞지 않는다. 토큰 갱신을 이유로 결과 불명인 업무 변경을 자동 재전송하지 않는다.
3. 엔티티 키·복합 키·문자열 리터럴·날짜/십진수 등 자료형과 `$filter`/`$select`/`$expand` 허용 범위를 정한다. 모델이 임의 조회식을 만들어 등록 필드·권한 범위를 넓히지 못하게 한다.
4. V2 `d.results`/`__next`, V4 `value`/`@odata.nextLink` 등 응답과 다음 페이지를 처리한다. 페이지 수·행 수·전체 시간 상한, 잘린 결과 표시, 허용된 원 서버/서비스 범위의 다음 주소를 검증한다.
5. 원 응답을 보존할지 공통 JSON으로 변환할지 API 계약에서 명시한다. 변환 결과와 등록 스키마·필드 안정 ID·마스킹·감사·오류 판정이 같아야 한다. 응답 헤더의 버전 정보가 필요하면 보호된 내부 계약으로 전달한다.
6. ETag/If-Match를 요구하는 변경은 조회한 버전과 실행 대상·승인을 연결한다. 충돌을 무시하는 와일드카드나 자동 재시도를 기본값으로 삼지 않는다.
7. `$batch`는 별도 지원 여부를 결정한다. multipart 또는 버전별 JSON 배치, 변경 집합의 원자성, 하위 요청별 승인·권한·부분 결과·불명 상태가 일반 단건 호출과 다르다. 현재 JSON 전용 범위에 자동 포함하지 않는다.
8. `$metadata` 가져오기와 전용 편집기는 선택 기능이다. XML 메타데이터 수입과 업무 본문 XML 지원을 구분하며 외부 참조·크기 제한과 스키마 변경 시 기존 필드/정책 보존을 설계한다.
9. 로컬 HTTP 대역으로 프로토콜과 실패 사례를 검증한 뒤 실제 고객 SAP에서 공동 검수한다. 대역 성공을 실제 SAP 인증·업무 실행 성공으로 기록하지 않는다.

## 5. 근거와 포기한 것

현재 필요한 일반 REST JSON 관리의 완료를 우선하면서 접속 구현 교체 지점을 확보한다. SAP 상세 속성을 미리 일반 화면에 추가하지 않으므로 화면은 단순하지만, 후속 SAP 구현에는 별도 설계·검수 시간이 든다. 공통 ID를 유지해 연결 관계 재작성은 줄일 수 있으나, 모든 연결 화면이 무수정으로 동작한다는 보장은 없다.

## 6. 되돌리기

SAP 착수 전에는 빈 선택과 종류 계약을 영향 CR로 변경할 수 있다. API 관리가 아직 구현 전이므로 현재 물리 명세 변경 비용은 낮다. 실제 여러 종류의 API와 자식·이력이 쌓인 뒤 별도 마스터로 분리하면 그룹·지식·실행·이력의 ID 변환과 권한/참조 검사 재작업이 필요해 비용이 높다. 공통 내용이 SAP 전용 필수값을 과도하게 요구하거나 실행 의미가 공통 모델과 맞지 않을 때 이 결정을 재검토한다.

## 7. 영향과 정본

현재 직접 영향은 REQ-604·REQ-608, ARCH-028, FEAT-001·004·302, ENT-011·059, SCR-001·004의 연결/종류 계약이다. 공통 빈 선택 구현은 integration의 기술 포트, 대상 시스템 관리·진단은 admin, 실제 업무 호출은 FEAT-203이 소유한다. 후속 SAP 상세는 관련 원천의 `@defer SAP OData`에서 이 문서를 참조한다. 현재 구현·검증·게이트 상태는 `project.state.yaml`이 정본이다.
