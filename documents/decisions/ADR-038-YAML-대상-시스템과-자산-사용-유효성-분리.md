# ADR-038 — YAML 대상 시스템과 자산 사용·유효성 분리

| 항목 | 내용 |
|---|---|
| 일자·상태 | 2026-11-01 · accepted · 사용자가 권장안의 요구사항·관련 문서·목업 반영을 명시 승인 |
| 등급 | High — 설정/보완 소유권과 저장된 실행의 현재 유효성 경계를 정한다 |
| 범위 | REQ-601·604·608·301·303·612·404·405, CR-030의 대시보드 소비. 제품 구현·G3 승인은 별도 |

## 1. 맥락

대상 시스템은 API 접속 정의와 Portal 사용자 계정 매핑의 기준이다. 기술 설정은 YAML에 있는데 화면에서도 허용 연결·기본값을 편집하면 소유권이 겹친다. 삭제된 설정을 DB 참조나 저장된 워크플로우가 계속 사용하면 호출 전에 오류를 설명하기 어렵다. 자산 수동 사용 설정과 기술 오류를 같은 상태로 덮으면 복구 때 운영자의 의도를 잃는다.

## 2. 대안

- 화면에서 기술 정의·기본 연결을 관리: 배포 없이 편집할 수 있지만 YAML과 DB의 우선순위·비밀/접속 경계가 중복된다.
- YAML 정본과 DB 표시 보완, 수동 사용과 자동 유효성 분리(선택): 필드 소유권과 실행 차단 원인을 구분한다. 동기화·참조 진단·운영 표시가 필요하다.
- 설정 제거 시 참조/자산을 함께 삭제하거나 자동 OFF: 불일치를 숨기지만 이력·저장된 정의와 수동 사용 의도를 잃으므로 선택하지 않는다.

## 3. 결정

REQ-604의 YAML 기술 정본·DB 표시 재정의를 채택하고 기본 연결을 철회한다. REQ-601.asset_availability의 수동 사용과 현재 기술 유효성, configuration_alerts의 ID 기반 원인 경고를 모든 새 호출 경로에 적용한다.

## 4. 근거와 포기한 것

이름·설명만 운영 화면에서 보완하므로 접속/비밀 정의의 배포 통제를 유지한다. DB 행과 참조를 보존해 어떤 연결을 고쳐야 하는지 알 수 있다. 저장된 정의·과거 승인으로 현재 사용 중지/누락 검사를 우회하지 않는다. 기술 설정의 화면 즉시 편집과 자동 연결 대체 편의는 제공하지 않는다. 업무 내용의 의미 영향 검토·관리자 간 승인 절차는 추가하지 않는다.

## 5. 되돌리기

기존 코드/제품 테이블은 이번 작업에서 바꾸지 않는다. 설계 단계에서는 요구·ENT/API·화면·TC를 함께 되돌릴 수 있다. 구현 뒤에는 필드별 재정의와 명시 연결·사용 설정·진단 기록을 이관해야 하므로 비용이 높다. YAML 배포 반영과 동기화가 운영 요구를 충족하지 못하면 기술 정의 변경 경로를 새 결정으로 검토한다.

## 6. 영향

대상 시스템·API·지식·카탈로그·도구·관리 대시보드 요건/목업과 연결/신원·워크플로우 소비 계약을 현행화한다. system의 현재 대시보드 슬롯과 새 경고 위젯 계획을 구분하며 admin 공개 조회의 소유권을 유지한다. 원본 감사와 추가 전용 이력 감사, 비밀 비노출·실행 사용자 확인·권한/신원 통제는 유지한다.
