# 05. 운영 — 무엇을 보고 무엇을 준비하나

> **운영 화면의 기능 목록은 [`documents/spec/31-features/_index.yaml`](../documents/spec/31-features/_index.yaml) 이,
> 지표의 판독 기준은 [`documents/design/turn-execution.md`](../documents/design/turn-execution.md) §7 이 갖는다.**
> 여기는 *운영을 인수받는 사람이 무엇을 알아야 하는가* 다.

## 1. 이 시스템의 운영이 보통과 다른 점

| 보통의 백오피스 | 이 시스템 |
|---|---|
| 설정을 바꾸면 배포한다 | **정책은 배포 없이 즉시 반영된다**(PRN-06) — 프롬프트 규칙 · 지식 · 그룹 매핑 · 마스킹 · 쿼터 |
| 잘못 바꾸면 롤백 배포 | **되돌리기는 정책 변경 이력이 유일한 수단이다**(FEAT-033) |
| 품질은 테스트가 지킨다 | **테스트로 지킬 수 없는 품질이 있다** — 프롬프트·지식·카탈로그를 고치면 평가셋으로만 회귀를 안다(FEAT-034) |
| 비용은 서버 비용 | **질의당 토큰 비용이 발생한다** — 전사 예산 계획에서 개인 상한이 유도된다(NFR-011) |
| 감사는 접근 로그 | **전량 감사이며 기록 실패는 처리 실패다**(PRN-07) |

## 2. 매일 볼 것

| 화면 | 무엇을 보나 | 이상 신호 |
|---|---|---|
| **품질 지표**(SCR-026) | 성공률 · 재질의율 · 신고율 · **권한 부족으로 실패한 질의 건수** | 권한 부족 실패가 늘면 **그룹 소속·매핑을 조정할 때다** — 사용자에게는 "정보 부재" 로만 보이므로 이 지표가 유일한 단서다 |
| **품질 신고 처리**(SCR-024) | 미처리 건과 **경과 시간** | 방치되면 **신고 자체가 들어오지 않게 된다** — 그러면 품질 개선 경로가 끊긴다 |
| **오류·실패 추적**(SCR-032) | 점유 획득 실패 · `LEASE_EXPIRED` 회수 · 대기 만료 · **중복 실행 후보** | **중복 실행 후보는 0 이어야 한다.** 0 이 아니면 되돌릴 수 없는 액션이 두 번 나갔을 수 있다 |
| **토큰·비용 통계**(SCR-023) | 전사 예산 소진율 · 등급별 초과율 | 소진율이 기간 경과율보다 빠르면 상한을 다시 배분한다 |

### `LEASE_EXPIRED` 회수를 읽는 법

**0 에 가까워야 한다.** 잦으면 두 가지 중 하나다.

- **인스턴스가 불안정하다** — GC 정지·DB 지연으로 멀쩡한 인스턴스가 점유를 빼앗긴다.
- **점유 유지 시간(L)이 짧다** — 특히 **실행 API 호출이 백오프·재시도로 길어질 때** 정상
  처리 중인 인스턴스가 회수된다.

**직전 노드가 도구 노드인 건을 분리해 본다.** 그쪽이 늘면 인스턴스가 아니라 L 산정의 문제다.
L·R·S(점유 유지·갱신 주기·스위퍼 주기)는 **실행 제한·운영 설정 화면**(SCR-018)에서 바꾼다 —
코드에 박혀 있지 않다.

## 3. 정확도가 낮을 때 — 순서가 있다

**프롬프트를 고치는 것이 첫 번째가 아니다.** 정확도는 메타데이터의 품질에서 나온다(PRN-10).

```
① 품질 지표에서 실패·재질의가 많은 질의 유형을 찾는다              (SCR-026)
② 스키마 카탈로그의 "조회 빈도 상위 중 메타데이터 미완성" 을 본다   (SCR-003)
③ 그 테이블·컬럼의 업무 명칭·설명·의미 유형·값 도메인을 채운다      (SCR-003)
④ 권장 조인 경로가 없어 LLM 이 조인을 추측하고 있는지 본다          (SCR-003)
⑤ 반복되는 질의를 인증 예제 쿼리로 승격한다                        (SCR-012)
⑥ 그래도 안 되면 지식의 태그·동의어를 보완한다                     (SCR-011)
⑦ 마지막에 프롬프트 규칙을 손댄다                                  (SCR-013)
```

- **②와 ③이 가장 효과가 크다.** *무엇을 채우면 오답이 줄어드는가* 가 지표와 결합해 데이터로
  나온다 — 짐작으로 채우지 않는다.
- **전부 채우려 하지 않는다.** 실제로 쓰이는 것부터 채우는 순서가 정확도 개선 순서와 일치한다.
- **⑦ 전에 평가셋을 돌린다.** 프롬프트·지식·카탈로그는 배포 없이 즉시 반영되므로 **회귀를
  감지할 수단이 평가셋뿐이다**(SCR-025).

## 4. 정책을 바꿀 때 — 되돌릴 수 있게

관리자 간 자산·권한 변경 승인은 두지 않는다. 제한된 업무 전문가와 관리자에게 필요한 대상의 변경 권한을 부여하고,
직접 저장과 변경 전후 이력을 함께 남긴다. Portal 사용자의 신청에 대한 관리자 승인은 유지한다.
정본은 [공통 직접 관리 규칙](../documents/spec/10-requirements/011-reference-integration.yaml)의 `REQ-601.direct_management`다.

지식의 업무 의미와 내용 적합성 검토는 운영·유지보수 조직의 자체 절차다. 제품은 단순 사용처·참조 현황 조회와
참조 무결성·SQL/API 계약 검증을 지원하며, 본문 전체 수집·LLM 영향 판정·검토 작업 배정/완료 기능은 제공하지 않는다.
필요한 자료를 권한과 반출 정책에 따라 확인하며 전체 DB 추출을 필수로 요구하지 않는다.
결정 근거는 [ADR-037](../documents/decisions/ADR-037-관리자-직접변경과-업무검토-경계.md)을 따른다.

| 규칙 | 왜 |
|---|---|
| **정책 변경은 이력에 남는다** | 매핑을 일시적으로 넓혀 조회한 뒤 되돌리는 행위를 추적하기 위함이다 |
| **과거 값을 참고해 새 변경으로 저장한다** | 이력을 직접 수정하지 않고 현재 권한·참조·기준 버전을 다시 검증해 정정 근거를 남긴다 |
| **한 턴은 시작 시점의 정책으로 처리된다** | 스텝 1에서 허용으로 판정한 것을 스텝 3에서 다른 기준으로 검증하면 **한 턴 안에 모순된 판정**이 생긴다. 변경은 **다음 턴부터** 적용된다 |
| **기본값은 닫힘이다** | 그룹 없는 신규 사용자, 매핑 없는 신규 테이블·컬럼·API 는 아무것도 열리지 않는다. **스키마 감지로 발견된 신규 컬럼도 매핑 전까지 차단된다** |
| **정책 관리 권한과 감사 열람 권한을 분리한다** | 접근 범위를 넓힌 사람이 그것을 감사하면 통제가 성립하지 않는다 |

## 5. 사고가 났을 때

| 상황 | 어디를 보나 | 무엇을 할 수 있나 |
|---|---|---|
| **잘못된 액션이 실행됐다** | 실행 이력(SCR-029) — API·파라미터·승인 이력 · 그 턴의 조회 결과 원문(액션으로 이어진 턴은 정책과 무관하게 보존된다) | **복구는 대상 시스템의 업무 프로세스와 매뉴얼을 따른다.** Hub 가 제공하는 것은 *무엇이 실행되었는지* 다 |
| **같은 액션이 두 번 나갔다** | 오류·실패 추적의 **중복 실행 후보** — `같은 턴 + 같은 도구·파라미터 + 서로 다른 점유 토큰` | 개별 건을 복구 절차로 넘긴다. **exactly-once 는 약속되지 않는다** |
| **개인정보가 노출됐다** | 실행 이력의 **정보주체 식별자 목록**과 **평문 열람 여부·근거 그룹** | 통지 대상을 특정한다 — 그 목적으로 식별자를 보존한다 |
| **LLM 공급사 장애** | 후보 설정 버전·원/후속 호출·오류 분류·전환 사유·계량 | **설계 정책:** [REQ-602](../documents/spec/10-requirements/011-reference-integration.yaml)의 보조 판정만 허용된 일시 장애에서 순서별 후보로 자동 대체한다. 소진/금지 오류·동의/예산 차단은 사유별로 조치하고 설정 오류는 관리자가 변경 이력을 남겨 수정한다. 주 추론은 사용자 수동 선택·명시적 새 턴 요청, 시스템 운영은 관리자 수동 설정 조치를 유지한다. 종결 원 턴을 자동 재개하거나 완료 업무를 재실행하지 않는다. 실제 운영 기능·공급 경로별 장애 시험과 agent/integration 런북은 구현 후 검증 대상이다 |
| **임베딩 모델 장애** | — | **태그 검색만으로 지식 검색이 계속된다** — 지식 검색 실패가 질의 처리 전체의 실패가 되지 않는다 |
| **DB 슬로우 쿼리가 발견됐다** | 쿼리 주석의 **턴 ID** | 그 ID 로 감사 이력을 역조회해 출처를 특정한다. **사용자 ID 가 아닌 턴 ID 를 쓰므로 DB 로그에 개인 식별자가 없다** |
| **사용자가 결과를 못 믿겠다고 한다** | 품질 신고(SCR-024) → 원 응답 이력 | **되돌림이 있었던 턴에서는 최종 응답을 만든 회차의 이력을 본다** — 버려진 회차의 SQL 로 분석하면 엉뚱한 결론이 나온다 |

## 6. 보관과 파기

| 것 | 기본 |
|---|---|
| 대화 이력 | **사용자 삭제는 논리 삭제만.** admin 은 삭제 표시분도 전량 조회한다 — **사용자가 감사 대상 기록을 지울 경로는 없다** |
| 조회 결과 원문 | **기본 미보존.** 데이터소스·테이블 단위로 켠다. 켜도 메타데이터보다 짧은 기간 |
| 조회 메타데이터 · **결과 지문** | **항상 보존.** 원문이 없어도 "그때와 지금이 다르다" 는 확인된다 |
| LLM 전송분 | **항상 전량 기록.** 무엇이 외부로 나갔는지가 감사의 핵심이다 |
| 재개 상태(체크포인트) | **턴 종결 시 정리.** 이전 회차는 종결 전에도 정리한다. **보관 기간이 원문 보존 기간보다 길 수 없다** |
| 물리 삭제 | **보관 기간 정책의 일괄 처리만.** 임의 물리 삭제 기능은 없다 |

> **저장하지 않기로 한 것과 저장에 실패한 것은 다르다.** 원문 미보존 설정에서도
> **메타데이터·전송분의 기록 실패는 처리 실패다.**

## 7. 착수 시 확정해야 할 것 — 운영 관점

**시스템 기능이 아니어서 우리가 값을 정하지 않는 항목이 18개 있다**
([`documents/spec/31-features/_index.yaml`](../documents/spec/31-features/_index.yaml) 의 `customer_agreements`).
그중 **운영 인수 전에 반드시 답이 있어야 하는 것** 다섯을 꼽는다.

| # | 항목 | 없으면 무슨 일이 나나 |
|---|---|---|
| 1 | **메타데이터 등록·검수 담당과 일정**(CON-016) | **정확도의 상한이 정해진다.** 이 인력이 없으면 시스템이 답을 틀리고, 그것은 프롬프트로 고칠 수 없다 |
| 2 | **1차 적용 업무와 프로세스 재설계 합의**(CON-017) | 기존 절차를 그대로 둔 채 대화 창구만 얹으면 **반복 수작업이 그대로 남는다.** 적용 전 지표가 없으면 **효과를 증명할 수 없다** |
| 3 | **읽기 계정의 메타데이터 조회 권한**(CON-018) | 카탈로그의 스키마 사실을 자동 수집할 수 없어 **12,000개 셀을 전부 수기로 등록**하게 된다 |
| 4 | **API 응답의 개인정보 경로 식별 담당과 변경 통보 절차**(CON-020) | **우리는 레거시의 응답 변경을 감지할 수단이 없다.** 필드가 하나 추가되고 그것이 개인정보면 미지정 경로로 닫히지만, **그것이 개인정보였다는 사실은 사람이 등록해야 드러난다** |
| 5 | **대화 이력의 보관 기간과 파기 방식 법무 검토**(CON-032) | 사용자가 채팅에 입력한 개인정보가 append-only 이력으로 장기 보존된다 — **감사 목적의 보관은 타당하나 삭제 요구와 충돌할 수 있다** |

## 8. 약속하지 않는 것 — 인수받는 사람이 알아야 한다

- **exactly-once 실행을 보장하지 않는다.** 중복이 0 인 것이 아니라 **중복이 생기면 반드시
  드러나고 복구 절차로 넘어간다**는 것이 약속이다.
- **턴 사이의 중복 방지는 대상 시스템의 몫이다.** 서로 다른 세션이 같은 대상에 같은 액션을
  내는 것은 정당한 병렬 업무이므로 Hub 가 막지 않는다 — 대상 API 의 멱등성에 의존한다.
- **공급사 장애 자체를 극복하는 수단이 없다.** 전환은 수동이다.
- **점유가 처리 지연을 줄이지 않는다.** 인스턴스가 죽으면 회수까지 최악 `L + S` 를 기다린다.
- **모니터링 화면은 제품 기능이 아니다.** 고객사 도구가 담당한다.
- **자체 rate limit 을 약속하지 않는다.** 대상 시스템의 제한 응답을 존중해 백오프한다.
