# 보안 — 계층 셋 · 인가 모델 · 접근 제어 체인

> **프론트에서 메뉴·버튼을 감추는 것은 UX 이지 보안이 아니다.**
> 프론트가 든 권한 사본은 재조회 전까지 낡을 수 있다 — 방금 회수된 권한의 버튼이 아직
> 보일 수 있고, **그 클릭을 막는 것은 서버다.**
>
> 개인정보는 [standard/safety/pii.md](../safety/pii.md) · [pii-vault.md](./pii-vault.md), 비밀번호
> 정책은 [knowledge/sys/user-role.md](../../knowledge/sys/user-role.md) 가 갖는다.
> **보안 헤더 규약은 아직 없다** — 이 문서에도 없다.

## 1. 계층 셋 — 프리픽스가 보안 등급이다

모듈러 제품의 목표 경로는 `/api/{모듈}/{계층}/{도메인}/{동작}`이다. 아래 단일 모듈
접두 설명에 해당하는 구분은 모듈 뒤 계층에서 읽는다. Hub의 현재 소스는 CR-038 이행 전
계층 우선 경로이며, 목표 분류기·정확 카탈로그·호출자·시드는 같은 전환 단위로 적용한다.
public/common도 인증 영역·정확 허용 목록·본인 범위/원천 증명을 검증하며 포괄 prefix 허용은
신규 조립에 사용하지 않는다. 업무 API를 common으로 옮겨 권한 검사를 생략해서는 안 된다.

| 분류 | 프리픽스 | 통과 조건 |
|---|---|---|
| **공개** | `/api/public/**` | 익명(`permitAll`) — 로그인 · 비밀번호 재설정 등 최소한 |
| **공통** | `/api/common/**` | **인증만.** 특정 메뉴에 소속시킬 수 없는 것 — 공통코드 조회, 사용자 검색 팝업, `auth/me`, 진행률 폴링, 파일 다운로드 |
| **업무** | `/api/service/**` | 인증 **+** `SYS_API` 에 행이 있고, 그 URL 의 `SYS_MENU_API` 메뉴 1~N 중 **하나라도** (메뉴, 액션) 권한 보유 — OR |

- **세 프리픽스 밖의 `/api/**` 는 무조건 403.** 미분류가 경로 차원에서 **fail-closed** 다.
- **분류가 URL 에 새겨지므로 별도 상수 목록이 없다** — 컨트롤러의 경로가 곧 보안 등급 선언이다.
- **오배치 위험이 한 곳 있다**: 업무 API 를 `/api/common` 아래 두면 **조용히 열린다.**
  URL 에 보이므로 **코드 리뷰가 지키는 지점**이다.
- 판별 신호 — 매핑하려니 **메뉴를 전부 나열하게 되는** API 는 업무 API 가 아니라 공통 API 다.
- 외부 원천 수신은 프로젝트 정본의 정확 경로·원천 검증 계약으로 정의한다. public이라는 이유로 브라우저 익명을 허용하지 않으며 검증기 미설정은 닫는다.

## 2. 인가 모델 — (주체 × 메뉴 × 액션)

**조직·부서 계층을 두지 않는다.** 역할 기반이며 개인별 예외를 허용한다.

```
SYS_USER ──< SYS_USER_ROLE >── SYS_ROLE ──< SYS_ROLE_MENU_AUTH >── SYS_MENU ──< SYS_MENU_API >── SYS_API
    └──────< SYS_USER_MENU_AUTH >───────────────────┘
                 개인별 예외 권한
```

**유효 권한 = 역할 권한 합집합 ∪ 개인 예외 권한.**

- **역할이 여러 개면 합집합이다 — 선택하지 않는다.** *"로그인 후 어느 역할로 동작하나"*
  를 묻지 않는다.
- **경로 결합은 없다 — 리프 단독 판정.** 조상 메뉴의 권한은 판정에 관여하지 않는다.
- **권한은 URL 이 있는 메뉴에만 부여한다.** URL 없는 노드는 순수 구조다.
- **유효 권한이 공집합이면 로그인을 차단한다.**

## 3. 액션은 넷에서 닫는다

| 액션 | 의미 | 예 |
|---|---|---|
| `READ` | 조회 | 화면 진입 · 목록·상세 |
| `SAVE` | 저장 — **추가·수정·삭제 포함** | 저장 버튼 · 모달 등록/수정 · 행 삭제 · 셀 편집 |
| `EXPORT` | 출력 | 엑셀 다운로드 |
| `EXECUTE` | **절차 발동** | 배치 수동 실행 · 승인/반려 · 발송 · 마감 · 강제 로그아웃 |

> **등록/수정/삭제로 쪼개지 않는다.** 그리드 저장이 리스트 CUD 일괄 처리라 행별 구분이
> **URL 이 아니라 페이로드 안**에 있다. 셋으로 쪼개 판정하려면 서비스가 페이로드를 열어
> 행 상태별로 검사해야 하고, **판정을 인터셉터 한 곳에 두는 원칙이 깨진다.**
> **서버가 API 경계에서 집행할 수 없는 세분 권한은 권한 화면의 장식일 뿐이다.**

> **`EXECUTE` 가 없으면** 위험한 버튼이 `SAVE` 에 섞여 *"저장 권한을 주면 배치 실행도
> 된다"* 가 된다. 실무의 권한 비대칭은 *"수정 vs 삭제"* 가 아니라 ***"일상 저장 vs
> 위험한 절차"*** 다. 그래도 남는 비대칭은 **메뉴를 분리해** 푼다(신청/승인 분리).

**`SAVE` 통합으로 인가 모델이 화면의 저장 패턴과 독립이다** — 셀 편집이든 모달이든 일괄
저장이든 전부 (메뉴, `SAVE`). 화면이 패턴을 바꿔도 부여 데이터를 재분류하지 않는다.

### `EXPORT` 하나만 집행되지 않는 경우가 있다

| 엑셀 경로 | 요청 | `SYS_API` 행 | 인터셉터가 |
|---|---|---|---|
| 임의 API (서버 POI) | 있다 | 있다(`export` 접두) | **집행한다** |
| 현재 페이지 · 전체 (프론트 생성) | **없다** | **없다** | 막을 것이 없다 |

**그 권한을 봉쇄로 읽으면 안 된다.** 실제 경계는 **`READ`** 다 — 조회할 수 있는 사람은
화면에 뜬 것을 옮겨 적을 수 있다. `EXPORT` 가 남기는 것은 *"이 사람에게 내려받기를
허용했는가"* 라는 **운영 사실**이고, 짝이 되는 것이 **다운로드 기록**이다. 진짜 봉쇄가
필요하면 답은 `EXPORT` 를 끄는 것이 아니라 **`READ` 를 주지 않는 것**이다.

프론트 생성 엑셀에는 말해 줄 API 가 없어 **메뉴가 직접 선언한다**(`SYS_MENU.EXPORT_YN`).
그때도 **`READ` 가 정의된 메뉴에만** 붙는다.

## 4. 인가 사실은 **데이터**다 — 코드에 선언이 없다

API 하나를 인가하는 데 필요한 사실은 둘이고 **성격이 달라 각자의 테이블에 둔다.**

| 사실 | 테이블 | 성격 |
|---|---|---|
| 이 URL 은 어떤 액션인가 | **`SYS_API`** (마스터) | **API 의 속성** — 메뉴와 무관 |
| 이 URL 을 어느 메뉴가 쓰는가 | `SYS_MENU_API` (매핑) | **정책** — 1 : N |

> **한 테이블에 두면** 같은 API 가 메뉴마다 다른 `ACTION_CD` 를 갖는 **모순이 저장될 수
> 있고**, 판정이 어느 행을 읽느냐에 따라 갈린다.

> **메뉴를 코드에 박으면**(`@PreAuthorize("hasMenuAuth('USER_MGMT','SAVE')")` 식) 두 번째
> 화면이 그 API 를 재사용하는 순간 **코드 수정·배포**가 필요하고, 나열을 잊으면 그 화면
> 사용자만 **조용히 403** 을 받는다 — **API 재사용에 벌금을 물리는 구조**다.

### 경로 완전 일치 — 패턴 매칭이 아니다

**업무 API 의 경로는 고정 문자열이다.** 경로 변수(`{id}`)·와일드카드를 쓰지 않는다.
행위 주체는 세션에서 얻고, 대상 식별자와 조회 조건은 **body** 에 담는다.

- **겹침이 구조적으로 불가능하다** — 같은 키의 행 N 개는 의도된 다중 메뉴 매핑뿐이다.
- **새 API 가 기존의 넓은 패턴에 자동으로 덮이는 일이 없다** — 새 API 는 반드시 새 행이다.
- `HTTP_METHOD` 를 두지 않는다. **키는 `API_URL` 단독**이며, 한 경로에 두 오퍼레이션을
  두려는 시도는 **`SYS_API` PK 충돌로 시드 배포에서 막힌다.**
- 쿼리스트링은 자유지만 **매칭에 참여하지 않는다.**

### 시드가 그 데이터를 만든다

```
컨트롤러 @RequestMapping  ·  endpoints.ts 선언  ─→ ./gradlew generateApiSeed ─→ SYS_API · SYS_MENU_API
```

**선언하지 않고 부르면 403, 선언만 하고 안 부르면 접근 범위가 조용히 넓어진다**
(AGENTS.md §8). 호출 URL 은 `features/{도메인}/api/endpoints.ts` 에만 둔다.

## 5. 접근 제어 체인 — 일곱

| # | 검사 | 실패 | 로그인 시 | 세션 중(매 요청) |
|---|---|---|---|---|
| 1 | 로그인 여부 | 401 | 인증 그 자체 | Security 필터 체인 |
| 2 | 계정 활성화 | 401 + 사유 | `isEnabled()` | **인가 인터셉터** |
| 3 | 사용 기간 만료 | 401 + 사유 | `isAccountNonExpired()` | 〃 |
| 4 | 계정 잠금 | 401 + 사유 | `isAccountNonLocked()` | 〃 |
| 5 | **비밀번호 만료** | **차단이 아니라 강제 변경 유도** | `isCredentialsNonExpired()` → 제한 세션 | 제한 세션이면 변경 API 외 403 |
| 6 | 메뉴·액션 권한 | 403 | 유효 권한 적재 — **공집합이면 차단** | 인가 인터셉터 |
| 7 | 개인정보 접근 권한 | 마스킹 유지 | — | 응답 직렬화 계층 |

- **2~5 는 Spring Security 의 `UserDetails` 네 플래그와 정확히 대응**하므로
  `AccountStatusUserDetailsChecker` 가 자동 검사한다. **직접 구현하지 않는다.**
- **5번만 별도 처리가 필요하다.** 비밀번호 만료는 *"차단"* 이 아니라 *"변경 화면으로
  유도"* 여야 한다 — `CredentialsExpiredException` 을 잡아 **제한 세션**으로 전환한다.
- **세션 중 재검사가 필요한 이유**: 세션 유지 중 상태가 바뀔 수 있다(관리자가 계정
  비활성화). 그래서 **2~6 을 인가 인터셉터 하나**가 매 요청 수행한다 — 캐시 조회 두 번이면 끝난다.

## 6. SPA 에는 "화면 로드" 요청이 없다

화면 접근은 서버가 내려준 **권한 메뉴 목록**으로 프론트 라우터가 제한하고, 서버가 실제로
지키는 것은 그 화면이 호출하는 **API** 다. JS 청크는 정적 리소스라 막지 않는다 —
**보호 대상은 화면(코드)이 아니라 데이터다.**

## 7. 보장하는 것 — 무엇을 믿고 쓰나

| 부르는 쪽이 기대해도 되는 것 | 근거 |
|---|---|
| 세 프리픽스 **밖의** `/api/**` 는 무조건 403 — 미분류가 fail-closed 다 | §1 |
| `/api/service/**` 의 판정은 **인터셉터 한 곳**이다 — 서비스에 인가 코드를 두지 않는다 | §4 · §5 |
| 계정 비활성화·잠금은 **다음 요청에서** 듣는다 — 재로그인을 기다리지 않는다 | §5 의 2~6 |

| 기대하면 안 되는 것 | 대신 무엇을 하나 |
|---|---|
| **`EXPORT` 가 내려받기를 봉쇄한다** | 프론트 생성 엑셀에는 막을 API 가 없다. 실제 경계는 **`READ`** 다 — 봉쇄가 필요하면 `READ` 를 주지 않는다(§3) |
| **`/api/common/**` 이 좁다** | **인증만** 본다. 업무 API 를 여기 두면 조용히 열리고, 막는 것은 검사가 아니라 코드 리뷰다(§1) |
| **선언만 하고 부르지 않는 API 는 무해하다** | `SYS_API` 에 행이 서면 **접근 범위가 넓어진 것**이다. 시드를 다시 만들 때 함께 지운다(§4) |
| **`X-Menu-Code` 로 판정한다** | 클라이언트 주장 값이며 **기록 전용**이다([logging.md](./logging.md)) |
