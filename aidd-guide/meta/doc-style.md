# 문서 작성 스타일

> `aidd-guide` 의 모든 MD 가 따라야 하는 작성 규칙. **LLM 학습 누락을 피하고 가독성을 확보**하기 위한 최소 표준.

## 분량 규칙

- **본문 + 메타블록 합쳐 200줄 이내** (운용 파일, type:operation/template).
- 200줄을 넘을 가능성이 보이면 **카테고리를 더 쪼갠다** (서브폴더 또는 토픽 분리).
- 코드 블록은 분량에 포함되지만, 표·리스트는 압축 가능하면 압축.

### 명시 예외 — **쪼개면 더 나빠질 때만**

넘는 것을 허용하는 조건은 하나다: **쪼개는 것이 독자에게 손해일 때.**

| 손해의 모양 | 예 |
|---|---|
| **부르는 이름을 잃는다** | ID 카탈로그를 쪼개면 그 ID 를 부르는 곳이 어느 파일인지 모른다 |
| **순서가 내용이다** | 필터·인터셉터의 순서를 두 파일에서 읽으면 순서를 알 수 없다 |
| **표가 갈리면 빠뜨린다** | 벤더별 대조표를 쪼개면 벤더 하나를 놓친 것이 드러나지 않는다 |

- **예외는 `_meta/lint.mjs` 의 `LENGTH_EXEMPT` 에만 적는다.** 파일이 머리말로 스스로
  선언하게 두면 **조용히 늘어난다** — 목록이 코드에 있어야 늘 때 눈에 띈다.
- **길다는 이유만으로는 예외가 아니다.** 위 셋 중 하나에 해당해야 하고, 사유를 목록에 적는다.
  형식을 바꾸면 **번호는 같은데 다른 문서**가 되어 지난 커밋의 인용이 어긋난다.

## Right Altitude (Anthropic)

> 시스템 프롬프트는 너무 추상적이지도 너무 구체적이지도 않은 **"올바른 고도"** 에서 작성. 본 시스템의 3 계층 추상도:

| 계층 | 위치 | 추상도 |
|------|------|--------|
| 1 | `INDEX.md` (루트) | 가장 추상 — 카테고리 분기만 |
| 2 | 카테고리 `INDEX.md` | 중간 — 진입 조건 + 파일 카탈로그 |
| 3 | 개별 운용 파일 | 가장 구체 — 실제 룰 + 예시 |

- 1 계층에 구체 룰 금지 (변경 시 라우팅 망가짐).
- 3 계층에 메타-원칙 금지 (구체적이어야 함).
- 카테고리 INDEX 가 1·3 계층 사이의 다리 역할.

## 인코딩·확장자

- **UTF-8 (BOM 없음)**
- 줄바꿈 `LF` (Windows 의 `CRLF` 도 git 이 정규화)
- 확장자 `.md` 만 사용

## 문서 구조 표준

```
---
{메타블록}
---

# 제목 (h1, 1개)

> 한 줄 요약 인용 블록 (강력 권장)

## 진입 조건 (있을 시)

- bullet list

## 본문

- 카테고리별로 자유 구조
- 표·리스트·코드 블록 자유 사용

## 관련 카테고리

- [링크](./상대경로)
```

## 마크다운 규칙

- **헤더**: `#` 1개(제목) → `##` 섹션 → `###` 서브섹션. h4 이상 자제
- **표**: 행이 5개 이상 넘으면 분리 또는 요약
- **코드 블록**: 언어 명시 (` ```ts `, ` ```java `, ` ```bash `)
- **링크**: 상대 경로 사용 (`./file.md`, `../category/INDEX.md`)
- **이미지**: 가능하면 ASCII 다이어그램 또는 mermaid 우선
- **이모지**: 시각적 구분이 필요할 때만 (✅/❌/⚠️). 남발 금지

## 인용 — 절은 번호가 아니라 제목으로

- **다른 문서를 인용할 때 절 번호를 쓰지 않는다.** 번호는 문서를 고칠 때마다 밀린다.

```
(X)  [grid.md](../standard/frontend/grid.md) §4
(O)  [grid.md](../standard/frontend/grid.md) 의 "컬럼 정의" 절
```

- **번호만 있는 인용(`24 §5`)을 만들지 않는다.** 두 자리 숫자는 문서 이름이 아니라
  **그 번호를 아는 사람만 읽을 수 있는 암호**다. 그런 인용이 이 저장소에 5,600곳까지
  자랐고, 해독하려면 지도 파일을 하나 더 만들어야 했다 — 그 지도까지 지우고 **문서
  이름으로 되돌렸다**.

## 언어

- **한국어 우선** — 본문은 한국어
- **고유명사·기술용어**: 원어 그대로 (Spring Boot, QueryDSL, AG Grid, Liquibase 등)
- **DB 컬럼·메서드명·파일명**: 백틱(`) 으로 감싸기

## 중복 금지

- 한 사실은 **한 곳에서만** 정의한다
- 다른 카테고리에서는 **링크로 참조**
- 동일 표·동일 리스트가 여러 파일에 있으면 → 공통 파일로 추출

## 시제·인칭

- 능동·현재형 — "한다" / "사용한다" / "금지한다"
- 가급적 명령형 또는 단언형 사용
- "~할 수도 있다", "~일 것으로 보인다" 같은 모호한 표현 자제

## 예시 코드 블록

```java
@RestController
@RequestMapping("/api/system/service/user")
public class UserController {
    @PostMapping("/getList")
    public ApiResponse<PageRes<UserRes>> getList(@RequestBody UserSearchReq req) { ... }
}
```

```ts
const columns: ColumnDef<UserRow>[] = [
  { field: 'userNm', header: MSG.USER_COL_NAME },
];
```

> **예시도 실물의 어휘로 쓴다.** 위 둘은 이 저장소의 규약이다 —
> API 경로는 기본 `/api/{계층}/{도메인}/{동작}`, 모듈러 제품은
> `/api/{모듈}/{계층}/{도메인}/{동작}`([standard/backend/api.md](../standard/backend/api.md)),
> 컬럼 문구는 `MSG` 키다(`AGENTS.md` §5-6). 남의 프로젝트 어휘로 예시를 쓰면
> **읽는 사람이 그것을 표준으로 베낀다.**
