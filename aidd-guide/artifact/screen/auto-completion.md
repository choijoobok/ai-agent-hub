# 보완 경계 — 채워도 되는 것과 물어야 하는 것

> **임의 생성은 결함의 원천이다.** 요건서의 빈 칸을 만났을 때 *규칙에서 나오는가* 를
> 묻는다 — 규칙에서 나오면 채우고 🤖 를 붙이고, 나오지 않으면 §9 로 보낸다.
>
> 규칙의 원본은 [standard](../../standard/INDEX.md) 다. 여기는 **그 규칙이 빈 칸을
> 채울 수 있는지의 판정**이다.

## 판정 한 줄

```
그 값이 다른 값에서 기계적으로 도출되는가?
   그렇다 → 채운다 (🤖)          아니다 → 묻는다 (§9)
```

## 채워도 되는 것 — 규칙에서 나온다

| 빈 칸 | 규칙 |
|---|---|
| **컬럼 헤더 키** | `{도메인}.col.{camelField}` — 상수는 `DOMAIN_COL_FIELD` |
| **조회조건 라벨 키** | `{도메인}.cond.{camelField}` |
| **API 경로** | 기본 `/api/{계층}/{도메인}/{동작}` · 모듈러 제품 `/api/{계층}/{모듈}/{도메인}/{동작}` — 동작은 **컨트롤러 메서드명 그대로** |
| **액션(`ACTION_CD`)** | 경로 **접두가 정한다** — `get*`→READ · `save*`·`delete*`→SAVE · `export*`→EXPORT · 그 외 EXECUTE |
| **프론트 폴더명** | 소문자 붙여쓰기 — 백엔드 애그리거트 이름과 대체로 대응 |
| **API 파일명** | 폴더 이름 그대로 — `features/order/api/orderApi.ts` |
| **서비스 이름** | 조회 `<기능>QueryService` · 명령 `<기능>Service` |
| **감사 컬럼** | [공통 컬럼 표준](../../standard/frontend/grid-columns.md) §3에 따라 업무 목록에 기본 합성. 추가 전용/사용자 명시 제외는 요건서 §1에 분류 |
| **`_DT` 컬럼** | `date` · `precision: 'day'` |
| **`_DTM` 컬럼** | `datetime` |
| **`_YN` 컬럼** | `ynFlag` · 편집하면 스위치 |
| **PK 컬럼** | 신규 행에서만 열린다 |
| **파생 컬럼** | 편집 선언이 없다 = 읽기 전용 |

## 물어야 하는 것 — 도메인이 정한다

| 항목 | 왜 물어야 하나 |
|---|---|
| **컬럼명 · 테이블명** | **실물을 읽는다.** 읽어서 없으면 *만들 것인가* 를 묻는다 — *있을 것 같다* 로 더하지 않는다 |
| **`_CD` 컬럼의 코드그룹** | 접미만으로는 **어느 그룹인지 모른다**. 그룹이 없으면 시드부터가 미결이다 |
| **목록에 낼 컬럼** | 표의 전 컬럼이 화면의 컬럼이 아니다 |
| **파생인가 입력인가** | 잘못 잡으면 **화면이 금액을 스스로 정한다** |
| **잠금·상태가 편집을 막는가** | 잘못 잡으면 **잠긴 행이 스스로 잠금을 푸는** 요청이 성립한다 |
| **기본 정렬** | 도메인 의도다. 어느 컬럼이 *가장 먼저 보여야 하는가* 는 규칙에서 안 나온다 |
| **페이징 모드** | 총 건수가 필요한가 / 대용량 이력인가 |
| **삭제 허용과 그 게이트** | 자식이 있는 행을 지울 수 있나 — **답이 화면 구조를 바꾼다** |
| **`EXPORT_YN`** | 메뉴가 선언한다. 적지 않으면 **아무도 그 권한을 못 갖는다** |
| **채번 규칙** | 서버가 정하나 사용자가 넣나 — 신규 행 기본값이 여기서 갈린다 |
| **검증 규칙 · 상태 전이** | 업무다 |
| **영향 테이블** | 실행이 무엇을 바꾸는가 — 추측하면 **롤백 지점을 잃는다** |
| **누가 어떤 버튼을 쓰나** | 권한 매트릭스 |
| **실제 데이터** | 샘플도 만들지 않는다 |

## 우선순위

```
1. 사용자가 명시한 값        ← 절대 바꾸지 않는다
2. 소스에서 읽은 사실        ← 확인된 것
3. 표준에서 도출한 값        ← 채운다 (🤖)
4. 추측                      ← 금지. §9 로 보낸다
```

## 보완했으면 표시한다

```md
| 컬럼 | 헤더 키 | 타입 | 비고 |
|---|---|---|---|
| `ORD_NO` | `order.col.ordNo` 🤖 | text 🤖 | (사용자 지정 컬럼) |
| `ORD_DT` | `order.col.ordDt` 🤖 | date · day 🤖 | |
| `ORD_STAT_CD` | `order.col.ordStatCd` 🤖 | code — **그룹 미정(§9-2)** | |

🤖 = 표준에서 도출 — 검토 부탁드립니다.
```

**표시하지 않은 보완은 사용자가 검토할 수 없다.** 그 순간 추측과 같아진다.

## 사용자 입력이 표준과 충돌할 때

```
1. 무엇이 충돌하는지 한 줄로 알린다 — "{입력값} 은 {규칙} 과 다릅니다"
2. 어느 쪽으로 갈지 묻는다. 임의로 고르지 않는다
3. 반복될 결정이면 커밋 메시지에 *왜* 를 적고, 버린 안이 있으면 ADR 로 남긴다
```

**사용자가 다시 그대로 지시하면 그것이 결정이다** — 따르고, 이유를 요건서에 한 줄 남긴다.

## 체크리스트

- [ ] 채운 값이 **규칙에서 도출되는가** — 아니면 §9 인가
- [ ] 컬럼·표를 **읽고** 썼는가, 추측했는가
- [ ] 보완한 항목에 🤖 가 있는가
- [ ] §9 의 각 항목에 **정해지지 않으면 무엇이 막히는지**를 적었는가
