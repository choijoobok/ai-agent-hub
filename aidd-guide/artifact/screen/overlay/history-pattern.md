# Overlay — 관리 변경 이력과 대용량 로그

## 1. 관리 데이터 변경 이력 — 저장과 조회의 공통 계약

**실제 반영된 관리 데이터의 성공한 저장을 재현하는 이력**에 적용한다. 로그인·요청·오류·배치 실행 로그는 §2다.
현재 행의 등록/수정 4컬럼만으로 과거 구성을 재현했다고 보지 않는다.

| 관리 화면 | 저장할 이력 | 별도 이력 메뉴의 화면 |
|---|---|---|
| 단일 그리드 | 저장에 성공한 변경 행마다 전체 관리 컬럼을 동형 이력 테이블에 추가 | 같은 조회조건·컬럼의 읽기 전용 그리드 + 변경 요약·변경일시 범위 |
| 상단 마스터·하단 탭 | 저장 단위의 마스터와 모든 소유 관리 자식 테이블을 같은 이력 번호로 복사 | 상단에 당시 마스터·변경 요약, 행 선택 시 같은 이력 번호의 하단 탭 |

### 저장 단위와 일관성

- 전체 테이블이나 현재 검색 페이지를 복사하지 않는다. 단일 그리드의 일괄 저장은 기존 행별 성공/실패 단위를 유지한다.
- 마스터·탭에서는 어느 소유 영역을 저장하든 **변경하지 않은 자식도 포함한 전체 구성**을 복사한다. 탭을 독립 저장하는 현재 계약을 마스터 전체 수정으로 바꾸지는 않는다.
- 동일 부모의 모든 관리 쓰기가 같은 잠금/일관성 경계에 참여한다. 부모·자식의 서로 다른 시점을 한 세트로 섞지 않는다.
- 현재값 변경, 이력 부모/자식 행, 명령 성공 결과는 같은 트랜잭션에서 성공하거나 실패한다. 조회와 같은 명령 재전송은 이력을 추가하지 않는다.
- 직접 변경은 현재 변경 권한으로 저장하며 **실제 반영 성공 때만** 이력을 남긴다. 입력 중이거나 저장 실패한 값은 실제 변경 이력으로 만들지 않는다. 신청·판정 업무가 별도로 명시된 경우 해당 정본의 반영 시점을 따른다. 철회된 절차의 과거 근거는 읽기 전용으로 보존하고 미반영 요청을 자동 반영하지 않는다.
- 최초 등록도 남긴다. 삭제는 제거 직전 전체 구성과 삭제 작업을 저장하며, 허용된 생성/수정은 반영 후 값을 저장한다.
- 이력 번호·원 식별자·작업 종류·저장자·이력 저장일시·변경 사유·명령 참조·형식 버전을 보존한다. 이력 번호는 집합 내 모든 복사 행을 잇는다.
- 이력 테이블명은 **원본 테이블명 + `_HIST`**다. 소유 관리 컬럼과 자료형을 보존하며 전체 데이터를 JSON 한 열로 대체하거나 현재 테이블과 조인해 과거 값을 합성하지 않는다.
- 모든 이력 테이블의 PK는 **`HIST_ID` 단일 서로게이트 키**이며 시퀀스 방식으로 발급한다. 공통 이력 번호 `HISTORY_NO`는 세트 연결용 별도 컬럼이다. 원 자식 키와 이력 번호의 조합은 PK가 아니라 유일 제약으로 중복을 막는다.
- 이력 저장일시 **`HIST_DTM`은 마스터 이력(단일 그리드는 해당 행)에만 저장**한다. 자식은 `HISTORY_NO`와 원 부모 키로 마스터의 시각을 참조한다. 자식 시각 컬럼·시계 조회·DB 기본값을 두지 않는다.
- 원 현재 행에 삭제 연쇄 FK를 두지 않고 같은 `HISTORY_NO`의 이력 세트 내부 관계로 검증한다. 같은 시각인 다른 저장 세트도 있을 수 있으므로 일시를 조인 키로 사용하지 않는다.
- 일반 변경 기능은 이력 행을 수정/삭제하지 않는다. 보존 종료 파기는 소유 정책에 따라 세트 전체를 처리하고 다른 기간의 보존·조사 보호와 혼합하지 않는다.

### 무엇을 복사하고 무엇을 표시하나

- 해당 저장 단위가 소유하는 모든 관리 테이블의 매핑을 화면 계약에 선언한다. 미조회 탭·숨긴 열을 빈 집합/삭제로 해석하지 않는다.
- 다른 화면 소유의 사용처, 실시간 연결 관측·샘플·세션·실행 로그·캐시 상태는 복사 대상이 아니다. 이력 화면에도 현재값을 대신 채우지 않고 당시 저장 대상이 아님을 안내한다.
- 비밀번호·해시·토큰·복호화 키·배포 접속 비밀을 복사하지 않는다. 비밀 작업은 안전한 관리 상태와 작업 근거만 남긴다.
- 고정 내용 버전·신청/판정 원장·철회 이전 근거는 소유 업무의 별도 근거다. 이력으로 예약 효력 시점을 앞당기거나 과거 요청을 재승인하지 않으며 당시 저장 문맥과 판 식별자를 보존한다.
- 이력의 원 등록/수정 컬럼은 복사한 값으로 유지한다. 이력 저장자·이력 저장일시는 별도 메타데이터이며 원 감사 컬럼을 덮어쓰지 않는다. 이력 저장일시는 커밋 완료 시각을 뜻하지 않는다.
- 이력 그리드는 [감사 컬럼 표준](../../../standard/frontend/grid-columns.md) §3의 추가 전용 두 컬럼을 기본 표시한다. 등록자/등록일시는 이력 기록자/기록일시로 매핑하고 원본 등록/수정 감사값은 당시 구성의 값으로 보존한다. 자식의 기록일시는 같은 이력 번호의 마스터 시각을 참조한다.

### 변경 요약

- 서버가 실제 저장 전후 값을 대조해 상단 값은 **`기준 정보`**, 자식은 **변경된 탭의 표시명**을 중복 없이 정해진 탭 순서로 열거한다.
- 한 탭 변경에도 전체 구성은 복사하지만 요약에는 그 탭만 적는다. 사유나 클라이언트 탭명을 신뢰해 요약을 만들지 않는다.
- 생성·삭제·특수 명령은 작업 구분을 함께 보존한다. 명시 저장이 성공했으나 업무 값이 같으면 `변경 없음`으로 구분하며 재전송과 혼합하지 않는다.

### 조회 화면 재사용 — 이력 목업을 따로 그리지 않는다

- 관리 화면마다 **별도 이력 메뉴·경로·READ/EXPORT 권한**을 연결한다. 관리 화면 안에 변경 이력 탭·JSON 스냅샷 모달을 중복 제공하지 않는다.
- 이력 SCR은 `view_kind: change_history`, `source_screen`과 이력 계약을 정의한다. 원 화면의 요건서·컬럼·배치·탭·검증을 상속하고 별도 요건서/목업 파일을 복사하지 않는다.
- 조회조건은 원 화면과 같고 **이력 저장일시 범위**만 더한다. 조건은 현재 테이블이 아니라 보존된 당시 값에 적용한다. 날짜 경계/시간대·기본값·상한은 조회 계약에서 정하고 임의 숫자를 추정하지 않는다.
- 상단 컬럼에는 변경 요약 하나를 추가한다. 이력 번호 등 처리 키는 숨은 문맥으로 유지하며 기존 감사 컬럼과 이력 메타데이터의 표시 매핑을 따른다.
- 상단 선택은 `(이력 종류, 원 식별자, 이력 번호)`로 하단 전체를 읽는다. 같은 원 식별자의 다른 저장 시점과 섞거나 최신 자식을 사용하지 않는다.
- 조회/반출 이외의 저장·추가·삭제·승인·실행·복원 버튼과 편집기를 제거한다. 원 화면 권한을 복사하는 대신 별도 이력 메뉴의 현재 권한과 대상 열람 범위를 서버에서 검사한다.
- 현재 행이 삭제돼도 보존된 이력만으로 조회한다. 누락·파기·미지원 형식은 정상 빈 구성과 구분하며 현재값으로 대체하지 않는다.

### 설계·구현 완료 검사

원 화면→이력 SCR/메뉴→조회 API→현재/이력 테이블 매핑→시험을 연결한다. 단일 그리드·탭 단독 저장·두 영역 동시 변경·등록/삭제·부분 성공·동시 저장·이력 실패·재전송·현재 행 삭제·기간 검색·권한/반출을 검증한다.
기존 구현은 현재 사실을 유지하고 변경 요청으로 이행한다. 구현 전 목표를 현재 동작으로 문서화하지 않으며 과거 이력을 소급 생성하지 않는다.

## 2. 대용량 이벤트 이력·로그 조회

**트리거**: 사용 이력·로그인 이력·에러 로그·감사 기록처럼 **행이 계속 쌓이는 표**를 본다.
**필수가 되는 절**: §0 페이징 · §2 조회조건(기간) · §3-2 기본 정렬.

## 이력 화면은 CRUD 화면이 아니다

| | 업무 화면 | **이력 화면** |
|---|---|---|
| 액션 | R · S · E · X | **R · E 만** — 저장도 행 추가도 없다 |
| 페이징 | offset(총 건수 있음) | **cursor** 를 먼저 검토한다 |
| 기간 | 선택 | **필수** |
| 정렬 | 여럿 | **한 컬럼** |
| 삭제 | 화면에서 | **파기 배치가 한다** |

## 반드시 묻는 것 여섯

1. **총 건수를 보여줘야 하나** — 보여줘야 하면 offset 이고, `COUNT` 비용을 감수한다.
   아니면 **cursor** 다.
2. **기간 상한** — 며칠까지 한 번에 볼 수 있나. **기본값도 함께.**
3. **기본 정렬 컬럼** — cursor 면 **한 컬럼만** 가능하다. PK 는 시간 순서가 아니므로
   **시각을 먼저 보고 PK 는 동률만 가른다.**
4. **자동 새로고침이 필요한가** — 필요하면 주기도.
5. **엑셀로 내보내나** — 이력은 전건이 크다. **전체 다운로드의 상한**을 정해야 한다.
6. **상세를 어떻게 보나** — 일반 로그의 긴 전문·스택은 목록과 분리한다. 관리 데이터의 변경 스냅샷은 §1의 별도 이력 메뉴·원 화면 재사용 규칙을 따른다.

## 흔한 누락

| 빠뜨린 것 | 일어나는 일 |
|---|---|
| **기간 필수** | 전건 스캔이 나간다 |
| **cursor 인데 총 건수를 그리라고 적음** | 이 모드는 총 건수가 없다 — 푸터의 그 자리에 **무엇을 넣을지**를 대신 정해야 한다 |
| **정렬을 둘 이상 열어 둠** | 서버가 400 이다. 정렬을 바꾸면 **커서를 버리고 첫 장**으로 간다 |
| **긴 텍스트를 일반 로그 목록에 무조건 적음** | 정렬/그룹 불가·페이지 비용을 놓친다. 전체 구성 이력 예외도 대상 키·페이지 상한을 유지한다 |
| **보존 기간** | 이 화면이 보는 표가 **며칠 뒤 사라지는지**를 사용자가 모른다 |
| **관련 이력과의 연결** | 한 요청이 여러 표에 흔적을 남긴다 — 잇는 키(`TRACE_ID`)를 적지 않으면 화면이 서로를 못 찾는다 |

## 적지 않는 것

커서 네비(`‹ 이전 · 다음 ›`) · 페이지 크기 후보 · 파기 배치 — **전부 표준이거나 다른
기능이다.**
