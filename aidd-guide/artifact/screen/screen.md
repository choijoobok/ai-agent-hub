# 메뉴 화면 워크플로 — **①~⑥** · 승인까지 **일곱 단계**

> **승인 전에는 아무것도 만들지 않는다**(AGENTS.md §6.3). 이 문서는 *그 승인에 도달하는
> 절차* 이고, 요건서의 **형식은 [`aidd-guide/artifact/template/02-requirements.md`](../template/02-requirements.md)**
> 가 갖는다.

## 메뉴 화면 작업의 **유일한 순서**

> **단계를 건너뛰지 않는다.** 특히 **③ 승인 전에는 소스를 건드리지 않는다**(AGENTS.md §6.3).
> **이 문서가 갖는 것은 ①~③ 이다** — ④ 뒤는 오른쪽 칸의 링크가 갖는다.

```
① 요건 정의서 ──→ ② 목업 ──→ ③ 사용자 승인 ──→ ④ 개발 · 테스트 ──→ ⑤ 사용자 직접 테스트 ──→ 완료
      ↑                          │                                          │
      └────── 반려 · 수정 ────────┘                                          │
      └──────────────────── ⑥ 개선 · 보완 요청 ────────────────────────────┘
```

| 단계 | 누가 | 무엇을 | 넘어가지 못하는 조건 |
|---|---|---|---|
| **① 요건 정의서** | **AI** | `requirements.md` — 컬럼·조회조건·버튼·검증·상태 전이·영향 테이블·API · **테스트 케이스**(정상·경계·거부). 모르는 것은 **묻거나 `ASM-###` 으로 적는다**(지어내지 않는다) | — |
| **② 목업** | **AI** | `/mockup` 이 `mockup.html` 을 **①에서 생성한다** — 배치·상태의 그림 | **①이 없으면 시작하지 않는다.** 목업이 요건서에 없는 것을 그리게 되면 **①을 먼저 고친다** |
| **③ 승인** | **사용자** | 두 문서를 확인하고 승인하거나 반려한다 | **승인 없이 BE·FE·시드 착수 금지** |
| **④ 개발 · 테스트** | **AI** | 소스 · **시드(④-a·④-b)** · `manual.md` 를 만들고 **게이트(AGENTS.md §7)를 초록으로** 만든다 → [playbook](../../playbook/INDEX.md) | **게이트가 초록이 아니면 ⑤로 넘기지 않는다** |
| **④-a 생성 시드** | **AI** | 선언을 고친 **직후** `./gradlew generateSeeds` — 메뉴 · API · 메시지 **키** → [standard/seed.md](../../standard/seed.md) | **손으로 고치지 않는다** — 훅이 차단한다. `checkSeeds` 가 초록이어야 한다 |
| **④-b 손으로 쓰는 시드** | **AI** | 메시지 **값** · 코드 · 권한 · 시퀀스 · 스키마 — `data/` 마지막 번호+1 로 **새 파일**, **`master` 에 include**, 캐시 버전 → [playbook/changeset.md](../../playbook/changeset.md) | **이미 적재된 changeset·CSV 를 고치지 않는다** |
| **④-c E2E 판정** | **AI → 사용자** | 사람 몫으로 남은 케이스를 세어 **3옵션으로 묻는다** — 지금 짠다 / ⑤ 뒤로 미룬다 / 짜지 않는다 → [quality/test-design.md](../../quality/test-design.md) | **묻지 않고 ⑤ 로 넘기지 않는다.** 다만 **E2E 로 잠글 것이 없는 화면은 물을 것이 없다** — 그냥 넘긴다 |
| **⑤ 사용자 테스트** | **사용자** | 실제로 화면을 써 본다 | **AI 의 게이트 초록이 이것을 갈음하지 않는다** — 돌아간 것과 쓸 만한 것은 다르다 |
| **⑥ 개선 · 보완** | **사용자** | 고칠 것을 말한다 → **①로 돌아간다** | **요건이 바뀌면 요건서부터 고친다** |

- **①과 ②는 한 번에 낸다.** 승인은 *둘을 함께* 보는 판단이다 — 요건서만 승인받고 목업에서 뒤집히면 승인이 무효가 된다.
- **②는 커밋에 담기지 않는다**(AGENTS.md §4-5). 새로 클론한 트리에 **없는 것이 정상**이고, 승인을 위해 필요하면 그때 만든다. `/manual-site` 전에 실제 캡처가 없으면 먼저 만든다 — 검토본의 화면 그림이 목업에서 나온다.
- **`manual.md` 는 ④에서 만든다.** 화면이 서기 전의 사용법은 추측이고, 추측한 메뉴얼은 고칠 곳을 알려 주지 않는다.
- **시드는 AI 가 만든다 — 사용자가 명령을 치지 않는다.** 고친 **그 자리에서** 돌려 같은 커밋에 담는다. **나중에 몰아서 만들면** 시드 커밋이 뒤로 밀려 **고친 사람이 아닌 사람의 PR 이 막힌다**.
- **④-c 는 묻는 자리이지 짜는 자리가 아니다.** E2E 는 **미룰 수 있는 유일한 검사**다 — 비싸고, 잠그는 것을 대개 사람이 대신 볼 수 있다. 나머지 게이트는 미룰 수 없으므로 묻지 않는다. **비용은 시간이 아니라 셀 수 있는 것으로 낸다**(시나리오 수 · 전제) — AI 는 벽시계 시간을 모른다.
- **⑥의 요청이 작아 보여도 ①을 거친다.** *버튼 하나* 가 검증·권한·영향 테이블을 건드리는 일이 흔하다. **다만 문구·정렬처럼 요건이 바뀌지 않는 것은 ④로 바로 간다.**
- **이미 구현된 화면을 문서화할 때는 순서가 거꾸로다**(①이 소스를 따라 쓰인다). 그 문서에는 **역으로 작성했다는 사실을 머리에 적는다** — 그러지 않으면 다음 사람이 그것을 승인받은 요건으로 읽는다.

## ①~③ 의 절차


```
1. 페이지 경로를 정한다        ← 폴더 이름이 여기서 나온다
2. 요건서를 복사한다           cp .../template/02-requirements.md .../{경로}/requirements.md
3. 소스에서 확인한다           표 · 컬럼 · 코드그룹 · 비슷한 화면
4. Overlay 를 고른다           화면 특성 → 반드시 채울 절과 물을 질문
5. 초안을 쓰고 미결을 모은다   §10 에 질문을 모아 한 번에 낸다
6. 목업을 만든다               /mockup 이 요건서에서 생성한다
7. 승인을 받는다               "승인 YYYY-MM-DD" 를 §0 문서 상태에 적는다
```

**목업이 이 절차 안에 있다.** 승인은 *요건서와 목업을 함께* 보는 판단이므로
(AGENTS.md §6.3 — ①과 ②는 한 번에 낸다), 요건서만 승인받고 목업에서 뒤집히면
그 승인이 무효가 된다. **목업을 뒤로 미루면 승인이 두 번 필요해진다.**

## 1. 페이지 경로를 먼저 정한다

**폴더 이름이 페이지 경로이므로**(AGENTS.md §6.1) 이것이 안 정해지면 문서를 놓을 자리가
없다. `screenRegistry.ts` 의 키가 될 값이며 `menu-tree.yaml` 의 `url` 과 1:1 이다.

- **기존 경로와 겹치는지 본다.** 겹치면 새 화면이 아니라 **기존 화면의 변경**이다.
- **경로를 나중에 바꾸면 폴더도 같은 커밋에서 `git mv` 한다.**

## 2. 서식을 복사한다

```bash
cp aidd-guide/artifact/template/02-requirements.md documents/screen/{페이지경로}/requirements.md
```

**서식 폴더를 통째로 복사하지 않는다** — 목업은 `/mockup` 이 만들고 메뉴얼은 구현 뒤에 쓴다.

**섹션을 지우지 않는다.** 해당 없으면 **"없음" 이라고 쓴다** — 빈 칸은 *아직 안 정했다* 와
구별되지 않는다.

## 3. 소스에서 확인한다 — **추측이 시작되는 자리**

| 확인할 것 | 어디 |
|---|---|
| 표와 컬럼이 실제로 있나 | `sources/backend/domain/…/entity/` · [knowledge/sys](../../knowledge/sys/INDEX.md) |
| 코드 그룹이 있나 | 시드 changeset · `SYS_CODE_GROUP` |
| 메시지 키를 새로 만드나 | `sources/frontend/src/shared/i18n/messageKeys.ts` · `MsgKey.java` |
| **비슷한 화면이 이미 있나** | `sources/frontend/src/modules/` · local 전용 샘플 여섯 |
| 페이지 경로가 비었나 | `screenRegistry.ts` |

> **비슷한 화면을 먼저 찾는 것이 이 단계의 절반이다.** 있으면 요건서가 짧아진다 —
> *`/sample/md-vertical` 과 같다* 한 줄이 스무 줄을 대신한다.

**없는 표를 요건서가 만들 수 없다.** 표가 없으면 그것부터가 미결이며 §10 에 적는다.

## 4. Overlay 를 고른다

화면 특성 → [artifact/screen/overlay/INDEX.md](./overlay/INDEX.md). Overlay 는 **요건서의 어느 절이
필수가 되는지**와 **무엇을 물어야 하는지**를 준다.

**둘 이상 겹치는 것이 정상이다** — 마스터-디테일 + 조회조건 + 엑셀은 흔한 조합이다.

## 5. 초안을 쓴다 — 세 가지를 구분해서

| 표기 | 뜻 |
|---|---|
| 그대로 | **사용자가 준 것** — 바꾸지 않는다 |
| 🤖 | **AI 가 보완한 것** — 검토 대상([auto-completion.md](./auto-completion.md)) |
| §10 | **모르는 것** — 미결로 모은다 |

**질문을 한 번에 낸다.** 초안을 다 쓰고 §10 에 모아서 묻는다 — 한 항목마다 멈추면
사용자가 같은 문맥을 여러 번 복원해야 한다.

### 적지 않는 것

- **어떻게** — 컴포넌트명·prop·훅·함수명. 그것은 표준과 구현의 몫이다.
- **이미 표준인 공통 동작** — 그리드 크롬·푸터·페이징·컬럼 필터·감사 기본 합성·조회/저장 흐름·
  권한 게이팅·HTTP 호출 방식. **적으면 표준이 둘이 된다.**
  감사 컬럼의 추가 전용/사용자 명시 제외 분류는 [공통 컬럼 표준](../../standard/frontend/grid-columns.md) §3에 따라 §1에 선언한다.

### 반드시 적는 것

**해석 여지를 없애는 식별자**: DB 테이블·컬럼명 · 공통코드 그룹 · 메시지 키 · 페이지 경로 ·
메뉴코드. 조건·검증·상태 전이는 **컬럼명(+값) 기준**으로 쓴다.

## 6. 목업을 만든다

**요건서에서 생성된다** — 손으로 만들지 않는다.

```bash
node .claude/skills/mockup/scaffold.mjs {화면} > documents/screen/{화면}/mockup.html
```

골격이 개요 바 · **테스트 케이스 표** · 확인 목록까지 담고 나온다(요건서 §0 · §테스트 케이스 · §미결).
**남는 일은 그림이고 그것만 그린다** — 절차의 상세는 [`/mockup`](../../../.claude/skills/mockup/SKILL.md) 이 갖는다.

- 그림이 요건서에 없는 것을 말하게 되면 **요건서를 먼저 고친다** — 목업은 다시 생성되므로
  여기에만 적은 규칙은 유실된다. 그러면 승인받은 것과 만들 것이 갈린다.
- 담는 것은 **배치와 상태**다. 구현 코드와 실제 데이터는 담지 않는다(AGENTS.md §6.2).
- **테스트 케이스 표와 확인 목록에 손대지 않는다.** 요건서에서 온 것이다.
- 메뉴얼이 실을 화면에는 `data-manual="키"` 를 단다 — **골격이 필요한 키를 다 적어 준다.**
- 끝나면 `node .claude/skills/mockup/scaffold.mjs --check {화면}` 이 초록이어야 한다.

**목업 신설·수정의 완료에는 최종 HTML 산출물 갱신을 포함한다.** 사용자는 `build/`의 최종
산출물 페이지에서 검토하므로, 관련 spec 생성물과 변경 목업을 갱신한 뒤 `deliverable-site`로
`build/deliverables/`를 생성·검사한다. 변경 화면은 설계 사이트에 삽입된 상태로도 확인하고
최종 답변에는 해당 산출물 페이지 링크를 안내한다. 검사만 요청받았을 때는 재생성을 강제하지 않는다.

**`manual.md` 는 여기서 쓰지 않는다** — 화면이 선 뒤다(AGENTS.md §6.3 ④).

## 7. 승인

- §0 의 **문서 상태**에 `승인 YYYY-MM-DD` 를 적는다.
- **§10 이 비어야 승인이다.** 미결이 남은 채 착수하면 그 항목은 **구현이 임의로 정하게 된다.**
- 승인 뒤에는 [playbook](../../playbook/INDEX.md) 으로 넘어간다.

## 요청이 모호할 때 — 묻는 다섯

```
- 페이지 경로: /{...} 로 하면 되나?
- 화면 유형: 단일 그리드 / 마스터-디테일(상하·좌우) / 디테일 탭 / 대시보드?
- 처리 유형: 조회 전용 / CRUD / 실행?
- 대상 표: {...} 가 맞나? 없으면 새로 만드나?
- 쓰는 액션: R · S · E · X 중 무엇인가?
```

**이 다섯이 정해지지 않으면 §0 을 채울 수 없고, §0 이 비면 나머지 절이 전부 흔들린다.**

## 기존 화면을 고칠 때

**새 문서를 만들지 않는다.** 그 화면의 요건서를 열어 **달라지는 절만** 고치고, §11 변경 이력에
한 줄 적는다. 소스와 **같은 커밋**에 담는다.
