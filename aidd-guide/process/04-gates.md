# 게이트 — AI의 과속 방지턱

## 1. 게이트 통과 4단계

게이트는 사용자가 "다음"이라고 말한다고 열리지 않는다. 아래 4단계를 순서대로 밟는다.

```
① Exit Criteria 체크   AI가 체크리스트를 항목별로 충족/미충족 판정 (근거 파일 경로 포함)
        ↓
② [QA-레드팀] 자기반박  AI가 자기 산출물을 공격 (실패 시나리오 3 / 누락 / 사용자가 반대할 지점)
        ↓
③ 결정 카드 + 역질문    사용자가 실제로 결정한 것 3~5줄(업무 언어) + AI가 확신 없는 것 1~2개 질문
        ↓
④ 사용자 승인 요청     미충족 항목 + 레드팀 지적 전문 + 남은 ASM 목록을 함께 제시
        ↓
⑤ 상태 갱신           gates.P?.status = approved, approved_at, cognitive_debt 카운터 갱신
```

②를 건너뛴 승인 요청은 무효다. AI는 자기 산출물을 반드시 먼저 공격해야 한다.
③도 건너뛸 수 없다. 사용자가 이해하지 못한 승인은 품질 장치가 아니라 책임 이전이다.
→ [10-cognitive-debt.md](./10-cognitive-debt.md)

모든 게이트의 공통 선행조건은 **승인 범위의 `pending_rechecks` 0건**이다. 다른 작업흐름은 막지 않으며 범위 판정은 [14-collaboration.md](14-collaboration.md)를 따른다.

## 2. 게이트별 Exit Criteria

### G0 — 착수 게이트 (P0 → P1)
- [ ] 시스템의 **목적**이 한 문장으로 정의됨 (`왜 만드는가`)
- [ ] **성공 기준**이 측정 가능한 형태로 3개 이내 정의됨
- [ ] **범위 안(In)** 과 **범위 밖(Out)** 목록이 각각 존재함 ← Out이 비어 있으면 미충족
- [ ] 이해관계자와 액터가 식별되고 각자의 목적이 기록됨
- [ ] 제약사항(예산·기한·기술·조직·규제)이 기록됨
- [ ] 트랙(Lite/Standard/Full)이 결정됨
- [ ] 기존 시스템 유무와 대체/연동 여부가 확인됨
- [ ] **기대치 정렬 완료** — J-커브·검증 비용을 설명하고 `charter.expectations.user_priority`(speed/quality/balanced)를 받음 → [11-verification-cost.md](./11-verification-cost.md) §2

### G1 — 요구사항 게이트 (P1 → P2)
- [ ] 모든 요구사항이 `REQ-###` ID를 가지고 `검증 가능한 문장`으로 기술됨
- [ ] 모든 FR이 최소 1명의 액터와 1개의 프로세스 단계에 연결됨
- [ ] NFR이 카테고리별로 존재 (성능·가용성·보안·확장성·운영성·규정준수)
- [ ] 용어사전에 업무 용어가 정의되고, 요구사항 문장이 이 용어만 사용함
- [ ] To-Be 프로세스가 정의되고, 각 단계에 담당 액터가 지정됨
- [ ] **범위 밖 목록이 P0 대비 갱신됨** (요구사항 도출 중 나온 "이번엔 안 함" 항목)
- [ ] 우선순위(MoSCoW)가 부여됨. **Must 70% 상한은 현재 차수 전체를 모은 전역 G1에서 적용**하고, 작업흐름 G1은 소유 요구사항의 우선순위와 근거를 판정함
- [ ] 요구사항 간 **모순 검사** 수행 결과가 기록됨
- [ ] **요구사항 정련 카드**([P1 §5](../phase/P1-discovery.md))가 작성되고 소유 FR의 `Must`·`Should` 가 `maturity: confirmed` 임 — `/trace --g1` 의 T14 오류 0. **이미 G1 을 승인받은 작업흐름의 카드는 소급 작성 대상이며 경고로만 센다.** 카드 연계가 양방향이고(`depends_on`↔`constrains` · `conflicts_with`) `realization` 이 `FEAT.reqs` 와 맞으며, G1·P1 기한의 `open` 이 남지 않음

### G2 — 아키텍처 게이트 (P2 → P3)
- [ ] 되돌리기 비용 High인 모든 선택이 ADR로 기록됨 (대안 2개 이상 + 포기한 것)
- [ ] 기술 스택이 `언어/런타임 · 프레임워크 · DB · 캐시 · 큐 · 인증 · 배포 · 모니터링` 축으로 결정됨
- [ ] 모든 NFR에 **측정 가능한 목표치**가 있거나, 목표를 미룬 **명시적 결정(`ASM-###`)과 측정**이 서 있음 — 전 항목에 `measurement`(무엇)와 `source`(어디)가 있고 `T7`이 잠근다. **재기 전에 세운 목표는 근거가 없고 게이트에서 협상 대상이 된다.**
      *미룬다는 결정 없이 비어 있는 것* 과 *미루기로 하고 재는 장치를 세운 것* 은 다르다.
- [ ] 시스템 컨텍스트 다이어그램(C4 Level 1) + 컨테이너 다이어그램(Level 2)이 존재
- [ ] 외부 연동 대상별 방식·프로토콜·데이터 소유권이 정의됨
- [ ] 인증/인가 방식이 결정되고 권한 모델(RBAC/ABAC 등)이 정해짐
- [ ] 개인정보/민감정보 취급 항목과 처리 방침이 정의됨
- [ ] **운영 주체와 배포 환경**이 확정됨 (누가 운영? 어디에?)

### G3 — 설계 베이스라인 게이트 (P3 → P4) ★가장 중요★
- [ ] 모든 FR이 최소 1개의 `FEAT-###` 로 실현됨 (미실현 REQ = 0)
- [ ] 모든 `FEAT-###` 이 상위 `UC-###`/`REQ-###` 로 역추적됨 (고아 기능 = 0)
- [ ] 모든 UC에 **기본 흐름 + 대안 흐름 + 예외 흐름**이 존재 (예외 없는 UC = 미충족)
- [ ] ERD의 모든 엔티티에 PK·필수여부·이력정책·삭제정책이 명시됨
- [ ] 모든 API가 `FEAT` 에 연결되고, 요청/응답/에러코드가 정의됨
- [ ] 모든 화면이 `FEAT` 에 연결되고, 화면별 액션·권한·유효성 규칙이 정의됨
- [ ] 핵심 UC(최소 3개)에 시퀀스 다이어그램 존재
- [ ] 모든 FEAT에 최소 1개의 `TC-###` (정상 1 + 예외 1 이상)
- [ ] 추적성 검사(`/trace`) 오류 0건
- [ ] **미해결 `ASM-###` 이 0건** ← 가정을 안고 구현에 들어가지 않는다
- [ ] 슬라이스 백로그가 의존성 순서대로 정렬됨
- [ ] **★ 사용자 승인 후 승인 범위의 spec 베이스라인 동결. 이후 변경은 CR 절차 ★**

### G4 — 슬라이스 미니게이트 (슬라이스마다)
- [ ] 해당 슬라이스의 통합 후 재시험 `pending_rechecks`가 없음
- [ ] 해당 FEAT의 모든 TC가 통과 (skip·xfail 0건)
- [ ] **중요한 위험의 반례 통과** — 변경된 보안·권한·정합성·비가역 동작의 필수 반례 누락 0건. 필요할 때만 집중 규칙 반전 ([`quality/redteam.md`](../quality/redteam.md))
- [ ] **`node .claude/hooks/quality-check.mjs` 통과** — 중복률 ≤5%, 예외 삼킴 0건, `@feat` 미태깅 0개 ([`quality/code-quality.md`](../quality/code-quality.md))
- [ ] 검증 범위·재사용 근거가 [`quality/test-design.md` §0](../quality/test-design.md)에 맞음. 자동 변이·고정 점수·비영향 전수 반복은 필수 아님
- [ ] DB 변경이 있으면 마이그레이션 스크립트 존재 + 롤백 방법 기재
- [ ] API 변경이 documents/spec/50-api/_index.yaml 과 일치
- [ ] 코드에 `FEAT-###` 주석 태그 존재
- [ ] 구현 중 발견한 spec 오류가 CR로 등록되고 처리됨
- [ ] 사용자 확인(데모 또는 스크린샷/실행 결과 제시)

### G5 — 검증 게이트 (P5 → P6)
- [ ] 현재 차수 필수 작업흐름의 코드 시험·문서 재검토 `pending_rechecks`가 없음
- [ ] 전체 TC 실행률 100%, 통과율이 합의 기준 이상
- [ ] NFR 목표치별 실측값이 기록됨 (측정 안 한 NFR = 미충족)
- [ ] 결함 대장의 Critical/High 잔여 = 0
- [ ] Medium 이하 잔여 결함이 사용자와 합의됨 (`알려진 이슈`로 문서화)
- [ ] 추적성 매트릭스가 REQ→TC까지 완결 (테스트 없는 REQ = 0)
- [ ] 테스트 수행 결과서 작성 완료

### G6 — 인도 게이트 (P6 → 완료)
- [ ] 배포가 재현 가능한 절차로 문서화됨 (수동 단계 포함 전부)
- [ ] 운영 런북: 장애 대응, 백업/복구, 모니터링 지표, 정기 작업
- [ ] 사용자 매뉴얼이 메뉴 구조 순서로 완결
- [ ] 설계·사용자·운영 세 사이트가 고객 브라우저에서 열리고, 실제 PNG로 `/deliverable-site --release` 통과
- [ ] 데이터 이행이 필요하면 이행 결과 검증 완료
- [ ] **운영 인수 시험 통과** — 사용자가 런북·매뉴얼을 보고 아래 3개에 답할 수 있음
      (① 로그인 장애 시 어디를 먼저 보는가 ② 데이터 복구 절차 ③ 신규 사용자 권한 부여 방법)
      답하지 못하면 **사용자가 아니라 문서의 결함**이다. 보강 후 다시 확인한다
      → [10-cognitive-debt.md](./10-cognitive-debt.md) §6
- [ ] 인수 확인서에 사용자 서명(승인 발화)

> 운영 인수 시험. 인지 부채라는 문제 자체와 설계 원칙 다섯도 거기 있다.

## 5. 차수와 게이트 — **한 벌이 차수마다 돈다**

**축이 둘이고 글자가 같다.** 로드맵 차수(`RM-P1`~`RM-P4`)는 *무엇을 내는가* 이고 방법론
단계(`P0`~`P6`)는 *어디까지 만들었는가* 다. **차수 하나를 내기 위해 단계를 한 바퀴 돈다**
(`documents/spec/50-api/_index.yaml` `roadmap_notes`). 그러므로 위 게이트 일곱도 **차수마다
한 벌** 돌고, `project.state.yaml` 의 `gates` 는 언제나 **현재 차수(`current.roadmap`)의
것**이다.

모듈별 프로젝트는 전역 한 벌 아래 `workstreams`를 둔다. **작업흐름 G3가 소유 기능의 구현만
연다.** 전역·작업흐름 게이트의 역할과 상태 형식은 [13-workstreams.md](13-workstreams.md)가 갖는다.

### 차수를 넘길 때 (`G6` 승인 직후)

1. 현재 `gates` 를 `roadmap_closed` 에 **한 줄로 접는다** — `{ roadmap, closed_at, note }`.
2. 일곱을 `not_started` 로 되돌리고 `current.roadmap` 을 다음 차수로, `current.phase` 를
   `P0` 로 놓는다.
3. **`G0` 를 백지에서 다시 하지 않는다.** 헌장은 제품 전체의 것이고 차수가 바꾸는 것은
   범위다 — 2차수부터의 `G0`·`G1` 은 **달라진 것만** 본다. 달라진 것이 없으면 그렇게 적고
   넘긴다. *다시 물었다* 와 *처음부터 물었다* 는 다르다.

### 뒤 차수는 게이트를 막지 않는다

`FEAT`·`NFR` 은 `roadmap: RM-Pn` 을 갖고, **아직 오지 않은 차수의 결손은 오류가 아니라
순서다.** `T5`(FEAT→TC)와 `T7`(NFR 측정)이 그것을 **경고로 내린다**
([05-traceability.md](./05-traceability.md)) — 오류로 세면 `RM-P1` 의 `G3` 가 `RM-P4`
때문에 영영 열리지 않고, 열려면 **아직 설계하지 않은 것의 테스트를 지어내야** 한다.
기준은 `current.roadmap`과 소유 작업흐름 G3다. 뒤 차수·G3 전 결손은 경고로 내리되,
**값이나 소유권을 읽지 못하면 낮추지 않는다** — 모른다는 이유로 게이트를 비우지 않는다.

## 6. 게이트 되돌리기

이전 게이트로 되돌아가야 할 때(요구사항 오류 발견 등):
1. `[PM]` 모자로 **되돌림 영향 분석**을 먼저 제시 — 폐기될 산출물, 재작업 범위, 대안
2. 사용자 승인 후 해당 게이트 status를 `in_progress` 로 되돌린다
3. 그 이후 게이트도 전부 `in_progress` 로 내린다 (승인 상태를 남겨두지 않는다). 작업흐름 내부 변경은 그곳과 영향받는 계약만 내리고, 경계를 넘을 때만 전역 게이트를 내린다([13-workstreams.md](13-workstreams.md) §7).
4. `documents/decisions/CHANGES.md` 에 CR로 기록한다
