# 목업 — 요건서에서 생성한다

**목업은 파생물이다.** 결정도 테스트 케이스도 [`requirements.md`](../../../aidd-guide/artifact/template/02-requirements.md) 가 갖고,
목업은 그것을 **설계자가 눈으로 확인하는 그림**이다. 그래서 규칙은 하나다 —

> **목업을 고쳐 요건을 바꾸지 않는다.** 고칠 곳은 요건서고, 고친 뒤 이 스킬을 다시 돌린다.

형식은 [`aidd-guide/artifact/template/03-mockup.html`](../../../aidd-guide/artifact/template/03-mockup.html) 이 갖는다.
**이 스킬은 형식을 재정의하지 않는다** — 순서와 판정만 정한다.

`.gitignore` 대상이므로 **새로 클론한 트리에는 목업이 없다.** 없는 것이 정상이고, 필요할 때 만든다.

브라우저 검토용 임시 스크립트·로그·캡처는 [빌드 안내](../../../aidd-guide/artifact/site-kit/BUILD-README.txt)의 작업별 경로에 둔다. `build/` 최상위에 쌓지 않는다.

## 0. 대상을 확정한다

```bash
node .claude/skills/mockup/scaffold.mjs --list
```

화면별로 요건서·목업·메뉴얼이 있는지와 **메뉴얼이 부르는 그림 키가 몇 개인지**를 낸다.

- 화면은 폴더 이름으로 받는다 — `log/access` · `access` · `user`.
  **맨 앞에 `/` 를 붙이지 않는다** — Git Bash 가 그것을 윈도 경로로 바꿔 버린다.
- **요건서가 없는 화면은 목업을 만들지 않는다.** 그 순서는 거꾸로다(`AGENTS.md` §6 ①→②).
- **`view_kind: change_history`인 이력 화면은 독립 목업을 만들지 않는다.** 원 관리 화면과 [공통 이력 패턴](../../../aidd-guide/artifact/screen/overlay/history-pattern.md)의 읽기 전용 배치·변경 요약·기간 조건을 상속한다. 원 화면에 이력 탭/스냅샷 모달을 덧그리지 않는다.

## ① 생성 — 골격을 받고 그림만 그린다

```bash
node .claude/skills/mockup/scaffold.mjs --write admin/system/log/access
```

골격이 **기계가 만들 수 있는 것 전부**를 담고 나온다:

| 골격이 주는 것 | 어디서 나오나 |
|---|---|
| 공용 `<style>` 블록 | 서식 `03-mockup.html` — **복사가 아니라 인용이다.** 색을 여기에 적지 않는다 |
| 개요 바 | 요건서 §0 메타 표 전 행 |
| 테스트 케이스 표 | 요건서 §테스트 케이스 — **그대로** 옮긴다 |
| 확인 목록 | 요건서 §미결 |
| `data-manual` 키 목록 | `manual.md` 의 `[설명](mockup.html#키)` 줄 |

**생성기는 요건서의 화면 계약을 읽어 그려 낸다.** §2 조회조건, §4 컬럼, §5 버튼 표와
§1의 마스터-디테일 축을 목업의 실제 폼·그리드·스플리터로 옮긴다. 빈 종이·스타일·테스트
표만 있거나, 요건서의 컬럼을 일반적인 `이름·상태`로 바꾼 목업은 만들지 않는다. 요건서에
특화 배치·상태가 있으면 그 사실을 요건서에 먼저 적고 생성기를 확장한다:

1. **요건서 §1 화면 구성의 배치를 그대로 옮긴다.** 요건서에 없는 요소를 그리게 되면 **요건서를 먼저 고친다** — 그것이 유실될 결정이다.
   배치·1:1 컬럼·하단 탭·엑셀 기본값은 [기본 UI 표준](../../../aidd-guide/playbook/master-detail.md) §1과 대조한다.
2. **초기 전체 화면 → 모든 탭·상세 영역 → 요소 상세 설명 한 목록 → 접힌 상태별 예시** 순서로 그린다. 초기 화면의 탭은 실제 클릭으로 영역을 전환하고 같은 상위 대상의 입력·선택을 유지한다. 각 영역 앞에 관리 대상·작업 순서·조회 계기·저장 범위를 설명한다. 탭별 그림에서는 반복되는 상단 목록을 생략한다. 빈·잠긴·편집·검증 실패·권한 없음 등 상태 예시와 메뉴얼 그림 키는 접힌 예시 안에 보존한다.
3. **그리드 어휘 다섯만 쓴다** — `.sf` 검색폼 · `.tb` 툴바 · `.grid` 그리드 · `.pg` 푸터 · `.split` 스플리터.
4. **한 파일로 완결한다.** 외부 CSS·JS·이미지·프레임워크를 쓰지 않는다.
5. **`data-manual` 키를 골격이 시킨 자리에 정확히 단다.** 하나라도 빠지면 `/manual-site` 가 보고한다.
   **키 없는 블록은 그림이 아니다** — 상태별 화면이 메뉴얼에 섞이지 않게 하는 규칙이다.
6. **실제 화면 요소의 번호는 문서 전체에서 공유하고 상세 설명은 모든 탭 그림 아래 한 영역에 둔다.** 초기 화면의 표시 요소부터 DOM 순서로 연속 번호를 부여한다. 기본 숨김 컬럼·다른 탭·닫힌 편집창·상태 전용 요소는 그 뒤 번호를 쓰고 같은 설명 영역의 접힌 추가 설명에 둔다. 초기 화면 번호·설명 목록·툴팁/접근성 번호를 함께 검사한다. 조회조건·버튼·탭·그리드 제목과
   컬럼은 `data-note="item-{순번}"`으로 표시하고, 하단 `id="note-item-{순번}"`에서 요건서의
   동작·입력·검증 의미를 설명한다. 같은 요소의 여러 배지는 하나의 설명을 가리킨다. 컬럼/필드는 설명·필수 시점(저장/행 존재/검수 전)·편집 조건·선택 출처·검증/실패 처리·예시를 분리해서 적는다. 읽기 전용은 입력 대상 아님으로 표시하고 미확정 길이/범위를 추정하지 않는다.
7. **그리드 툴바·행 상태는 샘플 실물과 공통 표준을 따른다.** [grid.md](../../../aidd-guide/standard/frontend/grid.md) §2~5와 system/sample 화면을 읽는다. 조회조건에는 초기화만 두며, 모든 그리드의 제목·건수는 왼쪽, 조회 → 행 추가 → 저장 → 업무 버튼 → 엑셀/설정은 상단 오른쪽이다. `columnDefs.tsx`의 번호 → 다중 선택 체크박스 → 편집 상태 → 업무 컬럼 → 삭제 순서와 노출 조건을 따른다. 앞 시스템 컬럼은 왼쪽, 삭제는 맨 오른쪽에 고정한다. 읽기 전용에는 상태가 없고 삭제 금지 행은 사유만 표시한다. 별도 수정 버튼 없이 초기 화면에서 편집 가능한 셀을 더블 클릭해 입력한다. 단순 값은 셀 안에서, 검색콤보·장문·설정은 해당 셀 편집기에서 처리하며 읽기 전용/제출본/현재 권한 잠금을 유지한다. 편집 그리드의 상태·삭제 컬럼을 생성하고 신규/수정/삭제·되돌리기를 시연한다. 툴바에 편집 취소 버튼을 두지 않으며 수정 행의 상태 컬럼 되돌리기로 해당 행만 원복하고 다른 행의 입력·선택을 유지한다. 기존 행 삭제는 저장 전 표시, 신규 행 삭제는 즉시 제거이며 참조 보호·권한·상태 잠금을 지킨다. 요건서의 영역별 저장 범위를 참조하고 하위 저장 버튼으로 독립 저장 계약/API를 만들지 않는다. 저장·신청·판정 동작의 종류는 화면 계약을 따른다. 철회된 절차를 버튼 이름이나 과거 목업에서 추정해 다시 만들지 않는다. 모달의 업무 입력/판정 버튼은 공통 모달 푸터 배치를 따른다.
8. **테스트 케이스 표와 확인 목록은 손대지 않는다.** 요건서에서 온 것이며, 여기서 고치면 다음 생성에서 사라진다.

요건서 §1의 **목업 상태 표**가 있으면 메뉴얼 작성 전에도 그 그림 키·상태·상세 영역·안내·허용 버튼·편집 상태를 생성한다.
표의 형식은 `02-requirements.md`가 정한다. §4의 `— 폼` 표제는 상세 입력 폼으로, 나머지는 그리드로 그리며
`예시` 열은 검토용 값이다. 선언한 상태·컬럼/폼 라벨·공통 스타일이 빠지면 `--check`에서 거부한다.
입력방식 `검색콤보`는 서식의 `후보 예시`로 검색·선택을 구분해 그린다. 검색 문자열은 선택값을 바꾸지 않는다.
`스냅샷 뷰어`는 JSON 예시와 같은 그리드의 `snapshotVersion`으로 읽기 전용 속성/값·배열 목록·원문 보기를 만든다. 해석 실패를 빈 정상 데이터로 표시하지 않는다.
상태 표의 선택 `빈 그리드` 열은 §4의 그리드 이름을 세미콜론으로 나열한다. 해당 상태의 문맥 밖 자식에 예시 행을 넣지 않으며, 잘못된 이름은 거부한다. 읽기 전용 장문 셀도 전체 내용 뷰어로 연다.

목록 선택에 따라 하단을 바꾸는 화면은 §1의 `목록 연동`·`대상 편집 조건`과 행 예시의 문맥으로 선택 대상/잠금을 선언한다. `목업 계산`은 곱셈·합계·비율(최종 버림 포함)의 시연만 허용하며 산식 정본과 연결한다. 계산열은 입력 변경 판정에서 제외하고, 미상/0분모는 `산정 검증 버튼`의 저장 등 명시 동작을 막는다. `행 추가 참조`는 조회조건·대상/단가 컬럼·정적 참조 예시로 같은 대상의 유효 단가와 중복을 검사하며 없으면 행을 만들지 않는다. `저장 후 실행 버튼`은 선택 월의 미저장 변경이 있을 때 막는다. 다른 대상의 입력·고정 스냅샷·상태 예시가 섞이지 않는지 독립 목업과 HTML 삽입본에서 검증한다. 제품 조회·집계·금액 정밀도·고정을 대신하지 않는다.

`셀 위 텍스트영역`은 system/sample의 `largeText`처럼 더블 클릭으로 textarea를 셀 위에 열고 Enter는 줄바꿈, Ctrl+Enter/포커스 이동은 반영, Esc는 원복한다. 읽기 전용은 전체 내용만 본다. 조회 결과 `스위치`는 직접 변경하지 않으며 미상은 꺼짐으로 바꾸지 않는다. `배분 유효성`은 명시한 계산 입력이 바뀔 때 예정 결과를 낡음으로 표시하고 메모만 바뀌면 유지한다. 원복·다른 행/탭 입력·독립 목업/HTML 삽입본을 함께 검사한다.

입력용 `설정 스위치`는 실제 공통 그리드처럼 한 번 눌러 편집본만 변경한다. 행 상태·원복·그룹/탭별 입력을 유지하며 현재 권한·행 조건·잠긴 대상에서는 비활성화한다. 조회 결과 `스위치`와 미상 값은 편집 가능으로 바꾸지 않으며 실제 저장·접근 효력은 요건서의 소유 계약을 따른다.
여부형 컬럼의 표현은 [공통 컬럼 표준](../../../aidd-guide/standard/frontend/grid-columns.md)의 스위치 규칙을 따른다.
한 화면에서 그룹 정의 저장과 자산 매핑 저장을 함께 제공하면 §1의 영역별 버튼으로 각 그리드의 저장 슬롯을 구분한다. 하단 편집을 상단 그룹 정의의 저장 단위에 자동 포함하지 않는다.

값은 **그럴듯한 예시**로 채운다 — 실제 데이터가 아니라 *이 화면이 무엇을 어떻게 보이나* 를 말하는 값이다.
문구를 인용할 때는 `db/changelog/data/*-init-message.csv` 의 `ko` 값을 쓴다. 화면에 뜨지 않는 말을 그리면 확인이 헛돈다.

## ② 검사 — 어긋난 것을 찾는다

```bash
node .claude/skills/mockup/scaffold.mjs --check              # 전수
node .claude/skills/mockup/scaffold.mjs --check log/access    # 하나
```

신규·수정 요건서는 `/menu-doc`의 요구사항 매핑 검사도 먼저 통과시킨다. 화면의 일부 지원을 요구사항 전체 충족으로 표현하지 않는다.

다음을 본다. **전부 어긋남이지 취향이 아니다:**

| 검사 | 어기면 무엇이 깨지나 |
|---|---|
| 메뉴얼이 부르는 그림 키 ↔ 목업의 `data-manual` | `/manual-site` 가 그림 없는 자리를 만든다 |
| 요건서의 케이스 ID ↔ 목업의 케이스 ID | 목업이 케이스를 몰래 늘렸다 — 요건서로 옮긴다 |
| 외부 CSS·JS·이미지 | 파일 하나만 열었을 때 깨진다 |
| 생성물 표식 | 손편집을 부른다 |
| `.screen` 화면 블록 | 스타일·표만 있고 실제 화면이 없는 목업을 막는다 |
| 요건서 §4 컬럼 ↔ 목업 그리드 헤더 | 컬럼 계약이 그림에서 사라지는 것을 막는다 |
| `data-note` 배지 → `note-*` 상세 설명 | 같은 요소는 동일 번호, 설명 목록은 하나. 누락·고아 설명과 설명 ID 중복을 막는다 |

**요건서를 고쳤으면 검사가 아니라 재생성이다** — ①을 다시 돌린다.

## ③ 최종 HTML 산출물까지 생성한다

완료 기준은 [화면 절차 §6](../../../aidd-guide/artifact/screen/screen.md#6-목업을-만든다)을 따른다.
신설·수정한 목업을 검사한 뒤 `/deliverable-site`를 이어서 수행한다. 관련 spec이 바뀌었거나
생성 문서가 없거나 낡았으면 `/doc-gen`으로 먼저 갱신한다.

```bash
node .claude/skills/doc-gen/gen.mjs
node .claude/skills/runbook/check.mjs
node .claude/skills/deliverable-site/build.mjs all
node .claude/skills/deliverable-site/check.mjs
node .claude/skills/deliverable-site/browser-check.mjs design
```

변경 화면의 요건·목업이 최종 설계 사이트에 실렸는지와 해당 화면의 선택·탭·편집 상태를
브라우저에서 확인한다. 최종 답변의 검토 링크는 `build/deliverables/design/index.html`의
해당 화면 페이지로 안내한다. 개별 `mockup.html` 생성만으로 완료라고 보고하지 않는다.

### 사용자 매뉴얼과의 연결

```
requirements.md ──/mockup──> mockup.html ──/manual-site──> build/deliverables/user/
```

목업이 형상 관리에 없으므로 **메뉴얼 사이트를 만들려면 목업이 먼저 있어야 한다.**
`--shots=png`(캡처만)로 돌리면 목업 없이도 되지만, 캡처가 없는 화면은 그림 없이 나간다.

전수로 만들 때:

```bash
for s in $(node .claude/skills/mockup/scaffold.mjs --list | sed -n '2,$p' | awk 'NF>2{print $1}'); do echo "$s"; done
```

**한 번에 다 만들지 않는다.** 자동 골격도 화면마다 요건서 §1의 배치와 대조한다. 상세 배치가
부족하면 먼저 요건서를 고치고, 화면 하나를 만들고 `--check`로 확인한 뒤 다음으로 간다.

## 넘어가지 못하는 조건

- **요건서 없이 목업을 만들지 않는다**(`AGENTS.md` §6 — ①이 없으면 ②를 시작하지 않는다).
- **목업에만 있는 규칙을 남기지 않는다.** 그림을 그리다 결정이 필요해지면 **요건서에 적고 나서** 그린다.
- **최종 HTML 갱신을 생략하지 않는다.** HTML 조립은 `/deliverable-site`로 수행하며 사용자 매뉴얼 정본은 `/manual-site`의 경계를 따른다.
